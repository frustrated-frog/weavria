# 记忆联合审查的实现与对照实验

本轮新增 `JointMemoryEvidenceAssessor`，将所问内容和记忆证据在一次模型调用中联合判断，复用已有条件图、供给协议、上下文预算和 Session 持久化。最终 32 个公共定向请求中状态判断全部正确；结果支持继续使用这条研究路线，不足以证明复杂真实任务也达到相同水平。

## 解决了什么问题

上一轮的首轮分解把“文档应该导出成什么格式”扩展成“内容类型、兼容性、导出选项”等规划前置条件，又把这些额外问题当成必须找齐的证据。第二轮还可能编造条件键。两次调用之间增加了错误传播，独立复核并没有自动带来更高准确率。

新机制缩小模型可编辑的空间：答案项必须来自用户原句；条件只能从已有记忆的封闭目录中选择；宿主依据这些有限关系计算状态。模型仍需完成真正的语义判断，宿主没有预先标注每题答案项、相关事实或适用条件。

## 请求如何流转

1. `MemoryContextSource` 取得已有授权和时间策略约束下的完整事实族。
2. `memory_joint_evidence.py` 的 `_input` 生成成员表、事实族及来源表、条件编号目录。条件按原始键和规范 JSON 值去重，`true` 与 `1` 不会合并。每个成员保留实际版本、文本、权威性、状态和有效时间。
3. 模型返回原句分区、逐答案项的固定角色向量、稀疏引文和条件判断。原句片段必须按顺序逐字拼回原始请求，包括空格与标点；每个答案项恰好拥有一个非空白片段。公共情境可以供多个答案项使用。
4. 宿主校验向量长度、引文身份、逐字定位、条件目录和情境归属，将有效关系翻译为原有条件图的有限边。
5. `memory_evidence_reduction.py` 由两种策略共用，统一归约为支持、缺失、条件未知、冲突或未验证；不接受模型直接写最终状态。
6. 现有 Context 编译器处理完整组的预算分配，证据落选则降为 `omitted`。现有 Session 包络重建和 SQLite 校验保证模型收到的判断与持久化报告一致。

这里增加了小型 `MemoryEvidenceAssessor` Protocol。原两轮 `ModelMemoryEvidenceAssessor` 和新联合策略都可接入 `HarnessMemory.evidence_assessor` / `MemoryContextSource.evidence`，不需要改 Memory Store、Runtime 或领域应用。

## 关键数据结构与条件语义

以“内部报告用什么语言？外部报告用什么语言？”为例，模型返回两个原文片段，分别属于答案项 0 和 1。两项可以读取同一个完整事实族，但各自只能根据自己的片段和公共情境判断条件，不能借另一项的场景。

若事实表有七个成员，每个答案项必须返回长度为七的 `roles` 向量；第 i 个位置固定对应成员 i。`direct` / `conflict` 位置必须恰有一条引文，`background` 不需要重复空引文对象。可见 JSON Schema 的 minItems/maxItems 就是本批实际成员数。引用表重复、缺失、越界或引文不存在，整批审查均无效。

条件目录形如 `0: audience=internal`、`1: audience=external`。模型只能返回编号、关系和原句片段依据：

- `entails`：所问情境满足这个条件；
- `disjoint`：所问情境排除这个条件；
- `unknown`：无法从当前题目情境确定，必须没有肯定依据。

直接支持或冲突成员使用的所有限定都必须出现。背景成员的无关条件允许省略；这是按角色缩减无关判断，不是把没有判断的相关条件默认设为成立。完整角色向量仍检查所有成员，包括例外和争议。

每个答案项的题目情境作为一个整体合取前提进入条件图。不能将 `A∧B → C` 错记为 `A → C` 与 `B → C`。内部前提键避开所有目标限定键，防止意外同名同值绕过模型判断形成恒等边。生成边仍是低信任语义判断，图闭包只保证相对于这些输入的执行正确性。

`given_conditions` 在联合策略报告中保存的是原文情境锚点，不是被写入长期记忆的新事实。它与条件边、成员版本、引文摘要一起用于解释与重算。本策略只记录一次调用的 `review_sha256`，`proposal_sha256` 保持空，不伪造独立复核。

## 有界工作与失败行为

继续使用 `MemoryEvidencePolicy`。联合策略对 `答案项数 ×（成员数＋条件目录大小）` 使用保守工作上限，默认 128；每题最多八个答案项、十六个原文片段。输入数据预算默认 128 KiB，结构化输出最大 64 KiB。条件只在相关成员上实际计算，但不借此突破保守上限。

构建目录使用哈希去重；校验和转换的核心成本为 `O(S×M×A)`，S 是总答案项数，M 是成员数，A 是目录大小。在当前工作上限下交叉扫描有界，之后使用已有的条件闭包算法。没有追加后台工作，也没有第二次纠错调用。

输入、输出或工作量超限会明确扣留；漏片段、漏成员、非法引文、未知条件编号及跨情境引用也会扣留。依赖故障产生 `unverified`；取消原样传播并清理调用。模型必须返回现有 ModelProvider 的外层 tool-call 动作包络，无法归一化的返回不会被当成正确缺失判断。

这些额外推理仍记录在源诊断里，尚未纳入 Runtime 主模型 Token 总量结算；默认不开启该能力。最终供给与主模型上下文仍计入完整字节和 Token 预算。

## 如何运行

```python
from weavria.harness import JointMemoryEvidenceAssessor, MemoryContextSource

assessor = JointMemoryEvidenceAssessor(
    provider,
    configuration_id="固定模型和推理配置摘要",
)
source = MemoryContextSource(
    memory_store,
    access=access,
    scope=scope,
    evidence=assessor,
    max_bytes=65536,
)
```

也可将 `assessor` 传给 `HarnessMemory(evidence_assessor=assessor, ...)`。省略配置时行为不变。旧策略仍保留作为对照，不自动迁移宿主的选择。

```bash
uv run pytest tests/memory/test_joint_evidence.py tests/memory/test_sufficiency.py -q
uv run python -m examples.memory_sufficiency --variant all \
  --output /tmp/joint-development.json
uv run python -m examples.memory_sufficiency --variant all \
  --dataset examples/fixtures/memory_sufficiency_holdout.json \
  --output /tmp/joint-regression.json
uv run python -m examples.memory_sufficiency --variant all \
  --dataset examples/fixtures/memory_joint_holdout.json \
  --output /tmp/joint-validation.json
```

真实实验显式使用 `WEAVRIA_MODEL_BASE_URL`、`WEAVRIA_MODEL_NAME`、`WEAVRIA_MODEL_API_KEY`。输出只落仓库外，包含公共材料的结构化动作、分类和允许记录的错误代码，不保存认证信息、原始响应或隐藏推理。

### 保留失败与验证边界

初版联合在开发集为 12/13；失败来自日期项没有填写无关语言条件。随后允许只背景成员的条件省略，但完整成员仍必须审查。再一次同配置对照发现多问句漏成员，以及 HTTP 200 后的输出归一化失败，因此改成固定角色向量、稀疏引文，并明确外层动作包络。没有丢弃这些失败后宣称首次全对，也没有添加自动重试。

新验证集在 v2 首次执行前冻结，首次联合 10/10、旧两轮 7/10、单轮 10/10。最终 v3 的 10/10 是对同一集合的复测；后续修改来自开发/旧回归失败，但仍不能把复测称为新一轮盲测。各版本结果是开发证据，不是严格独立的统计估计，也不是只改变一个变量的因果消融。

这是手工小型充分性数据集，尚未测最终回答、补证行为或长任务完成率。与朴素单轮只差一个开发案例，不能证明普遍准确率更高。明确证明的是一次调用上限和确定性校验；真实结果为减少两轮误拒提供了定向证据。

## 验收与下一步

新增或扩展的 19 个测试覆盖原句丢失、双场景隔离、未知条件、条件目录类型、内部键碰撞、必需条件缺失、引文/成员非法、容量前后边界、取消/超时，以及两种策略共享的主模型交付、预算降级和重开恢复。全量结果 1780 通过、24 项显式 Docker 集成测试跳过，Ruff、格式与 Pyright 通过。

当前仍可能把真正的请求片段错误标为公共情境，或对合法编号作语义错误判断；句法覆盖不等于语义完整。没有实现任意多事实连接、量词逻辑、原始来源再核验、最终答案校验和自动补搜。默认保持关闭。
