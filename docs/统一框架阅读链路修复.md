# 统一框架阅读链路修复

本轮承接 M1-06，目标是让原文阅读、回取、阶段工作记录和最终回答共享同一条可用链路。
设计见 [ADR 0082](decisions/0082-来源语境与可执行阅读反馈.md)。本轮不修改任务、评分、模型、
32K 窗口或原有调用与恢复额度，不据此宣称 M1 完成。

## 一次请求如何流转

1. 工具产出原始 Artifact；SourceIndex 为文本生成精确片段及所在文档、章节、代码作用域。
2. ContextCompiler 按需求词项和明确标识符选择紧凑或相邻原文窗口，实际计量后交给模型。
3. 模型可按问题主动恢复遗漏资料，或按原文地址调用 read_artifact。分页拒绝返回可执行的页长
   建议；成功页返回 next_read，供模型继续原始来源。连续恢复期间保留此前恢复片段，形成
   受原总额度及实际请求容量约束的阅读工作集，避免每轮从头阅读。
4. 模型通过 propose_work 写结论或疑点；宿主绑定本轮视图版本并生成稳定编号。接受流归约后，
   已有工具选择与上下文权重消费工作状态；笔记仍是可错的模型结论。
5. 常规完成路径不变；到达已有收尾边界时，局部原文可以支持 limited 回答，未覆盖的问题和
   未完成的穷举仍然明确保留。

## 剩余问题

M1-06 尚未关闭。多数运行仍不形成工作记录，局部原文解释、默认值与示例区分、最终原文件引用
和结构化结果类型仍不稳定。下一步应以保存轨迹检查“模型可见原文→阶段结论→最终输出”的
具体断点；不要再改题、放大预算、替模型写笔记，或只统计流程完成率。

连续恢复工作集在第三候选真实任务中未被触发（模型选择了工具分页），因此它目前只有确定性
测试、真实失败请求诊断和重放证明，不能单独宣称已有真实收益。

```bash
uv run pytest tests/context/test_structure.py tests/runtime/test_page_advice.py \
  tests/runtime/test_finalization.py tests/harness/test_work_records.py tests/tools/test_execution.py
uv run python -m examples.m1_harness --run --case documents_long_context \
  --env-file /path/to/local.env --out .weavria/m1/new-documents-diagnostic
uv run python -m examples.m1_harness --run --case repository_long_context \
  --env-file /path/to/local.env --out .weavria/m1/new-repository-diagnostic
```

模型输出、数据库和本地配置不提交。通用格式识别仍是启发式，标识符匹配仍属词法检索，工作
记录使用率必须由真实任务验证；确定性测试通过不能替代任务收益。
