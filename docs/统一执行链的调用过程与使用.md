# 统一执行链的调用过程与使用

`AgentHarness` 统一管理 SessionEngine、上下文编译、任务理解与记忆读写。推荐入口 `AgentHarness.from_config` 由框架成套组装这些组件；应用提供模型、工具、授权和能力配置。

当前集成阶段按[统一框架初步成功里程碑](统一框架初步成功里程碑.md)收口：固定三项剩余交付与验收条件，达成后结束本阶段；本文后续建议不能自动扩大里程碑范围。

## 推荐的 Python 接入

```python
from weavria.context import ContextCompilerConfig
from weavria.harness import AgentHarness, HarnessConfig, HarnessMemory
from weavria.runtime import RunLimits

config = HarnessConfig(
    configuration_id="my-agent-v1",
    context=ContextCompilerConfig(window_tokens=64000, output_tokens=4096),
    limits=RunLimits(max_duration=120, max_request_bytes=128000),
    working_records=True,
    memory_write="basic",
)
async with AgentHarness.from_config(
    state_path / "session.db",
    config=config,
    model=session_model,
    tools=tools,
    token_counter=execution_counter,
    reasoning_model=reasoning_model,
    reasoning_counter=reasoning_counter,
    memory=HarnessMemory(state_path / "memory.db", access, scope, "authenticated-author"),
) as agent:
    session = await agent.create("first")
    result = await agent.send(session, user_message, input_id="request-1")
```

示例中的连接、计量器、ToolRegistry、路径和 Memory 授权由宿主提供；完整可运行的构造见下方 CLI。执行输出上限须与 execution_counter 匹配，理解使用 reasoning_counter 自己的输出上限；声明的窗口应同时适用于两种模型。模型连接的关闭由宿主负责。

默认接通任务理解、任务模型视图、动态工具选择、历史选择和原文恢复。工作记录和记忆写入显式开启，运行时按任务需要参与。`memory_write="off"` 配合 Memory 存储表示只读召回；省略存储表示禁用记忆。可用 `task_understanding=False`、`history_retrieval=False`、`context_recovery=False` 关闭对应策略；工作记录依赖任务理解。原文恢复开关不控制普通 read_artifact 工具。

高级策略替换仍可用 `AgentHarness(...)`；推荐工厂接收的 HarnessMemory 不应包含手工构造的形成组件。组合规则与取舍见 [推荐配置与完整链路装配](decisions/0079-推荐配置与完整链路装配.md)。

## 入口与运行

可运行的领域无关入口为 `examples/harness_session.py`。它接收任意用户问题，可选读取指定目录内的 JSON 文档，没有内置领域流程。

```bash
# 先设置 WEAVRIA_MODEL_BASE_URL、WEAVRIA_MODEL_NAME、WEAVRIA_MODEL_API_KEY。
# 以下命令会调用真实模型；数据库仅保存在本地 .weavria 下。
uv run python -m examples.harness_session --session first \
  --message '本项目文档默认使用中文，请记住这个长期约定。' --memory
uv run python -m examples.harness_session --session second \
  --message '这个项目的文档语言约定是什么？' --memory --understand
```

启用 `--understand` 才进行结构化任务理解。启用 `--memory` 才形成和召回长期记忆。默认执行普通 AgentLoop 和联合上下文编译。`--documents` 可添加只读文档工具。工具实际选择、调用与反馈继续由模型和 Runtime 决定，不按问题关键词预编排执行路径。

此示例是调用入口，不是效果评测。模型可能不提取、不准入或错误解释约定，应结合返回的记忆处理状态和数据库中的来源检查，不能由一次回答正确推断记忆成熟。

## 沿代码阅读一次请求

1. `harness/assembly.py` 的 `send`：占用会话，续接旧记忆游标，再把请求交给原 SessionEngine。
2. `sessions/engine.py` 的 `send`：持久接受输入，查询相关记忆，调用可选的 TaskAwareSessionPreparer。模型看到的是来源数据，不是新增系统指令。
3. `runtime/agent.py` 的 `_prepare_ordinary_context`：接收 TurnPreparation，安装本轮工具视图与工作状态；`build_control_request` 联合选择历史、工具结果和记忆。后续能力变化必须有新 epoch。
4. 工具执行后进入 `_prepare_turn_settlement`：`settle_turn` 将已接受的工具记录归约成新 Need Ledger 和能力视图，然后可选计算进展。下一轮 ContextFocus 来自新工作状态，因此尚未解决的需求改变召回和上下文分配。
5. 模型提出完成后继续现有完成检查、反馈修复和收尾流程；记忆没有权限跳过这些步骤。
6. `assembly.py` 的 `_update_memory`：固定消费上界，按照事件顺序提取、审阅和准入，在数据库游标处结束。关闭时父请求与形成调用一起取消并结算。

与新增一个通用模块总线相比，这个设计保留了关键执行顺序，也复用了已有算法。与只做工厂相比，它补上了理解前召回、反馈归约和请求后形成三个真实执行阶段。

## 失败与观测

`HarnessResult.session` 是原始执行报告；`prior_memory` 和 `memory` 分别表示开始前和结束后的记忆追赶。completed 仅表示事件已消费，不等于每条信息都成为记忆。`extracted_candidates`、`admitted_candidates`、`rejected_candidates`、`deferred_candidates` 分别表示本次确认处理的候选数量，不是新增行数或累计存量；重试可能为零。deferred 状态表示本次预算未追平，failed 表示预期的形成或存储依赖故障，报告不携带原始异常正文。

同 input_id 重试取得原执行报告并续接形成；也可以调用 `flush_memory(session_id)`。不要为了重试记忆改用新 input_id，否则那是一个新的模型任务。取消可能发生在回答已持久完成之后，重新读取原报告即可确认。

默认两个形成阶段各最多 30 秒、512 个事件，同时受 Harness 父请求期限约束。`max_request_duration` 默认取 RunLimits.max_duration；前置追赶最多占父预算的 10%，后置形成使用剩余时间。这个上限不等于跨阶段的总模型调用数或 Token 上限。工具事实与助手回答不会作为用户长期偏好自动提取。应用仍须认证用户并绑定授权，一个 Harness 不能隐式服务不同身份。只读配置只需省略 extractor/reviewer。

## 当前限制与下一步

未新增自动崩溃恢复执行、后台记忆 Worker、Skills 引擎、向量检索或多 Agent 编排。记忆与 Session 是独立事务；理解和下一次决策可能读到不同记忆版本，这是每次重新召回的明确语义。紧急收尾仍不能无限等待语义刷新。

当前确定性用例使用脚本语义输出，只证明状态与模块协作。推荐工厂的组合回归已贯穿理解、形成、跨会话召回、来源失败后切换、工作记录、上下文编译、原文恢复与完成。下一步沿同一入口继续检查多轮延续、澄清和目标修订中的组合行为，补齐实际断点；真实任务收益仍需使用相同入口另行验证。

后续已接入[动态工具工作集](动态工具工作集的选择机制与实验.md)：统一入口启用任务理解时按未解决需求与失败反馈重新分配工具展示位置，已完成需求释放位置，并与上下文共享需求优先级。


## 配套记忆与修订后的连续性

高级构造入口可用一份配置组装记忆，不再分别维护提取、审阅、准入的开关：

```python
memory = HarnessMemory.from_model(
    memory_path,
    access,
    scope,
    "authenticated-author",
    model=memory_model,
    configuration_id="project-memory-v1",
    profile="conditions",  # basic / fact_sets / conditions，默认 basic
)
```

增强 profile 是显式选择，不代表算法效果已成熟。高级注入可使用 `admission=`，与审阅器声明不兼容会在初始化时报错。推荐入口内部调用这个形成工厂；CLI 已迁入推荐入口，启用记忆时仍默认 basic。

首次任务、澄清和运行中 steering 都按当前任务获取理解背景。工具反馈本身不重复解释任务。业务工具全部退休后，只要已有成果，支持工具仍能回读原文；退休表示不再需要获取新资料，不表示已经读完旧资料。

`AgentHarness(completion=...)` 可保留自定义结果验收，而不要求调用方自己构造 SessionEngine。完整设计、迁移语义和验证范围见 [组合契约与请求期限](decisions/0077-统一执行链的组合契约与请求期限.md)。

后续可显式开启 [有界工作记录](工作记录的执行过程与使用.md)：`working_records=True` 成套接入模型工作记录、来源引用以及由记录驱动的上下文与工具选择。
