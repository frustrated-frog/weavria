## 本轮能力与执行过程

记忆形成允许保存未声明开始时间的约定。此前消费装配总会排除它，明确从现在起的后续变更也被
准入层拒绝。本轮接通现有机制：

1. 宿主通过 `HarnessMemory.include_unknown_time` 选择是否召回 unknown 事实；from_config
   和 from_model 保留该选择，Session 配置也记录它。默认 False 保持兼容。
2. 自然用户输入经提取、审阅和准入形成原始约定，仍保持 `valid_from=None`，不伪造时间。
3. 新会话在同一授权作用域召回完整组，模型看到原值、来源及未知时间标记。它是否正确使用这些
   内容由真实任务验证，数据进入 Prompt 不等于任务通过。
4. 用户明确从当前时间改为新值时，准入复用内核已有的 supersede：旧记录产生 retracted 的
   新知识版本，新事实从明确时间生效。旧 head 查询仍返回旧记录；当前严格查询不编造更早历史。
5. 未来才生效的变更继续待处理，避免现在提前撤销 unknown 旧值。条件、来源与版本 CAS 保持原约束。

没有增加存储 Schema 或改写历史 journal。新策略只影响新形成决策，旧 deferred 计划不会自动
重判；这样保留原有计划的幂等性。具体替代方案、时间限制与迁移取舍见
[ADR 0080](decisions/0080-未知时间记忆的召回与明确替代.md)。

验收侧将固定用户修订放入独立 TaskGroup 任务，在 send 之外调用 steer；父调用取消时等待清理。
不改修订时机、文本或成功条件。理解失败报告增加框架分类、静态说明和尝试诊断，以区分预算、
声明格式和解释后校验失败。没有收集隐藏推理或 HTTP 凭据。

## 已确认的收益与剩余问题

首批文档记忆任务的 coverage/recent 均能完成四会话闭环：旧约定准入 1 条、首次回答中文、
修订准入 1 条、后续回答英文，没有 deferred；文档中途修订也开始通过。这些是本批次实测，
不能推广为所有记忆或修订任务都稳定。

代码审查记忆首个重复中，旧约定已经正确召回；新约定却因 `different_conditions` 被延后，
随后仍返回旧值。原始形成计划显示新旧限定条件不一致，这是另一种语义归一化问题，不能归因
于已修好的 unknown 时间拒绝。没有为了提高成功数取消条件检查。

一项澄清任务连续两次尝试均产生 `ValidationError:uncertainty` 诊断，准入预算充足，不能再归因于窗口不足。
长上下文、工作记录使用和事实/引用正确性仍需按实际轨迹评估，不改评分或由宿主补正确行动。

第二轮最终还记录了 `ValidationError:missing_capability_completion`，以及三次结构化意图/
Ask-or-Act 接受更新失败。执行阶段两组各有五次输出修复耗尽、两次完成修复停滞；收尾证据
不可用分别为两次和一次。对于 completed 但答错或漏读来源的任务，仍按原规则判失败。
