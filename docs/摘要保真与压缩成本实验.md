# 摘要保真与压缩成本实验

本实验回答“压缩后还能否回答原先能回答的问题、生成成本需要复用几次才能摊销”。它隔离摘要内容质量，不测试自主触发、不宣称 M1 长任务完成，也不自动调整生产开关。机制和设计取舍见 [ADR 0102](decisions/0102-摘要保真探针与压缩成本的配对评估.md)。

## 如何运行

```bash
# 默认只检查资料摘要、标签锚点和题集,无网络调用。
uv run python -m examples.summary_fidelity
uv run pytest -q tests/evaluation/test_summary_fidelity.py

# 显式真实实验;输出必须是新文件,重复实验轮换各组问答顺序。
uv run python -m examples.summary_fidelity --run --repeats 2 \
  --env-file YOUR_ENV_FILE --output NEW_REPORT.jsonl
```

如需复核实际摘要，可另加 `--representations-dir NEW_DIRECTORY`。这个目录只保留本实验冻结公开资料的原文、摘录、摘要视图，不写入 Git。默认报告不保存模型原答、引句正文或凭据。

`--statement-bytes` 默认 1400，范围 256–4096，限制所有摘要陈述文本的 UTF-8 字节合计。它不是 Token 换算。来源元数据仍包含在模型视图和供应商成本里。摘要失败记录为失败，不隐式扩大预算或重试。

## 资料与执行路径

冻结标签位于 `examples/data/summary_fidelity/cases.json`，原文复用已有 `examples/data/m1_harness/corpus.json`，没有复制填充成更长资料。共四个资料、24 个问题：

| 资料 | 重点 |
| --- | --- |
| 主动上下文恢复与预算闭环 | 恢复范围、任务修订、重复查询的例外、读取上限 |
| 统一执行链的组合契约与请求期限 | 记忆修复、完成后的超时、父期限与计数边界 |
| Harness 配置源码 | 默认值、依赖开关、可选时限、比例上界 |
| Context 预算源码 | 边界取值、输入预算耗尽、零安全预留、字节上界 |

每个资料另有一个原文未说明的问题。摘要生成器只看到任务与原文，不知道后续探针；问答模型只看到当前表示与题目，不知道参考答案。问答之间不共享对话历史。标签改变不会改变模型请求，有独立测试约束。

摘要不是直接拿模型输出字符串评分：先经真实 `compact_context` 工具验证，再经 `SessionContextCompiler` 重建来源图，取实际模型摘要视图。问答阶段移除原文旁路。首尾摘录基线与摘要的整个视图按字节匹配，最后以供应商实际 Token 核算，不保证两者 Token 相等。

## 如何读结果

每题有 facet 和 outcome，可以定位条件遗漏、错误答案、无引句支持及错误断言。原文组答错的题记为基线不可靠，不直接算为压缩损失；所有问题 ID 必须完整且唯一，漏题不会改善分数。

`eligible_on_probes` 仅表示这次冻结题集上保留了原文可回答性且存在输入节省。它不是语义正确证明。原句存在可能仍不足以支持答案；短答案别名与模型阅读能力也是测量误差来源。`regression` 不会因为压缩率好看而变成通过；`inconclusive` 不能当作零损失。

`break_even_reuses` 用生成总 Token 除以每次替换节省的输入 Token 向上取整。它排除离线评估成本，仅说明未来反复复用的理论摊销点。实际任务是否继续复用、准确率是否改善、等待时间是否值得，需要完整 Agent 实验回答。

## 2026-11-04 的真实结果

先以默认 1400 字节正文上限诊断，两次重复中 8 次生成有 5 次超正文预算、1 次生成格式失败、2 次接受。此轮还发现 JSON 转义引号会使正确引句被误判，已修正并增加回归。该开发版本的质量分不作为正式结论，不将失败调用忽略或自动修复。

随后冻结代码，以显式 2800 字节正文上限跑两次重复。模型为 `deepseek-flash`，temperature=0，窗口 32768，输出上限 4096，安全预留 512；四份资料与 24 个探针未改变。该预算是独立的参数诊断，未修改默认值，不能与前一轮混为同一受控对照。

| 资料 | 摘要生成（两次） | 已接受摘要的配对结果 | 每次问答输入 Token 变化 |
| --- | --- | --- | --- |
| 主动上下文恢复 | 两次均超正文预算 | 无可评分摘要 | 未知 |
| 统一执行链与请求期限 | 两次均超正文预算 | 无可评分摘要 | 未知 |
| Harness 配置源码 | 一次接受，一次模型输出非法 | 接受的一次保留全部 6 项探针，但没有节省 | 增加 375 |
| Context 预算源码 | 两次接受 | 两次均保留全部 6 项探针 | 分别减少 576、517 |

原文组 8 次问答的 48 项探针全部通过，包括对未说明问题拒答。Context 预算源码的两个摘要生成分别消耗 2972、3031 Token，按对应输入节省都需要约 **6 次复用**才能摊销生成 Token。这个结果只覆盖一个文件的两个重复，不能证明真实长任务会复用六次。

首尾摘录没有全面胜出：主动恢复资料遗漏重复查询例外、读取上限和修订额度；期限资料遗漏完成后形成超时、Token 账本边界、默认比例及独立 flush 期限。预算源码首轮摘录遗漏 max_passages 上限，第二轮在对应摘要尺寸下通过全部探针。配置源码本来就短，首尾基线保留了完整原文，没有输入节省。另一次摘录问答失败，保留为 `invalid_trial`，未计为零损失。

本次共发出 27 次 HTTP 请求。已报告的 Token 合计 61615，有 1 次请求未返回完整 usage，所以整个实验的确切总 Token **未知**，没有用零补齐。每条报告记录数据集、入口和逐文件实现摘要；本轮各条摘要一致。数据集 SHA-256 为 `2f6690449fd469d9cd84d20b5de17eaf5ec5a54f51da11adb71b4022d5a4c2aa`。

这些结果说明：来源字节变小并不保证模型输入 Token 变小；合法摘要也可能没有成本价值；正文预算约束仍频繁失败。当前机制能将这些情况分开记录，但没有证明自主压缩或最终任务成功率提升。

下一步优先将“存储字节节省”与“实际模型视图 Token 收益”区分开，并研究如何在明确预算内保留必要条件。应保留这些失败作为对照，不用增加强制摘要调用或隐藏重试掩盖问题。
