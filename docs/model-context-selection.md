# 从真实执行事实重建可回取的任务上下文

这一轮将原有模型与上下文切片接入实际执行：模型决定调用，Runtime 校验与授权，工具产生结果，结果保存为 Artifact，下一轮根据当前任务重建模型输入。选择器直接检索结果内容，不接收评测答案、必要调用标签或 `required_call_ids`。

解决的问题是：长任务积累的工具结果超过模型输入预算时，如何保留有用旧证据、避免大结果遮蔽事实，并让模型继续读取被省略的数据。执行循环、状态归约和工具校验支撑这条能力链；机制的重点是信息如何进入下一次决策。

本文中的 `AgentRun` 是单动作兼容入口。新增的批量轮次 `AgentLoop` 会强制保留上一整轮反馈及依赖闭包，避免并发兄弟的失败被筛掉；该约束来自接受事实，不是宿主标注的答案必要性。轮次语义、源码调研和实验见 [AgentLoop](agent-loop.md)。

## 可以直接运行

```bash
uv sync
uv run python examples/execution_context.py
uv run python examples/execution_context.py --json
```

示例读取仓库内的真实文本文件，实际执行 `read_source` 和 `read_artifact`，并输出答案、引用验证、调用次数、输入大小、依赖闭包与状态回放检查。无需网络或模型凭据。

`EvidenceReader` 是确定性的测试模型：预先固定资料枚举顺序，随后只从收到的输入中提取答案，找不到就返回 UNKNOWN；显式读取场景要求先调用 `read_artifact`。正确答案仅传给评测器，未传入模型或选择器。这隔离验证信息交付与执行机制，不能证明开放任务规划能力、真实 LLM 收益或达到成熟 Agent 项目的水平。

## 一次请求如何流转

以 `old-evidence` 为例，任务要求查找 Aurora 的 release code。第一份资料包含答案，后续四份资料是无关菜单。

1. `AgentRun` 接受 `TaskInput`，写入 `RunStarted`。工具目录来自注册信息，计入模型输入预算。
2. `EvidenceContextBuilder.build()` 读取状态中已接受的 `ToolRecord`，为成果建立索引，用当前目标与约束重新打分，生成 `EvidencePlan`。
3. Runtime 记录 `ContextSelected` 与 `ModelStarted`，实际调用 `ModelProvider`。框架重新校验返回的 `ModelResponse` 与工具调用能力。
4. `ModelDecided` 接受 `read_source` 决策。`ToolExecutor` 校验工具专有输入，给独立 Policy 提供归一化参数，再调用类型化后端。
5. 后端读取本地文件。输出经过工具专有 Schema 校验，`ArtifactStore.put()` 保存完整 JSON 快照；模型历史中的权威执行结果是小型成果收据。
6. `ToolRecorded` 接受收据、成果身份、工具版本、授权决策和实际读取关系。纯归约器更新 `RunState`，上下文只消费这份投影。
7. 每次新结果到达后重新构建输入。相关策略保留第一份资料的证据，并保留最新反馈；近期窗口只保留后来的资料。模型的最终答案因实际可见内容而不同。
8. `FinishAction` 经接受后才能形成完成终态；评测器从 Artifact 中按 JSON Pointer 与字符范围核验引用。

入口代码是 `src/weavria/runtime/agent.py`；接受规则在 `runtime/state.py`，检索和预算决策在 `context/evidence.py`，工具边界在 `tools/execution.py`，示例模型及评测在 `examples/execution_context.py`。

## 执行事实、完整成果与模型视图

| 对象 | 职责与权威边界 |
| --- | --- |
| ExecutionEvent | 带 Schema 版本、Run、序号、Step、Attempt 和 UTC 时间的执行事实 |
| RunState | 根据已接受事件得到的投影；任务、待执行决策、工具记录和终态以独立编码快照保存 |
| ToolRecord | 调用与反馈、成果引用、Policy 决策和实际读取依赖；成功收据必须与成果和授权一致 |
| ArtifactSnapshot | 完整工具输出；引用包含作用域、生产调用、内容 SHA-256 与 JSON 字节数 |
| EvidencePlan | 某次模型输入与选择报告；是可变任务下的临时视图，不是新的执行事实 |
| TaskInput | 宿主授权的当前任务目标、约束和修订；不从历史中猜测任务变更 |

工具返回的原始数据、执行收据和模型投影具有不同用途。`ToolRecord.exchange.observation.output` 保存成果收据；模型收到的 `ToolExchange` 可以是完整数据、精确片段或引用。视图转换不会改写已接受的工具记录。

Pydantic 的 `frozen` 不会递归冻结字典，因此运行日志、状态嵌套值、模型计划与成果均以编码快照隔离。取出的对象是副本，修改其中参数或结果不能改变下一轮输入及权威事实。SHA-256 检查证明字节一致性，不证明证据真实或调用者拥有权限。

当前日志仅存在 Run 实例内。`reduce_event()` 可重新归约出相同状态，但不会再次调用模型或工具，也不构成 Checkpoint、持久化恢复或执行重放。

## 当前任务如何驱动选择

完整 JSON 结果按字典、列表和标量递归索引。字典路径使用 RFC 6901 转义；字符串按最多 320 UTF-8 字节切片，保存原始 Unicode 字符的 `start/end`。片段值精确来自原文，不由模型生成摘要。JSON Pointer 与区间可以用于回取；数值等非字符串标量的区间为零。

工具还可声明 `context_paths`，指定结果中参与检索打分的内容子树。例如文件工具声明 `/text`，成果读取工具声明 `/value`，避免协议摘要与来源 ID 竞争正文相关性。声明由工具布局决定，对所有任务一致，不指定正确来源或答案；默认索引所有字段。完整成果仍保留全部数据，小结果的完整视图也可能包含其他字段，因此它不是脱敏或授权机制。

词项处理采用 Unicode NFKC、大小写归一化、英文词与中文二元字符片段。每轮使用当前目标和约束，对所有已接受结果的片段执行 BM25 打分：词项频率饱和、逆文档频率和长度归一化共同影响相关性。参数固定为 `k1=1.2`、`b=0.75`，词项求和顺序固定，避免进程哈希随机化影响排序。

每份结果有多种候选表示：成果引用、一个至多个高分片段；小结果若完整编码更省空间，直接使用完整表示。默认最多四个片段。预算选择先保留最新反馈及其依赖闭包，并在能容纳时给予最新结果一个最小可用片段，再逐步分配剩余预算。

相关策略比较“新增相关性 / 新增字节”，新增成本包含缺失的依赖来源收据。可以增加一份旧资料，也可以升级已选资料的片段数量；不会因为固定片段包过大而直接放弃整份资料。相同收益由相关分数和近期顺序确定地打破平局。最终历史恢复为执行时间顺序，不能通过排序伪造调用过程。

这是受约束的贪心策略，不保证全局最优。最新反馈的优先保留刻意限制了检索优化空间：需要让 Agent 消费刚发生的反馈，避免高分旧证据挤掉读取结果。最小片段也放不下时保留引用；连任务、指令、最新收据和依赖闭包都放不下时，Run 明确进入 `budget_exhausted`。

三种对照策略共享来源切片和校验，区别在历史分配：

| 策略 | 行为 |
| --- | --- |
| full | 全部完整结果；超预算就终止 |
| recent | 按近期顺序填入可容纳的片段，遇到无法容纳的历史项停止 |
| relevant | 按边际相关收益逐步选取和升级表示，同时保持读取依赖闭包 |

`recent` 内部也使用同样的片段排序，因此它是“近期资料 + 相同片段检索”基线。实验中的旧证据差异来自历史选择，不把不同的来源处理策略混为一谈。

## 读取关系如何建立

`read_artifact` 使用成果 ID、JSON Pointer、起点和长度读取原始内容。`length` 是统一的 JSON 载荷字节预算；字符串的 `start/end` 仍为 Unicode 字符位置，结构化值使用直属子节点游标，过大时提供更细的 Pointer。读取不能跨越 Run 作用域，调用结束后读取上下文关闭。

后端经 `ToolContext.read_artifact()` 读取成果时，框架自动记录生产调用。假设 B 读取了 A，C 又读取 B，选择 C 必须同时保留 B 与 A 的可回取引用。依赖由实际受控读取产生；模型参数里提到某个 ID，本身不会自动建立依赖。

`explicit-recovery` 会实际执行 `read_source → read_artifact → finish`。读取结果是新的成果，带原始来源身份与摘要，最终引用可以先验证新成果，再通过依赖回溯原始成果。闭包选择不会把原始大结果重新塞进 Prompt。

这一机制只追踪成果访问关系。后端绕过读取端口、使用外部资料，或模型在思想上关联两个调用时，框架不能推断全部语义依赖。后端是可信插件代码，`ToolContext` 不是操作系统沙箱。

## 执行、授权与任务演进

`TypedTool` 声明名称、版本、输入输出 Schema、只读或副作用行为、幂等预期、风险、审批、敏感级别、超时和尝试次数。输入先经过工具类型校验，再归一化；Policy 获得独立副本，不能通过修改参数改变实际执行内容或授权证据。

默认 `ReadOnlyPolicy` 只允许低风险、公开、无需审批且可安全重放的读取。当前 Executor 的硬边界还会拒绝写操作、未知幂等性和需要审批的操作；自定义 Policy 不能让未实现的审批流程或副作用语义凭空成立。当前 `max_attempts=1`，没有自动重试。

已执行成功的记录包含 Policy 版本、允许与否、理由、工具版本和归一化参数。输入校验失败、未知工具和硬边界拒绝可能尚未调用 Policy，因此不会伪造授权记录。工具异常变成安全的失败反馈，下一次模型可以修正参数或选择其他操作；外部取消继续传播，不能当作工具反馈。

宿主通过 `revise_task(task, expected_revision=...)` 更新任务，修订必须连续且满足比较更新条件。更新发生在模型 await 中时，旧响应会产生 `DecisionDiscarded`，工具或 Finish 都不能落地；更新发生在工具 await 中时，已开始的只读调用完成后保存真实结果，再按新任务重建输入。更新应在所属事件循环内调用；当前没有跨线程更新 API，也没有自然语言约束解析器。

Run 限制整体时限、模型尝试次数、工具尝试次数和完整请求字节。单次工具超时是可消费的失败反馈；整体时限是预算终态。取消会写入终态并重新抛出 `CancelledError`，合规依赖必须清理后传播取消。边界还检测后端吞掉取消后返回或抛出普通异常的情况；同步阻塞代码或主动撤销取消的恶意插件仍无法靠 asyncio 强制终止。

状态接受规则会拒绝重复调用 ID、乱序事件、未接受来源、跨 Run 成果、过期模型决策和没有 Finish 决策的完成结果。存储返回错误的执行身份是框架端口缺陷，终止 Run，不伪装成可修正的工具故障。

## 预算与观测

预算是 `ModelRequest.model_dump_json()` 的完整 UTF-8 字节数，包括工具目录、宿主指令、当前任务、历史及分隔符。先计算外壳与候选增量，再对最终请求重新编码核对；它不是供应商 Token 数或供应商实际 Prompt 的大小。

`EvidencePlan.metadata()` 包含策略版本、请求摘要、预算、选择原因、分数、表示类型与依赖，不包含工具正文。`ContextSelected` 事件记录大小、摘要与选中调用，原始模型请求只保存在本地计划中。事件记录模型接受的 Action，不记录隐藏思维链。

`AgentRun.events` 是拥有者使用的原始事实副本，可能含任务、参数与最终输出，不能直接当作脱敏日志外发。当前没有公开 Trace 导出器或隐私过滤流水线；应用不得把这些对象直接发布。Run ID 只约束存储命名空间，外部用户与租户授权仍须由适配器实现。

稳定反馈只记录错误分类、安全消息和原因类型。原始异常链通过 `AgentRun.failure_cause` 与 `tool_failure_cause(call_id)` 保留在拥有者的本地诊断通道，不进入模型、事件编码或报告；这些对象可能含私有输入，不能直接导出。

## 冻结实验与结果

实验使用 `examples/data/context/cases.json` 与同目录文本，Fixture、Solver、Evaluator 均为 v1；JSON 报告记录每个文件的 SHA-256。模型行为、每场景输入预算、工具、依赖锁和评测规则固定，三种策略共 12 次运行。来源范围核验从完整成果读取数据，而不是检查输入中是否出现答案单词。

| 场景 | full | recent | relevant |
| --- | --- | --- | --- |
| 小资料，4000 字节 | 正确且有来源 | 正确且有来源 | 正确且有来源 |
| 旧证据 + 四份噪声，4000 字节 | 超预算 | 完成但 UNKNOWN | 正确且有来源 |
| 大结果尾部事实，4000 字节 | 超预算 | 正确且有来源 | 正确且有来源 |
| 显式读取验证，2800 字节 | 读取后超预算 | 正确且有来源 | 正确且有来源 |

旧证据场景中 recent/relevant 都实际调用 6 次模型、5 次工具，峰值均为 3997 字节；recent 累计输入 17777 字节，relevant 累计 19433 字节。相关策略在这个场景消耗更多输入，换取旧证据送达，不能宣称普遍降低成本。完整策略只完成两次模型与工具尝试就超预算，更少的调用不代表任务完成更高效。

显式读取场景中 recent/relevant 都是 3 次模型、2 次工具，其中 1 次成果读取，峰值 2739 字节、累计 6294 字节。工具 Schema 的说明文字也计入预算；2600 字节只能容纳两个收据，无法交付读取值，故该冻结场景使用 2800 字节验证可用闭环。所有运行都满足输入预算、读取闭包和事件状态回放检查。没有报告 Token、真实模型延迟或长期任务成功率，因为本实验没有测量这些指标。

实验支持两个有限结论：自动内容检索能在该冻结旧证据场景保留答案，分段成果视图与显式读取能让该大结果和依赖链在预算下继续运行。资料枚举顺序仍由测试模型固定；没有验证自动发现工具、开放任务规划、语义推理或真实模型遵循约束的收益。

## 验证与当前局限

```bash
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

测试覆盖实际工具与成果存取、严格参数和输出、Policy 拒绝及参数隔离、精确来源与预算、缓存身份、当前任务重排、读取依赖、事件接受与回放、反馈修正、任务更新竞争、调用限制、超时、取消传播与清理。端到端测试执行上面的独立 CLI，再校验答案、引用、读取次数和结构不变量。

当前使用进程内成果存储与索引，限制单结果大小，但没有总存储配额、流式索引或持久化事务。切片可能截断词语，检索不理解否定、同义词和事实冲突；每轮重排与候选评估也会随历史增长而变贵。当前串行调用预算控制了规模，不能据此宣称支持无限长任务。示例文件工具只用于有界的小型本地开发资料，没有生产级文件系统隔离。

没有实现真实供应商、Token 预算、Checkpoint/Resume、幂等写入、自动审批、长期记忆、摘要和多 Agent。下一步优先接入一个真实模型的可选适配器与供应商输入计量，在冻结的领域无关任务上检验相关性、遗漏恢复和错误反馈是否改善完成率；根据失败证据再调整检索与能力暴露机制。

## 旧接口与设计记录

`build_context()`、`FullHistory`、`RecentHistory`、`FocusedHistory` 和 `ContextPlan` 保留兼容。它们只根据大小、时间与宿主必要性标记选择完整历史项，用于 ADR 0002 的历史基线；新 Runtime 不使用这些人工标签。

旧示例仍可运行：

```bash
uv run python examples/context_selection.py --demo
uv run python examples/context_selection.py --json
```

旧示例注入合成工具结果，不执行工具；它的 12 项比较证明显式必要性保留契约，与当前真实执行实验的证据等级不同。原有 Message、AgentRequest、ModelRequest 与 ModelResponse 的 v1 字段保持兼容；本轮新增 ArtifactRef、ToolAuthorization、ToolRecord 和版本化执行事件，没有修改旧持久化 Schema。

设计取舍见 [ADR 0002](decisions/0002-model-context-selection.md) 与 [ADR 0003](decisions/0003-execution-backed-context.md)。
