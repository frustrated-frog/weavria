# 第二小步：当前任务与必要证据驱动的模型上下文

本次实现了上下文选择和模型调用的离线闭环：输入当前任务与结构化历史，选择完整历史项，生成可检查的请求快照，实际调用 Fake Provider，再校验返回的 Action。

这个机制解决一个具体问题：有限输入预算下，如何让旧的必要工具证据不被近期噪声挤掉，并且持续向模型提供当前目标与约束。必要证据依赖和任务修改由宿主显式提供，尚未自动推断。

## 一次请求如何流转

```bash
uv run python examples/context_selection.py --demo
```

`demonstrate_task_update()` 会执行以下过程：

1. 宿主构建修订 1 的 TaskInput，目标是对比本地资料，允许考虑在线和离线运行。
2. `build_context()` 将宿主指令、当前任务和选择后的历史编码为 ModelRequest，并保存 ContextPlan 快照。
3. `call_model()` 实际 await FakeModelProvider。第一次模型决策是读取一份资料。
4. 示例注入一份合成工具结果，与该决策组成完整 ToolExchange。这一步不执行工具或文件 I/O，也不能作为真实运行证据。
5. 宿主构建修订 2 的 TaskInput，约束变为“只比较离线运行”。这只是显式更新，没有自然语言约束解析器。
6. 将旧资料的调用 ID 指定为必要证据，再提供一个大于剩余预算的噪声结果。选择器保留必要资料，省略噪声，保持原始顺序。
7. 第二次实际调用 Fake Provider，核对收到的任务修订、当前约束和结构化历史。返回仍由脚本预设，不用于答案质量评估。

输出中可观察到：两次调用，任务修订为 `[1, 2]`，当前约束为“只比较离线运行”，第二次请求是 553 字节，并保留了 `evidence` 调用的完整输入与结果。

## 为什么这样组织输入

| 对象 | 职责 |
| --- | --- |
| TaskInput | 宿主传入当前目标、约束和修订；不从历史自动推断 |
| ToolExchange | 一次已完成调用及结果，校验 call_id 与工具名关联 |
| ModelRequest | 分开保存宿主指令、当前任务和按时间排列的历史 |
| ContextPlan | 保存一次模型输入的独立序列化快照及选择元数据 |
| ModelResponse | 只有一个已归一化的 Action，仍须框架重新校验 |

历史中的文本只接受 user/assistant 角色，system 指令独立由宿主提供；工具输出通过 ToolExchange 表示，不把孤立工具结果硬编码为字符串。原有 V1 Message 和 AgentRequest 保持不变。

TaskInput 的 revision 与 schema_version 含义不同：前者标识这次任务输入的修订，后者标识数据协议。框架还没有 Task 更新状态机，不能仅凭 revision 数字证明更新合法或完整。

把当前任务与历史分开表达，可以在数据层明确区分当前约束和过去记录。这不证明真实模型一定遵循新约束，也不构成 Prompt Injection 防御；供应商适配器的编码及真实模型评测尚未实现。

ContextPlan 保存字符串快照，每次取出 request 都重新生成对象。修改原始工具参数，或修改取出的嵌套结果，都不会改变该计划。计划是模型输入快照，不是 Runtime Event、RunState 或 Checkpoint。

## 三种可替换策略

`HistorySelector` 是一个 Protocol，策略只接收内容以外的选择元数据：原始索引、调用 ID、JSON 大小和是否必要。该切片专门验证显式依赖与大小约束，不提供文本语义相关性评分。

| 策略 | 行为 | 保证与代价 |
| --- | --- | --- |
| FullHistory | 保留全部历史 | 超预算就失败，不静默裁剪 |
| RecentHistory | 从最新项开始保留连续后缀，遇到无法容纳的项就停止 | 简单基线，可能丢失必要旧证据 |
| FocusedHistory | 先保留必要证据，再按新到旧填入可容纳项 | 保留指定依赖，最终恢复原始时间顺序；不保证全局最优 |

框架检查策略返回的索引类型、范围、重复项、预算与证据保留承诺。必要依赖不存在时失败；声明保留依赖的策略若省略必要项，也会失败。当前目标和宿主指令始终保留，策略无法修改它们。

工具调用和结果是一个选择单元，避免裁剪后只剩工具结果。它还不是完整的对话依赖图：某份资料依赖早期的用户解释，或几个调用互相依赖时，需要宿主提供更多必要项或以后设计更完整的依赖机制。

选择报告包含策略版本、预算、原始索引、调用标识以及保留/省略原因。报告不默认包含模型与工具内容；原始校验异常仍可能包含输入，未来 Trace 导出必须独立脱敏。

## 字节预算为什么能精确计算

本步使用 `ModelRequest.model_dump_json()` 的 UTF-8 字节数。它包含指令、当前任务、完整工具数据、Schema 字段和 JSON 分隔符。

固定外壳先用空历史编码；每个历史项增加自身的 JSON 字节，加上项之间的逗号。选择完成后再次编码完整请求，检查实际大小与估计完全相等。测试覆盖中文、Emoji、换行、引号和反斜杠，避免把字符数量误当字节数量。

这不是供应商实际 Prompt，也不是 Token 数。未来 Token 预算必须针对供应商实际编码的完整输入计数，并预留输出预算；不能简单假设各项 Token 数可独立相加。本步仍会遍历并校验输入历史，不解决原始大结果的提前卸载或按需加载。

## 可复现实验与结论

```bash
uv run python examples/context_selection.py
uv run python examples/context_selection.py --json
```

冻结条件：Fixture v1、Evaluator v1、三个策略均 v1、Fake 响应脚本 v1、锁定的 uv 依赖。四个合成场景各自固定任务、历史和必要调用，三个策略使用相同的 2100 字节预算，共 12 次策略比较。

| 场景 | 完整历史 | 近期历史 | 证据优先 |
| --- | --- | --- | --- |
| 旧证据 + 近期噪声 | 超预算，无调用 | 1627 字节，必要证据丢失 | 2089 字节，保留必要证据 |
| 必要证据在近期 | 超预算，无调用 | 1973 字节，保留 | 2089 字节，保留 |
| 所有内容可容纳 | 847 字节，保留 | 847 字节，保留 | 847 字节，保留 |
| 必要证据自身过大 | 超预算，无调用 | 719 字节，必要证据丢失 | 明确超预算，无调用 |

所有成功构建的输入都实际传递给 Fake Provider，并核对收到的请求与计划一致；失败的输入不会触发模型调用。报告同时记录预算、请求字节、选中索引、证据保留情况与调用数。

实验说明：显式保留依赖可以避免窗口策略丢失必要旧证据；证据本身过大时，当前策略会暴露问题而不会悄悄继续。所有内容都能容纳时，三种策略没有区别。不能从这些人工场景推断策略在真实任务上更优，也不能推断长任务完成率、答案质量或 Token 成本改善。

## 模型调用边界与验证

`ModelProvider` 声明工具调用能力，返回归一化 ModelResponse。`call_model()` 独立复制输入，使用 asyncio 的时间限制管理当前 await，重新验证响应并检查能力；它不执行工具、不进行重试。

- Provider 异常归为 MODEL_FAILURE；非法响应与不支持的工具决策归为 INVALID_MODEL_RESPONSE。
- 时间限制归为 TIMEOUT，原始原因保留为异常链。已经过期的调用不会进入 Provider。
- 外部 CancelledError 继续传播；合规 Provider 必须在取消时清理资源并重新抛出。
- Provider 若吞掉自身超时取消后返回普通结果，框架检查时间限制是否已经过期，拒绝把它报告为成功。这不构成强制终止阻塞代码的沙箱能力。
- Fake 每个实例最多一个活动调用，不产生后台任务；已开始但取消的调用消耗一个脚本位置，取消前未调度的调用不消耗。

时间限制当前只约束 Provider 的异步 await。整体 Run Deadline、单调时钟注入、调用预算以及执行身份仍由后续 Runtime 负责。

```bash
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

测试验证结构关联、当前输入、完整选择单元、精确预算、策略违规、快照、调用交付、失败分类、超时和取消清理，并检查 Core/models/context 的静态依赖边界。真实模型测试尚未加入。
