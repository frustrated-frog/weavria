# 真实文档语料的词形与语义检索实验

本轮把评估从人工编写的短事实推进到四份完整官方文档，并实现了可选的英文词形归一化、Dense 上下文窗口和扩展锚点去重。结果支持继续保留这些策略进行实验，不支持把 Hybrid 或较长窗口无条件设为默认。设计取舍见 [ADR 0119](decisions/0119-真实文档检索中的词形与语义窗口.md)。

## 语料、题目与指标

语料是 CPython `v3.12.8` 的 `asyncio-task.rst`、`subprocess.rst`、`pathlib.rst` 和 `logging.rst`，合计 **231199 字节**。保留代码、RST 标记、示例和全部正文，不只抽取答案附近段落。独立于查询按空行段落贪心打包为 **178 个原文单元**，常规目标 1400 字节，超长原始段落保持完整。每个单元具有文件名、起止行及文档来源 SHA。

清单位于 `examples/fixtures/document_memory_retrieval.json`。在首次基线执行前人工冻结 24 道有答案的问题和 4 道语料外负例；开发、验证两组各 12 道正例和 2 道负例，包括字面查询、词形变化、同义转述及中文查询英文文档。问题和标注行号只交给评分器，不参与切块、候选生成、向量编码或检索过滤。

这是真实文档上的**人工标注小型检索集**，不是公开标准 Benchmark，也不是从真实用户流量采样的完整任务集。每题标注一个支持段落，未穷尽所有等价表述。因此 Hit@k 表示“指定原文段落是否在前 k 个结果中”，MRR@3 表示其排名倒数；漏掉标注段不等于其他返回段落必然无用。没有用这些指标冒充最终问答正确率。

八种策略使用相同的授权快照、最多 3 个完整事实族、20000 字节交付预算、32 个每通道候选和 2048 次选择搜索上限。按最终 `MemoryMatch.score` 对已选结果排序评分；所有运行均未耗尽选择搜索上限。纯 Dense 不调用生成模型；所有策略也都没有答案重排器或标注驱动的过滤。

## 一次请求在代码中如何流转

1. `examples/document_memory_retrieval.py` 验证文件 SHA，保留每段原始字符和行范围，将整个公开文档集映射为 `MemoryRetrievalSnapshot`。这是检索实验的快照输入，不测试授权服务、自动记忆形成或真实会话管理。
2. `TaskMemoryRetriever` 在相同快照上按需求执行 BM25 和/或真实 E5 编码。词法分析器对 `approval/approver/approves` 产生共同词干，同时保留各自原词。正文和事实键完全不改写。
3. Dense 新表示重复携带主体、属性和条件，正文尽量沿句子/空白分窗并适度重叠。窗口只是排名表示；编码器检查实际 Token 长度，完整向量校验后才发布缓存。
4. Hybrid 沿用既有 RRF 与事实族覆盖选择；选择结果包含完整原文和来源。实验评分器到此才查看标注行号。生成答案、引用语义审查和缺口重审没有被这个检索实验替代。

独立的补证链路还把扩展器核对过的 `preserve_quotes` 传为 `expansion_anchors`，从别称查询中扣除这些锚点的词项。`history_query_digest` 同时绑定别称与锚点。扣除只作用于辅助查询，不删除主查询限制，不删除原文，不改变事实族成员或证据接纳规则。

## 真实编码器对照结果

2026-11-11 的首次验证与最终代码复测排名一致。开发集用于观察问题；验证集未用于调整词干算法、窗口大小、融合权重或阈值。后续 sign-off 修复只影响带扩展锚点的补证分支，本表不执行该分支。

| 策略 | 开发 Hit@1 / Hit@3 | 开发 MRR@3 | 验证 Hit@1 / Hit@3 | 验证 MRR@3 |
| --- | --- | --- | --- | --- |
| 原词法 | 8/12 · 9/12 | 0.708 | 5/12 · 9/12 | 0.569 |
| 原 Dense | 9/12 · 10/12 | 0.778 | 8/12 · 8/12 | 0.667 |
| 原 Hybrid | 7/12 · 10/12 | 0.694 | 5/12 · 9/12 | 0.556 |
| 词法 + 词形 | 8/12 · 10/12 | 0.736 | 8/12 · 10/12 | 0.750 |
| Dense + 窗口 | 7/12 · 12/12 | 0.778 | 6/12 · 10/12 | 0.639 |
| Hybrid + 词形 | 8/12 · 10/12 | 0.736 | 8/12 · 9/12 | 0.694 |
| Hybrid + 窗口 | 8/12 · 11/12 | 0.778 | 5/12 · 10/12 | 0.597 |
| Hybrid + 两项 | 9/12 · 11/12 | 0.819 | 7/12 · 10/12 | 0.694 |

几个必须保留的负面结果：

- 较长 Dense 窗口改善了前三条覆盖，却让验证 MRR 从 0.667 降到 0.639。更完整的上下文也会引入邻近话题，不能只挑 Hit@3 宣称全面提升。
- 词形词法在这组验证题上的 MRR 高于所有 Dense/Hybrid 变体。这不证明词法普遍更强，只表明本语料里精确词汇仍很有价值。
- 新 Dense/Hybrid 仍未命中 `p4`（中文询问目录链接的默认行为）和 `l4`（中文询问日志退出处理）。前者原词法能命中；跨语言理解和融合相互干扰仍然存在。
- **所有策略在四道语料外负例上都返回了候选，空召回为 0/4。** 词面重叠和当前 E5 相似度下限不能充当“证据足够”的判断。这里没有生成错误答案，但同样没有证明拒答能力。

每个策略使用独立空缓存开始，后续问题复用同一批文档向量，查询向量不缓存。最终一次运行记录：

| 策略 | 首题编码块数 | 首题耗时 | 后续题平均耗时 | 平均交付字节 |
| --- | ---: | ---: | ---: | ---: |
| 原词法 | 0 | 31 ms | 29 ms | 7179 |
| 词法 + 词形 | 0 | 61 ms | 83 ms | 7059 |
| 原 Dense | 1061 | 23.9 s | 75 ms | 7753 |
| Dense + 窗口 | 356 | 27.0 s | 62 ms | 7684 |
| 原 Hybrid | 1061 | 22.8 s | 71 ms | 7812 |
| Hybrid + 两项 | 356 | 28.4 s | 105 ms | 7903 |

更少的块不等于更少的编码计算，较长序列仍可能更贵。本轮同机还运行了质量检查，以上是实测成本记录，不是隔离环境下重复采样的性能基准。不能据此宣称某方案稳定快多少。缓存容量在实验中统一为 8192，避免 1061 块超过默认 1024 项缓存而导致不公平的反复冷编码。

## 旧失败请求的完整链路复测

对 `memory_refinement_holdout.json` 的旧四题，继续使用真实 `deepseek-flash`、temperature=0、max_output_tokens=10000、传输参数 `reasoning_effort=none`，每次只允许一次扩展、一次补充检索及最多一次重审，保持单个事实族名额。

第一次加词形后，两边仍是 3/4。审计公开工具动作发现，两次模型都生成 `approves the plan / authorizes the plan / final approval authority`；词形虽然打通 approver，也打通 plan/planning，背景因此在两路重复计分。这个失败没有删除，也没有靠提高别称权重掩盖。

加入**仅对保留锚点去重**后，同轮最终对照：

| 策略 | 最终值正确且引文可定位 | 模型总调用 | 平均耗时 | 错误非空回答 |
| --- | ---: | ---: | ---: | ---: |
| 扩展 + 词面 | 3/4 | 14 | 3838 ms | 0 |
| 扩展 + 词形 | 4/4 | 16 | 4793 ms | 0 |

旧问题 `who signs off the plan?` 最终返回 `Mira Chen`，引文为语料原句 `Approver: Mira Chen.`，补证报告为 adopted。该结果验证的是这条已知回归链路；四题是合成旧集，不能替代上面的真实文档实验或证明一般任务收益。引文定位检查也不是独立语义裁判。

## 复现与配置

真实文档和模型输出只放外部缓存，不进入 Git。清单 SHA 为 `fe58b30d195b96ea57acfaeac1b10af2e9f21026a4dcf32951a1211a9a82e96f`，完整候选语料投影 SHA 为 `50099855b95198379208729186f19bcf54db480b6c85d7bf4b83bc560ba071b0`。

编码器为 `intfloat/multilingual-e5-small`，沿用此前固定的量化模型：模型 SHA `dd476dd0c2514e9b9be83aeb3853fac0763e0bdf4a71645407587d77c48a2d88`，tokenizer SHA `0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39`。macOS arm64、CPU 单线程，onnxruntime 1.31.1、tokenizers 0.23.3、numpy 2.5.4、snowballstemmer 3.0.1。脚本输出实际模型身份、策略身份和逐题来源行范围，不隐瞒运行参数。

将下面两个 `/path/to/` 替换为本地模型文件；`--download` 只用于显式下载清单指定的四份官方文档，文件校验不符即失败：

```bash
uv sync --extra local-memory --extra lexical-memory
uv run --extra local-memory --extra lexical-memory python -m examples.document_memory_retrieval \
  --model /path/to/model.onnx --tokenizer /path/to/tokenizer.json \
  --corpus-dir /tmp/weavria-real-docs --download > /tmp/weavria-docs-comparison.json
```

默认比较八种策略；`--split development` / `--split validation` 分组，`--variants dense dense_windows hybrid hybrid_both` 限制策略。每行记录期望段、实际选中段、排名、编码/缓存计数、耗时、字节和搜索是否耗尽。可直接根据行号回读 RST，检查未标注的等价支持段。

应用配置仍通过已有入口：

```python
policy = MemoryRetrievalPolicy(
    mode="hybrid",
    lexical_normalization="english_snowball",
    dense_view="contextual_windows",
    max_duration=120,
)
```

将该 policy 交给现有 `TaskMemoryRetriever` 或 `HarnessMemory.retrieval`。较大语料首次编码可能超过默认 20 秒，期限需由宿主显式选择；不要把降级当作 Dense 成功。旧 Reranker 校准应按新的候选身份重新进行。旧补证实验新增 `--lexical-normalization english_snowball` 参数，仍使用原有模型环境配置。

## 执行承诺、局限与下一步

确定性测试覆盖：词面与词干并存、标识符保护、别称归一化、背景重复计分、全锚点回退、完整原文与条件覆盖、事实族预算闭包、缓存复用、元数据容量失败、取消与超时后的缓存清理、可选依赖缺失、清单防篡改及标签不进入快照。全库检查结果为 **1824 passed、24 skipped**；跳过项为显式 Docker 沙箱集成测试。Ruff、格式与 Pyright 通过。

当前没有做：自动学习通道权重、通用同义词图、中文形态分析、真实文档完整问答与引用语义评测、冷启动性能优化。现有 E5 配置和相似度下限也没有重新校准。

下一小步应冻结更大的公开文档问题与完整相关性标注，将候选召回接上原问题证据审查，重点测跨语言漏召回、无答案判断和最终引用，而不是继续提高召回数量掩盖噪声。若比较重排或通道选择，应同时保留词形词法这个有竞争力的朴素基线，以及本轮各策略的失败案例。
