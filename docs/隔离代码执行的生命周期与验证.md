# 隔离代码执行的生命周期与验证

## 本次新增能力

Agent 可以通过 `execute_python` 消费已经接受的 Artifact，在一次性 Docker 工作区里运行 Python，根据正常工具反馈修正代码，最后把指定结果文件连同来源、代码哈希和执行配置身份保存为 Artifact。它适合 CSV/JSON 数据处理、源码分析和小型文件生成。Docker 是显式宿主依赖，不会在默认导入、测试或 FinScope 接入时自动启动。

这是一个完整的单次执行切片。持久解释器、跨调用可变工作区、网络访问、安装依赖和远程 Worker 尚未实现。架构决定与第一方资料见 [ADR 0104](decisions/0104-隔离计算与显式成果导出.md)。

## 一次请求如何流转

1. 宿主构造 `DockerPythonSandbox`，给出已安装镜像的完整 `sha256:` ID，注册 `python_execution_tool(backend)`。工具版本绑定镜像和资源配置；策略显式允许这个工具及版本。
2. 模型提供代码、输入 Artifact 地址和导出文件名。`PythonExecutionInput` 先拒绝绝对路径、路径穿越、重复/嵌套文件名和超量代码。模型不能指定 Docker 参数、宿主目录、网络权限或资源上限。
3. ToolExecutor 验证参数与 Policy。默认 `ReadOnlyPolicy` 不授权 `isolated_compute`；`SandboxToolPolicy` 对指定名称/版本放行，普通读取仍交给原策略。外部 `side_effect` 仍被执行器拒绝。
4. `ToolContext.read_artifact` 只读取当前已接受来源，校验运行归属，记录依赖。指定字段转为 UTF-8 文本或稳定 JSON，通过标准输入传入容器；不挂载宿主目录，也不向代码提供原始 API 密钥。
5. 容器内监督程序准备只读输入。用户代码以 UID 65534 在 `/workspace/work` 运行，可以写 `/workspace/outputs`。监督程序有独立身份，用户 stdout/stderr 通过独立管道收集，不能作为控制协议。
6. 执行成功后只读取声明的普通 UTF-8 文件。逐层目录描述符加 `O_NOFOLLOW` 防止链接逃逸，拒绝设备、FIFO、超量文件和非法编码。文件须具备监督程序可读权限；默认 0644 可用。输入和输出采用不同目录，原 Artifact 不可变。
7. 宿主验证返回协议并确认容器已删除，再把结果交回 ToolExecutor。随后走现有 Artifact、ToolRecorded、SQLite 和 Context 链路。`code_error` 保存有界 stderr，模型可在下一轮提交修改后的代码；没有工具内部模型调用或自动修复。
8. CompletionPolicy 独立核验任务成果，不能只凭工具调用成功或进程退出码 0 宣布任务完成。

核心源码可依次阅读：`tools/python_execution.py` → `sandbox/docker.py` → `sandbox/process.py` → `sandbox/_guest.py` → 原 ToolExecutor 的 Artifact 接受路径。`sandbox/contracts.py` 定义版本化输入、结果、资源配置与可替换端口。跨模块依赖已纳入架构测试。

## 执行与失败语义

| 情况 | 行为 |
| --- | --- |
| Python 异常 | `code_error`，保留有界日志，不发布结果文件 |
| 超过壁钟期限 | `timed_out`，终止计算并销毁容器 |
| stdout/stderr 超限 | `output_limit`，保留上限内日志并停止计算 |
| 非法或缺失的导出文件 | `export_error`，附异常类别与路径，不发布部分文件 |
| 观察到 SIGKILL/137 | `process_killed`，不凭退出码推断一定是 OOM |
| Docker/监督程序协议故障 | 明确工具失败，不伪造成功结果 |
| 删除无法确认 | `SandboxCleanupError` / 框架错误，保留容器名供核查 |
| 调用取消 | 清理完成后传播 `CancelledError`；清理失败附诊断，仍保持取消语义 |

CLI 管道由有界读任务处理；取消发生在创建进程期间时，先取得句柄，再终止进程组并回收 reader。清理任务使用 shield 等待，重复取消也不能使它脱离所有者。容器删除前核对每次调用独有的 owner 标签，随后只按核对过的不可变容器 ID 删除；名称碰撞或重新占用不能导致误删另一容器。

容器采用只读根目录、断网、no-new-privileges、CPU/内存/PID/tmpfs 限制，仅给监督程序配置初始化属主与降权所需的 CHOWN、SETUID、SETGID。生成代码降权后没有这些权限。容器不是绝对隔离保证：Docker daemon、镜像与宿主内核属于信任前提。调用进程硬崩溃时依赖容器内期限和 `--rm` 收敛，没有实现持久 orphan 任务接管；Daemon 不可达时不能承诺立即删除。

## 使用与观察

默认检查冻结资料，不启动 Docker 或模型：

```bash
uv run python -m examples.sandbox_execution
```

使用宿主已安装的 Python 3.12+ 镜像，先取得不可变 ID，再显式运行：

```bash
SANDBOX_IMAGE=$(docker image inspect python:3.12-slim --format '{{.Id}}')
uv run python -m examples.sandbox_execution --run \
  --image "$SANDBOX_IMAGE" --env-file .env.finscope-debug \
  --output /tmp/weavria-code-result.json
```

`--output` 使用排他写入；环境文件只由模型适配器读取，模型生成代码不会获得其中的凭据。示例使用既有 AgentHarness 入口、完整工具反馈及独立 CompletionPolicy。因为完整反馈须在执行前预留最坏大小，示例配置 196608 字节请求预算和 131072 Token 窗口；较小模型应收紧 SandboxLimits 的日志/输出上限，同时配置匹配的 TokenCounter，不应绕过反馈准入。

SDK 的关键装配方式：

```python
backend = DockerPythonSandbox(image=immutable_image_id)
tool = python_execution_tool(backend)
policy = SandboxToolPolicy(versions={tool.descriptor.name: tool.descriptor.version})
# 在 AgentHarness.from_config 中传入 tools、policy 和任务自己的 completion。
```

结果文件当前以 UTF-8 文本存储在工具 Artifact 的 `execution.files` 中，拥有 Artifact 哈希并可沿 JSON Pointer 回读；不是宿主文件下载路径。默认每次输入最多 128 KiB、导出合计 8 KiB、每路日志 1 KiB，执行 5 秒、128 MiB 内存、32 个 PID、16 MiB 工作区。用户代码可用标准库；预装第三方库需要宿主选择另一份固定镜像。

## 下一步与边界

首步验证的是受控执行与成果链路。跨调用恢复仍通过显式 Artifact 输入重新执行，不恢复 Python 变量、进程或打开的文件；包含隔离计算的运行不自动放开原只读 resume/任务接续限制。重放安全表示没有可累积的外部业务写入，不保证随机数、时钟和线程调度确定性。

后续优先研究版本化工作区与可复用执行成果：哪些文件可以作为下一次输入、并发修改如何隔离、失败分支如何丢弃，以及如何给长任务保留可靠的文件状态。届时再扩展恢复语义，不能只复用一个持久容器就宣称具备 Durable Execution。
