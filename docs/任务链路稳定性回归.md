## 冻结输入与配置

- 原问题是项目内中国稀土数据汇总，覆盖新闻、财务、行业、市场表现、研究结论，并要求标注缺失。
- 问题 SHA-256：`fe6d4890e5462c81cc6a841abcd0efa345e8bb9885000fdd9f0b247a5fead9ff`。
- SQLite 冻结副本 SHA-256：`59455c36d776ac515bc3b1837877896a21e136841f31889c14b468a5587f96e3`。
- 旧会话每次从同一个只读取得的冻结副本开始；新会话每次使用新的临时数据库，不累积前次试跑结果。
- 走正式 create_app、HTTP ASGI、SQLite、任务准备、Compiler、Runtime 和真实 FinScope 后端。
- 模型 deepseek-flash、temperature=0、JSON 模式；理解输出上限 8192，执行 4096，窗口 32768，
  安全预留 256，声明的计数器为 cl100k_base。它不是对供应商实际分词或隐藏提示的精确宣称。
- 理解期限 180 秒，Run 期限 180 秒，20 次执行模型调用、20 次工具调用；宿主字节限制 1048576，
  无额外 HTTP body 上限。最终两个阶段均显式 reasoning_effort=none。
- 收尾预留 2 次模型调用、30 秒，仍在原 Run 父预算内。阶段期限之和与单次请求实际耗时不可混淆。

后端数据与模型服务修订没有冻结，模型名称也不是固定权重版本；这不是严格的统计成功率实验。
部分迭代并行运行、共享本机 CPU，因此延迟也不能用来单独归因某项策略的速度收益。

## 如何复跑

使用 `examples/finscope_stability.py`。先通过环境注入本机已有的模型和 FinScope 连接配置，密钥不得
写进命令行、文档或仓库。运行需要显式开启真实模型与后端访问：

```bash
WEAVRIA_RUN_LIVE_MODEL_TESTS=1 uv run python examples/finscope_stability.py \
  --question-file /private/path/question.txt \
  --context-file /private/path/page-context.json \
  --seed-database /private/path/frozen.sqlite3 \
  --session-id EXISTING_SESSION_ID \
  --repeats 3 \
  --output /private/path/new-results.jsonl
```

输入问题和上下文文件使用调用方自己的私有文件；context-file 应符合 FinScope PageContext。
不指定 seed-database / session-id 时只测试新会话；指定时两者必须成对，会依次测试冻结历史和新会话。
脚本会读取 WAL 一致的快照、使用独立临时数据库，拒绝覆盖旧评测输出，仅导出无内容指标。
冻结历史不会被写回原会话。复跑前应核对同一模型参数和上述限额，尤其是两个推理配置与收尾预留。

本轮同时新增确定性回归，覆盖格式修正、权限上限、目标跨度、字段归属、请求超限、取消清理、
慢上下文准备、纠错停滞收尾、发布否决、独立必需行动、版本包络与持久化刷新。全仓检查使用：

```bash
uv sync
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

## 当前边界与下一步

本轮解决的是能复现的准备/收尾中断和错误反馈闭环，没有建立逐句事实核验器。最终回答中的金融
结论不能仅因 HTTP 200 或 completed 就视为已核验。旧会话仍可能需要接近 Run 的时间上界，
性能尚有改进空间；本轮保证预留纳入准备路径，不宣称完成了上下文算法性能优化。

下一小步应冻结跨领域任务和更明确的结果核验标准，分析多余调用、错误参数、真实事实覆盖与成本。
若继续深化任务状态，应设计更精简的模型视图，避免将完整宿主元数据长期作为模型工作空间。
不能把持续扩大包络或增加重试当作这项工作的替代品。
