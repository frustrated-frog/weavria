# 记忆内核与双时间事实

本轮新增 `weavria.memory` 第一批实现。它让宿主明确接收的长期断言拥有作用域、证据引用、修订历史和双时间查询能力，并可在重启、重复投递和并发修改后保持一致。它还不是完整的自动记忆系统。

## 一次事实如何进入记忆

假设用户在 1 月 1 日说“用中文回复”，宿主于 1 月 2 日保存；另一会话在 1 月 15 日收到“从 1 月 10 日起用英语回复”。

入口是 `SQLiteMemoryStore.commit(access, batch)`：

1. `MemoryAccess` 明确授予项目作用域的写权限。来源由宿主确认来自已经接受的输入，记录为 `MemorySource`；其原文仍保存在 Session 或其他来源系统。
2. 第一批次提交一个 `add`，生成断言版本 1，现实有效起点是 1 月 1 日，系统记录时间是 1 月 2 日。
3. 第二批次提交 `supersede`，携带目标版本号、新断言以及新来源。新断言的有效起点是 1 月 10 日，系统记录时间是 1 月 15 日。
4. 纯归约器检查事实键、时间和版本条件，保留中文断言的新投影 `[1日,10日)`，增加英语断言 `[10日,开放)`。旧的“中文持续有效”知识版本在 15 日退役，其原断言仍可审计。
5. SQLite 将来源、事件、版本和消费游标一起提交。只有提交成功，才返回 `MemoryReceipt`；相同批次重试返回原结果。

## 为什么要两个时间

| 查询 | 返回 |
| --- | --- |
| 现在看 1 月 12 日有效的偏好 | 英语 |
| 现在看 1 月 9 日有效的偏好 | 中文 |
| 站在 1 月 14 日，查询当时认为 12 日有效的偏好 | 中文 |

`valid_at` 回答“哪个现实时间”，`known_at` 回答“站在哪个知识时间”。后者不会看见 15 日才提交的修订，也不会通过旧版本的退役字段泄露这次修订。

时间相同的提交用 `at_head` 区分。head 只在一个精确作用域内递增，其他租户写入不会改变本作用域的可见版本或 BM25 分数。

未知有效时间不是“永远有效”。断言可以明确保存未知时间，但严格查询默认不返回它；需要时显式设置 `include_unknown_time=True`。

## 数据与执行过程

| 源码 | 职责 |
| --- | --- |
| `src/weavria/memory/contracts.py` | 版本化的作用域、来源、断言、命令、事件与召回协议 |
| `src/weavria/memory/reducer.py` | 新增、补强、区间尾部替代、争议与撤销的纯状态转换 |
| `src/weavria/memory/store.py` | 事务、幂等、CAS、游标、读快照、事件重放和线程生命周期 |
| `src/weavria/memory/retrieval.py` | 已授权快照内的 BM25 与含完整来源的预算选择 |
| `examples/memory_kernel.py` | 两个宿主实例跨会话修订、三种查询、基线对照与资源探针 |

SQLite 是权威存储；事件不变，版本和游标可重建。数据库与模型契约均为 v1，不改变现有 Session 数据库或公开请求版本。

查询先按作用域、知识边界、有效时间及精确事实字段筛选，再计算可见语料内的 BM25。英文数字归一化、中文单字与双字分词支持基本短词检索；词项分数不表示事实可信。结果中的断言与来源必须一起满足整个输出的字节预算。没有足够空间时返回明确的省略数，不交付失去来源的半条记忆。

审计读取按页进行：`events(after_head=..., limit=...)`、`history(after_revision=..., limit=...)`。审计包括后来的修订，因此不能拿它替代历史时点召回。

## 不变量与取舍

- 来源与命名空间不会由模型自行升级为权限；已注册来源不能换内容复用 ID。
- 一个批次中失败任意一步，事件、来源、投影和游标全部回滚。
- 不接受旧修订覆盖新状态；重复相同批次返回原回执，不重复归约。
- 同一来源反复被看见不会提高置信度；纯模型来源不能直接变成陈述或观测事实。
- 争议保留双方，不因 BM25 分数高就择一为真；撤销一方不会自动洗掉另一方的争议标签。
- 取消后可能已经提交，但不会遗留一个无人等待的后台写入；重试原批次身份可判明结果。
- `retract` 只是撤销当前断言，不是隐私物理删除。

第一批选择在 SQLite 筛选后的快照上计算 BM25，没有接入 FTS5、外部向量服务或图数据库。这样可以保证历史和作用域的语料统计隔离，但每次查询会重新读取、分词和评分。默认候选数 10,000、候选序列化字节 16 MiB，超限失败；这是单机有界实现，不是大规模检索架构。

时序修订目前只支持完整尾部替换或同起点纠错。任意区间的多次切分、模糊实体匹配、语义冲突发现都尚未实现；有意缩小命令语义，避免用猜测污染权威历史。完整设计与替代方案见 [ADR 0039](decisions/0039-可追溯的双时间记忆内核.md)。

## 运行与观察

```bash
uv sync
uv run python examples/memory_kernel.py
uv run python examples/memory_kernel.py --distractors 1000
uv run pytest tests/memory -q
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

示例使用临时目录，不写入仓库数据，不调用网络或付费模型。两个独立 Store 生命周期模拟跨会话持续使用，来源、自然语言和预期答案均为明确构造的合成材料。宿主直接构造类型化断言与时间，不声称模型已学会解析用户的记忆意图。

2026-10-23 本机观察：固定三个时序问题，双时间实现通过 3/3，最新值覆盖基线通过 1/3；后者无法回答两个历史问题。1,000 条合成干扰断言、10 次宽词项查询、中位召回耗时约 20.9 ms。该时间包含 SQLite 读取、解码、分词、BM25 和结果预算装配，受机器和缓存影响，不是延迟 SLA。

验证分为四类：

- 契约：UTC、半开区间、未知时间、Schema、作用域、来源、修订及游标。
- 故障：事务中途 SQL 错误、取消、关闭取消、deadline、时钟倒退、独立连接写入竞争、投影损坏与重建回滚。
- 进程：提交前杀死写入进程，数据库没有半批结果；提交后杀死进程，重试返回原回执。
- 检索：中文一字和两字、英文 ID 归一化、数字紧邻汉字、完整来源预算以及外部作用域不影响分数。

这些证据只支持当前内核与合成机制的声明。它们不能证明自动记忆质量、真实跨会话问答准确率、Agent 行动改善或达到成熟框架水平。

## 本轮边界与下一小步

尚未接入 SessionEngine 的自动消费、模型提取、语义 Admission、自动冲突检测、Recall Planner、Context Token 预算、记忆工具、长期经验学习、语义合并、向量检索和物理删除。Working/Conversation 仍属于已有 Runtime/Session，未复制到新的数据库。

下一步优先完成“已接受事件 → 带原文定位的候选 → 独立准入 → 本内核提交”的形成机制，验证错误来源、局部作用域、纠错与事实变化。在此基础上再把任务需求驱动的召回接入 TaskAwareSessionPreparer 和上下文编译器，并冻结无记忆、历史窗口和 BM25 基线的真实任务评测。
