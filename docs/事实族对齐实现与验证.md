# 事实族对齐实现与验证

本轮实现“同一实体属性、不同适用条件”的有据归组。它补齐了形成阶段与完整组召回之间的一条实际断链，但没有让整个记忆模块达到成熟状态。相邻真实任务仍有复核截断和协议失败，保持显式启用，不以确定性测试通过代替能力验收。

## 为什么需要独立关系

已有 `align_candidate` 面向 equivalent/change/correction/conflict，要求条件一致，然后才可能强化、争议标记或覆盖目标。一般规则与条件例外不能通过这条路径互相对齐，否则 README 例外可能修改所有文档的规则。

`MemoryFamilyAlignment` 只表达“应一起考虑的实体属性”。例如原谓词 `technical_document_default_language` 与新谓词 `文档语言` 可在有据判断后共享规范键；README 条件、英文值和原文不变。这样召回匹配例外时，即使一般规则词法得分为零，仍可以完整同行。它也不让记忆直接满足工具证据需求。

## 数据结构与调用链

1. `ModelMemoryExtractor` 产生原始候选，`ground_memory_candidates` 把引用落到焦点原文。
2. `ModelMemoryReviewer(family_alignment=True)` 在已有完整有界快照上返回 Review v3。`families` 与目标修订 `alignments` 分开，不能给同一候选同时授予新事实归属和覆盖权限。
3. `ConservativeMemoryAdmission.compile` 先检查可保留性、作用域、条件和时间；`align_family` 核对目标 ID/版本、semantic 类型和引用，再只替换 subject/predicate。
4. 原有重叠与批次冲突检查继续运行。把同条件的矛盾新值塞进同族会被待定，不能假借归组绕过 conflict。不同条件的独立事实则通过 add 写入。
5. `MemoryFormationEngine` 保存原始提取与含归属依据的计划；提交使用 memory head CAS，将事实和游标原子接受。锚点在复核期间变化会重新复核，已落地提取可复用。
6. `recall_groups` 沿用规范键分组，Context 仍只能完整交付或省略该组。没有新增读时模型调用或第二套事实账本。

每个候选至多一个既有锚点、两项字段对应；每项最多 8 个引用。最多 8 个候选、128 条 reconciliation 事实，仍沿用原快照和输出字节限制。归属校验不引入无界图遍历；原准入的快照扫描和批次碰撞检查仍是主要工作量。没有声明生产吞吐改善。

## 使用方式与升级

```python
formation = MemoryFormationEngine(
    memory_store,
    ModelMemoryExtractor(provider, configuration_id="my-config"),
    ModelMemoryReviewer(
        provider,
        configuration_id="my-config",
        family_alignment=True,
    ),
)
```

调用方仍负责身份授权、来源窗口和总期限，不自动后台学习。默认 reviewer 仍使用 v2 协议；新模式使用 v3。准入策略升至 v3，流水线版本变化；已有形成作业不能被另一套版本静默续写。旧流水线恢复需保留原实现/配置，当前不提供跨流水线迁移。

Review v1/v2 的持久化字节不增加 `families`；v3 是显式新协议。断言与事件 Schema、数据库 DDL 不变，既有事实不会被自动重分组。最后代码检查还给默认 reviewer 的提示/Schema 变化标记了适配器版本 2.1，并重命名内部兼容序列化方法；这两项不改变下列实验的模型输入和准入行为，实验仍绑定实际启动时的源码摘要。

## 不变量与确定性验证

回归覆盖：跨词汇归组、零分一般规则同行、原候选留证、条件/值/时间/来源不变、原锚点不被更新、重复作业不重复写入、重建和重开一致；过期目标、缺失目标、伪造引用被待定；同条件与同批矛盾不会静默写入；先前作用域/语义拒绝不能被归组覆盖；复核期间锚点被撤回必须重读重评；模型适配器不能接受不同配置协议。

存储取消、故障回滚、崩溃后阶段复用继续由原形成及存储测试覆盖。归属没有增加独立后台任务或事务。


## 真实模型结果：2026-11-01

模型 `deepseek-flash`，思考 enabled/high，8192 输出上限，90 秒形成/消费期限，消费单次调用且关闭输出修复。其余冻结配置同[自然形成实验](自然记忆形成与跨会话消费验证.md)。共 74 次真实调用，服务端报告合计 183,036 Token，包含失败；未提高预算、放宽 Schema 或覆盖失败后重跑挑选结果。

## 当前限制与下一步

这是完整的同族准入垂直切片，不是完整 Memory Engine 成熟验收。宿主证明引用位置、版本和更新边界，不能确定性证明任意两段自然语言确实同实体同属性；错误的模型同族判断仍可能误合并。条件的语义等价、包含与优先级也不是当前确定性求解器的能力。

不支持旧库自动合并/拆分、同批未接受候选互相归组、多目标争议原子解除。提取器仍可能把冲突描述提取成摘要事实。本轮评分只判断有限语言值和实际交付来源，不能替代关系结构验收。

下一步应继续收敛形成链：先按协议失败、提取落地失败、复核截断分别设计有界恢复与输出复杂度控制，保持已接受阶段可复用；随后处理竞争断言的显式形成及冲突集合纠正。只提高 Token 上限或默认重试不会解决这些机制问题。当前不进入工作区、沙箱或其他新模块。

后续已实现显式有界生成修复、宿主尝试收据与复核引用复用，见[记忆形成修复与引用复用](记忆形成修复与引用复用.md)。争议形成和提取截断仍有实测失败。
