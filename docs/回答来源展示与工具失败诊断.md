# 回答来源展示与工具失败诊断

## 本次修改

按用户的显示偏好，FinScope Agent 回答默认不输出内部 source_id 或 `[来源:...]` 标签。
需要自然说明证据时可以使用发布方、文档名称和时间。

FinScope 前端的共享 AgentConversation 组件增加 Markdown 文本节点过滤，去掉普通正文、
列表和表格中的 finscope、market-pulse 来源标签。完整页和市场悬浮窗共享同一行为；当前组件
已持有的回答也会按新规则重新渲染。正常链接、代码示例和用户输入不变。

过滤只改变展示，不改写 Runtime 已验收成果、候选摘要、Artifact、来源身份或工具执行事实。
模型即使仍生成历史风格的来源标记，也不会让普通回答再次充满内部技术标识。

## 本次工具失败的原因

对截图对应的运行做只读检查，共 20 个工具调用，16 个成功，4 个失败：

| 调用 | 原因 | 对应契约 |
| --- | --- | --- |
| 财报读取使用带后缀的股票代码 | 本地参数校验失败 | 财务资源要求资料库的数字记录 ID |
| 财报读取改用六位股票代码 | HTTP 404，该数字对应的资料库 ID 不存在 | 股票代码与资料库 ID 不是同一标识 |
| 个股预测检索使用公司名 | HTTP 400 | 该检索把 query 作为 security code 发送 |
| 归因历史检索未给 qualifier | 本地参数校验失败 | 需要标的类型，例如 STOCK |

失败项仍是失败事实。整个 Run 可以基于成功兄弟结果交付有限回答，并明确缺失数据；不要求每次
探索调用都成功，也不能把 HTTP 错误当成已验证为空。

## 参数与失败诊断

应用工具描述和输入 Schema 补充标识要求：财务子资源先从 financial_instruments 获得记录 id，
未匹配到目标时应报告缺口；预测和归因历史查询使用已取得的证券代码；归因历史需给 qualifier。
这些要求仅在 apps/finscope，不进入通用 Runtime。

FinScopeWorkspaceClient 保留 HTTP 状态码，400/422 分类为 INVALID_TOOL_ARGUMENTS，404 明确
提示资源未找到并要求核对目录 ID，429 和 5xx 保持原有可重试依赖故障语义。错误消息使用应用
生成的安全说明，不复制后端响应体。参数说明有助于模型选择合法输入，但不承诺模型从不犯错。

## 验证与边界

- React 组件回归包含旧风格来源标签、中文标点、Markdown 加粗、表格、正常链接、代码示例、
  用户原文及失败工具标签，验证展示过滤不会把真实失败改成成功。
- Agent 完整页、客户端和市场悬浮窗相关测试通过，TypeScript 与生产构建通过。
- Python 参数化回归覆盖 HTTP 400、422、404、429、503 的类别、状态提示、重试属性及错误体不泄露。
- 对本次两个 HTTP 失败执行原有只读 GET 复核，确认 404 是指定资料库记录不存在，400 是查询
  参数被后端拒绝；未触发刷新、生成或写操作。

本轮不重放付费模型，也不改写历史失败记录。来源的逐句语义核验、规划覆盖审计的稳定性和工具
条件参数的完整 JSON Schema 表达仍是独立问题。下一步应结合真实轨迹评估参数错误是否减少，
不能仅凭参数描述变详细就宣称所有工具调用已可靠。
