# 原句锚定查询扩展的实现与实验

后续实现：词形归一化、扩展锚点去重及真实文档 Dense/Hybrid 对照见[真实文档语料的词形与语义检索实验](真实文档语料的词形与语义检索实验.md)。下文保留本轮 v2 的历史结果，不将后续修复倒写为首次实验成功。

本轮新增 `ModelMemoryQueryExpander`，在记忆缺口补证中将用户关系表达映射成可能出现在材料中的术语。主要解决 residual 查询词面不匹配，仍使用原任务、授权快照、完整事实族和原问题重审。它能改善部分问答，不是一个已经解决全部语义检索问题的模块。

## 为什么需要两路排名

第一版让模型提出别称、保留实体条件的引文，然后直接拼到残差查询后。模型往往保留整段背景名称，长背景的 BM25 分数再次压过别称，旧四题从 3/4 降到 1/4。增加约束 Prompt 没有解决排序算法中的竞争。

最终设计使用 `MemorySelectionDemand` 携带两个字段：query 保留原残差前缀与原文锚点；expansion 只包含最多三条短别称。宿主把它映射为 `MemoryDemand`，检索器分别计算两路 BM25，避免把原始分数直接相加。

每个需求内，词法主视图权重为 1，别称视图权重为 2；Hybrid 模式的 Dense 权重为 1。各路名次 r 贡献 `(k+1)/(k+r)`，按权重加权并除以有效通道权重之和，k 沿用现有 rank_constant。无别称命中时不计入其分母。融合后的名次倒数进入原来的多需求覆盖选择器。权重 2 表达缺失项补证时优先探索新词的设计选择，并非有大规模调优证据的最优值。

两路候选共用 max_candidates、max_groups、字节预算和整个事实族闭包，不能通过增加一条通道扩大最终供给。每个需求最多多一次词法扫描；若忽略已有 Dense 计算，新增主要成本是候选语料词项扫描和融合排序，不创建并发后台任务。纯 Dense 模式不能启用此词法扩展，配置阶段会拒绝。

## 一次请求的代码流程

1. `HarnessMemory.query_expander` / `MemoryContextSource.query_expander` 显式配置扩展器。没有 refinement、retriever 或 evidence 的组合无法开启。
2. 初次检索与审查发现 missing，`memory_refinement.py` 仍先构造旧残差查询。
3. `memory_query_expansion.py` 将原问题、缺失项描述、残差查询送入一次结构化模型调用。没有语料候选、事实文本、答案标签、MemoryAccess 或可执行 Tool。
4. 每个缺失项返回焦点原句、要保留的实体/时间/否定/场景引文、短别称。宿主验证身份覆盖、逐字原文定位与容量，生成两个排名视图；不允许模型直接输出替代原任务。
5. `select_task_memory` 在同一快照上把两个视图交给 `TaskMemoryRetriever`，融合结果只改变候选选择。重排序器的候选版本增加 lexical-expansion/1，避免把改变后的候选分布冒充原分布。
6. 有新材料且没有丢失旧证据闭包时，审查器在完整原问题下重审。仍只接受 missing → supported，原有其他状态不变；未改善则保留初次供给。
7. Context 编译器按实际 Token 预算裁剪，Session 持久化最终供给及嵌套诊断，重开后保留扩展决策。

## 约束实际能保证什么

原问题不被修改，查询锚点能逐字定位，权限/时间快照不变，生成别称不会被写入记忆或作为支持证据。扩展器看不到答案库，不能靠逐题预先选择材料伪造检索收益。

它**不能保证**模型找全所有实体、保留了所有条件的语义，也不能保证别称同义。原句定位只能证明文字来源。模型可能遗漏关系术语、产生过宽的概念，或者让错误实体排名靠前。最终重审也是模型语义判断，所以这不是数学上保证的零误答机制。测试与真实错误非空答案指标共同观察该边界。

每个缺失项最多三条 64 字符别称、八条 256 字符保留引文，整批最多 32 项。输入预算默认 32768 字节；两个查询视图分别最多 2048 字符，超限整个提案回退原残差，不能截断末尾条件。默认一次扩展调用期限 20 秒，可显式调整；追加选择和重审继续使用 refinement 期限。Session 总期限可以中断全部工作。

超时、无效提案或不可用模型都记录失败并退回旧残差；取消原样传播并清理。失败后不增加重写尝试，不增加第三次检索。未出现 missing 时不调用扩展器。

## 版本和成本证据

`ContextRefinementReport` v2 增加 `ContextQueryExpansion`，记录策略版本、输入/提案/查询摘要、模型调用尝试数及失败。v1 序列化保持旧字段。成功扩展的输出摘要覆盖原查询和别称两个字段，必须与实际选择查询摘要一致。外层 `ContextSupplyReport` 沿用 v5，嵌套报告独立版本化；旧程序不支持新嵌套 v2，不宣称反向兼容。

`refinement.model_calls` 现在包含扩展调用。原有“外层取消使 assessor 未返回时，无法从返回报告恢复其内部全部调用数”的局限仍在；真实实验从传输层计量总调用。辅助调用尚未统一纳入 Runtime 主模型 Token 总账。

## 如何运行和观察

```python
from weavria.harness import (
    MemoryContextSource,
    MemoryRefinementPolicy,
    ModelMemoryQueryExpander,
)

source = MemoryContextSource(
    memory_store,
    access=access,
    scope=scope,
    retriever=retriever,
    evidence=assessor,
    refinement=MemoryRefinementPolicy(),
    query_expander=ModelMemoryQueryExpander(provider, configuration_id=config_id),
    max_bytes=65536,
)
```

省略 query_expander 保持旧残差策略，省略 refinement 保持单次召回。相同参数也可通过 HarnessMemory 传入。

```bash
uv run pytest tests/memory/test_query_expansion.py tests/memory/test_refinement.py \
  tests/memory/test_task_retrieval.py -q
uv run python -m examples.memory_refinement \
  --dataset examples/fixtures/memory_query_expansion_blind.json \
  --variants refined expanded wide --output /tmp/query-expansion.json
```

真实实验使用已有 WEAVRIA_MODEL_* 环境配置。输出位于仓库外，保存公开 Fixture 的标准化动作与诊断，不保存密钥、原始响应或隐藏推理。期望答案仅由本地评测器读取，不送给模型。引用定位指标不等同于独立语义蕴含评测。
