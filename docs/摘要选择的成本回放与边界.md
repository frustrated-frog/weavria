# 摘要选择的成本回放与边界

## 本次能力与使用方式

编译器可以在摘要生成后，根据同源原文和摘要的正式请求 Token 成本，决定是否让摘要正文参与上下文分配。它解决的是“存储字节减少却使模型输入变大”的问题。详细算法、失败语义和 Schema 见 [ADR 0103](decisions/0103-同源请求计量驱动的摘要选择.md)。

通过宿主已有配置使用，无新依赖、隐藏模型或独立执行器：

```python
ContextCompilerConfig(
    window_tokens=32768,
    semantic_compaction=True,
    summary_selection="token_savings",
)
```

宿主继续提供匹配端点的 `SessionTokenCounter`。默认 `coverage` 是旧选择基线。可以独立启用 `summary_guidance` / `summary_preparation`，成本策略不会自动开启生成或读取。可在 `SessionContextCompiled.compilation.summary_selection` 查看两侧计量、身份摘要与原因。

举例：已经接受的原文、摘要及恢复区间进入编译器；`source_units` 先保留恢复区间；`compare_summary_costs` 分别渲染原文和摘要请求；原文方案不支付不需要的摘要引用；摘要方案不能删除受保护原文。若增加 Token，正文退回引用，原文进入正常效用分配。`read_artifact` 和 `RecoverContext` 的正常执行、授权与额度不因成本拒绝而改变。

## 冻结真实候选回放

复用 0102 实验 `statement_bytes=2800` 下保存的三个真实模型摘要，不重新生成、不重新问答。模型当时为 `deepseek-flash`；本次不调用网络模型。输入仅含公开冻结资料与模型派生表示，保存在 `/tmp`，没有提交生成文本。

```bash
uv run python -m examples.summary_token_selection \
  --representations-dir /tmp/weavria-fidelity-final-2800-views \
  --output /tmp/weavria-summary-token-selection-v2.jsonl
```

其他机器可先按[摘要保真与压缩成本实验](摘要保真与压缩成本实验.md)生成自己的 `--representations-dir`。CLI 校验冻结源 SHA-256、一层来源地址和保存视图，将陈述重新交给生产工具和编译器；不信任导入的执行身份。`--output` 必须为新文件。独立生成会产生不同候选，因此不能称为重现下面的同一组结果；相同输入散列和计数器版本才能复现同一次回放。

计数器：`openai-compatible-session/7[tiktoken/0.14.0/cl100k_base;frame=32]`，日期：2026-11-04。

| 保存候选 | 原文方案 Token | 摘要方案 Token | 差值（原文减摘要） | 新策略 |
| --- | ---: | ---: | ---: | --- |
| harness_config 第一次 | 1106 | 1279 | -173 | 拒绝正文 |
| context_budget 第一次 | 2022 | 1475 | 547 | 允许参与选择 |
| context_budget 第二次 | 2022 | 1521 | 501 | 允许参与选择 |

旧 `coverage/full` 对照接受三份正文；新策略拒绝第一份。该份摘要方案 JSON 从 3671 减少到 3559 字节，**字节确实更少，但 Token 增加了 173**。其余两份允许入选，不代表质量自动通过或最终请求一定减少同样数量。

保存视图的 SHA-256，按表格顺序：

```text
51012fc5e07af84b790c05afc987f9d830eb4098cfb53fee42a61ea0a592e475
e447c03b7c422d8ccdeb399ac9c0e8117d716533f95710c94373fd0d5a892de7
9cf9880a60fe84d79675371ab2c9b8f4b35904e6229b2cde5f3736797455f06a
```

上一轮保真问答的供应商实际输入增量分别是 +375、-576、-517。本次是 Runtime 封装及指定本地计数器的比较，不能把数字混在一起。对同一问答提示使用本地计数器，增量分别为 +314、-560、-514，进一步说明请求包装和分词器校准都影响结果。方向一致只支持此三份材料，不证明所有任务都能正确估计收益。

## 验证与下一步

```bash
uv run pytest tests/context/test_semantic_compaction.py \
  tests/harness/test_summary_harness.py tests/evaluation/test_summary_fidelity.py
```

测试使用冻结离线 BPE 和 Fake Model 验证执行不变量，真实摘要回放验证已有候选在真实编译路径下的成本决策。两者均不证明自主 Agent 更会选择压缩时机。本次全量 `ruff check`、`ruff format --check`、`pyright` 均通过；全量测试 1559 项通过（84.44 秒）。额外补充拒绝摘要后的原文恢复断言后，相关 Context 测试 32 项通过，类型与格式再次通过。

当前没有解决生成前收益预测、自动质量验收、最终分配中的冗余摘要、全部混合表示最优搜索、实际复用次数及生成费回本；也没有将新策略默认开启。下一小步优先对齐实际模型的计量与 usage，再把成本、必要原文覆盖和摘要保真放到同一组真实任务中验证，避免用新增开关替代收益证据。
