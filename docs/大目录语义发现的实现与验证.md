# 大目录语义发现的实现与验证

日期：2026-11-13。设计依据：[ADR 0124](decisions/0124-大目录语义发现与分阶段能力暴露.md)。

## 本次能力与问题边界

新增可选择的 `ModelCapabilityDiscovery`，处理任务准备阶段的大目录召回。原有 BM25 会在模型理解前删除未命中的工具；这会使跨语言或动作改写任务失去正确能力。新策略按预算完整扫描策略可见的能力卡，合并候选，然后只展开候选的完整 Schema。后续任务理解、完成条件、动态工作集和工具授权保持各自职责。

本轮的“渐进暴露”明确指**能力卡 → 候选完整协议 → 最终执行工具视图**。没有实现执行过程中的主动搜索工具、交互式反复补搜、Skill 加载或工具链自动合成。发现模型只返回候选名称，既不能执行工具，也不能把候选直接写入已满足的需求。

## 一次请求如何流转

以冻结任务“查出 api.example.test 的 HTTPS 凭据到期日”为例：

1. `harness/session.py` 从本次注册表应用发现 Policy，得到全部可发现且可用的工具。开启语义发现时，词法检索不再预先裁剪这个集合。
2. `harness/understanding.py` 在发现前建立准备期限，把原任务、适用历史、应用上下文与澄清状态交给发现组件。发现后解释器只能使用剩余期限。
3. `harness/capability_discovery.py` 对稳定名称排序。能力卡保留说明、风险、行为、审批标志和字段概览；字段概览明确不是完整协议，完整描述符摘要绑定后续展开对象。
4. 分批规划使用 `ModelRequestContextCompiler` 编码实际请求。既受每批数量限制，也受 Token 和 HTTP 字节限制。单卡放不下时明确失败；所有扫描批次在首次模型调用前规划好。
5. 每批调用模型提名，验证名称必须来自该批、不重复、不超限。合并提名超过最终限额时再调用一次全局比较。不同批次不比较模型自报分数，也不按批次先后直接截取。
6. 在首轮该任务中，完整扫描 96 项工具后，发现器交出六项候选，其中包含 `read_tls_certificate`。原有理解器查看六项完整协议后，只声明该工具。词法基线漏掉它并选择了认证配置读取工具。
7. Session 仍只安装理解结果允许的执行视图，执行参数与权限继续由 Runtime/Tool Policy 校验。卡片、提名和语义规格都不能证明实际返回数据满足需求。

注册对象展开前再次核对目录快照，防止插件在异步发现期间改变协议。工作状态是调用局部值，不把候选、扫描游标或失败留在共享策略单例中。

## 算法与预算取舍

设目录有 N 项，实际准入的每批容量为 B，单批提名上限为 L，最终候选上限为 K。扫描需要约 `ceil(N/B)` 次调用，提名并集超过 K 时增加一次合并调用，再进入原有任务理解。B 会受任务上下文长度和卡片大小影响，不能只用 `cards_per_batch` 推断实际调用数。

这条路径以线性扫描换取每张卡都有机会被语义模型检查。它免除了词法预筛的不可见缺口，但仍可能被模型误判、每批名额或压缩后的字段概览影响召回。全覆盖报告只证明全部卡片被发送并得到合法回应，不能证明工具发现完备。

默认限制：512 项工具、8 MB 完整目录、每批最多 24 项、每批最多提名 4 项、最终最多 12 项候选、最多 32 次发现调用、累计最多 120000 个本地计量输入 Token。模型每次输出、单请求窗口与传输字节受宿主编译器限制。它们是允许上限，不保证任意 512 项目录都能在宿主期限内完成。

累计 Token 是调用前的宿主计量值，不冒充供应商账单。发现预算独立记录，辅助模型 Token 尚未统一计入执行 Run 的 Token 账本。发现和解释共享父准备期限，外层 Harness 请求期限也继续生效。

## 失败、归档与兼容

扫描或合并失败时不发布部分候选，不换成词法结果偷偷继续。容量、超时、模型失败、非法提名与报告写入失败分别诊断。取消传播并等待所拥有的模型调用清理，不开启后台扫描。

报告包含目录、上下文、能力卡及实际请求摘要，已发送工具名称、本地 Token/字节计量、计量器身份、选中名称、提名摘要、扫描数量与失败分类。非法名称不回显入诊断；`out_of_batch`、`duplicate_name` 等宿主定义代码用于区分原因。报告不采集凭据、目录正文或隐藏推理。

直接调用 `discover` 返回报告；准备记录 `TaskUnderstandingRecord v2` 携带成功报告。v1 保留原字段顺序、序列化形状和严格版本校验。TaskFrame 与 Session 持久化 Schema 未变。Session 保存策略版本和最终目录身份，**不会自动把详细发现报告写入 Journal**：需要归档时使用异步 `on_report` / `discovery_reporter`；失败报告从 `CapabilityDiscoveryError.report` 取得。报告接收函数也受准备期限约束，写入失败阻止后续解释。

## 如何使用

推荐入口显式选择：

```python
from weavria.context import ContextCompilerConfig
from weavria.harness import AgentHarness, CapabilityDiscoveryConfig, HarnessConfig
from weavria.runtime import RunLimits

config = HarnessConfig(
    configuration_id="large-catalogue/1",
    context=ContextCompilerConfig(window_tokens=32000, output_tokens=4096),
    limits=RunLimits(max_request_bytes=256000),
    preparation_max_duration=60,
    semantic_discovery=CapabilityDiscoveryConfig(
        cards_per_batch=24,
        nominations_per_batch=4,
        max_candidates=12,
    ),
)
# 在已有 AgentHarness.from_config(...) 调用中传入 config。
# reasoning_model 与 reasoning_counter 由宿主提供,发现与解释共享它们。
# 可传 discovery_reporter=archive_report,其中 archive_report 是异步归档函数。
```

发现卡片能够分批放下，不代表后续任务解释的固定协议和候选 Schema 一定能放下；理解阶段继续独立准入。上面的容量是显式宿主配置，没有修改全局默认预算。

## 冻结实验与全部结果

目录与问题固定在 `examples/fixtures/semantic_capabilities.json`：12 项具体能力加 84 项组合生成的干扰能力，共 96 项；8 个中文、西班牙语和英文问题，包含双工具需求与无需工具的直接回答。目录构建不读取期望答案。工具是禁止执行的评测占位对象，真实模型自主完成发现和任务理解，**这里只评价最终工具选择，不评价业务结果或端到端完成率**。

比较三种路径：原 BM25/Schema 预筛、语义卡扫描、完整协议目录。所有路径使用相同任务原文、原有理解器、60 秒准备期限、32000 Token 窗口、4096 输出上限和 256000 字节传输上限。模型为 deepseek-flash，temperature=0，reasoning_effort=none。每题轮换策略先后顺序；第二轮完整复跑相同八题，保留首轮结果，不按题挑选较好成员。

| 运行 | 策略 | 最终工具集合完全正确 | 实际模型调用 | 供应商总 Token | 累计墙钟秒 |
| --- | --- | ---: | ---: | ---: | ---: |
| 首轮 | 词法预筛 | 3/8 | 12 | 67570 | 19.691 |
| 首轮 | 语义扫描 | 7/8 | 38 | 177575 | 36.738 |
| 首轮 | 完整目录 | 8/8 | 8 | 229425 | 15.198 |

供应商 usage 覆盖全部尝试。总调用包括原有理解器的有界协议纠正；发现器没有增加非法输出重试。供应商适配器已有 JSON 尾部分隔符修复在部分调用中触发，三种策略共享同一适配器，没有为语义发现放宽规则。

首轮西班牙语容量任务在第二批出现非法提名，24 项已扫描、整次发现失败。首轮只留有通用错误类别，不能从它反推出具体越界名称或错误类型；因此随后补充安全的细分诊断。复跑该任务成功，不能据此声称消除了这类错误。两轮之间未改筛选提示、名额、目录、问题或决策算法，后续修改是诊断、组合接入和契约验证；报告保留实际运行时逐文件摘要。

逐请求核对两轮共同发出的 30 个扫描请求，摘要全部一致。相同扫描输入仍产生不同提名，temperature=0 不能视为确定性保证。

词法路径将部分漏召回的外部查询解释成无需工具，或在近似候选中选择错误动作。语义路径在成功成员中找到了遗漏的能力，完整协议交付量明显下降；首轮成功任务只需展开 0–6 项。但完整目录在此次配置中**仍能容纳**，其正确率更高、调用更少、延迟更低。首轮共同成功的七题，语义方案总 Token 为 168080，完整目录为 200759；复跑八题分别为 191299 与 229417。节省 Token 与增加延迟同时存在，不能只报告其中一项。

小样本、同一模型、合成目录、同题复跑不支持统计显著性或普遍泛化结论。每批强制名额、批次排列的语义影响、真实异构工具目录以及窗口无法容纳全目录时的任务表现，仍需独立验证。
