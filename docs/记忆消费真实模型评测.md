# 记忆消费真实模型评测

本页保留原分支历史实验，并在后半部分记录 2026-10-31 主线整合重测。两者使用同一任务与评测预算，但适配器协议和计量器已演进，不能把跨日期差异全部归因于记忆机制。

2026-10-25 完成 10 个固定项目设置任务的三臂、两次重复试验，并在只补充失败诊断记录后按同配置复测。它验证“上一会话已接受、已规范化的记忆，能否帮助下一会话回答”，不重新评测自然语言形成，也不证明长期复杂任务收益。

## 冻结条件与评分

- 数据：`examples/data/memory_recall/cases.json`，`memory-recall-consumption/1`。包括一般规则/README 例外、争议 shell、前后时区、数据库纠错、失效日志级别、格式化命令、改写查询及未知有效期。
- 原始文本先作为真实 SessionInput 写入 prior 会话，Fake 只负责确认输入；宿主按冻结数据生成规范化 MemoryBatch。真实模型只参与新会话作答，新会话没有 prior 历史窗口。此安排刻意隔离消费机制，不得当成自然形成收益。
- 三臂为无记忆、既有 BM25 逐条 top-1、完整事实组 top-1；后两者使用同一已接受快照与相同评分，随后均进入 Context。完整组允许一个组包含多个成员，因此占用正文可能更多；它与提高单条 k 的效果尚未作完整消融。
- `deepseek-flash`，`https://api.deepseek.com`，显式 enabled/high 思考配置，输出上限 8192，90 秒；每次任务仅一次模型调用，关闭输出修复重试，轮换三臂顺序。temperature=0 不保证思考模式下确定性。响应实际模型标识均为 `deepseek-flash`，供应商别名不可当作固定权重版本。
- 统一请求上限 16,000 字节，Context window 32,768、输出预留 8192、安全余量 256；显式使用 `cl100k_base` 估计输入 Token，它不是 DeepSeek 精确分词器，服务端 usage 单独报告。
- 仅答案与 source_id 集合同时精确正确才通过。未知、失效或争议需要 unknown；无记忆臂也有应答 unknown 的正确案例。预期答案不进入模型请求，有 HTTP 替身测试核验。

```bash
export WEAVRIA_MODEL_BASE_URL=https://api.deepseek.com
export WEAVRIA_MODEL_NAME=deepseek-flash
export WEAVRIA_MODEL_MAX_OUTPUT_TOKENS=8192
export WEAVRIA_MODEL_TIMEOUT_SECONDS=90
uv run python -m examples.live_memory_recall --live --repeats 2 \
  --output .weavria/memory-recall-new-run.json
uv run pytest tests/test_live_memory_recall.py -q
```
