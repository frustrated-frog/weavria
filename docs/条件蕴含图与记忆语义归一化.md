# 条件蕴含图与记忆语义归一化

本轮把记忆的条件比较从字符串相等扩展到可组合的条件蕴含。新增机制针对同一实体、属性下的不同条件表述：哪些只是说法不同，哪些只存在单向包含，哪些不能同时成立。它与上一轮时态事实集配合，让真正等价的命题能够进入同一个集合参与纠正，而不会把独立例外并入一般规则。

对应设计取舍见 [ADR 0073](decisions/0073-条件蕴含图与记忆语义归一化.md)。此功能显式启用，原字符串策略仍保留为基线。

## 1. 先定位原有机制的限制

旧 `align_candidate` 即使拿到了完整字段对应，只要 qualifier 对 qualifier 的值字符串不同，就返回不同条件。它能避免未经解释的合并，却不能表达同义、蕴含或互斥。例如两个表述含义相同、键名和值写法都不同，原路径也无法归一。

直接去掉字符串比较同样不够：同一主题下的两个条件可能只部分重合。新路径将“模型识别局部语义关系”与“宿主组合条件合取”分开，模型不直接生成需要写回的 canonical qualifiers。

## 2. 条件图实际计算什么

每个节点是 `(candidate|target, qualifier_key)`，其含义是原始命题中的完整角色与值。节点身份不依赖英语键名、中文词语或行业词典。同样的词语放在不同角色中，不自动等价。

模型给出的 `MemoryConditionLink` 有三种关系：

- `equivalent`：双向蕴含，编译为两条有向边。
- `entails`：左条件成立时右条件成立。
- `disjoint`：两个条件不能同时成立。

边可以跨侧，也可以在同一侧。后者使冗余条件可计算：若候选 A 与目标 B 等价，且目标 B 蕴含目标 C，那么候选 A 足以覆盖目标的 B∧C。逐字段一一配对会错误地认为缺了一个条件；合取闭包允许一个条件推出多个条件。

算法分别以候选全部条件、目标全部条件作为初始真命题，执行多源 BFS。对每个到达节点保存一条稳定的最短推导路径，不重复计算环或把重复边当额外置信度。相同角色键且类型和值都相同，可以直接加入恒等边。

| 闭包结果 | 返回关系 | 对写入的作用 |
| --- | --- | --- |
| 两侧各自能覆盖对方全部条件 | equivalent | 可以复用锚点的条件表示 |
| 仅候选覆盖目标 | candidate_entails_target | 不等价覆盖；同族新事实保留原条件 |
| 仅目标覆盖候选 | target_entails_candidate | 同上 |
| 只有联合条件包含互斥对 | disjoint | 保持不同条件 |
| 任一侧自身闭包包含互斥对 | inconsistent | 本次条件解释不用于归一化 |
| 其余 | unknown | 不从缺少证据推断等价 |

空条件集是空合取，表示没有显式限制。单向可证明不代表反向在自然语言中必定不成立，因此这里不把单向关系命名为“严格子集”。

这些结论的形式含义很具体：在正原子合取、一元 Horn 蕴含与互斥组成的有限理论中，闭包计算给出全部正原子后果；对一个未到达的原子，把闭包外原子取假即可构造反例模型。测试用独立布尔赋值穷举检验这一点。算法不证明模型提供的语义边真实，也不是通用的一阶逻辑或自然语言推理器。

## 3. 一次输入如何写入记忆

1. 现有提取器从接受的原文提取命题、模态、时间和逐字引用，本轮不改变提取器。
2. `ModelMemoryReviewer(semantic_conditions=True)` 提供主体/属性对应、更新意图，以及局部条件关系。模型视图使用原始 qualifier 键，不要求生成数据库 ID 或最终分片。
3. `ConditionSetReviewWire` 从固定快照恢复目标 ID、版本和引用。`MemoryReview v6` 保存这些可重放输入，旧 Review 版本的序列化保持原样。
4. `ConservativeMemoryAdmission` 调用 `compare_memory_conditions`。只有双向覆盖成立才把候选的 qualifiers 复用为目标的形式。原 extraction、引用、时间与模态不变，conflict/change/correction 的新值也不变。
5. 同条件候选进入上一轮 `compile_fact_sets`，继续计算竞争、时间交叠、局部纠正和残余分片，再原子提交。

独立验证中的离线配置展示了这一调用链：旧记忆只有 `environment=离线环境`；同一次真实提取得到的新命题包含 `environment=离线` 与 `network_connection=无`。新复核给出环境条件等价，以及离线环境蕴含无连接的关系。闭包证明两组条件互相覆盖，宿主将新命题复用为旧条件形式，再由事实集把旧“清空”纠正为新“保留”。生产代码没有离线、网络或缓存的词语规则。

这轮没有写全局别名表，也没有把模型一次判断变成永久本体。对齐依赖本次目标版本与完整记忆快照；CAS 冲突后复用提取、重新解释新快照。取消和超时留下可恢复作业；已完成输入的重复处理不再调用模型。新增了 Review v6，Assertion、SQLite DDL 与旧策略恢复语义不变。

## 4. 为什么选这个方案

字符串同义词表会持续吸收应用特例。embedding 相似度可以帮助找候选，但相似度本身无法区分包含、排斥和等价。让模型一次性重写全部条件，则难以观察哪里丢失了限制。

当前选择以局部语义关系作为不确定输入，使用可重放的图运算组成整体关系。它不需要训练数据或新增运行时依赖，也保留了未来更换语义解释器的空间。关键收益是可计算的组合语义，不能以“又加了一次复核”或图这个名称本身证明技术深度。

## 5. 如何运行

启用时同时配置 reviewer 与 admission，继续使用已有的提取器和存储：

```python
from weavria.harness import (
    ConservativeMemoryAdmission,
    MemoryFormationEngine,
    MemoryGenerationPolicy,
    ModelMemoryReviewer,
)

reviewer = ModelMemoryReviewer(
    provider,
    configuration_id="fixed-model-config",
    family_alignment=True,
    generation=MemoryGenerationPolicy(max_repairs=1),
    set_reconciliation=True,
    semantic_conditions=True,
)
admission = ConservativeMemoryAdmission(
    set_reconciliation=True,
    semantic_conditions=True,
)
engine = MemoryFormationEngine(store, extractor, reviewer, admission=admission)
```

```bash
uv run pytest tests/memory/test_conditions.py \
  tests/memory_formation/test_semantic_conditions.py \
  tests/test_live_memory_conditions.py
uv run python -m examples.memory_condition_scaling
uv run python -m examples.live_memory_conditions --live \
  --dataset examples/data/memory_conditions/validation.json \
  --output .weavria/新的条件归一化验证.jsonl
```

模型配置通过环境变量注入。真实实验必须显式传 `--live`，输出以独占创建方式打开，不覆盖失败记录。

## 6. 验证与性能证据

### 确定性语义与生命周期

256 种含跨侧边、同侧边、环、等价和互斥的理论，分别对四个布尔原子的全部赋值进行穷举，与闭包结果比较。另有空合取、未知条件、角色不同但值相同、冗余条件的传递路径与输入顺序不变性测试。

集成测试验证：同义条件实际替换旧值并保存规范表示；单向包含和互斥不覆盖；同族例外保留条件；矛盾图不被应用；重建、重开和旧 Schema；取消/超时后只复用提取；并发写入后重新计算集合；模型请求不接收评分标签；实验结束和失败均关闭客户端。

最终全仓 1319 项测试通过，Ruff、格式检查、Pyright 通过。测试数量与形式正确性不替代自然语言任务结果。

### 纯算法规模

BFS 为 O(V+E)，稳定排序为 O(V log V + E log V)，返回路径最多额外复制 O(V²) 个节点。上限为每侧 16 个条件、256 条输入关系。没有将模型延迟隐藏在图计算成绩中。

Python 3.12.13、macOS arm64，本地每组 1000 次；计时不启用 tracemalloc，峰值内存另测一次。稠密等价图覆盖大量环：

| 每侧条件数 | 输入关系数 | 中位计算时间 | 峰值内存 |
| --- | ---: | ---: | ---: |
| 2 | 4 | 0.009 ms | 3,328 B |
| 8 | 64 | 0.033 ms | 16,440 B |
| 16 | 256 | 0.113 ms | 31,288 B |

### 真实模型对照协议

数据指纹：开发集 `d61f3df33aada04248d5738e4ecbe88ff226ab814afb3103f78b1cfd2f26ed08`；验证集 `dec0ea7d2da980343ba6ffdc2f8085b88058d3bc7a9881624be554e70aaef796`。其中个人偏好输入绑定 user scope，项目规则绑定 project scope；这项输入授权信息由宿主提供，答案与条件关系标签只进入评分器。

评分检查完整最终快照：纠正题只留下有新来源的新值，独立条件题保留带各自来源的两个值，不能有额外或 contested 记录。值只做大小写和首尾空白归一；因此正确但冗长的值表述也可能被判失败。此指标是严格的记忆形成结构正确率，没有测试下游 Agent 消费收益。

## 7. 当前限制与下一步

本轮做深的是局部条件合取的组合推理及其与时态记忆更新的连接。它还不能自动修复提取器错误拆分的命题、把来源角色从误填的条件中移走，或分解隐藏在 predicate 内部的适用限制。语义边判断错误仍可能导致错误合并；形式证明只针对给定的边。

不支持析取、量词、多前提联合蕴含、全局跨锚点别名传播、概率校准或嵌套 JSON 条件的自然语言形成。旧记忆中的嵌套条件会保持未决，不强行转换为字符串。没有宣称该模块已经达到成熟框架的通用记忆质量。

下一步应深化来源到命题的结构化分解：把属性、参与者角色、适用条件、时间与来源归属保存在同一个有证据的结构中，防止提取阶段丢掉关系。条件闭包可以继续作为其后续计算层，不能用更多同义词补丁掩盖错误的上游结构。
