# 记忆形成真实模型评测

本轮把 [记忆形成与修订决策](记忆形成与修订决策.md) 从 Fake/HTTP fixture 验证推进到真实模型诊断。**恢复后已完成 v2 条件对齐与联合区间修订，以及三轮主评测和一轮独立留出评测。** 实验只测自然语言输入如何形成可查询的记忆，不测下一轮 Agent 完成任务的收益。主数据集仍是开发诊断集，不能当作泛化成绩；另新增六个冻结的留出案例，证据范围仍然很小。

## 固定条件与计分

- 原诊断日期：2026-10-23；恢复后主评测 UTC 时间为 2026-10-23 15:59:36 至 16:12:43（北京时间跨越 10 月 23–24 日），随后执行留出评测。
- 数据：`examples/data/memory_formation/cases.json`，`memory-formation-pilot/1`，12 个案例，每轮 15 次有效时间查询。预期答案只进入评测器，不进入提取或复核输入。
- 两臂共享同一次提取及原文定位结果。朴素基线按主体、谓词、条件仅保留最后一个值，也检查 scope/retention；实验臂额外做独立复核、准入和双时间修订。
- 模型：`deepseek-flash`，接口 `https://api.deepseek.com/chat/completions`，显式 `thinking=enabled`、`reasoning_effort=high`，串行执行，无模型重试。
- 正式复测：每个案例三轮，单阶段 90 秒，输出预算 8192，`json_mode=false`。请求发送 temperature=0，但 DeepSeek 思考模式忽略此参数，因此不能宣称采样完全确定。
- 先统计完整 trial；模型、原文定位或提交失败的 trial 记为执行失败，两臂均不纳入条件语义成绩。只有完整 trial 的所有查询都正确，该 trial 才算正确。条件语义成绩必须同时公布完成覆盖率。
- 值使用有限别名归一化后做多重集比较；README 条件只按条件值中是否出现 README 计数。此评测器不是一般自然语言蕴含判定器。

官方文档查询于 2026-10-23：[模型与接口](https://api-docs.deepseek.com/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。文档将当时的 Flash 指向 V4.1-Flash-1017；接口返回的模型标识仍是 `deepseek-flash`。这是服务端别名，不是可长期固定的权重摘要，日后重跑必须记录响应模型与日期。

## 诊断发现与本轮修改

首轮使用旧提取器和默认 4096 输出预算，12 个案例只有 6 个完整执行。随后保持旧提取器，显式指定 high 思考模式的诊断轮也只有 6 个完整执行：4 个案例因候选 Schema 校验失败，2 个案例在复核时得到 `finish_reason=length`。这些 trial 不纳入有效语义成绩。

发现的问题包括：

1. **模型看到的 Schema 与实际校验规则不完全一致。** `current`/`unknown` 禁止附带有效期时间戳，旧 JSON Schema 却只表达独立可空字段。现在用条件 Schema 表达互斥规则，并说明 current 由宿主解析。Pydantic 校验没有放宽，已保存 v1 候选 JSON 不变。
2. **事实表示漂移。** 同一项目规则会被解释成作者偏好；值里混入“未来可能修改”的叙述；条件被翻译或把时间写入条件。提取器 v2 明确主体、单一值、条件与时间各自职责。这是生成契约改进，不能替代实体或条件的语义对齐算法。
3. **失败不可诊断。** 原报告只有最外层异常名。报告 v2 增加安全的异常类型链、HTTP 状态、响应模型、Token 用量、结束原因和逐案例进度。只采集允许字段，不保存原始响应、思考内容、请求头或凭据。
4. **需要区分接口可运行与机制有效。** 新汇总同时统计执行覆盖率、完整案例上的查询正确率与整例正确率，不把空结果或局部完成误当成功。

第一次诊断修复将提取器从 `model-memory-extractor/1` 更新为 `/2`，当时复核器和准入器不变。恢复后的本次实现进一步将复核器和 `conservative-memory-admission` 都更新为 `/2`。旧未完成作业仍绑定旧 pipeline，不能修改版本号后强行续跑，须用匹配的旧实现继续；当前没有作业策略迁移工具。

## 源码中的一次失败

复测第一轮的纠错案例中，旧断言的条件为 `{"document":"技术文档"}`，新候选为 `{"文档类型":"技术文档"}`。独立复核识别出 correction，并指定了旧目标；准入器仍因 `different_conditions` 保存待定决定、推进消费游标，保留旧事实。

这里存储与恢复语义正常，任务结果仍然错误。把“没有误覆盖”报告为“记忆已正确纠错”会掩盖核心能力缺口。仅放宽字典相等检查也不合适：真正的 README 例外必须保留其额外条件，不能被归并成一般规则。

未来变更案例还可能同时提取出“从新日期用英文”和“之前用中文”两个候选；两者都指向同一旧目标时，需要联合区间修订，而当时的单目标准入会暂缓冲突。这不能通过丢弃旧事实或按候选返回顺序选一个来解决。

## 恢复后的实现与完整评测

[条件对齐与区间修订](记忆条件对齐与区间修订.md) 已实现两项受限机制：复核器提出绑定目标 revision、携带原文引用的逐字段映射，宿主验证条件完整覆盖后规范化；同一旧目标的多个候选必须覆盖完整且无重叠的旧区间，再编译为一次原子撤回与分段新增。未知起点、缺段、真正例外或不完整映射继续待定。任意条件值的语义翻译不在本次能力内。

## 复现与证据

在当前隔离分支安装依赖，并由环境注入密钥，不要写进脚本、命令历史或提交文件：

```bash
export WEAVRIA_MODEL_BASE_URL=https://api.deepseek.com
export WEAVRIA_MODEL_NAME=deepseek-flash
export WEAVRIA_MODEL_THINKING=enabled
export WEAVRIA_MODEL_REASONING_EFFORT=high
export WEAVRIA_MODEL_MAX_OUTPUT_TOKENS=8192
export WEAVRIA_MODEL_TIMEOUT_SECONDS=90
uv run python examples/live_memory_formation.py --repeats 3 \
  --output .weavria/memory-formation-frozen.json
uv run python examples/live_memory_formation.py --repeats 1 \
  --dataset examples/data/memory_formation/holdout.json \
  --output .weavria/memory-formation-holdout-rerun.json

uv run pytest tests/memory_formation tests/test_live_memory_formation.py -q
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

本地 `.weavria/memory-formation-pilot.json` 和 `memory-formation-diagnostic.json` 保存已完成诊断的结构化候选、决定及查询；第二份还包含允许的传输元数据。`.weavria/memory-formation-paused/manifest.json` 和同目录 SQLite 文件保存中断时的审计快照。整个目录被 Git 忽略，凭据未写入文件；评测进程与临时启动器均已关闭。

恢复后的 CLI 每完成一个 trial 就追加并同步写入同名 `.jsonl`，记录该 trial 的配置与版本，即使中断也能保留已完成结果。当前仍没有自动跨进程续跑报告的能力，重新运行须使用新输出路径并保留旧证据；不能把已保存形成作业的恢复能力等同于评测报告续跑能力。报告记录数据集摘要、策略及模型配置，不能用某一次响应的长思考内容解释或证明模型能力。

## 下一步的机制边界

本次已完成有据字段对齐和单目标完整区间分区。确定性验证共 793 项测试通过，Lint、格式与类型检查通过，包含映射不完整、真实例外、区间缺口、乱序、版本兼容和事务失败回滚。测试证明执行契约，不替代上面的模型收益评测。
