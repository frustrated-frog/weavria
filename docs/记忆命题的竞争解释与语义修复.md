# 记忆命题的竞争解释与语义修复

本轮在记忆提取阶段加入可以实际重建命题的搜索。已有提取器仍产生初值；新机制从原文识别完整含义，提出不同的命题组织方案，在同一次比较中选择改善方案，再交给现有形成管线。它可以合并被拆散的关系、修正适用条件，也可以保留原解释。

这是有界、模型参与评分的局部搜索。宿主负责候选管理、选择和执行语义，模型负责语义分析与重建；它没有独立解决自然语言理解，也不代表 Memory Engine 已经成熟。设计取舍见 [ADR 0074](decisions/0074-记忆命题的竞争解释与语义修复.md)。

## 1. 为什么需要改变提取结果

设原文为“面向访客的资料采用格式 A”。把它拆成“资料格式为 A”和“资料受众为访客”，两个独立属性就丢失了“访客条件限定这个格式”的关系。后续条件图无法从缺失的连接中计算等价关系；继续复核只能拒绝，不能恢复那条连接。

本轮让提取阶段具有重新组织命题的能力。生产代码没有业务词典、场景编号或答案标签；参与者角色、属性与条件都从调用方提供的原文中分析。公开端口仍为 `MemoryExtractor`，应用可以组合自己的初始提取器和语义模型。

## 2. 一次输入的执行过程

入口是 `ModelMemoryRepairingExtractor.extract`：

1. 调用初始 `MemoryExtractor`，解析已有引用，得到一份 `MemoryInterpretation`。它包含整组候选及各候选的断言模态。
2. 模型从焦点原文识别最多八个 `MemoryMeaningUnit`。一个单元应保留完整参与者、属性、适用条件与时间；先前来源只辅助指代解析。此调用看不到初始提取，避免沿用初值的错误拆分。
3. 首轮总会调用 `rebuild_meanings`，从完整原文生成一至两个完整解释，允许合并、拆分或重新附着条件。这里返回整组命题，避免依赖容易错位的数组补丁。不能凭初值自评就结束搜索。
4. 逐项解析来源引用，按内容指纹排除已经尝试的解释。候选排列变化不产生新指纹；文本、引用或其他字段变化仍可能产生新指纹，这不是语义同义去重。
5. `compare_meanings` 在一次调用中，对当前解释和新方案使用同一组固定含义单元评分。比较只展示候选的结构化字段，原文单独提供；候选 `text` 中抄录的条件不能补救结构化字段的遗漏。初值质量取自第一次竞争比较；若只生成了重复方案而没比较，其质量保持未知。
6. `select_interpretation` 根据逐维支配关系选方案。没有合格改善时保留原解释。若允许第二轮，模型会收到上一轮失败方案及其比较结果，避免只靠同一提示反复生成。
7. 返回 `MemoryExtraction v4`，包含选中解释、初值、含义单元、所有经过比较的替代方案、评分与生成收据。现有 `MemoryFormationEngine` 保存提取，再做关系复核、条件图计算、时态事实集修订和事务提交。

固定含义单元是模型分析结果，不是宿主手工标注，也不是评测答案。它们可以遗漏或拆错；固定下来只是使同次搜索有一致的比较坐标。

## 3. 选择算法真正承担的决策

每个含义单元用一条 `MemoryMeaningAssessment` 同时携带等级与主要缺陷，避免两条平行数组失去对应关系：

| 等级 | 含义 |
| --- | --- |
| 0 | 结构表达了错误含义 |
| 1 | 没有保留该含义 |
| 2 | 只保留部分关系或条件 |
| 3 | 结构完整且忠实 |

一份 `MemoryInterpretationQuality` 保存每个单元的 assessment，以及无来源主张数量 `unsupported`。这些等级是有序判断，不是概率或经过标定的置信度。

设当前向量为 `g`，替代方案为 `h`。替换必须同时满足：所有单元 `h[i] >= g[i]`，无来源主张不增加，且至少一个单元改善或无来源主张减少。比如 `(3, 0)` 不能被 `(2, 3)` 替换，虽然总分增加了；它丢失了原本完整的第一个含义。

多个合格方案先比较等级总和，再比较无来源主张数、命题数，最后用内容指纹稳定打破同分。较少命题只是同等覆盖后的选择项，不能靠删除事实换取更高优先级。把错误主张删除为遗漏可以从 0 提升到 1，但仍不能称为任务完成。

选择器为 O(H×U)，H 至多 3、U 至多 8。指纹另有候选序列化与排序成本。真正耗时的是模型调用：默认一轮时，在初提取之外增加分析、生成和比较三次调用，全部重复时省去比较；最多两轮时额外五次调用。协议修复次数由已有 `MemoryGenerationPolicy` 另行控制，全部共享同一期限。

这不是全局搜索或 beam search。它只保存一个当前解，不能经过暂时退化的方案走到更优解；对不同轮次重新评估的等级也可能漂移。逐维不退化只针对同次比较中的模型评分，不能推导出真实语义绝不退化。

## 4. 持久化、失败与系统协作

新机制不直接写 Memory Store。选中解释经过原有 reviewer 和 admission 后才形成持久事实，随后供召回与 Context 消费。它不改变主体授权、既有 Assertion、SQLite DDL 或时态事实集规则。

`MemoryExtraction v4` 显式保存搜索记录。旧 v1–v3 序列化不增加 `search` 字段。选中候选必须与搜索记录的重放结果一致；存储重开、投影重建与已完成作业的重试都可以复用完成的 v4。复核只接收选中候选，不会把未选中的尝试混进事实。

模型失败、非法输出或不可解析的来源不会偷偷接受未经比较的候选。外层期限覆盖初提取、分析、生成、比较与同步校验；`CancelledError` 继续向父调用传播，不转为普通失败。没有后台任务。

当前没有搜索中途的持久检查点。提取阶段完成前取消或崩溃，重新运行会再次调用初提取和搜索；完成结果保存后，后续 CAS 冲突或复核重试才可以复用。也没有把失败搜索静默降级为初值的策略；实验中该臂提取失败时，其消费探针计失败。

## 5. 如何接入和运行

```python
from weavria.harness import (
    ConservativeMemoryAdmission,
    MemoryFormationEngine,
    MemoryGenerationPolicy,
    ModelMemoryExtractor,
    ModelMemoryRepairingExtractor,
    ModelMemoryReviewer,
)

initial = ModelMemoryExtractor(
    provider,
    configuration_id="fixed-model-config",
    generation=MemoryGenerationPolicy(0),
    claim_modalities=True,
)
extractor = ModelMemoryRepairingExtractor(
    initial, provider, configuration_id="fixed-model-config", max_rounds=1
)
reviewer = ModelMemoryReviewer(
    provider,
    configuration_id="fixed-model-config",
    generation=MemoryGenerationPolicy(1),
    family_alignment=True,
    set_reconciliation=True,
    semantic_conditions=True,
)
engine = MemoryFormationEngine(
    store,
    extractor,
    reviewer,
    admission=ConservativeMemoryAdmission(set_reconciliation=True, semantic_conditions=True),
)
job = await engine.process(access, accepted_input, max_duration=240)
```

调用方准备 provider、store、access 与已接受输入。新增搜索显式启用，原提取器仍可独立使用作为基线。

```bash
uv run pytest tests/memory_formation/test_interpretation_search.py \
  tests/test_live_memory_interpretation.py
uv run python -m examples.live_memory_interpretation --live \
  --dataset examples/data/memory_interpretation/validation.json \
  --output .weavria/新的语义修复回归.jsonl
uv run python -m examples.live_memory_interpretation --live \
  --dataset examples/data/memory_interpretation/captured_failure.json \
  --output .weavria/新的历史错误修复.jsonl
```

模型配置从环境变量注入。输出以独占方式创建，不能覆盖之前的失败记录。`captured_failure.json` 是有意保留并检查过的合成材料真实模型输出：它来自上一轮已记录的错误提取，不含凭据、私人数据或隐藏推理。该组直接重放初值，不重新抽样，也不应混算成新输入泛化成绩。

## 6. 验证方法与结果

确定性测试穷举两维等级的全部前后组合，验证支配选择；检查同分顺序、错误重组回滚、第二轮重组与失败反馈、重复方案停止、完整结果提前停止、SQLite 保存与重开、旧 Schema、超时与取消清理。消费实验测试同时覆盖新提取、固定错误初值、成功与失败，保证标签不进入提取或搜索请求，失败不从分母消失。

真实模型实验分开衡量搜索评分与独立消费。消费模型只看到结构化候选和问题，不能读取候选 `text`、引用原文或搜索评分；答案标签只参与本地匹配。它衡量结构是否足以支持条件选择，不是完整 Agent 任务或生产 MemoryContext 效果。生产消费可以看到更多原文，不能把本实验差异直接外推到端到端收益。两者使用同一供应商模型，错误也可能相关。

固定配置为 deepseek-flash、temperature=0、8192 输出上限、thinking enabled/low；初提取与搜索各 180 秒、消费探针 60 秒、HTTP 90 秒，语义修复一轮、协议修复零次。两臂复用同一个初提取，消费顺序逐案例交替。结构消费要求返回 ASCII 标识或 unknown，严格匹配，不用搜索器自评分当答案正确率。

本轮最终全仓 **1333 项测试通过**，`uv sync --locked`、Ruff、格式检查、Pyright 通过。它们验证执行行为，不证明语义质量。

### 开发过程中的失败

开发集两例、四个探针。第一版两臂均 1/4，主要是探针返回“格式K7”等带类别名称的文本而严格标签为 K7；没有修改旧分数。随后明确探针只返回 ASCII 标识。第二次开发运行原路径 3/4，搜索路径 0/4：模型的平行等级/缺陷数组失配。第一次四例验证原路径 8/8、搜索路径 0/8，搜索均未完成；这次失败记录完整保留。

从开发材料诊断并将等级和缺陷合成 assessment 后，旧错误重放虽然可以完成，却被分析器自评为完整、没有启动重建。这促成最终版本的两个机制调整：原文分析看不到初始提取；首轮总会尝试替代方案。最终数据重跑属于已见材料回归，不能再称独立验证。

### 最终版本的历史错误重放

这里重放上一轮真实生成的两个命题：培训资料的受众是新同事；培训资料格式为 PDF，另把“长期”放进 qualifier。期望修复的是受众与格式之间的条件附着，不是改写 PDF 这个值。

最终运行确实生成了两个替代解释并完成比较，但模型仍将初值和第一个替代方案都评为 `(3, 3)`，另一个方案为 `(2, 3)` 且有一个无来源主张。宿主按既定规则保留初值。因此 **已知结构问题没有被修复**。独立消费两臂均 2/2，也说明这两个问答没有辨别出那处结构缺陷，不能把答对解释为结构正确。

本次重放初值无新增模型费用；搜索增加 3 次调用、17,390 Token、73.59 秒，消费共 4 次调用、2,942 Token。较早的自评提前停止版本为搜索 1 次/6,391 Token、29.18 秒，同样没有修复；最终版本探索更充分，但本例没有收益。没有挑选一个成功生成来替代这个失败结论。

## 7. 当前局限与下一小步

已实现的深度在于从错误初值主动生成整组替代解释、保留竞争方案、按逐含义的非退化关系选择，并把选中结果接回持久形成管线。条件图仍只处理正确形成之后的局部合取关系；搜索不能替代关系表示本身。

含义单元发现、角色分析和评分仍依赖模型。八单元/八命题容量、局部搜索路径、候选顺序偏差、评分漂移和额外调用成本都是真实限制。没有训练过的语义解析器、关系级不确定性传播、全局实体本体、自动调参或长期学习。

下一小步应沿实际失败深化参与者、属性与条件的联合表示和解释，尤其是如何让适用条件在多个命题间保持正确附着，以及如何发现被自评漏掉的关系缺项。重点应是改善命题结构的构造与选择，而非继续增加审批字段或领域词表。
