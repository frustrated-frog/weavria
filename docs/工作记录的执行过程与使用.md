# 工作记录的执行过程与使用

本次新增的是当前任务的短期工作记录。它让 Agent 在长任务中保留简短计划、阶段成果、失败尝试和下一步问题，并据此调整上下文与工具展示。

## 如何启用

在现有 AgentHarness 配置中增加 `working_records=True`，并提供任务理解器。框架自动组合工作工具、归约和模型工作视图，无需应用自己写计划循环。计量器须支持已有 TaskModelView 要求的完整传输计量。

```python
async with AgentHarness(
    session_path,
    model=model,
    tools=tools,
    context=context_config,
    token_counter=counter,
    understanding=understanding,
    working_records=True,
) as agent:
    session = await agent.create()
    result = await agent.send(session, "比较这些资料，查清差异后给出结论")
```

可运行的真实模型入口为：

```bash
# 配置 WEAVRIA_MODEL_BASE_URL、WEAVRIA_MODEL_NAME、WEAVRIA_MODEL_API_KEY 后使用。
# 此命令会调用模型，--documents 指向自己提供的 JSON 文档目录。
uv run python -m examples.harness_session --session work-demo \
  --message '比较文档中的方案，保留已否定的尝试，并核对关键原文。' \
  --working-records --documents ./documents
```

简单请求可以直接回答，不强制生成计划。默认不启用此功能；本轮没有运行付费模型任务评测。

## 沿一次请求读代码

1. `assembly.py` 成套配置工作记录，SessionEngine 将支持工具与业务目录分开。初始工作修订号为 0，模型从 TaskModelView 看到当前需求 ID 和工作状态。
2. 模型可以正常调用业务工具，也可以通过 `propose_work` 提交下一步意图和笔记。`work.py` 中的工具校验所引用 Artifact 的访问范围与 JSON pointer，返回提议，暂不修改状态。
3. Runtime 持久接受工具结果后，TaskAwareSessionPreparer 先刷新证据，再调用 `reduce_work`。它按记录顺序核对任务与工作修订号，接受替换或返回冲突诊断。
4. `working_set.py` 使用下一步需求的有界软偏好分配工具位置。`context.py` 使用同样的偏好和来源地址生成检索需求。模型下一轮不仅看到计划文本，也获得重新分配的信息和能力。
5. `task_view.py` 将工作记录放在有界 progress 中，源材料仍保留在 Artifact。完成验收继续依靠 Frame、NeedLedger 和真实工具结果，不依靠笔记中的结论。
6. steering 进入原有重新理解流程；需求变化沿依赖关系传播，过时笔记退出活跃集合，旧下一步意图清空。新任务仍可读取已接受的原始成果。

例如已读完一个大文档后，业务读取工具可以退休。工作记录保存“已取得文档，下一步核对末尾兼容性说明”及 `/value` 来源地址；下一轮上下文会优先考虑该来源，同时原文读取工具继续可用。这比单独增加一个 plan 字段多了状态对信息分配的实际作用。

## 数据结构与取舍

最多 6 条笔记，每条摘要最多 240 字符；整个更新最多 4000 UTF-8 字节，工作状态最多 8192 字节。这里的字节只是结构上界，不等于模型 Token；最终请求继续由 ContextCompiler 计量。

采用全量替换有界集合，模型需要主动保留仍有用的记录。相比细粒度补丁，它避免删除、重排和覆盖操作的额外冲突协议；代价是较长的更新输入和可能遗漏仍有用的笔记。旧版本没有物理删除，仍存在于原事件与提议 Artifact。

笔记都属于模型推断。来源有效不保证摘要正确；关联需求是模型声明的依赖，不是完美语义分析。下一步偏好只有 2 倍且最终封顶，不会直接强制工具调度、授予权限或宣布需求满足。

## 如何验证与观察

```bash
uv run pytest tests/harness/test_work_records.py -q
uv run python -m examples.working_records
```

固定实验只证明相同需求下，工作意图改变工具与上下文分配，并报告记录大小。组合测试使用真实存储与 Fake 模型，验证记录接受、成果引用、工具退休、修订、取消和版本兼容。两者都不能代替真实长任务收益评测。

## 当前范围

只支持当前 Run 的有界工作记录。尚未自动形成历史摘要、判断最佳压缩时机、自动选择原文回取范围或实现 Resume；也没有自动学习更好的偏好权重。工作更新本身消耗工具与模型轮次，可能增加成本。

下一步应在同一工作状态上实现阶段摘要与定向回取，而不是另建笔记系统。详细协议、失效算法和迁移语义见 [ADR 0078](decisions/0078-工作记录驱动的上下文与能力选择.md)。
