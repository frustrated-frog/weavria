# 证据驱动的工作失效与局部重规划

本轮把 Need Ledger 的证据变化接入已有工作图。此前 ADR 0112 的结论版本依赖和 ADR 0122 的证据重验，主要依赖模型先修改上游笔记；现在宿主可以从接受的证据变化触发失效。设计见 [ADR 0129](decisions/0129-证据变化与工作状态的增量重规划.md)。

## 一条执行链

假设模型读取配置，形成“容量为 12”的事实笔记、依赖该事实的“可以同时运行 10 项任务”，以及独立的审计日志要求。随后工具返回容量变为 8 的资料。

1. `TaskAwareSessionPreparer.advance` 从已接受 ToolRecord/Artifact 生成新的 NeedLedger。模型声明或未接受的工具结果不能触发这一步。
2. `reduce_work` 在消费本轮工作提案之前调用 `reconcile_work_evidence`，比较每条笔记关联需求的证据摘要。相关事实笔记被锁存为失效，已有结论依赖图继续传播到建议；独立分支保持原笔记版本。
3. 若本批同时包含旧视图生成的 `propose_work`，证据变化已推进工作修订号，旧 CAS 提案被拒绝，业务工具成功结果不回滚。
4. 同一个 WorkingState 进入既有 Session 语义提交。Task Model View 显示失效、当前可重验前沿；上下文需求提高相关证据的取回权重；工具工作集恢复探索优先级；完成门禁拒绝仍含陈旧结果的交付。
5. 模型提交根结论的新来源和判断。`ModelWorkRechecker` 在工具调用内核查原文，生成绑定本次完整提案和旧工作版本的收据。归约器再核对保留的结果是否引用当前 Ledger 的支持证据，以及原根关联需求是否取得完整资料。
6. 根结论通过后获得新版本，即使文字相同也如此。后继仍然失效，需要按前沿单独重验；独立结果无需重做。全部必要结果有效后，既有完成策略才允许交付。

这条链没有增加第二套工作状态，也不把图当作固定 Workflow。工具调用、取证顺序、候选结论与是否撤回仍由模型决定；宿主约束状态与接受条件。

## 从原文建立关联

真实任务显示模型经常引用 Artifact，却省略内部 `need_ids`。因此 `associate_work_needs` 依据已接受来源的 Run、Call、Artifact ID、内容摘要和 JSON Pointer，匹配 Ledger 绑定，为笔记补充保守的材料依赖。模型明确提供的关系保留。

这只说明“笔记引用了该需求的材料”，不说明文字被材料蕴含。字段父子范围相交也建立依赖；聚合字段可能产生额外失效。关联超过单笔记四个需求的现有上限时拒绝整个提议，不截断后伪装闭合。没有引用的笔记仍依赖模型声明，无法自动找全自然语言关系。

关联只改变接受后的工作投影。原始工具提案与审查收据仍绑定原提议，来源补充由确定性的宿主规则完成，回放不再调用模型。

## 状态、算法与失败

WorkingState v4 新增两个有界字段：`evidence_heads` 为每条活跃笔记保存一个 SHA-256 摘要；`evidence_invalidated` 保存已失效且尚未完成重验的笔记 ID。最多六条笔记，仍使用 8 KiB 状态上限。工具准入为摘要、失效标签和来源匹配可能补充的 Need ID 预留空间，模型视图沿用原有上界。

摘要包含关联需求的状态、缺失字段和接受的证据绑定（含时效、作用域和证明强度）。不摘要全局 evidence_revision、失败次数或无关工具活动。绑定按身份排序，字典按键排序；只改变记录排列或全局版本不会触发重算。绑定内部地址顺序变化仍可能触发保守重验。

证据同步对相同输入幂等。每次新变化推进工作 CAS，失效保持锁存：A→B→A 不能自动复活旧结论。拓扑传播保留 `changed`、`missing`、`blocked_by` 三类既有诊断；直接证据失效由新增 ID 集合解释。只有父节点当前有效的前沿可以提交重验，仍被阻塞的节点原样保留，不因根修复而自动清除。

证据归属扫描受六笔记、每笔记两引用限制，随 Ledger 的绑定和地址数线性增长；摘要对关联绑定排序。结论图最多六节点、每节点五条边，使用原有拓扑归约。当前没有增量维护完整历史的证据索引；长历史成本仍取决于已有 Ledger 构建和绑定扫描。

无法取得完整资料、审查证据不足、模型返回非法引用或旧来源无法匹配当前 Ledger 时，工作提案不提交。取消与超时由原有 Runtime 工具边界负责，归约只使用局部不可变候选状态，不产生后台任务或新增模型循环。数据库仍用已有语义提交事务，不新增表。

本轮结果支持“执行链连接与拒绝条件成立”，不支持“真实 Agent 重规划能力已提高”。下一步应研究更易使用的局部工作更新协议、来源选择和失效修复反馈，减少模型在全量替换工作集时维护内部身份与依赖版本的负担；同时保留宿主 CAS、原文权限和独立验收，不能通过删门禁提高完成率。

## 当前边界

这是已经接入执行链的增量失效与重验机制，不能保证开放长任务被“完美解决”。尤其不能观察工具没有报告的外部变化，不能证明模型声明的结论和依赖完整，也不能形式化证明模型审查正确。新增支持材料也会保守触发失效；同内容的新调用若有新 Artifact 身份仍可能引起额外重验。

保留结果的来源检查要求每个旧关联需求有当前支持资料，但不证明候选引用覆盖全部语义条件或所有新证据。反证、时效变化及数据作用域由现有 EvidenceExtractor/NeedLedger 提供；默认结构提取器不能凭空判断文档哪一版具有现实权威性。后续应重点研究实际失败的材料选择与修复行为，并在多任务、多模型下检验收益，不能用放宽门禁来替代这一工作。
