# 工作结论依赖与局部重验

本阶段把已有工作笔记升级为带版本依赖的工作状态。它处理的问题是：上游结论变了，哪些后继需要重新检查，哪些独立工作可以继续使用。

## 一次请求怎样流转

假设模型在 `propose_work` 提交四条笔记：统计 A、依赖统计的分析 B、依赖分析的建议 C，以及独立发现 D。初次接受后四条笔记版本均为 1，B 绑定 A/1，C 绑定 B/1。

1. 模型用新资料修正 A，提交整个工作集，保留 B、C、D 的原绑定。
2. 工具先检查来源访问和输入，再生成提案 Artifact。归约器检查任务版本、工作集 CAS 和处理游标，接受后将 A 更新为版本 2。
3. B 的 `dependency_issues.changed` 包含 A；C 的 `blocked_by` 包含 B。D 仍为版本 1。原始资料与旧提案没有被删除。
4. 下一轮模型能看到上述诊断，相关需求重新获得探索权重，上下文优先回取 A、B 的资料。提前 Finish 会收到 `work_dependency_stale`。
5. 模型重新检查 B，显式改成依赖 A/2。B 获得版本 3；C 此时显示 B 的版本改变，仍不能交付。
6. 模型重新检查 C，改成依赖 B/3。C 获得版本 4，失效闭包清空，正常完成验收继续执行。D 始终不用重做。

示意输入中的依赖写法：

```json
{"note_id":"analysis","kind":"result","summary":"当前分析结论",
 "depends_on":[{"note_id":"statistics","revision":2}]}
```

版本从当前 `working_state.note_revisions` 读取。同一提案里的新笔记或内容有变化的笔记将取得 `working_state.revision + 1`。工具采用全量替换，因此要保留仍有用的笔记。省略任务和工作集版本仍由宿主绑定；存在结论依赖时应使用稳定的 `note_id`。

重新绑定只是模型声明“我已重新检查”，不代表 Runtime 独立证明了结论。最终正确性和引用检查仍由对应完成策略负责。

## 沿源码阅读

- `src/weavria/harness/work.py`：协议、DAG 校验、逐笔记版本、失效原因、提案归约、任务修订和压缩。图最多六个节点，每节点最多五条边，8 KiB 状态预算保持不变。
- `src/weavria/harness/context.py`、`progress.py`：取回待重验结论的来源并调整下一步建议；不把改笔记算成新的证据进展。
- `src/weavria/harness/completion.py`、`finalization.py`：阻止使用失效结果收尾。
- `tests/harness/test_work_dependencies.py`：版本竞争、部分重验、重放、端到端拒绝/恢复、重开和旧数据兼容。

删除上游会使后继显示 `missing`；恢复相同文字也使用新版本。父节点尚未重验时，后继显示 `blocked_by`。修改任务需求继续使用已有需求失效规则，幸存的跨需求后继不会失去这个约束。

## 复现实验

```bash
uv run python -m examples.work_dependencies
uv run pytest tests/harness/test_work_dependencies.py tests/harness/test_work_records.py tests/harness/test_acquired_work.py tests/harness/test_progress.py
```

冻结图包含 A→B/C→D 的菱形依赖及独立的 E→F。五种输入分别是不修改、修改 A、B、D、E。

| 五种输入合计 | 不失效 | 其余节点全部重做 | 版本依赖 |
| --- | ---: | ---: | ---: |
| 重验笔记数 | 0 | 20 | 5 |
| 陈旧笔记仍可使用的次数 | 5 | 0 | 0 |
| 不必要的重验次数 | 0 | 15 | 0 |

这些数字说明已声明图上的失效范围和局部重验机制成立。实验没有让真实模型发现依赖，没有测模型正确性、Token 节省或用户任务完成率，不能据此声称已经达到成熟 Agent 的规划能力。

## 本阶段边界

依赖由模型显式声明；漏声明的关系仍可能导致旧结论继续使用。框架不会自动识别新旧资料的语义冲突，也不会把新资料自动当作旧资料的修订。退出活跃工作集的节点不会存入一个无限扩张的任务图。跨任务接续的历史笔记仍需在新任务中重新确认，历史状态不是新任务的完成判据。

本阶段的完成标准是版本依赖、失效、逐层重验、上下文反馈、最终验收与持久化一致性跑通。真实模型收益仍待验证；下一步优先补领域无关任务中的依赖发现和重验质量实验，再判断是否引入更复杂的语义核验机制。

详细取舍见 [0112 ADR](decisions/0112-工作结论的版本依赖与增量失效.md)。

本次验证：`ruff check .`、`ruff format --check .`、`pyright` 均通过；全量 `pytest` 为 1705 通过、24 跳过。跳过项是需要显式配置 Docker 镜像的既有测试，本轮未重新执行。工作依赖与原有工作链路的定向测试为 39 项通过，压缩视图及任务修订链路另有 4 项通过。
