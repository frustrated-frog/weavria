# 两个领域的单读反证自然形成与复用实验

## 实验口径

上一轮在种子反证和目标首读均已固定时测过反馈的消费效果。本轮从空 SQLite 会话开始，让正式 SessionEngine 和真实模型连续完成两次相同查询。用户要求在本次任务中查证并给出来源。模型可自由提出单读或批读、决定读取次序、提交判断、采用建议、复核或直接回答。工具按来源清单填入内容版本。实验只提供两份资料的路径和任务，没有指定失效来源、调用次序或期望的判断。

固定两组独立的合成资料。公交运营任务查现行末班时刻，软件归档任务查当前桌面导出器的默认压缩格式。每组有一份已失效但看来相关的资料和一份权威现行原文。奇偶轮对调资料路径在用户问题中的顺序，同一轮的所有策略取得相同顺序。

每个领域六轮，每轮三种策略，三组独立调用真实 Provider。六轮遍历三种策略的六种执行顺序。三组使用相同版本工具、判断协议、模型、预算和判分器。普通组关闭单读经验，排序组开启经验但关闭反馈附注，展示组两者都开启。每轮核对三组首次请求摘要。第二次任务继承本组自然形成的会话历史，模型仍须交付本次读取的原文。

正确要求执行完成、答案值与引用匹配，并且读取工具在该 Run 确实执行且相应原文完整送达到模型请求。生成了引句、形成可复用回执、检索命中、影响排序和实际展示分别计数。端到端成本包含首次查询与复查的全部真实模型调用和工具执行，统计供应商报告的输入和输出 Token。超时、无回执、未展示、失败和主动直接读到正确来源的任务均保留在分母中。

预先约定，只有两个领域各至少两次独立复查实际展示，展示组每个领域的正确任务数均不下降、对另外两组的总 HTTP 调用与总 Token 均减少，才报告跨领域的端到端节省。结果不足时，根据执行轨迹指出流失发生在哪一步。

公交展示组第二、三轮中，模型第一步主动单读旧表，准确引用了撤回声明，随后读公告并答对。这两轮都未经历预算拒绝，现行索引要求的“拒绝后采纳推荐单读”没有发生，故两条判断都未形成回执。第五轮中模型先提出双读，预算拒绝后读旧表，产生了可复用回执。复查时反证改变建议，模型拿到公告及旧表引句后直接作答。该轮复查用了 3 次 HTTP 调用和 6856 个 Token，普通组和仅排序组各用了 4 次调用，分别消耗 9321 和 9378 个 Token。三组的完整轨迹独立生成，此处是一次观察。

软件归档展示组的六次初查中，三次直接走到了现行资料，另三次收到旧指南但未产生可核验的负向判断。排序组独立产生并复用过一条旧指南反证，因此两个领域均有自然形成的实例。对缺失的判断，已接受的模型决策只能证明没有留下可用引句，无法进一步区分模型省略判断和候选引句未通过校验。

## 成本归因与下一步

普通、排序、排序并展示三组的全程 HTTP 调用合计分别为 **92、89、87**，总 Token 分别为 **184353、176349、173983**。其中初查调用分别为 50、48、45 次，复查分别为 **42、41、42** 次。初查开始时都没有历史反证可供展示。两组独立运行，即使看到同样输入，模型也可能选择不同动作。因此总量优势不足以证明附注带来了端到端节省。按事前条件，实际展示只有公交 1/6、软件归档 0/6，未达到跨领域门槛。本轮交付为实验与计量，正式策略沿用上一轮的边界。

下一小步优先检验**主动单读后明确纠正选源**的情形。候选条件是同一任务、同一版本下，模型引用已完整送达的失效原文，随后主动改读另一份来源并取得当前证据。先在已有路径旁记录这种事件，比较新增命中和误用率。软件归档的遗漏还需要单独观察判断形成环节。当前数据只来自两个合成资料集、同一模型和完全相同的复查问题。

## 复现和核对

```bash
uv run pytest -q tests/test_natural_read_counterevidence.py
uv run python -m examples.natural_read_counterevidence --env-file .env.m1-openai --rounds 6 > /tmp/weavria-natural.jsonl
```

真实模型为 `gpt-6-luna`，推理力度为 `medium`。窗口 32000 Token，输出预留 2048 Token，单请求最多 16000 字节，每次查询最多 7 次模型决策和 5 次工具调用。两份资料共用同一个内容寻址的只读工具，单次反馈上界为 6000 字节。批读可能被拒，单读取决于当轮剩余预算。在线命令会产生模型费用。

每行 JSON 属于一个领域、一个轮次、一个策略，`seed` 和 `repeat` 分别对应初查与复查。`reads` 记录真实执行顺序，`delivered` 来自该 Run 的持久请求。`old_judgments` 数接受的模型决策中绑定旧原文摘要的负向判断，`stored_negatives` 数完整送达后通过 SQLite 核验的经验回执。复查时依次检查 `recalled_negative`、`displacements` 和 `shown`，分别对应拒绝事件中的历史反证、反证改变原有赢家、模型输入中的原文附注。按任务计算命中率时，同一字段大于零只计一个任务。成本从真实 HTTP transport 读取，供应商没有报告的 Token 保留为空。
