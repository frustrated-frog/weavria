# 记忆条件对齐与区间修订

本切片修复真实模型试验暴露的两个问题：相同条件的不同字段名阻止纠错，以及一条明确变更被拆成多个候选后无法共同修订旧区间。设计见 [ADR 0041](decisions/0041-记忆条件对齐与联合区间修订.md)。

## 一个请求怎样执行

已有断言：项目技术文档语言为中文，条件为 `{"document":"技术文档"}`。用户纠正后，提取器产生英文候选，条件却是 `{"文档类型":"技术文档"}`。

1. `ModelMemoryExtractor` 保留原始候选及原文引用，不直接修改旧事实。
2. `ModelMemoryReviewer` 返回 MemoryReview v2，在判断 correction 的同时给出 MemoryAlignment：绑定候选序号、目标 ID、目标 revision，逐项对应主体、谓词和条件。
3. `align_candidate` 验证每一对路径、引用的唯一定位、当前输入来源和双向条件覆盖。两个条件键不同但值相同，可以规范化成旧键；真正缺失的条件不能靠布尔“等价”绕过检查。
4. 准入器用规范候选编译 mutation；原始 extraction 不变，review 保存全部映射，batch 保存最终写入。出现过时 revision、伪造引用或未覆盖条件时，记录待定决定。
5. 形成引擎仍用 read-head 与目标 revision 做 CAS；事实、消费游标和作业完成记录在同一事务中提交。并发写入使计划失效时，重新复核新快照。

## 对齐究竟保证什么

`MemoryFieldMatch` 使用 JSON Pointer 表达 `/subject`、`/predicate`、`/value`、`/qualifiers/<键>`，键中的 `~` 和 `/` 必须转义。每条对应都需要当前输入中的逐字引用，且来源已经被原候选引用。

- 主体只能对应主体。
- 谓词和条件必须在两边全部覆盖，不能出现未知路径或重复路径对。
- 条件键改名目前要求条件值字面相同，不自动翻译或合并任意条件值。
- 条件折叠进谓词时，条件值还须逐字出现在另一侧的断言文本或谓词中。例如“技术文档”已经写进谓词语义和断言文本，可以提供明确映射；README 不能无依据地消失。
- 值别名只允许在 equivalent 关系下显式对应；change/correction 的新值不会被规范化成旧值。
- 对齐不能改变作用域、有效时间、权威性或置信度。

这些检查约束映射的结构、来源与版本，**不能证明模型的语义判断必然正确**。即使引用完整，模型仍可能错误理解主体或值等价。当前不是通用本体对齐或实体消歧系统。

## 多个候选怎样共同修订时间

旧事实是 `[1月1日, 无结束)` 的中文。新输入明确给出“1月10日起用英文，之前仍用中文”，提取器可能产生两段：`[1月1日, 1月10日)` 中文和 `[1月10日, 无结束)` 英文。

`partition_mutations` 按起点排序，维护一个从旧起点开始的游标；每段起点必须等于游标，再将游标推进到该段终点。最终游标必须等于旧终点。这个有界排序与扫描同时检测空隙、交叉、缺尾和候选顺序差异，不按返回顺序选胜者。

通过后生成一个撤回旧断言的 mutation，加上各段独立断言；旧值片段合并旧来源与新来源。整个 batch 原子提交，历史 head 仍能看到原区间。若任何一段与其他现存事实或同批候选冲突，整组暂缓，不能仅撤回旧断言。

当前最多八个候选，分区检查为 O(k log k)，批内冲突检查为 O(k²)，与完整作用域快照比较为 O(kn)。完整快照仍受既有 128 条/256 KiB 限制，超限显式失败；没有以 top-k 代替完整冲突检查。

## 版本与恢复

MemoryReview v2 新增 `alignments`。v1 的序列化不增加字段，仍可读取；v1 携带非空映射或未知版本被拒绝。MemoryFormationPlan/Job 的外层结构不变，嵌套 review 自带版本，SQLite 不需要改表；旧二进制不能读取新的 v2 review 作业，不能把这种拒绝误称为兼容。

复核器升级为 `model-memory-reviewer/2`，准入器升级为 `conservative-memory-admission/2`。模型适配器要求返回 v2，防止生成结果静默退回旧协议；直接使用旧 v1 review 时仍执行保守字面条件规则。旧未完成作业必须使用匹配的 pipeline，当前不提供自动迁移。

## 验证与观察

```bash
uv run pytest tests/memory_formation tests/test_live_memory_formation.py -q
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest
```

重点测试包括 `test_alignment_preserves_conditions_and_persists_proof`、`test_joint_partition_is_atomic_and_order_independent`、`test_joint_partition_rolls_back_all_segments_on_completion_failure`。分别验证字段对应及审计、双时间分区与排列不变性、事务失败后所有事实和游标均不推进，再重试同作业成功。

真实模型沿用 12 个诊断案例并运行三轮，额外冻结六个日志时区、数据库和脚本配置案例作为小规模留出检查。两臂共享相同提取结果，预期答案不进入模型输入。结果见 [真实模型评测](记忆形成真实模型评测.md)，不能用 Fake 的准确判断证明真实语义效果。

评测 CLI 新增 `--dataset`，每个已结束 trial 立即写入同名 `.jsonl` 并刷盘，记录配置、数据集摘要、结构化决定和用量；全部结束后生成汇总 `.json`。中断后可审计已结束 trial，但尚无自动跨进程续跑命令。凭据和思考内容不写入报告。

## 当前边界

未知起点、争议目标、任意区间手术、跨目标联合纠错、非完整分区和任意条件值同义替换仍暂缓。没有自动归并所有相似记忆，也没有新增隐式后台消费者。

下一切片是保证召回与 Context 的事实完整性：将竞争版本、条件例外、来源和有效时间作为完整组分配预算，避免先正确形成记忆、后被摘录丢掉条件。之后再验证跨会话真实任务收益；本切片不宣称已接通自动召回或完整 Memory Engine。
