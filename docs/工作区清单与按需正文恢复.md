# 工作区清单与按需正文恢复

后续已加入[工作区动态工具接入与成本验证](工作区动态工具接入与成本验证.md)，删除示例中的重复目录并支持显式动态模式；本文保留该阶段的历史实验数据。

## 新增能力与动机

上一阶段已经能从不可变工作区继续计算、保留未修改文件并合并兄弟版本，但完整结果把导出正文和工作区正文一起放进反馈。即使模型下一步只需引用一个版本，也要为整个文件容量预留反馈空间。设置 `context_paths` 无法单独解决这个问题：完整反馈和 raw 候选仍可能包含全文。

本阶段新增 `workspace_manifest_tools`：执行和合并返回清单，正文保存为受控 Artifact 附件；`read_workspace_file` 按版本、路径分页。后续计算仍在宿主恢复原文件，模型不必先读取或重写全部正文。旧版完整快照构造器保留，便于兼容和对照。

这是一项有界的信息交付机制，不是文件保密机制：日志仍完整交付，生成的 Python 可以显式打印正文。它也不改变文件内容的低信任属性。

## 一次请求如何流转

以先生成 `statistics.json`、再生成 `report.txt` 为例：

1. 模型调用 `execute_workspace_python`。既有工作区工具在独立容器中计算并构造 v1 完整结果。没有额外模型调用，也没有第二次沙箱执行。
2. 包装层通过 `ToolContext.stage_attachment` 保存完整结果。附件和最终结果使用相同 Run/Call 身份；此刻附件只是暂存，不产生 `ToolRecorded`。
3. 包装层从同一完整结果计算 v2 清单：`state` 是完整结果的引用；`workspace` 包含 revision、父版本、文件路径、SHA-256 和 UTF-8 字节数。执行状态、日志、错误及合并冲突保留，文件正文不进入清单。
4. 原 ToolExecutor 保存清单，Runtime 接受最终工具结果。上下文编译器沿用 complete-feedback 规则，交付整个清单；其 raw 候选也只包含清单，不会再次载入附件正文。
5. 第二轮使用**外层结果的** `artifact_id` 与 `workspace.revision` 作为 base。`load_workspace_state` 先验证父结果在本轮接受视图中，再解析 `/state`，检查附件生产者和完整引用，重新计算清单并验证 revision。
6. 通过验证后，仅在本次 ToolContext 内授予附件读取权限，复用原 Artifact 输入端口挂载文件。新版本自动保留 `statistics.json`，加入 `report.txt`。后续调用必须重新验证父结果，不能直接拿私有 `state` ID 绕过它。
7. 需要查看正文时，模型调用 `read_workspace_file`；只将所需页面作为新反馈。CompletionPolicy 则通过 `CompletionContext.read_attachment` 读取权威正文并独立验收，不以模型最后一句“完成”代替检查。

来源依赖仍登记为父结果的生产 Call。页结果包含完整来源引用、JSON pointer、文件哈希和父版本；`next_read` 始终指回父结果，不会把上一页误认为全文。

源码阅读顺序：[附件身份核验](../src/weavria/artifacts/attachments.py) → [调用级暂存与授权](../src/weavria/tools/execution.py) → [清单及状态恢复](../src/weavria/tools/workspace_storage.py) → [工具装配与分页](../src/weavria/tools/workspace_manifest.py) → [独立成果验收](../examples/sandbox_execution.py)。设计取舍见 [ADR 0106](decisions/0106-工作区清单与受控附件恢复.md)。

## 数据结构、边界与失败语义

| 数据或操作 | 契约 |
| --- | --- |
| `WorkspaceManifestOutput` v2 | 独立版本化的公开清单协议；正文附件仍保存既有 v1 完整结果 |
| `WorkspaceManifest` | 最多 8 个文件，总容量至多 64 KiB；路径、文件大小及哈希明确，revision 沿用原快照算法 |
| `stage_attachment` | 每次调用最多 32 个附件，共享 `min(4 MB, FeedbackBounds.max_result_bytes)` 字节额度；单个引用的 JSON 表示至多 1024 字节 |
| `read_owned_attachment` | 只校验父子身份和内容完整性；调用方必须先授权父结果，它本身不是授权 API |
| `read_attachment` | 验证同一 Run、同一生产 Call、不同 Artifact ID、精确引用及摘要；异步存储返回后再次检查上下文是否关闭 |
| `read_workspace_file` | `start/end` 按 Unicode 字符计数，`length` 限制页面 JSON payload 字节数；支持 1–4000 字节，过小无法容纳字符时沿用既有分页错误 |
| v1/v2 互操作 | 两种 base 均可恢复，完整与清单分支可以合并；revision 不依赖交付表示 |

附件额度在等待存储之前扣除，同一次调用内并发暂存不会重复获得额度。存储失败不退还该调用的额度；已存附件不等于已接受的执行事实。取消或超时可能留下孤立附件，但正常 Runtime 没有接受父结果就不能沿附件恢复，也不会改变共享 HEAD。`CancelledError` 原样传播，超时使用现有 TIMEOUT 分类。

未接受父结果或另一生产者的引用会拒绝访问；清单与正文不一致、v2 协议损坏归为 INVALID_TOOL_OUTPUT；错误 base revision、文件不存在等仍是参数错误。哈希只证明内容一致，不能证明调用者有权限或内容在业务上正确。

`ToolContext(accepted_artifacts=None)` 仍保留原有宿主开发模式的不限已接受视图行为。正常 Runtime 显式传入接受视图；宿主若主动使用不限视图模式，不能宣称具有相同隔离保证。历史回取、跨 Run 和只读 Resume 限制保持原样；父结果已经退出可读视图时，应先按原流程恢复来源。

## 使用方式与兼容

```python
from weavria.tools import SandboxToolPolicy, ToolRegistry, workspace_manifest_tools

tools = workspace_manifest_tools(backend, workspace_bytes=8192)
registry = ToolRegistry(tools)
policy = SandboxToolPolicy(
    versions={
        tool.descriptor.name: tool.descriptor.version
        for tool in tools
        if tool.descriptor.behavior == "isolated_compute"
    }
)
```

执行和合并仍需宿主按版本授权；文件读取仍须经过接受视图。新入口沿用 `execute_workspace_python` 和 `merge_workspace` 名称，版本带 `manifest-2-` 前缀。Registry 不可同时注册同名的完整与清单版本；原 `workspace_execution_tool`、`workspace_merge_tool` 构造器保持完整反馈入口，输出 Schema 不变。

```json
{
  "base": {"artifact_id": "已接受的外层结果ID", "revision": "清单中的64位revision"},
  "path": "statistics.json",
  "start": 0,
  "length": 1000
}
```

以上是 `read_workspace_file` 的参数形状，示意占位符需替换。继续计算只需传同一个 base，不能在 `inputs` 再重复声明已自动挂载的文件。

## 验证方法与实验结果

确定性测试覆盖：直接附件访问拒绝、未接受父结果、错误 Run/Call、清单篡改、损坏协议、容量与关闭上下文、存储后取消和超时、Unicode 分页、混合 v1/v2 分支合并、完整反馈的上下文准入以及 CompletionPolicy 原文核验。16K Token 窗口用例验证：完整反馈超预算，清单可进入上下文且不含正文，之后仍可恢复相同文件。它证明执行契约，不证明模型一定会选择正确的文件。

真实 Docker + Harness + SQLite 测试对两种表示运行同一错误—纠正链路：第一阶段成功，第二阶段代码错误不发布版本，纠正后成功；关闭数据库后重读父结果及附件，把相同文件恢复到全新容器。模型动作由测试提供，不是智能能力测评。

本次最终检查：Ruff Lint、格式和 Pyright 全部通过；默认套件 1629 项通过、15 项 Docker 测试默认跳过；显式启用 Docker 后沙箱套件 84 项通过，包含上述容器测试。新增清单专项测试为 12 项。

## 尚未解决与下一步

附件仍保存每个版本的完整状态，不做块级去重或孤立附件回收；存储量并未减少。按需分页限制的是模型交付量，当前恢复需读取、校验完整有界状态，时间复杂度仍为 O(文件总字节)，并不是存储端范围读取。也没有持久 Python 解释器、进程续跑、跨 Run 自动授权或新式可变 HEAD。

下一步应把现有动态能力选择接到这个工具包：按当前任务需要暴露执行、阅读或合并，计入完整 Schema 成本；用固定工具集合、不同文件大小及确实需要回取正文的任务验证选择收益和漏读风险。先解决已经观测到的成本与可用性问题，再决定是否有必要引入文件级存储去重。
