# 记忆形成修复与引用复用

本切片处理尚未接受的模型提案如何重新生成，以及如何减少复核输出中的重复引用。它没有改变记忆的真值、作用域、条件或冲突判断标准，也没有解决所有自然形成问题。

## 从输入到持久化

显式配置 `MemoryGenerationPolicy` 后，提取和复核分别调用 `generate_memory`。宿主固定本阶段来源、候选快照和目标 Schema，最多进行 `max_repairs + 1` 次调用。第一次非法结果只生成固定诊断；下一次仍针对同一输入生成。没有接受的结果不会写入事实、不会推进消费游标。

提取检查原文引用，再把成功候选及宿主生成的尝试收据交还 `MemoryFormationEngine` 保存。复核使用紧凑 wire：例如一个字段对应的 `citations: [0]` 指该候选第一个已经落地的引用。宿主通过 `ReviewWire.expand` 还原完整 `MemoryFieldMatch`；准入策略仍检查焦点来源、字段覆盖、目标版本和条件关系。不能借引用编号跨候选取证，也不能让模型自行写入“已经通过”的收据。

最终仍经过原有计划保存、memory head CAS 和原子提交。完成作业重放不重新调用模型；CAS 重评复用提取，但重新评估更新后的事实快照。原有保存成功后的取消结算语义不变。

## 失败与费用边界

| 情况 | 行为 |
| --- | --- |
| 可修复的 Provider 输出协议错误 | 在剩余额度与期限内重新生成 |
| 返回 Finish、错误工具名、候选 Schema 错误 | 拒绝并发出固定诊断 |
| 提取引用不落地、复核漏候选/引用编号越界 | 拒绝并在额度内重新生成 |
| 模型输出截断、输出超过 64 KiB | 不重复相同生成路径 |
| 引用展开超过 256 KiB | 拒绝，不能用短 wire 绕过容量 |
| 鉴权、依赖、输入预算失败 | 不作为输出修复处理 |
| 条件不符、语义不支持、争议待定 | 继续由准入决定拒绝/待定，不为强行准入重试 |
| 取消或阶段总期限耗尽 | 停止调用并清理，已持久化阶段保留 |

所有尝试共享同一阶段 monotonic 期限，且受形成父期限约束；新尝试没有新的完整时间预算。策略最多两次修复、三次调用。CAS 重评还有原 `max_attempts` 上限；人工再次恢复是另一轮显式调用，当前不提供跨所有人工恢复的永久费用账户。

成功收据包含顺序、固定结果代码、请求与响应摘要、耗时，不保存原始响应、异常正文或隐藏推理。失败收据在 `MemoryFormationError.generation` 中供宿主记录，评测器已保存。取消、父期限或进程崩溃可能没有完整失败收据；它不是崩溃一致的全模型调用账本，不能宣称完整 Durable Execution。

## 表示和版本

模型提取 wire 只包含候选，复核 wire 只包含判断、对齐及引用索引。宿主生成字段不进入模型 Schema。提取持久化升级为 `MemoryExtraction` v2，复核为 `MemoryReview` v4，带成功尝试收据；旧版本读写不新增字段。数据库 DDL 不变，形成流水线版本变化，旧作业不能静默切换策略续写。

引用复用不删减事实或压缩语义。确定性测试中，18 个字段使用同一条长引用的完整表示超过 64 KiB，编号表示仍小于该限制，展开后原文完全相同；更大的引用展开被明确拒绝。这里证明的是表示成本和内容保留，不代表所有模型任务都会省 Token，更不能把供应商思考开销等同于输出 JSON 大小。

## 使用与验证

```python
policy = MemoryGenerationPolicy(max_repairs=1)
formation = MemoryFormationEngine(
    memory_store,
    ModelMemoryExtractor(provider, configuration_id="my-config", generation=policy),
    ModelMemoryReviewer(
        provider,
        configuration_id="my-config",
        family_alignment=True,
        generation=policy,
    ),
)
```

默认不传 `generation` 保留无修复、完整引用路径。`max_repairs=0` 则启用引用复用与收据，但不多调用，可用于拆分表示变化和重试收益。

```bash
uv run pytest tests/memory_formation/test_memory_formation.py tests/test_live_memory_lifecycle.py -q

uv run pyright
uv run pytest -q
uv run python -m examples.live_memory_lifecycle --live --family-alignment --generation-repairs 1 --repeats 1 --output .weavria/generation-new.json
```

新回归验证非法动作/Schema/引用后的单次接受、伪造收据拒绝、次数耗尽、截断及依赖失败不重试、取消清理、总期限、引用编号边界、展开容量、收据落库重开、完成作业重放，以及真实 HTTP 适配→Session→形成→关闭重开→消费。Fake 和 HTTP 替身不证明语义判断正确。

## 实验与限制

真实模型使用原四组连续情景及客户邮件相邻情景，配置保持 `deepseek-flash`、enabled/high、8192 输出上限、90 秒阶段期限、一次消费调用且无消费修复。保留所有首次结果；不增大输出预算来制造通过。

本轮仍不处理“冲突描述被提取成摘要事实”、多目标争议解除、条件蕴含求解或自动修复已形成的错误记忆。引用编号不提供额外语义权威。模型在生成可用正文之前就耗尽思考额度时，本次引用复用也无法保证消除截断。

README 例外及纠正、到期过滤和临时/假设隔离检查点通过。冲突第二条输入被提取为零候选，既有中文规则未进入 contested，故该检查点回答错误；这说明“形成调用正常完成”不等于“形成语义正确”。最终纠正的提取以 length 截断，原库保留，未自动重复调用。完整组失败的两个检查点均为冲突情景。

主实验形成共 19 调用、45,206 输入 / 41,915 输出 Token、241.58 秒；消费共 36 调用、54,600 输入 / 5,017 输出 Token、51.24 秒。合计 55 调用、146,738 Token，含失败及修复成本。成功形成更多输入，也消耗更多成本，不能只比较最后答案。

客户邮件相邻实验北京时间 00:25:29–00:26:35，2 个输入阶段中 1 个形成完成、1 个在提取阶段截断；9 次消费均完成。逐条和完整组均为 2/3 结构评分、1/3 形成未失败且评分通过；无记忆为 0/3。完整组没有证明这一相邻场景已经修好。形成 3 调用 / 15,603 Token / 52.65 秒；消费 9 调用 / 14,931 Token / 13.33 秒，合计 12 调用 / 30,534 Token。
