# 记忆形成与修订决策

本次在双时间记忆内核上增加显式形成流水线：消费已接受的用户输入与运行中纠正，提取带原文定位的候选，复核其语义和作用域，再提交可追溯的写入决定。它解决“何时值得写、应该新增还是修订、失败后怎样继续”，尚未把记忆注入 Agent 的下一轮 Prompt。

设计取舍和持久化协议见 [ADR 0033](decisions/0033-记忆形成的证据准入与可恢复提交.md)。

## 一次请求怎样流转

假设宿主把会话绑定到项目 P，1 月 1 日用户说“本项目从今天起用中文写文档”。

1. `SessionMemoryIngestor.ingest_next` 读取下一个 SessionEvent，绑定其序号、内容摘要、精确文本和作者。模型无法更换项目 P。
2. `ModelMemoryExtractor` 从原文提取“项目文档语言=中文”，带原文引用；不会获得 mutation 或存储权限。
3. `ground_memory_candidates` 在原文里解析 Unicode 码点起点并核验切片相等；保存候选后才继续复核。
4. `SQLiteMemoryStore.reconciliation` 返回同作用域完整、有界的当前事实快照及 head。
5. `ModelMemoryReviewer` 单独判断候选是否受原文支持、是否保留条件、怎样关联既有事实。`ConservativeMemoryAdmission` 再把判断编译成安全范围内的操作。
6. 保存计划；`commit(expected_head=..., formation_id=...)` 原子推进事实、消费游标和作业完成状态。完成的作业重试不会再次调用模型。

1 月 2 日用户说“1 月 10 日起改用英文”，复核为 change 后：中文有效期是 `[1月1日, 1月10日)`，英文是 `[1月10日, 无结束)`。如果用户说“之前说错了，一直是英文”，复核为 correction 后：中文断言撤回，英文接替原区间。查询 `at_head=1` 仍可看到修正前系统接受的中文断言。

“今后只有 README 用英文”保留 `document=README` 条件，可以形成独立事实，不能修改一般文档语言。指代、同义键、变更/纠错区别仍由真实模型判断，宿主不会给它标注答案。

## 关键数据结构

| 对象 | 作用 |
| --- | --- |
| `MemoryFormationInput` | 固定的证据窗口、来源位置、时区和宿主作用域 |
| `MemoryCandidate` / `MemoryCitation` | 不可信解释与逐字引用；没有最终断言权限 |
| `MemoryReconciliation` | 包含未来和未知有效时间的当前事实快照与 head |
| `MemoryReview` | 对每个候选的一次独立语义复核 |
| `MemoryFormationPlan` | 全量准入决定、写入 batch、读 head |
| `MemoryFormationJob` | 不可改写的已保存候选、各次计划与完成记录 |

候选和计划不属于召回事实；用 `formation` / `formation_history` 审计，只有 MemoryBatch 接受的断言进入 `recall`。每个作业阶段独立持久化，模型失败、取消和进程退出后可复用已完成阶段。

## 宿主怎样接入

以下在异步宿主中执行。`session_engine` 是已打开的 SessionEngine；`provider` 是宿主配置的公开 ModelProvider。不要为读取同一个 Session 文件再打开第二个 owner。

```python
from pathlib import Path
from weavria.harness import (
    MemoryFormationEngine,
    ModelMemoryExtractor,
    ModelMemoryReviewer,
    SessionMemoryBinding,
    SessionMemoryIngestor,
)
from weavria.memory import MemoryAccess, MemoryScope, SQLiteMemoryStore

scope = MemoryScope(tenant_id="local", kind="project", key="project-p")
access = MemoryAccess(
    principal_id="authorized-host",
    readable_scopes=(scope,),
    writable_scopes=(scope,),
)
binding = SessionMemoryBinding(
    session_id="conversation",
    scope=scope,
    author_subject="user-p",
    timezone="Asia/Shanghai",
)
async with SQLiteMemoryStore(Path(".weavria/memory.db")) as memory:
    formation = MemoryFormationEngine(
        memory,
        ModelMemoryExtractor(provider, configuration_id="chosen-model-config-v1"),
        ModelMemoryReviewer(provider, configuration_id="chosen-model-config-v1"),
    )
    consumer = SessionMemoryIngestor(session_engine.store, formation)
    # 每次一个事件，调用方显式限制本次工作量并拥有生命周期。
    for _ in range(32):
        job = await consumer.ingest_next(access, binding, max_duration=60)
        if job is None:
            break
```

`MemoryAccess` 与绑定由可信宿主提供，不是用户认证服务。模型或导入文本不能据此自授权限。更新模型或生成配置时更新 configuration_id；既有未完成作业的版本不能静默更换。此版本尚无自动策略迁移工具。

真实模型实验须显式配置 `WEAVRIA_MODEL_BASE_URL`、`WEAVRIA_MODEL_NAME` 和需要时的 `WEAVRIA_MODEL_API_KEY`，然后运行：

```bash
uv run python examples/live_memory_formation.py --repeats 3
```

结果默认写到被 Git 忽略的 `.weavria/memory-formation-results.json`，记录数据集摘要、配置、策略版本、结构化候选与准入决定，以及每条查询结果。两组共享候选及逐字定位；朴素基线也保留条件键并检查 scope/retention，只省略独立复核和历史区间维护，避免拿完全不做边界检查的策略作对照。

12 个冻结案例聚焦文档语言约定，覆盖未来变更、过去纠错、README 例外、否定、重复、假设和一次性指令。评测器只做有限别名归一化与结果多重集检查；无法理解任意释义，也不等于通用语义评测。`qualified` 仅统计包含 README 的条件。模型或写库出错的 trial 标记 `complete_trial=false`，不得计作有效能力成绩。没有 Token 使用量时不推算 Token 或价格。

本次验证结果（2026-10-23）：全量 770 项测试通过，Ruff、格式检查和 Pyright 通过；相比前一阶段新增 38 项检查。本次环境未配置真实模型，所以目前只有确定性执行验证和本地 HTTP fixture 结果，没有真实模型收益结论。

## 当前局限与下一步

- 只消费用户原文与明确 steering，不消费工具、助手推断或成功轨迹；不形成 procedural memory。
- 单次最多八个候选、八篇证据；历史窗口只看前 64 个事件。缺少更远的指代证据时应待定，不能宣称理解完整会话。
- 完整比较最多 128 条事实、256 KiB；超限停止。没有混合向量召回或完整实体消歧。
- 未知起点不会按采集时间补齐。原事实起点未知时，带新起点的“变化”暂不自动切分；多个目标需要联合修订时也待定。
- 置信度固定为未经校准的 0.5；第二次模型复核可能重复第一次的错误，无法保证语义真实性。
- 拒绝/待定是已完成决定，会推进游标。待定记录可审计，尚无自动重新审议或人工批准接口。
- 形成记录含原文，并在各阶段重复保存固定窗口；没有遗忘、脱敏导出、加密或压缩生命周期。本地库与访问权限由宿主治理。
- 当前只改变可检索事实集合，不自动改变 Agent 的上下文，也没有验证跨会话任务完成收益。

下一小步先运行并分析真实模型试验，定位错误写入、漏记与纠错误判；再将已准入记忆作为带来源和有效时间的 Context 输入，验证任务感知召回如何改善下一次请求。
