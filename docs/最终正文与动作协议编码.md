# 最终正文与动作协议编码

2026-11-06 的页面问题来自最终候选正文。原问题为“今天市场表现如何”，保存的
FinishAction.output 本身是一个带 answer 字段的 JSON 字符串。段落换行被包在内层 JSON
中，页面按原文渲染后显示对象、引号和换行转义。

OpenAI-compatible 适配器使用 JSON 传输动作，但 FinishAction.output 承载用户正文。
原收尾协议只说明把用户请求的 JSON 编码到 output 中，没有说明普通问答应直接提供正文。
本次统一单步、会话和收尾三条路径的协议说明，明确普通回答使用文本或 Markdown，
段落换行只经过外层编码；用户明确要求 JSON 时，仍可交付 JSON 文档。

适配器继续只解析动作层。用户正文可能有意包含 answer 字段、代码或转义示例，
因此不能按字段名自动拆包，也不能全局替换反斜杠。该修复改变模型可见的格式约束，
不构成输出格式的确定性保证。历史运行与既有页面消息保留原始接受结果，新消息采用新协议。

回归测试覆盖三个请求入口，验证正文和用户要求的结构化内容都逐字保留。
协议提示增长计入现有请求预算，计量器版本推进到 openai-compatible-session/8。
固定指令预算用例的窗口增加 128 Token，仍同时断言旧字节上界拒绝、精确 BPE 预算接受。

运行检查

```bash
uv run --extra finscope pytest -q tests/models/test_openai_compatible.py tests/context/test_compiler.py
```

真实模型复测使用原运行保存的收尾请求和证据，不重新调用业务工具。旧协议重放也可能返回正常正文，
说明问题并非每次必现；修复协议的两次重放均返回正文和真实换行，均未增加 answer 对象。
这些样本不能估计格式错误率。
