## 共同容量断点与责任

冻结配置只给出 16384 总窗口、4096 输出预留、1024 安全预留，即 11264 输入 Token。
它没有满足开启工作记录后的组合预留。一个实际任务的初始请求为 3199 Token；加上模型工作视图
增长 10735、下一步反馈 4096、控制反馈 1020，共需 19050，执行请求因此在发送前被拒绝。

对首轮 66 个已接受的初始任务解释作无网络重放，所需输入容量范围为 16493–20666 Token。
这是容量诊断：使用首轮已形成的解释、Fake 执行模型和空只读记忆，不计为真实任务通过，也不证明
后续增长一定可容纳。未形成合法解释的六项不在该范围内。

工作记录按最多 8192 字节、进度与指令按声明上界预留，未知内容采用保守 Token 上界；它不能
等同于当前文本的 BPE 实测量。当前策略对小窗口不友好，但删除这些预留会破坏后续反馈承诺。
首轮冻结前未检查该组合容量，是本次验收配置错误，不应归因为模型能力不足。
