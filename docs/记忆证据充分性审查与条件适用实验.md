# 记忆证据充分性审查与条件适用实验

本轮完成了可选的“问题需求 → 证据审查 → 条件计算 → 上下文投影 → Session 持久化”链路。真实模型对照没有证明两轮方案优于单轮，因此默认保持关闭。工程契约通过不等于语义策略成熟。

## 为什么要增加这一层

上一轮交叉重排仍把缓存规范供给给“PostgreSQL 的具体版本”问题，把报告归档偏好供给给“最近报告的完成日期”问题。它们共享主题，但缺少所问的具体信息。继续提高相似度阈值不能表达这种差别。

本轮的判断对象是**已授权、已检索、已通过源预算选择的记忆断言**。不是全库答案存在性，不是原始来源真实性，也不是最终回答的充分性。未召回的事实不会被此机制恢复。

## 一次请求在源码中如何流转

1. `harness/memory_context.py` 沿原来的检索流程得到完整 `ContextSupply`。可以与原词法策略、逐需求 Hybrid、可选重排组合，均不改变作用域和双时间筛选。
2. `harness/memory_sufficiency.py` 的 `ModelMemoryEvidenceAssessor.assess` 第一轮只发送原始需求；`QuestionAnalysis` 返回原子信息需求和有引文定位的任务条件。候选材料不会反向影响首次分解。
3. 第二轮收到原问题、分解、完整事实族、稳定成员序号和已给条件表。每个需求必须审查每个成员，包括例外和争议版本。输出直接支持、背景相关、冲突，以及有限的语义条件边；不要求输出推理过程。
4. 宿主逐字检查引文、需求覆盖和完整成员矩阵。成员序号绑定本次快照中的真实 `memory_id/revision`，不能由模型换成另一个版本。条件判断复用 `memory/conditions.py` 的有界图闭包。
5. `core/context_evidence.py` 记录每个需求的状态、依赖的完整事实组、条件前提和边、成员版本、引文摘要、两轮输出摘要、调用次数。`ContextSupplyReport` v4 绑定任务版本、需求摘要和源供给摘要；旧 v1–v3 的序列化不变。
6. `context/compiler.py` 先移除只背景相关或未验证的组，再参与原有 Token/字节预算分配。完整审查诊断属于必计量的包络，不能被当成普通可选段落挤掉。若正文依赖落选，`project()` 把相应判断降成 `omitted`。
7. `SessionRequest` v11 把最终判断传给主模型。`sessions/engine.py` 重建同一个包络，`sessions/store.py` 落库前再次校验其与源报告投影相同。任务理解入口也使用同样的过滤视图，不能从准备阶段重新引入已拒材料。

例如，问题同时询问内部报告语言和最近一次完成日期：如果族内有适用的语言规则，但没有日期记录，两项需求分别为 `supported` 和 `missing`。若语言规则在最终预算分配中落选，第一项变为 `omitted`，第二项仍为 `missing`。主模型可以继续取证或明确说明缺口；这些状态不直接决定任务终态。

## 条件计算与关键不变量

条件是有限合取。任务给定条件在图的 `candidate` 侧，事实限定在 `target` 侧。相同键且类型和值完全相同可以建立恒等边；其他蕴含、等价、互斥边来自可出错的模型提案。宿主只沿明确的边求闭包，不根据业务词表猜测。

- `equivalent` 或 `candidate_entails_target`：已给场景覆盖事实限定。
- `unknown` 或 `target_entails_candidate`：缺少应用该事实的前提，不能反向推断。
- `disjoint`：该事实不适用于当前场景。
- `inconsistent`：前提自身冲突，不能利用逻辑爆炸宣称支持。

问句里的“给外部读者”也是给定场景，不要求它写成陈述句。相反，“可能对外，但受众未定”不是确定的外部场景。`unresolved` 条件只保存用于诊断，不进入图，即使其猜测值碰巧等于事实限定，也不能自动建立恒等边。

每个原子需求的归约优先级为：分解未被复核通过 → 未验证；有适用争议/冲突 → 冲突；有相关但条件未知成员 → 条件未定；有适用直接证据 → 支持；否则缺失。不同成员共同组成的事实族始终不可拆分。

模型仍可能提供语义错误但格式合法的条件边。图计算只保证**相对于给定前提和边**的正确性，不保证这些边是真理。引文存在也只证明定位正确，不证明引文蕴含需求。

## 有界执行与兼容性

默认最多 128 个“需求 × 成员”检查，结构化输入数据最多 128 KiB，两轮共用 60 秒期限。每轮通过共享的结构化模型适配器校验输出，上限 64 KiB；不做隐藏重试，不截断完整事实族。源预算还会计量增加诊断后的最终供给，装不下时显式报告容量不足。

失败产生 `unverified` 而不是伪装成“没有答案”；取消直接传播并等待调用清理。能力或依赖失败不会释放未经检查的候选。模型调用次数记录在源诊断中；这是每次源审查的额外成本，当前尚未并入 Runtime 主模型调用数和 Token 用量结算，不能把原有 Run 成本指标当成包含本功能的总成本。调用仍受源期限和父调用期限约束。

`SessionRequest` v11 可独立启用审查，不隐式开启语义摘要；旧 v8–v10 的摘要报告校验保持生效。v4 源报告同样没有降低旧重排和相关度的绑定要求。

## 如何启用与运行

宿主显式构造适配器，拥有模型连接的生命周期：

```python
from weavria.harness import MemoryContextSource, ModelMemoryEvidenceAssessor

assessor = ModelMemoryEvidenceAssessor(
    provider,
    configuration_id="固定模型和推理配置的标识",
)
source = MemoryContextSource(
    memory_store,
    access=access,
    scope=scope,
    retriever=retriever,  # 也可以沿用原检索策略
    evidence=assessor,
    max_bytes=65536,
)
```

`HarnessMemory` 可通过 `evidence_assessor=assessor` 接入。默认 `None`，不会在普通记忆检索时新增模型调用。

契约回归：

```bash
uv run pytest tests/memory/test_sufficiency.py -q
```

显式真实模型对照，使用现有 `WEAVRIA_MODEL_BASE_URL`、`WEAVRIA_MODEL_NAME`、`WEAVRIA_MODEL_API_KEY` 环境变量；不需要本地 ONNX 模型：

```bash
uv run python -m examples.memory_sufficiency \
  --output /tmp/weavria-sufficiency.json
uv run python -m examples.memory_sufficiency \
  --dataset examples/fixtures/memory_sufficiency_holdout.json \
  --output /tmp/weavria-sufficiency-holdout.json
```

实验只使用公共手写材料。结构化动作、判断与用量写到仓库外，不保留供应商原始响应、认证信息或隐藏推理。HTTP 故障会停止实验，不能把服务故障当成正确拒答。

## 真实实验与失败分析

日期：2026-11-09。供应商响应模型：`deepseek-flash`；temperature=0，max_output_tokens=10000，两轮共用 120 秒实验期限，最多 128 配对。配置 SHA-256：`ef4aecff534501d53033f7f9bfb145be3fb158bd790c790e824ce4ab3ce3b02c`。没有按题调整配置、阈值或预算。

所有方法看到相同的完整公共事实集，不把人工答案标签、逐题指定的候选组或预先拆好的问题交给模型。对照是有基本证据规则的单轮生成判断，并非把“召回到东西”直接判作充分的弱基线。这隔离了充分性判断的收益和成本；没有验证召回质量或最终生成答案。

初版两轮在开发集为 9/13。其遗漏问句自带的场景条件、把未定受众当成确定属性，因此新增 `given/unresolved` 的显式区分。修正后仍留下真实失败：

- 开发集的外部语言请求：模型给目标事实虚构了不存在的 `artifact` 条件键，宿主拒绝整个审查；没有跳过非法边来换取成功。
- 受众未知请求：第一轮自行增加主题、篇幅等用户没有问的规划前置条件，第二轮否决了分解。
- 受众未定请求：第二轮试图把已排除的未知条件重新用作图前提，被宿主拒绝。
- 验证集的离线格式、实际版本号和争议压缩算法：存在过度分解或分解完整性否决，最终保守扣留。不能把这些 `unverified` 算作语义正确的缺失/条件/冲突判断。

两个上一轮的误召回请求都被识别为 `missing`，但单轮基线也做到了。这个结果支持“充分性应区别于相关性”，**不支持“两轮一定优于单轮”**。两组均没有错误放行不足材料，只能描述这 22 个小型定向案例，不能推导通用错误率。

本地原始结果分别位于 `/tmp/weavria-sufficiency-experiment.json`（初版）、`/tmp/weavria-sufficiency-v2.json` 和 `/tmp/weavria-sufficiency-holdout.json`；临时文件不保证长期保留，复现命令和固定数据保存在仓库。

## 当前边界与下一步

已实现完整成员审查、条件图复用、未知模态隔离、模型可见缺口、预算裁剪后的降级，以及可持久化诊断。18 个新增契约测试验证这些承诺，不能证明模型理解准确。

本轮完整测试为 1761 通过、24 项显式 Docker 集成测试跳过；Ruff、格式检查和 Pyright 通过。

尚未实现跨多个事实的关系连接、原始来源重新核验、最终答案蕴含校验、审查结果缓存、自动重搜缺失材料和全 Run 推理成本统一结算。单一成员直接支持不了的复杂推导保持未解决，不把合成演示称作已支持。

下一步应先改进“答案字段分解”与“规划前置条件”的边界，并比较更少中间语义转换的联合结构化判断；不能继续用增加审查轮数或放宽条件校验掩盖误拒。当前发布为显式实验能力，默认不启用。
