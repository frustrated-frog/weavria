# 上下文编译与信息恢复

## 本次能力与问题

`SessionEngine` 可以显式启用任务感知的联合上下文编译。它在**每次模型决策之前**，从持久会话原文、当前 Run 的工具成果和已接受的任务需求重新选择输入。历史交互与工具证据共享预算，工具反馈和任务修订会触发下一次编译。

过去会话历史先占用独立字节额度，工具证据再使用剩余额度。两个选择器不能直接比较“旧交互中的关键细节”和“刚读取的重复资料”，也无法约束模型的 Token 窗口。本次把这个决策放在同一个编译边界中，同时保留 Runtime 的字节约束、工具准入、持久化与取消语义。

交付范围是**精确片段选择、联合资源分配与原文恢复**。它没有生成摘要，没有替代权威事件，也没有证明真实模型的长任务成功率已经提高。初始设计及第一方研究来源见 [ADR 0029](decisions/0029-任务感知的联合上下文编译.md)；后续分配、证据访问与资源修正见 [ADR 0030](decisions/0030-上下文预算交换与证据访问闭包.md) 和 [修复讲解](上下文编译修复与资源边界.md)。

## 一次请求如何流转

1. `sessions/engine.py` 的 `prepare_turn` 取得最新任务、已提交语义头和历史交互。启用编译器后，历史不再预占一个固定选择额度。
2. `harness/context.py` 将当前 `TaskFrame` 与 `NeedLedger` 投影成 `ContextFocus`。未满足、部分满足、冲突、过时和已经满足的需求使用不同软权重；证据绑定提供原文地址。工作标识及修订必须一致。这些提示只影响检索，不改变用户任务、Policy 或完成验收。
3. `context/compiler_sources.py` 校验当前工具记录的顺序、依赖图和 Artifact 身份，索引原文，产生不同表示。每个候选都是完整交互或配对的工具调用与回执。
4. `context/compiler.py` 保留任务、指令、任务观察、控制反馈，强制保留最近两次交互的条目以及最新已执行工具反馈。最新工具输出的最低回执是硬约束；实际数据表示获得每个调用独立的 0.25 软收益，与需求覆盖共同竞争预算，避免按出现顺序预占正文空间。
5. `context/allocation.py` 从最低集合联合分配正文，并通过有限降级与交换撤回低价值选择。每个候选组合都重建完整 `SessionRequest`，使用实际传输文本的 BPE 计数和 JSON 字节数检查两个约束。
6. Runtime 在修订与提交锁下接受选择结果。`SQLiteSessionStore.prepare_request` 在同一事务中保存请求快照、准备事件和编译报告，随后才调用模型。事务失败时不会发送请求。
7. 模型提议调用后，以当前选择的完整依赖闭包建立可读访问视图，同步用于反馈预留、工具实际读取和回放验证。工具完成、证据绑定变化或用户修订后重复以上步骤。输入始终来自原文与已接受状态，不会把上一次截短的视图反复截短。

`tests/sessions/test_context_compiler.py` 给出可运行的恢复过程：先保存三次交互，第一条长文本末尾包含 `Aurora password is violet`；关闭并重开 Session 后，新任务要求找回密码。编译器给出非零 `start` 的原文片段，模型替身据此调用 `read_session_history(run_id, field="assistant", offset=start, length=400)`，下一轮读到真正恢复的原文后完成。测试检查原始历史未变、每次模型调用前已提交对应报告，并再次重开数据库验证报告仍可读取。这验证恢复协议与生命周期，不代表模型会自主作出同样决策。

## 候选与分配算法

关键结构如下：

| 结构 | 内容与职责 |
| --- | --- |
| `ContextDemand` / `ContextFocus` | 当前任务修订、检索文本、软权重、已接受证据地址 |
| `IndexedSource` | 校验后的工具记录、不可变成果快照、原文片段 |
| `ContextUnit` | 来源身份与摘要、所属通道、依赖祖先、是否必须保留 |
| `Representation` | 原文、片段或引用的完整序列化载荷与覆盖特征 |
| `ContextCompilation` | 与准确请求摘要绑定的预算、策略、选择和覆盖诊断 |

工具字符串按最多 320 UTF-8 字节划分原文片段，地址包含 JSON Pointer 与原始 Unicode 字符区间。对象和数组使用惰性迭代器栈遍历索引，标量保留准确值。工具候选包含引用、排名前 1/2/4/最多 8 个片段及完整数据。`context_paths` 只限定评分子树，沿用既有语义；它不充当权限或脱敏边界。

历史交互按用户文本、助手文本和追加指令分别选取最佳单一连续区间，候选包含一个片段、以最佳片段为中心的相邻区间及完整文本。调用目录、失败状态、来源引用和未完成调用标识不拆散。最近两次交互最低表示从每个文本的 256 字节前缀起步；升级后可选择其他精确区间，始终保留交互身份与恢复地址。较旧交互可以省略正文或整个条目。

查询采用 Unicode 规范化、英文词与中文双字特征。对每个需求，按原文片段中的文档频率计算归一化 IDF 权重。相同需求词共享一个特征，完全相同的相关片段共享一个小幅新信息奖励。已知的不同证据地址各有特征，使被账本识别为冲突的来源有机会共同保留；编译器自身不判断事实真假或发现语义矛盾。

对已选择表示集合 `S`，覆盖效用为：

```text
U(S) = Σ特征 f max(0, 所选各表示在 f 上的权重)
```

重复来源不会重复获得同一需求词的收益。每次提议加入或升级一个表示时，补上缺失依赖祖先的最低引用，已有祖先只计费一次。约束是完整请求的输入 Token 和序列化字节预算。

分配器分别执行两条贪心路径：按边际收益排序，以及按边际收益除以归一化资源增量排序。资源增量取 Token 压力与字节压力的较大值。两条路径都从相同强制集合出发，最后选效用较高、相同时 Token 更少的可行结果。绝对收益路径避免单一密度策略被一个廉价小项阻挡大收益项；小规模穷举测试覆盖这个陷阱，但不是全局最优证明。

表示之间的 BPE 成本不严格可加，前缀与区间的内容也不一定嵌套，所以每次都计算完整边际效用与完整请求成本。不会套用标准背包或子模问题的近似保证。两条贪心之后最多执行四轮单供给项/单接收项局部交换，逐次恢复最低约束与依赖闭包，尝试删除、降级和替换。它仍可能错过需要多个来源同时交换的更优解。

设候选来源数为 `N`、每个来源表示数为 `V`、选中或升级次数为 `K`，每条路径最多检查约 `K×N×V` 个组合；每个新组合还有完整序列化、特征聚合及分词成本。搜索默认最多访问 4,096 个候选，并缓存最多 4,096 个组合成本；来源缓存默认容纳 256 个单元，另有来源字节、索引片段、索引编码字节和评分估算门限。历史原文索引可跨任务修订复用，选择与评分重新计算。Session 历史候选仍沿用最近 64 次交互窗口。`max_passages` 约束表示大小，原文索引另受 `max_index_passages` 约束；这些不是恒定内存或 RSS 保证。

来源加载、索引、片段评分、排序、候选搜索与计量定期让出事件循环，取消沿所属 Run 传播。单次同步 JSON 解析、散列、序列化和 BPE 仍不能被硬抢占。准备容量超过配置时抛出 `ContextCapacityError`，Run 终止为 `context_capacity`；区分必要闭包与总候选容量不足，不静默丢弃来源。具体资源默认值、取消限制与压力探针见 [修复讲解](上下文编译修复与资源边界.md)。

## Token 计量与工具准入

```text
可用输入 Token = 窗口 Token − 最大输出预留 − 安全余量
```

`OpenAICompatibleSessionProvider.token_counter` 使用与实际发送共用的消息构造器。计量包括可信指令、适配器协议说明、会话、任务、工具描述、观察和工具历史；不是只统计正文。正文使用显式选择的真实 BPE，消息框架使用宿主声明的保守额度。模型输出上限不能超过编译配置的输出预留。

编码和框架额度必须匹配实际 endpoint。代码不能获知供应商隐藏提示、精确消息模板或收费 usage，因此这个承诺以配置正确为条件。默认 `framing_tokens=32` 不是适用于所有兼容服务的模型规格。

未来工具结果尚不可知，不能用本轮压缩率保证下一轮反馈可放入。准入使用更保守的充分条件：普通字节 BPE 的 Token 数不超过 UTF-8 字节数；将指令从 JSON 移到可信消息只减少转义，再另计固定协议和框架。请求存储与消息正文使用同一种 Pydantic JSON 编码，防止浮点格式差异破坏上界。扣除外层开销后，这个字节上界交给最低反馈预留器。启用编译器时，预留器验证本次选择的 `EvidenceAccessView` 并仅为其完整闭包预留；派发工具使用持久化的相同访问视图，隐藏成果不能凭 ID 回读。未启用编译器时仍预留全部已接受历史。

这保证的是既定请求骨架下的最低回执容量，不承诺完整工具结果可直接进入模型，也不承诺未来扩大的 TaskFrame 或新增指令一定可放入。该充分条件可能拒绝实际很容易压缩的大参数调用。最低输入超出 Token 或字节预算时分别终止为 `context_tokens` 或 `context_bytes`，不会删掉强制反馈继续执行。

## 启用与兼容

默认 Session 继续使用原有字节策略。编译器和计数器必须一起配置；`AgentRun` 与 `LegacyAgentLoop` 不会自动启用新路径。

```python
from pathlib import Path

from weavria.context import ContextCompilerConfig
from weavria.models import OpenAICompatibleConfig, OpenAICompatibleSessionProvider
from weavria.sessions import SessionEngine

# transport、registry 由应用提供；这些窗口参数只是配置示例。
provider_config = OpenAICompatibleConfig(model="configured-model", max_output_tokens=4096)
provider = OpenAICompatibleSessionProvider(provider_config, transport=transport)
counter = provider.token_counter(encoding="cl100k_base", framing_tokens=32)
engine = SessionEngine(
    Path("session.db"),
    model=provider,
    tools=registry,
    context_compiler=ContextCompilerConfig(
        window_tokens=32768,
        output_tokens=4096,
        safety_tokens=512,
    ),
    token_counter=counter,
)
```

接入前应按 endpoint 配置编码、窗口与框架额度，并用 `async with engine` 管理生命周期。`history_budget_bytes` 和旧 `history_mode` 在编译器启用时不负责历史分配，由联合策略替代。原有 `RunLimits.max_request_bytes` 仍然生效。

`tiktoken` 是可选运行依赖，通过 `uv sync --extra tokenization` 安装；开发环境为测试安装它。首次加载一个尚未缓存的公共编码可能下载词表，需在离线部署前预热。默认单元测试使用内存内冻结的小词表运行真实 BPE 算法，不访问网络。

兼容策略明确区分旧格式和新能力：

- `TextExcerpt` v1 保持前缀含义和原样序列化；新的 `LocatedTextExcerpt` v2 增加 `start`，明确表示原文字符区间。完整文本仍校验 SHA256。
- `ConversationItem` / `ConversationView` 保持 v2 外壳，新增的嵌套表示有独立版本；视图策略标记为 `context-compiler/2`。`SessionRequest` 仍为 v5。
- 只有新增 `context_compiled` 事件使用 `SessionEvent` v4，其余事件仍写 v3。旧数据库记录不改写，无需 DDL 迁移；旧读者不能理解新增事件或区间表示，应先升级读者再启用编译器。
- 启用编译器的 Run 配置快照使用 v2，保存完整编译参数和计数器版本；未启用时继续保存原有 v1。
- `ContextCompilation` v2 增加搜索步数与截断诊断；`BatchAdmitted` v2 持久化精确证据访问视图。两者旧 v1 保持原样序列化，外层协议版本不变。
- 编译诊断不复制原文，只保存来源与需求摘要、来源标识、表示选择和计量。准确请求仍按既有 Session 存储规则持久化；这项变化没有新增日志脱敏方案。

## 可复现实验与结果

```bash
uv run python examples/context_compiler.py --window-tokens 2600
uv run python examples/context_compiler.py --window-tokens 1800
uv run python examples/context_compiler.py --window-tokens 4000
uv run pytest -q tests/context tests/core/test_context_contracts.py \
  tests/models/test_tokenization.py tests/sessions/test_context_compiler.py \
  tests/harness/test_session_preparation.py tests/evaluation/test_context_compiler_experiment.py
```

冻结数据位于 `examples/data/context_compiler/cases.json`，内容来自 `bb17ea0` 的公开项目规范与 ADR 原文，包含每份原文的来源和摘要。整个数据集 SHA256 为 `904ff6e27cc01c46b38e8a36cf2f712bf7b148594eb835664ea0f9c912613f5e`。8 个用例重组真实技术原文为合成历史与工具轨迹，共 16 个目标原文短语。答案标签仅由评测器在最终可见历史中检查，不传给分配器，也不把任务文本中的同名词当作证据。

基线共享原文、表示候选、硬约束、Token 编码与预算：`full` 要求全部原文，放不下就失败；`recent` 按新近来源优先；`relevance` 累加每个来源的独立相关性；`coverage` 使用跨来源饱和覆盖。因此 `recent` 是在同一候选库上的新近优先，`relevance` 是 IDF 特征的独立加和，它们不等同于原有分离预算的实现或 BM25 基线。

以下是 V1 初始交付的 2026-10-23 本地运行记录；修复后的分数相同、编译耗时增加，重跑记录见 [修复讲解](上下文编译修复与资源边界.md)。初始配置为：`tiktoken 0.14.0 / cl100k_base`、框架额度 32、输出预留 256、安全余量 128、字节上限 13,000。窗口 2,600 对应输入上限 2,216：

| 策略 | 编译成功 | 两个短语都保留 | 保留短语 | 总输入 Token | 峰值输入 Token | 8 例编译总耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全量 | 1/8 | 1/8 | 2/16 | 741 | 741 | 110 ms |
| 新近优先 | 8/8 | 3/8 | 9/16 | 15,984 | 2,214 | 162 ms |
| 独立相关性 | 8/8 | 3/8 | 9/16 | 15,697 | 2,202 | 489 ms |
| 饱和覆盖 | 8/8 | 6/8 | 13/16 | 15,709 | 2,206 | 372 ms |

全量的低 Token 总数来自 7 次拒绝，不能理解为更省成本。耗时包含索引、分配与计数，不包含工具执行、模型调用和词表初次下载；它是一次本机观测，不是吞吐或延迟 SLA。覆盖策略每例 5–182 次组合计量，耗时约 2–74 ms。

预算敏感性以保留短语数报告：

| 窗口 / 输入上限 | 新近优先 | 独立相关性 | 饱和覆盖 |
| --- | ---: | ---: | ---: |
| 1,800 / 1,416 | 7/16 | 8/16 | 8/16 |
| 2,600 / 2,216 | 9/16 | 9/16 | 13/16 |
| 4,000 / 3,616 | 10/16 | 11/16 | 13/16 |

结果支持“同一候选集上，联合覆盖能够减少部分重复信息占位”这一有限结论。极小窗口没有优于独立相关性；扩大窗口后覆盖策略也未继续提升。`history_tail` 仍为 0/2，`recovery_boundary` 为 1/2，说明词面特征和单一区间不足以保住分散事实。测试中构造的 Aurora 尾部恢复成功，不能替代这些失败结果。

这里没有真实模型调用、真实用户任务成功率、摘要保真率或模型自主恢复率。短语可见也不证明模型能正确理解、组合或引用它。不能据此宣称超过成熟框架或达到完整上下文工程的技术目标。

## 当前边界与下一小步

当前选择器不理解同义改写、否定关系、跨片段推理和未知矛盾。一个需求词被覆盖不等于需求已经满足；`uncovered_demand_ids` 只是词面/地址覆盖诊断，不能驱动完成验收。已知证据地址是软收益，预算紧张时仍可能无法同时保留冲突双方。

未引入生成式摘要、跨会话长期 Memory、向量检索、无限历史索引、学习型策略或崩溃后自动续跑。窗口以外的原文仍可通过现有 Session 读取工具取得，但本编译器不主动检索整个数据库。外部工具权限和 Session 范围仍受原有边界约束；启用编译器时当前 Run 成果额外限于此次准入视图，完全省略的来源需在后续选择中重新纳入后才能读取。

下一步应针对失败用例，研究**需求覆盖不足时的多区间原文恢复决策**：哪些缺口需要再取原文，怎样在词面不匹配时发现候选，怎样避免重复恢复，以及恢复后是否实质改善任务完成。先冻结更广的领域无关任务与真实模型配置，再比较覆盖、纯相关性和恢复策略的正确性、引用质量、额外调用及总成本；有证据后再考虑带来源与版本链的生成式压缩。
