# 断言模态与时态事实集修订

本轮解决“记忆更新只能针对一条旧记录”的机制限制。新的形成路径把竞争说法组织成同条件下的时态事实集，计算哪些时间段仍有争议、哪些时间段已经被明确纠正。它不把最近一次输入直接当作赢家。

对应决策见 [ADR 0072](decisions/0072-断言模态与时态事实集修订.md)。这是一项显式启用的能力；原逐目标策略仍可作为基线。

## 1. 从单条覆盖到集合修订

假设现有两条实际记录：一条说 1 月 1 日起使用中文，另一条说同日起使用英文。它们适用条件一致，尚未裁定。用户接着说明：“仅核实 1 月 10 日至 20 日，应使用英文；其他日期争议仍在。”

在命题及适用条件已正确解释的前提下，确定性算法计算出的结果如下。真实模型能否完成此前的解释，另见第 7 节。

| 有效区间 | 事实值 | 状态 |
| --- | --- | --- |
| 1 月 1 日至 10 日 | 中文、英文 | 两项均 contested |
| 1 月 10 日至 20 日 | 英文 | active，来源为本次纠正 |
| 1 月 20 日起 | 中文、英文 | 两项均 contested |

这五个分片由代码计算。模型不负责列举它们，也不需要宿主预先提供正确答案、冲突标签或分片方案。未被纠正的其他条件，例如某一种文档的独立例外，不进入这次更新。

旧策略的困难是：每个候选只能修改一个目标，contested 目标又不能单独 supersede。一次一条地解除争议会形成顺序依赖，甚至留下同组其他竞争记录。集合修订把这件事变成一次完整的事实变换。

## 2. 命题与说法的状态分开表示

`ModelMemoryExtractor(claim_modalities=True)` 使用 `ClaimExtractionWire`，分别表达：

- asserted：直接陈述或明确纠正后的命题。
- reported：明确存在的记录或说法，可以仍有争议。
- hypothetical：可能性、建议或假设。
- quoted：翻译、示例等任务中被引用的文字。

reported 的意思是“材料报告了这个命题”，并不是“这个命题已被证实”。例如两份真实规范互相矛盾时，两种内容都可以进入后续集合计算；假设和任务引用不会被写成事实。`MemoryExtraction v3` 持久化每个候选的模态，不把模态或来源身份塞进 qualifiers。

时间有效性、争议状态、变更状态属于命题的附属信息。它们不应分别成为“规则尚未确定”“规则在某日失效”这样的独立属性，挤占真正的事实召回。提取器保留原始引用和纠正用语，独立关系解释再处理它与既有记忆的关系。模态和语义分解仍由模型判断，类型不能证明自然语言解释正确。

## 3. 一次输入如何流转

1. `SessionMemoryIngestor` 从已接受的输入构造固定证据窗口。
2. `index_memory_evidence` 把完整原文无损切成带编号、精确 Unicode 位置的片段。`ModelMemoryExtractor` 提取独立命题及模态，只选择证据编号；宿主还原完整字面引用，经 `ground_memory_candidates` 验证后保存 extraction。
3. `ModelMemoryReviewer(set_reconciliation=True)` 接收候选和完整记忆快照，通过 `FactSetReviewWire` 输出语义关系。`anchor`、`resolves` 使用本次快照编号，`mapping` 表达字段对应，`citations` 只给出一次候选引用编号。
4. `FactSetReviewWire.interpret` 从冻结快照恢复稳定 ID、版本和完整引用。持久化使用 `MemoryReview v5`，长期状态不保存瞬时编号。
5. `ConservativeMemoryAdmission(set_reconciliation=True)` 使用已有语义对齐，将同实体、同属性、同适用条件的候选交给 `compile_fact_sets`。
6. `memory.fact_sets.rewrite_fact_set` 完成连通分量、端点扫描、区间差集、证据合并和分片合并。
7. Harness 为新分片分配确定性 ID，构造一个 retract/add batch。SQLite 原子提交事实、Journal、源游标与作业完成状态。后续 Session 通过完整事实组召回看到更新。

字段对应和值相等必须分开：`/value → /value` 可以只表示两个值位于被比较的字段。只有 equivalent 才复用旧值的规范表示；conflict、change、correction 始终保留候选的新值。集合纠正的锚点也可能已经持有正确值，但仍要修订整个受影响集合，不能退化为一次 reinforce。

对齐仍区分“同一主题属性”与“完全相同的适用条件”。条件例外可以加入同一召回族，但不因此参加一般规则的冲突消解。

## 4. 核心数据结构与算法

`fact_key` 包含 scope、kind、subject、predicate、qualifiers，不包含值、来源或时间。不同条件是不同计算集合。

`MemorySetProposal` 表示已对齐命题及是否属于明确修订；`MemorySetFragment` 表示计算后的命题、active/contested 状态和参与计算的旧记录 ID；`MemorySetRewrite` 表示最小撤回列表与新分片。它们是纯计算值对象，不执行存储或模型调用。

### 交叠连通分量

按起点排序并维护当前分量的最远终点。下一个起点严格小于终点时加入当前分量；无终点视为持续有效。相邻半开区间不交叠。只计算与新候选相连的分量，其余记录保留原 ID 和版本。

这一层很重要：新事实可能只与 A 相交，而 A 又与 B 相交。只处理直接命中会遗漏后续竞争区间。完整连通分量允许代码在整个相关时间线上重新计算，同时保留不受影响的部分。

### 端点扫描

在每个时间端点先移除结束的命题，再加入开始的命题，得到下一个单元中的有效命题集合。对每个时间单元：

- 没有明确修订：保留全部有效值。出现不同值时标记 contested。
- 有明确修订：仅使用修订命题生成该区间的结果。
- 同一时间出现不同值的两个修订：不按输入顺序选择，形成明确的未决结果。
- 原有 contested 标记不会因为重复说了一遍相同值而自动变为 active。

全部未知有效时间时，使用一个不可拆分的未知单元；已知与未知时间混合时返回 `mixed_validity`，不把未知时间伪装成负无穷。

### 支持合并与最小更新

同一个时间单元中，只有值、权威性和认识状态一致的命题才能合并支持。来源 ID 去重，置信度取最小值，避免把同一来源的重复陈述当作多次独立投票。不同权威性或认识状态仍分别保留。

相邻分片的内容、支持集合和状态完全相同时合并；来源变化也会保留端点。完全没有变化的旧记录直接保留，不先撤回再创建。新分片的来源指向实际支持它的证据；旧记录和本次更新仍可从 Journal 按知识时间回放。计算结果中的 derived_from 是调用方可用的来源线索，当前落库的跨版本关系通过同一 batch 的撤回/新增及原始证据重建，并未另建关系图数据库。

分量与端点排序为 O(n log n)。每个时间单元仍需处理有效支持及稳定的来源顺序，最坏为 O(n² log n)，另计实际内容复制成本。未变化记录使用内容索引匹配，不对每个新分片再扫描所有旧记录。当前实现利用已有的有界完整快照；没有宣称支持无限规模集合。

## 5. 为什么模型只输出关系

初版模型协议复用了完整判断、长目标 ID、逐字段引用结构。真实样本中既出现状态信息过度提取，也出现复核截断。因此最终协议把一次语义决策收敛为：候选编号、语义关系、证据判断、锚点编号、字段对应、引用编号、明确纠正覆盖的目标编号。

提取侧同样不再要求模型抄写引用或计算字符偏移。每段最多 1024 个 Unicode code point，优先在后半段句末或换行切分；所有字符恰好保留一次，不按答案选择片段。跨片段的条件须引用多个编号。完整形成输入仍然保存原文，最终候选保存实际引用，所以后续恢复不依赖瞬时目录。

版本与引用的还原、有效区间分解、竞争状态传播、来源合并、分片 ID 和持久化操作均由宿主负责。这减少模型必须同时生成的重复信息，使模型调用承担语义判断，确定性代码承担可计算的集合运算。没有放宽实体、条件、来源或时间语义。

## 7. 性能和任务实验

### 确定性与规模证据

最终全仓 1305 项测试通过，Ruff、格式、Pyright 通过。确定性替身验证执行与集合语义，不证明自然语言提取质量。

规模实验使用 Python 3.12.13、macOS arm64，同一台本地机器每个规模运行 10 次；时间测量不包含 tracemalloc，峰值内存单独运行一次。输入为交叠区间及一次局部纠正，不含模型、SQLite 或网络。新内容索引消除了未变化分片匹配中的全表扫描，但不宣称每种小规模输入都比原循环更快。

| 旧命题数 | 中位计算时间 | 峰值内存 | 新分片数 | 所需 mutations |
| --- | ---: | ---: | ---: | ---: |
| 8 | 0.80 ms | 51,248 B | 14 | 22 |
| 32 | 10.62 ms | 148,556 B | 35 | 67 |
| 128 | 76.18 ms | 441,164 B | 35 | 163 |

32、128 条的这两个交叠输入超过当前 batch 的 64 条 mutation 上限：表中是纯计算结果，不表示存储层已经支持原子提交这些规模。运行记录为 `.weavria/memory-fact-set-scaling-final-20261101.json`，算法文件 SHA-256 为 `091df1e765f7e5631158c388ca2424ea61deca336ad73a993174751dccfb3944`。

### 真实模型实验口径

模型为 deepseek-flash，temperature=0，输出上限 8192，形成/消费期限 90 秒。消费阶段仍只有一次模型调用，最多一个完整事实组，32768 上下文窗口使用 cl100k_base 代理计数。新数据 `memory-conflict-sets/1` 是领域无关的自然语言**合成情景**：三方竞争、局部纠正、同一输入的两种竞争说法，共 9 个消费检查点；它不是生产用户流量，也不足以支持成熟度或统计显著性结论。

每次运行同时包含无记忆、逐条召回和完整事实组三个消费臂。下表主要报告完整组。`pipeline` 要求形成没有执行失败且消费评分通过；它并不自动证明形成的全部命题正确。尤其是期望 unknown 的题，即使记忆为空也可能答对，必须同时检查实际快照。

最后一组在相同低思考配置下各运行一次（`--thinking enabled --reasoning-effort low --repeats 1`），模型、数据、消费预算相同。事实集臂使用 extractor/5、reviewer/6.1、fact-set-memory-admission/2；基线使用 extractor/3、reviewer/4、conservative-memory-admission/3。它比较的是整条形成路径，不能把差异全部归因于集合算法。

### 从失败样本修正实际算法

上述 partial 场景的模型已经给出了“1 月 10 日至 20 日使用英文”的纠正候选，却同时为不同值生成 `/value → /value` 对应。宿主最初将这种字段对应解释为值等价，错误地把英文复制回旧中文；这不是靠换模型或重试能够解决的问题。

最终 `fact-set-memory-admission/3` 修正了这个语义：conflict/change/correction 可以声明值字段对应，但不得改变候选值，只有 equivalent 才允许旧值归一化。使用同一份已经记录的提取与关系判断、同一份纠正前快照进行离线回放，当前实现得到第 1 节的五个片段。没有重新生成模型结果，也没有手工预设分片。

这份来自合成情景的规范化模型结果作为有意维护的回归材料保存在 [partial_correction.json](../tests/memory_formation/fixtures/partial_correction.json)，仅含形成输入、规范化提取、快照与关系判断，不含凭据、供应商原始响应或隐藏推理。可独立运行：

```bash
uv run pytest tests/memory_formation/test_fact_set_formation.py \
  -k recorded_model_decisions_produce_correct_partial_resolution
```

冻结回放证明的是实际语义结果下的宿主计算修复，不能替代新的完整模型任务实验。最终代码没有再次运行付费的整组形成/消费，因此上表保留修复前失败，不把回放结果计入任务通过率。

## 8. 当前限制与下一步

自然语言的命题分解、条件归一化与纠正意图仍可能出错。新算法没有把这些判断偷换成确定性真理，也不提供概率校准或来源独立性估计。模态首先保存在形成证据中，召回的 Assertion v1 仍使用原有 stated/observed/inferred 与来源、文本表示。

单个 batch 上限仍为 64 个 mutation。复杂区间或多来源组合可能产生过多分片；此时不提交半个事实集。快照上限仍为 128 条，不支持在不完整的检索结果上宣称完成集合消解。

未知时间与已知时间混合、复杂否定条件、跨语言条件本体统一和来源权威性的校准排序尚未解决。下一步应根据真实失败继续深化命题和条件的归一化，以及长期更新导致的分片与索引成本；不能据此宣称整个 Memory Engine 已成熟。

后续条件比较机制见[条件蕴含图与记忆语义归一化](条件蕴含图与记忆语义归一化.md)。
