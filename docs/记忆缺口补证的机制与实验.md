# 记忆缺口补证的机制与实验

本轮把记忆审查中的 missing 转成实际的二次候选选择，避免“知道缺什么却继续读相同背景”。它是一个显式启用的 Context Source 策略，主 Runtime、长期记忆写入、NeedLedger 的证据满足语义均保持原有规则。

## 调用路径和核心决策

`HarnessMemory.refinement` → `MemoryContextSource.retrieve` → `refine_task_memory` → 一次 `retrieval_snapshot` → `select_task_memory` → `assessor.assess` → 残差查询 → 二次选择 → 有新增且保留旧证据时重审 → 接纳或保留初次供给 → Context 编译与 Session 持久化。

需求账本已有的 `need:…` ContextDemand 标识一路保留。查询只是需求的检索投影，不能修改原任务或直接把 NeedState 改成 satisfied。最终回答模型收到的仍是原问题、实际供给、最终证据判断；需要工具原始证据的完成义务继续由已有工具证据链验收。

设查询词项集合为 Q，初次审查对该答案项判为 background 的成员正文词项并集为 B。补证查询为按原词序去重的 `Q − B`，为空时回退原查询。`residual_memory_query` 与 BM25 共用 Unicode NFKC、大小写归一化、中英文词项提取。新查询长度仍最多 2048 字符。这是一种有界的背景负反馈，不含手工逐题词表；计算成本为查询与背景正文总词项数的线性量级，存储为去重词项集合。

例如第一次读到“alpha overview migration deployment report is available”，问题“……what is the beta code?”整个句子被模型标作 missing。直接拿这句重搜仍会选中 overview；减去背景词项后，beta/code 获得候选发现机会。只有新候选提供 B7 且在**完整原问题**下通过语义审查，才发布新的支持判断。

多个需求有不同缺口时保留需求身份，有缺口的需求权重为 8，其余至多 0.5。已有检索器负责组闭包和限额选择。初次直接支持、条件未知、争议材料全部受到保护，不能靠丢掉反例得到更好结果。候选中的答案项按 `(demand_id, description)` 精确对齐，允许的唯一变化是 missing → supported，且至少发生一次。

## 不变量与边界

- 同一请求只读一个授权快照。补证期间出现撤回或更新，仍使用原 head；下一次请求读取最新状态。这是快照一致性，不是永远使用最新事实。
- 最多追加一次选择、一次 assessor 调用，无后台任务。无新增组不重审，原有证据被挤出时直接拒收。
- 重审仍使用原始需求。残差词项不能成为条件前提、授权依据或记忆事实。
- conditional/conflict 单独存在时不触发自动补证；它们需要澄清或独立证据。unverified 也不在此路径重试。
- 追加阶段超时或检索依赖失败保留初次供给；取消传播并清理。候选审查返回失败报告时保留其诊断。
- 模型重新划分原文片段会导致描述不一致，本轮保守拒收，即使两个描述实际上同义。这会产生误拒，没有用模糊匹配掩盖。
- 完整最终报告计入源字节预算，Context 编译器继续按 Token 决定材料是否留下；必要依赖被裁掉后 supported 仍降级为 omitted。

## 版本与诊断

`ContextSupplyReport` 新增 v5，附带 `ContextRefinementReport`，记录策略版本、初次/候选判断、补证查询摘要、检索次数、审查尝试数和停止原因。最终 evidence 必须等于接纳的那次判断，摘要继续绑定实际供给。v1–v4 的序列化保持旧字段集合，新版可读取旧数据；旧版本程序不支持新 v5 报告，不宣称反向兼容。

`assessment_attempts` 记录 assessor 入口尝试数；`model_calls` 仅汇总已经返回的判断报告。若外层超时中断尚未返回的 assessor，其内部调用和 Token 无法从已返回报告恢复。真实实验通过传输层计数总调用，主 Runtime 的辅助调用 Token 统一结算仍未实现。

## 如何运行

```python
from weavria.harness import HarnessMemory, MemoryRefinementPolicy

# 现有配置必须同时提供 TaskMemoryRetriever 与 evidence_assessor。
memory = HarnessMemory(
    ...,
    retrieval=retriever,
    evidence_assessor=assessor,
    refinement=MemoryRefinementPolicy(max_duration=60),
)
```

也可以在 `MemoryContextSource(..., retriever=..., evidence=..., refinement=...)` 直接启用。缺少检索器或审查器会在构造时拒绝，默认 refinement=None。

```bash
uv run pytest tests/memory/test_refinement.py -q
uv run python -m examples.memory_refinement --output /tmp/refinement.json
uv run python -m examples.memory_refinement \
  --dataset examples/fixtures/memory_refinement_holdout.json \
  --output /tmp/refinement-holdout.json
```

真实实验显式使用现有 `WEAVRIA_MODEL_*` 环境配置。脚本在临时 SQLite 中写入公开人工事实，由真实 BM25 自主选择初始和补充材料，不传答案、逐题候选标签或人工需求分解给模型。两种策略均最多供给一个事实族、65536 字节，用相同联合审查器和最终回答模型。最终短值严格比较，引用逐字定位；该定位指标不等于独立语义蕴含评测。

## 实验结果

2026-11-11，deepseek-flash，temperature=0，max_output_tokens=10000，配置摘要 `c2eed90558954b0bc30b38aa84616d579533eb0c7832e87287951d24cab48761`。

第一版直接复用 missing 描述，开发集单次召回与补证均为 3/8。模型把整句作为答案项，查询未变，补证一直停在 unchanged。这个失败促成了残差查询机制；没有修改题目、答案或添加案例专用规则。

残差机制的开发集复测：单次召回 3/8，补证 8/8；两者引文定位均 8/8。总模型调用 16 → 22，平均延迟 1946 → 2811 ms。五个有答案的困难案例获得支持；真实缺失案例保持拒答，简单已支持与条件未确定案例没有追加审查。该八题已参与开发，结果不能冒充独立盲测。

开发集摘要 `86b17d8fb8b60f3a9a91ffd402454c21f2640308008ccfe13bb2848354471dbe`。原始首轮和复测记录分别在仓库外 `/tmp/weavria-refinement-first.json`、`/tmp/weavria-refinement-residual.json`，公开输入和复现代码入库。

v2 机制固定后另行冻结四题验证集，首次执行结果：

| 数据集 | 单次选择正确 | 缺口补证正确 | 总模型调用 | 平均延迟 |
| --- | --- | --- | --- | --- |
| 开发集复测 8 题 | 3/8 | 8/8 | 16 → 22 | 1946 → 2811 ms |
| 新验证集首次 4 题 | 1/4 | 3/4 | 8 → 11 | 1727 → 2838 ms |

验证集的博物馆湿度上限、客服响应期限补证成功；未记录的测量值继续拒答。失败案例是“who signs off the plan”与“Approver: Mira Chen”没有可匹配的残差词，BM25 没有发现新候选，两种策略都拒答。保留这个失败，没有为该题加入同义词规则。

验证集摘要 `d4116e21c0b65458314913c443d3d216e1f9b86938a1e75d2ac8dde49b8ce643`，结果在 `/tmp/weavria-refinement-holdout.json`。调用配置包含 transport 的 `reasoning_effort=none`。以上单次执行不含统计显著性结论，不能把延迟差异推广到其他模型或部署。

确定性检查：全量 1793 passed、24 skipped（显式 Docker 环境项）；Ruff、格式和 Pyright 通过。新增 13 项测试覆盖真实库候选选择、整次快照的并发撤回边界、无进展与保护决策、超时/取消清理、预算、会话重开及中英文残差查询。编译后的材料裁剪仍复用原有回归测试。

## 当前尚未解决

这是小型公开人工问答实验，尚非真实长任务或大规模检索收益证据。固定一个事实族的预算刻意暴露候选被背景挤占的情形；更大预算下应另做对照，不能推广为普遍提升。词项负反馈无法保证解决同义改写；背景判断错误也可能移除重要查询词。复杂多跳事实组合、跨源工具补证、用户澄清闭环和查询策略学习仍未实现。

下一步应研究保留任务实体/条件的语义查询改写，并与当前残差查询、扩大初始候选及混合召回做等成本比较；同时把最终答案验证扩展到真实文档问答，而不是继续在已知开发题上叠加规则。
