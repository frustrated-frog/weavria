# 反馈预算修复后的定向验收

2026-11-20 在主分支上复测前一批出现反馈预算阻断的四个冻结任务。每题用 `coverage` 和 `recent` 各跑三次。执行、任务理解与记忆形成共用 OpenAI `gpt-6-luna`、`reasoning_effort=medium`、JSON 模式和 4096 个输出预留 token。模型沿用默认采样。试验保持 M1 原有的语料、问题、评分、预算、并发数与重试检查。任务文件与实际源码散列保存在各题的 manifest 中。[任务与执行配置](统一框架里程碑验收任务与执行.md)

同场景的历史 DeepSeek 切片是 6/24（`coverage` 5/12，`recent` 1/12）。两批间同时更换了模型和读取机制，分数差无法单独归因。对读取机制的因果检验沿用四个冻结现场的配对回放，同一现场的旧策略有 2/4 把必需原文送入下一请求，新策略为 4/4。[历史批次](M1冻结任务在当前主分支的完整复测.md) · [同现场回放设计](decisions/0137-反馈预算受限时的单步读取与同现场回放.md)

## 24 次端到端结果

原入口计分 **1/24**。四个任务均取得六份独立结果，坐标齐全且无重复。唯一通过的是 `repository_long_context-recent-2`。这批仅覆盖原 12 个任务中的四个，不能更新完整 M1 门槛。

| 冻结任务 | coverage 通过 | recent 通过 | 必需来源均可见 |
| --- | ---: | ---: | ---: |
| 文档多步取证 | 0/3 | 0/3 | 2/6 |
| 文档长上下文 | 0/3 | 0/3 | 4/6 |
| 文档中途修订 | 0/3 | 0/3 | 0/6 |
| 源码长上下文 | 0/3 | 1/3 | 6/6 |

供应商回报的模型名均为 `gpt-6-luna`。执行、理解和记忆分别调用 263、30、30 次，323 次均返回 HTTP 200。合计使用 2,307,871 token，记录 136 条工具回执。历史同题为 274 次模型调用、2,001,044 token、136 条工具回执。统计包含失败样本。

24 个终止记录中，11 个完成收尾检查，8 个为 `finalization_evidence_unavailable`，5 个为 `admission_replan_exhausted`。8 个收尾证据不可用的样本分布于源码长上下文（5 次）和文档长上下文（3 次）。源码长上下文的 5 次失败均无已接受的工作记录，成功样本有两次工作状态更新。这项共现尚不能建立因果关系。

## 从预算通知跟到模型输入

以每条 `BatchRejected(feedback_budget)` 为起点，把通知与同一 Run 的下一次模型决策相连。有明确工具及参数或正页长上限时，检查模型是否只发起这一次读取，同时保留目标和游标，页长允许更小。随后按调用 ID 依次核对准入、成功工具回执，以及后续已归档模型请求实际包含的原文。仅有 Artifact 句柄或文件名不能计入来源送达。

对单文件，按散列与冻结语料核对原件，再核对进入模型请求的文本区间。对合并文件，按各源文件在包内的字符区间计算交集。表中的“必需来源均可见”表示一次试验中每份必需文件都有至少一段原文送达。它无法说明关键答案恰在可见区间内，修订任务还须单独检查证据属于哪一轮。

110 次反馈预算拒绝中，57 次给出具体单读或正页长建议，38 次在下一次决策被采纳。这 38 次全部通过准入并成功执行。其中 27 次把所需来源原文送入后续模型请求，8 次送入了其他文档的原文，另外 3 次在工具完成分页后直接终止。单独统计收窄读取依赖后通过准入的全部调用，共 56 次，其中 52 次送达原文，33 次送达所需来源。两种统计有重叠。

## 定位样本

- `documents_multistep-coverage-3` 成功交付并引用两份必需文档，冻结评分唯一判错的字段是 `retry_method`。答案在解释中给出 `flush_memory(session_id)`，评分约定值为裸方法名 `flush_memory`。将此类失败计入正式成绩，另行区分字段格式和事实正确性。
- `documents_steering-coverage-1` 的收尾答案给出了正确的工具、容量和字节数。答案引用了使用说明，缺少评分要求的 ADR 0078。该次修订的来源完整性单独影响了交付。
- 三次被采纳的分页读取均指向必需的 `agent.py`，并在磁盘留下正文，但下一次模型请求没有发生。在 `repository_long_context` 下，`coverage-3`（拒绝事件 144）、`recent-1`（150）、`recent-3`（130）实际取回的字符区间分别是 `[66794, 67564)`、`[68475, 69269)`、`[66101, 66892)`。成功回执后均只剩本轮结算、进展评估和 `finalization_evidence_unavailable`。

下一步优先从这三个回执回放收尾上下文的构造，配一个成功交付的对照。固定任务目标、证据义务和剩余预算，验证最新必需原文能否进入收尾请求，再用原评分检查答案与引用。如果收尾请求确实放不下，应区分具体缺失的证据与预算。这个切片的停止条件是能逐例解释三个终态，并验证实际交付或明确的预算阻断。
