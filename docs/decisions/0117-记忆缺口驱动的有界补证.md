# 记忆缺口驱动的有界补证

状态：已实现，显式可选；定向实验结果见实现文档。

## 问题与机制

ADR 0116 可以报告某个答案项缺失，但原召回只执行一次。完整问题中的大量背景词可能挤占有限事实族名额，导致库中有答案却没有交付。继续增加审查轮数无法补回未被选中的材料。

本轮在 MemoryContextSource 内实现最多一次追加选择。初次审查的 missing 描述形成查询，随后用该答案项逐成员的 background 判断作负反馈，减去这些已读背景正文覆盖的词项，保留尚未覆盖的查询词项；归一化与切词复用 BM25，残差为空则回退原查询。该词项差集只影响排名，不删除事实或原始条件。原 ContextDemand 身份保持不变；有缺口的需求权重为 8，其他需求降至最多 0.5。采用现有 TaskMemoryRetriever 的 BM25/Dense/混合策略及整族预算选择，不新增逐题关键词表、候选标签或查询生成模型。若需求来自 NeedLedger，原有 need: 标识贯穿两次供给；这些软检索提示不将记忆判断写成已满足的工具证据。

仅 missing 触发补证。conditional 需要建立真实条件，conflict 需要消歧，unverified 表示审查失败，三者均不能通过假定条件或重复模型调用自动消除。若同时有 missing，候选重审也必须保持这些其他状态不变。

## 同一快照与单调接纳

一次 retrieve 只读一次完整授权快照。二次选择复用同一 head、scope、valid_at、known_at 和来源闭包，避免把并发修订的新事实混进原判断。下一次 retrieve 才读取新的快照。

候选必须包含新事实族，且保留初次所有 supported/conditional/conflict 依赖。否则不进行第二次模型审查。重审输入仍是原问题，不能拿短补证查询代替用户意图。

两次审查按 demand_id 和原文描述精确对齐；描述重复、集合变化或任何已有状态退化都会拒收。至少有一个 missing 变为 supported 才接纳，否则保留原供给。这是相对于语义判断的单调性，不能确定性证明语义正确。原句重新分区可能造成误拒，是当前刻意采用的保守取舍。

未采用无界循环或无条件合并：前者可能耗尽预算；后者增加材料也会吞掉全部上下文预算。相同组数/字节上限下重新选择，可能因无法同时容纳旧支持与新材料而停止，阶段不宣称解决紧预算下的最优重排。

## 执行、失败和持久化

MemoryRefinementPolicy 为追加检索和审查共同设置期限，最多两次选择、两次 assessor 调用。每个 assessor 自身的模型调用上限保持原配置。无新材料不重审，依赖失败或无收益保留初次供给，取消整体传播。最终完整报告超过源字节预算时显式 capacity，不静默裁掉诊断。

ContextSupplyReport v5 新增 ContextRefinementReport：初次判断、候选判断、查询摘要、检索次数、审查尝试数和停止原因。最终 evidence 必须严格等于被选中的一次判断，并继续绑定实际材料摘要。v1–v4 序列化不新增字段；旧报告可直接读取。已有 ContextCompilation / Session 存储其嵌套报告，无需改写旧事件。

模型证据入口使用最终 evidence，旧判断仅供诊断。源诊断保留完成的模型调用数；若外层超时在 assessor 返回前中断，assessment_attempts 明确记录该尝试，但无法伪造其内部实际 Token 或调用数。主 Runtime 总 Token 结算仍不包含这些辅助调用。

## 验证

用真实 SQLite 和 BM25 加语义替身测试实际候选改变、旧证据保护、无新增、无收益、重新分区、超时、取消、并发修订、预算、会话重开。语义替身只证明控制协议。新增全句缺口描述的回归，确保真实模型首轮暴露的同查询无进展问题受到覆盖。另用冻结公共人工语料比较一次选择与缺口补证的最终短答案、逐字引文、调用和延迟，不将八个案例的表现解释为复杂任务能力。
