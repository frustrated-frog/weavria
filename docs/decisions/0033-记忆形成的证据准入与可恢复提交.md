# 0033 记忆形成的证据准入与可恢复提交

- 状态：实现，执行契约已验证；真实模型收益尚未验收
- 日期：2026-10-23
- 前置决策：[0032 可追溯的双时间记忆内核](0032-可追溯的双时间记忆内核.md)

## 问题与范围

记忆内核能够可靠提交宿主提供的断言，但不能自行决定哪些对话值得记住，也不能把“现在变了”“原来说错了”和“只对某个文档例外”混为覆盖写入。模型直接调用记忆存储会让提取、解释、授权与副作用成为同一个不透明动作。

本切片实现已接受用户输入及 steering 的显式消费、带原文区间的候选、独立语义复核、保守准入、双时间修订以及中断恢复。它影响未来可被召回的事实集合，本次还不改变 Agent 的 Prompt 或可选工具。任务感知召回、实体别名索引和工具结果学习继续独立推进，不以这一切片宣称完成完整 Memory Engine。

方案依据是用户绑定的网页讨论“记忆模块”：ChatGPT 会话 `6ada4aa4-3448-83ec-8a76-50284201e7c5`，快照 `45607105-b1c2-4e24-bfe5-efc226f7ace1`，同步时间 2026-10-23 01:59:57（北京时间）。该快照只包含采集时已加载的讨论分支。实现结合当前代码、研发宪章以及 0032，而非把讨论快照当作仓库指令。

## 分层与真实决策

`memory` 只依赖标准库与 Pydantic：保存来源、候选、决定和事实，执行事务与版本前置条件。`harness` 使用公开 Memory、Core、Model API，负责从自然语言形成候选、独立复核和准入。Core、Runtime、Session 不反向导入 Harness 或 Memory。

宿主选择 `SessionMemoryBinding`，明确 session、作用域、作者和时区，并提供读写授权。模型不能指定租户 ID、项目 ID、授权、断言 ID、版本或 mutation。模型实际承担原子事实拆分、指代、条件和时间理解，以及新事实与已有事实的关系判断；宿主不预先告诉它某句话属于“纠正”还是“变更”。

提取器与复核器是可替换 Protocol。内置实现分别通过 `ModelProvider` 调用一次模型，返回封闭结构；可使用同一模型，也可使用不同模型。独立调用不代表统计独立或可靠性保证。

## 核心流程与不变量

1. `SessionMemoryIngestor` 从消费游标后读取一个已接受事件。只把 `SessionInput.text` 和 `SessionTaskUpdated.update.directive.text` 作为提取来源；其他事件以空决定推进游标，不调用模型。
2. 保存 `MemoryFormationInput`：绑定完整事件摘要、精确文本摘要、发生时间与最多七条近邻用户文本。只查看之前最多 64 个事件，不读取将来的事件，也不截断原文来伪造完整证据。
3. 提取 `MemoryExtraction`。每个候选必须引用当前输入，可额外引用窗口内历史。宿主核验逐字原文及 Unicode 码点区间；省略起点时，仅接受唯一匹配。
4. 保存已定位候选，再读取整个作用域的当前非撤回事实，包括过去、未来和未知有效时间。最多 128 条、最多 256 KiB；超限停止，不能把 top-k 未命中当作不存在冲突。
5. 独立复核器逐候选判断支持性、作用域、条件、时间及关系；宿主准入器编译为结构化决定与 `MemoryBatch`。决定绑定读取时的记忆 head。
6. 保存写入计划，再在一个 SQLite 事务中检查 head、目标 revision 与消费游标，提交事实日志、投影、游标和形成完成记录。

逐字定位仅证明“这些字存在”，不证明候选蕴含于原文。语义复核也会出错。确定性部分能够保证禁止越域、保留条件、时间区间合法、读写版本一致，不能保证自然语言事实为真。

### 决策规则

| 关系 | 处理 |
| --- | --- |
| 新事实 | 新增；相同条件事实已有重叠区间则待定 |
| 同义重复 | 必须值相同、条件一致；只增加来源，不提高置信度 |
| 明确变更 | 已知旧起点与更晚的新起点，替换剩余尾部；旧事实保留此前有效区间 |
| 明确纠错 | 在原区间上撤回错误断言、写入修正值；系统此前知道什么仍可查询 |
| 未解决冲突 | 同条件且有效时间重叠时保留争议，不按新旧自动选胜者 |
| 条件例外 | 可作为独立条件事实新增，不能覆盖一般事实 |
| 无法确定 | 保存待定决定，消费本次事件；不写入事实 |

本 ADR 最初的 v1 对同目标多候选全部待定，不按返回顺序择一。后续 [ADR 0034](0034-记忆条件对齐与联合区间修订.md) 在 v2 增加了一个受限例外：有据字段对齐后，显式构成同一旧区间完整分区的候选可以原子提交；其他同目标竞争和跨目标联合修订仍待定。规范化后的条件必须精确一致，没有完整实体消歧或别名知识库。

所有生成断言当前都是文本值的 semantic/user_statement，`epistemic_status=stated`。`confidence=0.5` 是固定、未经校准的占位值，不代表模型准确率；重复提及不增加它，当前准入与检索也不把它当作胜负依据。

## 持久化、重试与取消

SQLite schema 从 v1 加法迁移到 v2：新增 `memory_formation` 版本记录和 `memory_guards` 读 head 前置条件。旧 `MemoryBatch` / `MemoryEvent` 的 v1 JSON 字节、指纹、幂等身份均不改写。

形成身份由 scope、stream、position 决定，不包含模型或策略版本；升级模型不能让同一事件被消费第二遍。既有作业必须使用相同输入、主体和 pipeline 版本继续；改变版本需要显式迁移，目前无自动迁移入口。`configuration_id` 必须由宿主随模型和生成配置变化更新。

候选一旦保存就不可重写；计划可以在新 head 上重做，每次尝试保留独立 revision。head 检查也覆盖“比较期间插入了原先不存在的相关事实”，比只检查目标 revision 更强。代价是同一作用域的无关写入也会导致重新比较。默认最多四次尝试，超过后留下可恢复作业并报冲突。

取消和超时向上传播；已提交给存储 worker 的操作仍被等待，直到事务完成或回滚。取消不是“肯定没有提交”，重试同一个作业可判定结果。事实、游标与完成标记没有分开提交的窗口。模型调用若已返回但候选尚未持久化，进程崩溃后可能重新调用；并发消费者也可能重复推理，不宣称模型调用 exactly-once。

来源错误、模型错误、存储故障和容量不足不推进游标；完整且被拒绝或待定的决定会推进游标。待定决定可审计，但当前没有自动重新审议队列。形成日志含用户原文，需要与事实库同等的隐私管理；它不是默认日志导出内容。

## 替代方案与取舍

- 模型直接写记忆：成本较低，但语义解释与权限、副作用不可分离，难以复核和恢复，未采用。
- 只做原文匹配：无法识别否定、假设、条件丢失，不能替代语义复核。
- 只比较 BM25 top-k：成本低，但遗漏竞争事实后可能错误新增；本阶段选择完整有界作用域，超限显式失败。扩大规模需要可靠候选召回和完整性策略，不能简单提高阈值。
- 全局最后写入胜出：不能同时表达变化、纠错和条件例外，只作为评测中的朴素基线。
- 自动在 SessionEngine 每轮后台运行：引入隐式成本及生命周期，暂不采用。宿主显式调用并负责等待，未创建无人跟踪任务。
- 通过工具调用身份读取历史 Tool Output：当前 Session 来源授权绑定活跃调用，后台消费者不能伪造该身份。工具成果学习需要独立授权来源接口。

## 验证与验收范围

确定性验证覆盖范围定位、越域、条件丢失、时间不确定、四种修订、竞争插入、同作业竞争、超时取消、阶段恢复、进程退出、事务失败回滚、v1 迁移、容量失败，以及真实 SessionEngine 用户输入和 steering 的消费。

真实模型入口 `examples/live_memory_formation.py` 冻结 12 个中文自然语言案例，共享相同候选对照“条件事实仅保留最后值”与“复核后准入”，记录有效时间查询结果、README 例外保留、错误、调用次数和延迟。预期答案仅进入评测器，不给提取器或复核器。数据集、模型配置与策略版本进入结果；原始模型输出和凭据不保存。

2026-10-23 已执行真实 DeepSeek Flash 诊断，详情见 [记忆形成真实模型评测](../记忆形成真实模型评测.md)。提取器 v2 补充生成约束，`MemoryCandidate` JSON Schema 现在表达既有时间互斥规则；v1 持久化字节及保守准入规则未变。该窄域开发试验不能证明长期 Agent 任务收益，后续 [ADR 0034](0034-记忆条件对齐与联合区间修订.md) 已实现受限字段对齐和完整区间分区，并完成三轮开发集及六例留出验证；一般语义对齐与跨会话任务收益仍未解决。**执行机制可交付，不能据此宣称语义形成能力已成熟。**
