## 问题：词法未命中不等于不需要工具

任务准备此前先用 CapabilityResolver 的词法与 Schema 召回裁减目录，再把剩余目录交给任务
解释器。原有冻结任务 `What time is it now?` 需要 `read_clock`，但工具说明是
`Read the current clock`，初始时又没有已编译的需求，因而词法召回为空。固定解释器返回的
合法工具随后被判为不可用。中文、西班牙文与英文说明之间也有同类问题。

这不是必须靠模型格式修正解决的问题：工具已经在进入模型前被丢弃。词法得分为零无法区分
“无关能力”和“表达方式不同的相关能力”。即使有正向命中，也可能只是日志中的 time 一词，
因此只在零结果时扩展仍会漏掉真正需要的 clock。

需要区分两件事：解释器可以查看哪些候选的说明，以及执行模型可以调用哪些工具。
前者属于有预算的发现上下文；后者仍由解释结果、宿主注册表及执行策略共同决定。

## 决策与算法

1. 保留原 resolve 路径：Policy 过滤、词法/需求/Schema 召回、排序、数量限制。其结果继续用于
   大目录、容量回退和执行中的需求驱动发现。
2. 新增 CapabilityResolver.preparation_catalogue：只从宿主注册表取发现策略允许且可用的
   描述符。过滤后数量不超过 max_candidates 时，按原注册顺序返回完整小目录；默认上限为
   12，可配置范围仍是 1–64。超过上限返回 None，不任意截取第一页，不绕过策略。
3. TaskAwareSessionPreparer 把完整小目录作为理解阶段首选，把原排序结果作为容量回退。
   两个目录相同时不做额外预检。初始输入、澄清回答和 steering 重理解沿用同一入口。
4. TaskUnderstandingEngine.prepare 新增可选 fallback_tools。它必须引用首选目录中相同的
   工具注册对象；同名但换 Schema、说明或执行器，以及未登记工具都被拒绝。已有直接调用者
   不提供回退时，仍按原来的严格目录准入行为工作。
5. 解释器收到目录前，先按实际 CapabilityView 的 JSON UTF-8 字节计算目录容量，包含输入、
   输出 Schema 和应用证据画像。可选扩展超过原 max_catalogue_bytes 时退回排序目录。
6. 新增可选、同步且无 I/O 的 TaskUnderstandingInputAdmission.input_fits 端口。
   ModelTaskInterpreter 用实际任务、历史、目录、指令和输出 Schema 构建初始请求，再复用
   自己发送时的 ModelRequestContextCompiler 检查 Token 和完整传输字节。扩展请求无法
   容纳时，在首次模型调用前改用回退目录；真正发送时仍再次执行原准入。
7. 接下来的规格校验、需求编译、Frame/目录摘要和模型请求摘要全部使用实际选定目录。
   visible_tool_names 只取经过验证的 selected_capabilities，不从发现目录直接复制。

这不是新增一个规划 Agent，也没有新增模型调用。词法与语义解释承担不同责任：前者在规模
较大时降低候选成本，后者在已知的小目录内判断真实任务是否需要某个能力。

## 一次请求如何流转

以 `What time is it now?` 为例：

1. SessionEngine 持久化原始 TaskInput，提供宿主能力上限。
2. 排序召回可以为空；完整、策略可见的小目录仍包含 read_clock。
3. 目录和真实初始请求通过容量检查后，解释器查看 read_clock 的说明与 Schema。
4. 解释器可以提出使用 read_clock；宿主检查所选名称、字段和需求关系。
5. 成功准备后只把 read_clock 放入本轮执行视图。直接回答和澄清仍是空业务工具视图。
6. Runtime 调用经过参数校验与 Tool Policy；结果持久化并进入后续证据、进度和完成验收。

发现一个时钟不等于证明它的读数满足当前性要求。默认结构证据提取器仍会把没有时效证明的
current 需求保留为未知；本次没有为了让演示完成而放宽该规则。端到端执行回归使用稳定的
归档读取，时钟原样例用于验证准备阶段的目录可达性。

## 不变量、失败和兼容

- 私有能力仍默认不可发现；自定义策略可以显式改变发现范围。模型文本不能改变该策略。
- 完整小目录不能越过宿主注册表，不执行工具，也不自动授予调用权限。
- 副作用工具可以作为意图候选供解释器判断是否需要澄清，但当前只读执行器仍拒绝执行。
- 只有模型调用前的容量不足可以选回退目录；模型异常、非法规格、覆盖审计失败、超时或取消
  不会触发换目录再调用，不会悄悄增加一次解释。
- 回退后的必需请求仍不合规时，沿用 CONTEXT_BUDGET_EXCEEDED 和原诊断；不提高预算。
- 第三方解释器可以不实现预检端口。此时只保证通用目录字节准入，真实传输的最终准入仍由
  解释器/适配器负责。ModelTaskInterpreter 未配置编译器时也不宣称完成 Token 预检。
- 预检只判断初始请求，不证明未来纠正或覆盖审计请求必定能容纳；后续每次请求继续独立准入。
- 超时和 CancelledError 沿用既有边界；解释器被取消后必须完成清理，不产生 Runtime 工具调用。
- 策略版本更新为 capability-resolver/4、task-aware-session/7、task-understanding/11、
  model-task-understanding/10。旧 Frame、事件、会话快照不改写；没有持久化 Schema 迁移。
- 实际 Frame 的 catalogue_sha256 和理解请求摘要绑定最终目录；不把扩展前摘要冒充实际输入。

## 替代方案与取舍

- **给 clock 补 time、多语言同义词**：可以提高局部召回，但依赖每个工具维护完整表达列表，
  不能修复“检索结果被误当成能力上限”的结构问题。本次不增加时钟或金融特例。
- **词法为空时暴露全部执行工具**：混淆发现与执行，而且正向干扰命中仍会漏选，不采用。
- **任意目录都全量发给解释器**：无法控制上下文成本，不采用。只在数量和实际容量都允许时
  使用完整小目录；大目录仍保留原路径及其召回限制。
- **立即增加 Embedding、另一个语义路由模型或分页发现协议**：有潜在价值，但会引入新的
  依赖、调用、状态与失败边界。先修复小目录的错误耦合，再用大目录失败样本确定下一机制。

直接回答也可能多看一些无关候选，目录 Token 成本可能上升；这是一项显式取舍。
任务解释指令继续要求不因目录提到某个领域就选择工具。本次没有证据证明真实模型的误选率
不会上升，需要冻结跨领域任务和模型配置后另行比较。

## 复现、基线与结果

```bash
uv run python -m examples.capability_preparation
uv run pytest tests/harness/test_preparation_discovery.py tests/harness/test_capabilities.py
uv run pytest tests/test_capability_preparation_experiment.py tests/test_task_model_view_design.py
```

基线通过可替换 Resolver 关闭完整小目录，保留同样的词法、需求和 Schema 召回；两组共享原有
examples/data/task_understanding/cases.json、同一注册表、12 个候选上限和 256000 字节目录限额。
报告包含数据集/目录摘要、策略版本、每次输入目录、解释调用数、选择和失败。没有修改冻结
任务、预标记宿主工具或删除失败样本。

| 指标 | 仅排序预筛选 | 有界完整小目录 |
| --- | ---: | ---: |
| 4 个冻结规格准备成功 | 3 | 4 |
| current_time 准备结果 | 不可用能力错误 | 只选择 read_clock |
| 直接回答/澄清的执行业务工具数 | 0 / 0 | 0 / 0 |
| 每例固定解释器调用数 | 1 | 1 |
| 四例目录组件 UTF-8 总字节 | 1433 | 5712 |

这是一项固定规格的准备链路消融，不能证明真实模型理解、任务完成率、Token 或费用收益。
目录组件增加了 4279 字节，实际模型成本仍需计量完整请求。ADR 0062 当时只成功准备五例的
原始测量不重写；当前探针六例全部成功准备，不能混用分母来宣传投影收益。

确定性测试另外覆盖：中英西不同表达、正向干扰命中、过滤后计数、宿主发现策略、未知能力、
大目录不全量暴露、目录字节回退、真实 BPE 与传输字节准入、同名注册替换拒绝、超时及取消
清理，以及真实 Session/SQLite 的读取、反馈持久化与最小执行范围。

本轮全仓 Ruff、格式检查、Pyright 与 Pytest 通过，共 1135 项测试；新增 19 项确定性回归。
未运行付费真实模型对照，不能把该测试数量当成 Agent 能力提升的证据。

## 当前限制与下一步

本次解决小目录中词法误裁导致的准备失败；大目录跨语言召回、可交互能力发现、技能组合与
真实模型误选率尚未解决。执行中的 EvidenceResolver、进度评估、记忆召回和自动 Resume
没有改变。TaskModelView 仍只是 ADR 0062 的设计与离线原型。

下一步接入模型工作视图时，应继续保持完整宿主状态、实际发送内容和增长预算证明的分离，
并在统一冻结任务上观察无效调用、完成质量及完整请求成本。
