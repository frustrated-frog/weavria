# 在单读反馈中展示改变排序的反证

2026-11-23 接受。适用于已启用单读经验、配置上下文编译器，并具备按内容版本读取工具的会话。

## 为什么只展示一次

一份被撤回的旧表曾完整送达，表上也确有撤回声明。[ADR 0149](0149-用当前需求与来源版本约束单读反证.md) 已能据此优先建议读公告。但当模型收到公告时，它看不到旧表为何失去优先级，可能再读一次。把旧表永久放入对话会增加成本，也会在用户后来查询旧时刻、权限撤销或来源更新时造成干扰。本次把旧任务、旧判断和原文短句绑定在与这次选源直接相关的工具反馈上。决定是否复核其他来源的权力仍由模型和当前工具策略共同控制。

## 一次读取如何流转

1. `ReadFeedbackBudget` 在同一组可完整交付的候选上计算两种排序。先比较按交付结果估计的成功率，再加入当前来源版本的最新明确判断。赢家改变时，在拒绝事件的 `ReadRetryPrediction` v4 中保存原提案下标和历史回执下标。后续模型即使改变调用 ID，也须通过现有的动作摘要匹配才能算采纳。
2. SessionEngine 先编译普通决策请求。只有刚推荐的单条读取成功，且编译后的请求实际包含其完整原文，才追查同一 Run、任务修订及相邻模型轮次已持久化的拒绝事件。按回执主键回取旧原件，沿用同会话、冻结配置、历史可见性和大小限制。
3. 重新核对旧动作与当前候选的归一化参数、工具版本、内容摘要，按当前 Run 权限再次授权。使用原件的 JSON Pointer、字符区间和引句摘要还原短句。旧权限已撤回、检查失败或授权超时均省略附注。授权等待受干预约束和外层 Run 取消约束。
4. 原需求及约束、原判断、来源定位、版本和短句进入 `TurnFeedback` v2 的 `previous_read`，作为低信任观察交给模型。仍然要求正常选源、执行及引用当轮证据。可选附注和原先的预算预留一起重新编译，若超限或挤掉其他任何模型可见内容，则使用先前的普通视图。最终采用的请求及预算报告一起持久化。

## 兼容性和取舍

`HarnessConfig.read_retry_feedback` 可独立关闭展示。需要同时启用单读经验，且会话支持上下文编译和声明了版本参数的工具。开启时在 Run 配置 v12 冻结 `observation/1`。恢复旧 Run 时依据原配置选择反馈格式。经验沿用冻结配置分组，新开关配置下的历史从本组首次试验开始累积。普通反馈继续使用 v1 原有编码，已有 SQLite 卷无需迁移。原件及历史请求不作回填。

单纯交付公告最省首轮预算，但对照中仍出现了复读。禁止读取已撤回来源会破坏历史查询。将附注作为低信任材料的对照实验验证了消费效果，正式入口选择已有的工具反馈归属关系，避免长期留在模型上下文，也避免为了生成解释再调用一次模型。对照只覆盖固定版本、同一任务现场的小型原件，原件检索上界为 2200 字节。

只问当前时刻时，独立主链路复测中四轮有三轮减少了旧表复读，一轮持平。双时刻和更新任务各四轮均保留必要读表与正确引用。下一次检验应让模型自行形成反证并选择首读，测量整个任务的自然命中率和总成本。[成对验证与复现命令](../公告读取后展示历史反证的成对验证.md)
