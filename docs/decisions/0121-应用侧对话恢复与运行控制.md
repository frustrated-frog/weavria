# 应用侧对话恢复与运行控制

状态：已接受。范围仅为 `apps/finscope` 和 FinScope 宿主界面。

## 问题与归属

FinScope 页面需要恢复历史、观察执行和停止模型/工具。Harness 已提供持久化轮次、事件、Artifact
和贯穿执行的 Task 取消语义。界面的请求跟踪与业务跳转属于应用适配层，不改变通用框架契约。

## 决策

保留原同步消息接口；新增返回 202 的请求接口，前端按稳定 `input_id` 轮询。
采用轮询而非 Token SSE：本轮所需的是可验证的阶段和工具状态，框架持久事件已满足这一要求。
阶段由真实执行事件投影，不记录或返回隐藏推理。请求范围由接受输入的 run_id 约束，历史请求不会
混入新请求的执行轨迹。工具开始和记录分别呈现读取中、成功或失败。

宿主持有每个请求的 asyncio Task，关闭页面不隐式取消；显式停止和进程正常关闭都 cancel 并 join。
SQLite 写入通过 shield 结算后传播取消，避免接受请求后丢失执行所有权，或完成结果被迟到停止覆盖。
重复输入相同参数只读已有请求，不派发第二次模型；同 ID 不同参数及同会话并发新输入返回冲突。
异常重启只标记中断，不自动再次执行。

UI 索引使用应用自己的 SQLite 文件，仅维护宿主会话目录和展示投影。框架事件与 Artifact 仍是事实
来源，读取经公开 store API，不耦合框架表。旧会话可用浏览器保存的 ID 纳入索引；没有凭据的旧 ID
不会被扫描框架私有表来发现。此应用仍是本机单用户单进程，不以 ID 作为远程多租户授权方案。

证据卡片只来自本次成功调用，读取保存的原始 Artifact；工具 observation 中可能只有裁剪视图或
Artifact 引用，不能当作原文。读取前先按 session/run/call 约束记录，不跨会话查询 Artifact。
业务链接由固定资源类型及校验过的参数构建，模型提供的任意 URL 不成为应用导航入口。

分钟复盘通过已有资源工具新增 kind，显式使用只读后端模式。应用计算区间覆盖和后续收益时只用
同日连续分钟证据，午休不计交易分钟，缺失不补零。净流向变号仅是确定性观察。

## 验证与局限

Fake Model 验证输入去重、参数冲突、理解/执行阶段取消、清理等待、重启后的历史，以及原始证据的
会话隔离。分钟测试验证只读路由、缺口、时间范围和后续收益。这些是契约与执行测试，不宣称提高
模型推理或工具选择成功率。本轮不做统一全文检索、不建立固定业务问题集，不修改核心 Harness。
