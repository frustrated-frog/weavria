# 0076 按需求覆盖选择动态工具工作集

状态：已实现，2026-11-01。

## 问题与决策

原 TaskAwareSessionPreparer 在每次反馈后对旧工具集合和新发现集合取并集。目录查询有单次数量限制，但跨轮集合会增长；已完成需求不能释放工具描述空间，同一种需求的高分候选也可能挤掉其他需求的候选。

本轮在现有解释、发现、归约与授权之间加入可替换的工具工作集选择策略。原单调并集保留为低层默认基线；统一 AgentHarness 在配置任务理解时采用有预算的自适应策略。原始工具注册表仍是能力上限，策略只改变下一轮展示哪些工具，不执行动作或推导新授权。

机制：按未解决需求分别查询已有 CapabilityResolver，合并候选；同一需求的候选收益具有递减性，以加权覆盖增益除以描述字节成本进行贪心选择，同时比较最佳单工具解。选择同时受工具数量与描述字节预算限制。需求状态、依赖阻塞与下游解锁价值确定权重，ContextFocus 使用相同权重。已完成需求退出工具选择目标，但其数据和来源锚点仍能进入上下文。

失败惩罚限定在当前需求、当前运行实际观察到的工具路径，不从一次失败推导整项能力永久不可用。成功后的旧失败不继续惩罚。保留已有工具有轻微稳定性偏好，但无新增覆盖收益的工具不会仅凭“以前展示过”常驻。未解决的独立 capability_result 义务单独建覆盖目标，避免没有信息需求的动作任务被清空。

## 取舍与不变量

该算法优化的是展示预算下的估计需求覆盖，不是任务完成概率，也不保证全局最优。词法和 Schema 发现仍是候选召回限制。替代工具的实际输出仍经过原证据绑定与完成检查，不能凭工具入选就把它当作合格证明来源。副作用工具只能来自解释已明确选择的集合，动态发现继续只加入只读候选。

工具退休、重新激活与集合变更推进 capability epoch；无变化保持 epoch。底层不可变注册表、ToolPolicy、参数校验和副作用语义不变。预算不足时记录未覆盖目标，不偷放超预算工具；最终模型请求仍由 ContextCompiler 按完整传输和 Token 预算检查。描述字节不是精确 Token 数。

设计公式、运行方法、复杂度限制及固定轨迹实验见[动态工具工作集的选择机制与实验](../动态工具工作集的选择机制与实验.md)。本轮不把合成选择收益当作真实模型任务收益。

统一入口版本升级为 unified-harness/2，任务准备器版本升级为 task-aware-session/9；未新增或修改持久化 Schema，实际视图仍通过原有 SemanticSnapshot 保存。
