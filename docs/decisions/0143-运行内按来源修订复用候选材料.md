# 0143 运行内按来源修订复用候选材料

2026-11-21，已采纳。

## 要省掉哪一次读取

一次模型视图构建中的预算回退与摘要试编译已经共享一次取材结果。同一 Run 执行只读工具后会再次构建视图，此时任务查询可能完全相同。上一轮已经查过的资料值得复用，但刚发生的权限变化、资料更新、选择器状态变化以及新工具结果带来的预算竞争，都可能改变下一轮应该交付的原文。

这里采用条件读取。宿主每轮向来源询问当前修订，来源可以确认上次结果仍可使用。固定生存时间难以同时保证更新及时和读取节省。按最终请求缓存又会把上轮的材料筛选及预算决定带进本轮。复用的单位因此取为**单个来源、筛选前的有序候选全集**。

## 从来源到请求

贡献者在 `ExtensionDescriptor` v3 中设置 `conditional_material=True`，声明 `before_compile` 阶段，并挂载 `ExtensionHooks(read_material=...)`。同一贡献者只能装配一种读取方式。普通取材钩子维持逐轮读取。

1. 宿主比较目标、约束及其顺序、任务修订和决策阶段。与上一次成功取材有任何差异，或这是新挂载时，向来源传入 `previous=None`。
2. 来源在当前权限下确定一个一致的快照。返回 `ConditionalMaterial(revision, bundles)` 交付该版本的完整候选，其中空元组表示当前来源为空。返回 `ConditionalMaterial(previous, None)` 确认上次快照有效。适合接入的来源包括不可变文件版本和在同一读事务中核对版本与正文的数据集。插件负责让修订标记覆盖会改变候选的全部源状态，包括授权可见范围。
3. 宿主只接受对本来源、本查询实际给出的标记的确认。冷读取收到确认，或拿同一标记返回不同的有序内容，会报 `invalid_snapshot`。拒绝访问和来源故障沿用原失败路径。命中时从私有序列化字节重建材料，照常扣除本轮条数和字节容量，然后重新执行本轮的选择器和分配器。
4. 整批取材和筛选成功后才替换上批缓存。后续兄弟来源失败或取消时，已经返回的新候选不能单独进入缓存。每个 Run 只保存最近一批，所有缓存正文合计受来源字节上限及 100 条候选上限约束。进程恢复后从冷读取开始。

来源每次仍有一次条件探测。收益取决于版本检查相对于读取、扫描或反序列化原始来源的成本。频繁改版或每轮任务需求不同的运行只能获得较少命中。[读取与发布边界](../../src/weavria/sessions/extensions.py) · [来源声明](../../src/weavria/sessions/extension_plan.py)

## 归档如何核验

执行条件读取的请求使用编译报告 v20。`store.explain_extension_request(...).material_reads` 给出来源名称、修订标记的 SHA-256、完整候选数、有序内容散列及 `loaded` 或 `reused`。内容散列覆盖带生产者命名空间的编号与正文，包括被选择器拒绝的候选。SQLite 提交时核对冻结清单中的读取者，编译契约核对完整候选散列。旧版描述和请求报告沿用原有编码。报告的 `policy_version` 仍指向实际使用的分配策略。

`reused` 表示同一次挂载中来源确认了上一批取材结果。构建候选视图也可能填充缓存，所以它不能推出上一次已发给模型的请求交付了该原文。模型实际采用的来源可在同一次归档的 `choices` 中查询。归档保存调用证据，在线运行的正文缓存随挂载释放。[编译契约](../../src/weavria/core/context.py) · [归档读写](../../src/weavria/sessions/store.py)

## 对照与结束条件

运行 `uv run python -m examples.conditional_material`。两个来源分别读取按内容散列发布的文件，材料来自仓库中的恢复协议 ADR。模型替身在同一查询中连续发起三次只读工具调用，第四次结束。独立发布者在第二次和第三次请求之间更新手册文件，两组使用相同的修订、运行身份、模型动作和预算。用实际读文件次数衡量 I/O，从重新打开的 SQLite 读取每轮决策，并将归档请求散列与发给模型适配器的请求逐一比对。[可运行对照](../../examples/conditional_material.py)

| 模型调用 | 基线完整读取 | 条件读取手册 | 条件读取参考资料 | 请求字节与基线相同 |
| --- | ---: | --- | --- | --- |
| 1 | 2 | 载入 | 载入 | 是 |
| 2 | 2 | 复用 | 复用 | 是 |
| 3 | 2 | 载入新修订 | 复用 | 是 |
| 4 | 2 | 复用 | 复用 | 是 |

基线读取正文 8 次，条件读取 3 次。第三份模型请求交付了新手册及原参考资料。这一结果验证了当前对照中的读放大和请求等价性。端到端延迟与模型回答质量需要各自的测量。

回归另外覆盖权限撤回、虚假确认、空材料、修订冲突、命中后预算收紧、筛选器改判、查询或阶段变化，以及取消后重新取材。子进程在工具结果结算后退出，重启后同一来源修订再次完整读取，已结算工具只调用一次。上述三个条件——稳定来源减少实际读取、变化来源在下一请求交付新原文、错误与恢复路径保持一致——构成本轮验收边界。[条件读取回归](../../tests/harness/test_conditional_material.py) · [进程恢复对照](../../tests/sessions/test_crash.py)
