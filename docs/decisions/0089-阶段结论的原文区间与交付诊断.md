# 阶段结论的原文区间与交付诊断

## 失败请求定位

以只读方式检查原有隔离树的 `.weavria/m1` 诊断数据库。用 `SELECT model_call,data FROM request_views ORDER BY model_call` 找到执行请求，按 `current.history` 中的原文范围、`current.task_model_view.progress.working_state` 和 `runs.report` 核对三个边界。

- 文档第三候选 recent-1 的第 2、3 次模型请求含资料包内 51333–52241 的推荐接入示例和 43823–44141 的工作记录使用指南。0079 的 12623–13022 片段是记忆处理结果，缺少默认值定义；0078 的相关原文未交付。阶段笔记把示例写成默认值，并把两个结论都指向同一资料包的整段 `/text`。最终回答继承错误默认值，并引用包装文件和使用指南。这里同时有原文选择和来源粒度的问题。
- 源码第三候选 coverage-2 的第 8 次请求保留两页原文、三条阶段结果和正确原文件名。最终回答保留正确的文件引用，但把数字写成字符串。这里的问题发生在输出映射，而非原文丢失。

## 改动与边界

`propose_work` 允许工作引用附带半开字符区间。宿主检查指针和值域，按原文装饰标题解析单一来源名；区间横跨文件时保留原文地址但不猜测文件名。普通单文件可使用原始 Artifact 的路径字段。输出标签仍属于原始资料的低信任元数据。阶段工作视图保留标签和原文地址；上下文编译器将接受的区间用作有界软锚点，使同一大字段里的无关片段无法满足该锚点。旧指针引用的序列化保持原样。对区间的核对证明它属于已接受 Artifact，不能证明模型阅读过全部区间或结论被证据支持。

M1 runner 仅补充通用交付说明，包括区分默认值与示例、保持 JSON 原始类型、引用原始来源及按用户要求记录带原文区间的结论。冻结语料、任务、评分和预算未改，评分答案不进入请求。诊断可用 `--case <case_id> --diagnostic-repetitions 1` 指定单项每臂一次，该选项不能用于完整验收。
