# ADR 0028：行动收益量纲与局部失败控制修正

- 状态：已实现
- 日期：2026-10-22
- 范围：行动干预、进度评估、价值统计、准入与事件回放
- 前置：[ADR 0027](0027-基于执行反馈的贝叶斯行动价值控制.md)
- 本文替代 ADR 0027 的单位调用收益公式、低收益否决条件及固定门控组合方式；保留原始提议、批次归因、事件驱动更新、风险估计与失败关闭协议。

## 问题与复现

`9985eb1` 将批次出现进展的概率除以调用数。三个正向样本的 Beta 后验均值为 0.8，四调用批次得到 0.2，低于默认 0.25；即使每轮四个调用各补齐一个字段，也会被拒绝。调整阈值无法纠正概率和收益量的混用。

同时，Need 的 `UNAVAILABLE + can_retry=False` 仅表示已观察路径未提供有效证据，不能证明该工具的其他参数、备用来源或未来能力均不可行。旧评估器先生成全局 `stop`，主动干预随后阻止备用工具，局部失败因而成为错误的任务级约束。

新回归在旧实现上复现了宽度 4、5、8 的有效批次被拒绝、三次中性观察被过早否决，以及主来源失败后备用来源无法执行。修复不引入 Critic 或模型自报奖励。

## 收益量与不确定性

继续保存“是否产生进展”的 Beta 后验，作为诊断信号；它不再承担收益量估计。义务完成、字段覆盖、独立来源分别保留计数，不加权、不相加，避免同一成果同时覆盖字段与满足义务时被重复计分。

对每个维度 d，以已接受的累计收益 `G_d` 和完整批次累计提议调用数 `C` 更新 Gamma–Poisson 率模型：

```text
先验：Gamma(shape=1, rate=1)
后验：Gamma(shape=1 + G_d, rate=1 + C)
均值：μ_d = (1 + G_d) / (1 + C)
标准差：σ_d = sqrt(1 + G_d) / (1 + C)
乐观上界：U_d = μ_d + uncertainty_scale × σ_d
```

单位是“该维度的收益单元 / 提议调用”，可以大于 1。失败和跳过调用也进入成本；不会把成功样本的成本单独挑出来。默认至少三次观察，且**三个维度的乐观上界全部低于 0.25**，才作低收益否决。回归仍使用独立 Beta 后验下界控制，`mixed` 同时贡献收益与回归。

例如每次四调用获得四个覆盖单元，三轮后 `G=12, C=12`，覆盖率均值为 1；一调用三次均无收益时上界为 0.5，仍可探索；八次均无收益时上界为 2/9，才触发默认低收益拒绝。八调用长期仅获得一个单元仍可能被判为低收益，这取决于真实收益密度，而非宽度本身。

`ActionGainEstimate` 持久保存各维度计数、成本、均值和区间。v2 的 `expected_progress_per_call` 仅为最大分量均值的紧凑摘要；决策实际逐个检查收益向量。不能把该字段解读为成功概率或统一效用分数。

这些区间是指定计数模型下的后验矩区间，没有精确置信水平。默认先验、共同的计数阈值、同桶平稳性和 Poisson 假设尚未由真实任务校准；相关的并行结果也可能使区间过窄。修复证明量纲和控制行为，不宣称统计模型已经成熟。

### 为什么不用“进展概率 × 条件收益 / 成本”

它也是合理候选，但需要额外估计正向条件下的收益分布，尤其要定义零正向样本的先验及两个估计之间的依赖。当前 Profile 已有各维度总收益与调用成本，直接估计收益率足以消除错误量纲，也能表达零收益的不确定性。以后可用真实轨迹比较两者。

## 停止结论的范围

`need-progress-assessment/2` 保留 Need 的失败事实与 `can_retry`；不把它们扩张为来源永久关闭、能力穷尽或任务不可完成。开放义务下出现不可重试路径失败，建议 `constrained / replan / observed_paths_unavailable`；新增能力建议 `replan / new_capability_available`，不会被旧失败抢先转成 stop。

模型或工具预算确实耗尽时，仍可产生 `blocked / stop / continuation_budget_exhausted`。自定义可信评估器依然可以提供任务级 stop；它必须自己承担该结论的证据责任。默认评估器没有穷尽搜索空间的证明，因此不新增貌似完整但没有依据的来源级、能力级阻塞枚举。

端到端回归经过真实 SessionEngine、工具后端、EvidenceResolver 和 NeedProgressEvaluator：主工具抛出非重试 ToolFault，备用工具成功；两者都有 ToolStarted，Need 的开放义务归零。最终文本未独立核验，所以 `task_outcome` 仍是 `unverified`，不会把取证成功等同于答案正确。

## 价值范围与探索门控

新 `ActionValueScope` 从已接受 ProgressAssessment 的 `unchanged_open_ids + reopened_ids` 得到当前开放义务集合。价值键现在包含任务修订、控制目标、开放义务范围和完整行动族多重集。不同开放义务集合不再共享负面统计，调用 ID 和参数措辞不会生成新范围。Reducer 重建同一范围并核对，伪造名称不能获得新冷启动桶。

若评估器没有完整列出开放义务，scope 标为不完整：不依据该范围作统计否决，也不接管固定门控。首次无评估同样保留原回退规则。这不是候选动作级 Action Hypothesis：同一开放集合内，不同目标的调用仍可能混合。跨宽度共享和调用级归因继续推迟，避免把并行协作收益随意平分。

`semantic-progress/6` 的 `inspect` 增加可选 `adaptive_exploration=False`。Runtime 仅在已持久接受允许判定、具备 v2 收益估计且义务范围完整时传入 True：

- 价值策略拥有该候选的探索停止决策，固定同族次数不再抢先否决；
- 精确重复与批内重复仍由语义前沿检查拒绝；
- 能力视图、反馈预算、工具预算、最大批次、权限与截止时间继续独立生效；
- 没有有效统计判定时，固定同族阈值仍生效；
- `record_admission` 只在 BatchAdmitted 接受后记账，并保留实际采用的门控方式。

外部 ProgressPolicy 实现需要接受这个新增的可选关键字参数。自定义策略可以保留自己的限制；Runtime 不会在收到其拒绝后强行派发。更换目标或批次组成可能重新冷启动，但不能绕过总预算；本轮未宣称跨桶的最优探索分配。

## 执行链路与兼容

一次候选经历：`TurnDecided → 规范化动作身份与义务范围 → ActionInterventionChecked → 普通准入 → BatchAdmitted → ToolStarted / ToolRecorded → TurnSettled → ProgressAssessed → Profile 更新`。被拒绝的批次没有工具派发；未结算或未评估的结果不贡献样本。

- 行动价值算法从 `progress-action-intervention/3[...]` 开始生效；当前 v4 在其上增加“验证就绪后无进展则收敛”语义；新 Run 记录 `bayesian-action-value-ledger/2`。
- ActionValueContext / Profile / Estimate 与有价值反馈的 InterventionNotice 支持 v2；外层 ControlEvent 仍是 v3。
- Context / Profile v1 不添加 scope 字段，Estimate v1 不添加 gain_estimates，保持历史 JSON 和摘要。v1 仍约束旧概率字段不超过 1，v2 允许计数收益率超过 1。
- Ledger v2 必须绑定 v2 的已接受义务范围；不从旧统计推断丢失的义务信息，不自动迁移 v1 Profile。
- `tests/fixtures/action_value_v1.json` 在修改前由 9985eb1 的合成工具执行生成，包含实际摘要和数值；回归逐事件解码、验证旧摘要并比较最终 Profile，避免拿新代码重新生成“兼容样本”。

取消、超时、任务修订期间的旧候选丢弃与效果边界不变。本轮不增加后台任务。可重放统计仍不等于自动继续崩溃前 Run。

## 验证与局限

冻结的 16 个机制场景覆盖：冷启动、少量与持续中性、1/3/4/5/8 宽度的成比例收益、宽批次稀疏收益、回归、混合收益及三个独立维度。新策略判定为 16/16，hard-stop-only v1 基线为 11/16；按候选判定计算避免 14 次低价值或高风险调用，误干预 0。这是策略模拟计数，未实际派发这些评测候选，不是节省真实 Token 的结果。

另外用 Runtime 集成测试验证默认停滞阈值下可以积累八次同范围中性样本，下一批次在 ToolStarted 前被价值策略拒绝；精确重复仍被普通准入拒绝。Session 集成测试验证备用来源实际派发。旧日志重放、范围篡改、任务修订、超时与取消测试验证工程承诺。

```bash
uv run pytest tests/runtime/test_intervention_policy.py tests/runtime/test_control_loop.py \
  tests/harness/test_progress.py tests/harness/test_session_preparation.py \
  tests/evaluation/test_action_value.py
```

没有运行付费模型或开放任务 A/B。本轮不证明完成率提高、长期成本下降或阈值最优。下一步仍是候选行动绑定有效义务，再用 Evidence Provenance 验证归因；这比继续细分没有可验证依据的统计桶更有价值。
