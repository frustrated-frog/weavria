# 0039 可追溯的双时间记忆内核

## 背景与实施范围

2026-10-23 实现网页“记忆模块”方案的第一批：独立记忆内核、时序事实持久化、基础写入和查询。基于 `codex/context-compiler-v1` 的 `cf870cb12a11847cf65e5f891c0fd7d5357459cb`，在隔离分支 `codex/memory-kernel` 开发。

设计输入是项目绑定讨论的快照 `45607105-b1c2-4e24-bfe5-efc226f7ace1`，采集于 2026-10-23 01:59:57 北京时间，方案消息为 `turn:2ef64706-c9a4-47d4-b112-bbb1f5e3e720:assistant:0`。快照仅包含采集时已加载的分支；本轮没有重新核验其中论文和外部项目的版本、成绩及会议信息，不把这些陈述作为实现效果的证据。

本轮解决的具体问题是：多个会话获得的事实会变更、被纠正或相互冲突。如果只保留一份最新文本，历史查询无法区分“当时成立”与“当时已知”；如果重复消费和并发修订没有事务边界，则会重复写入、丢失更新或留下无法重建的索引。

本决策遵守研发宪章第 3、9、10、14、20 节。自动候选提取、语义准入和任务感知召回属于第二批；本轮不修改现有 SessionRequest、Context 或 Runtime 的公开行为。

## 记忆所有权与信任边界

新增独立 `weavria.memory`，依赖标准库与现有 Pydantic，不依赖 Runtime、Session、应用或外部记忆框架。核心架构测试增加 memory 层，其他层没有自动获得导入它的权限。

`MemoryAccess` 是可信 Python 宿主提供的读、写授权集合。作用域由租户、类别及键组成，类别包括 tenant/user/project/session/agent；匹配必须完全相同，没有父级继承、自动跨项目共享或凭 ID 访问。全租户作用域本身也是一个精确命名空间，不代表自动读取该租户所有子命名空间。此机制不是认证服务，也不是隔离恶意 Python 插件的沙箱。

`MemorySource` 保存已接受来源的引用、内容摘要、来源类别和观察时间。宿主负责确认上游事件已被接受、原文摘要正确以及用户身份；内核检查来源已注册、不可换内容复用 ID、属于当前作用域且可被断言引用。单纯持有一个 SHA256 不能证明断言受原文支持。第二批的来源适配器与 Admission 才负责原文核对、证据支持和作用域晋升，模型不能直接构造宿主授权或提交命令。

`MemoryAssertion` 区分种类、权威标签、置信度与认知状态。纯模型来源不能提交为 stated/observed；已有来源反复出现不增加置信度。权威标签的业务解释仍由宿主准入策略负责，本轮没有定义通用的来源权威排序。semantic/episodic/procedural 是分类标签，本轮没有实现经验归纳或程序性策略学习。

## 两个时间轴与修订算法

所有日期必须带时区，序列化为 UTC。现实有效区间为 `[valid_from, valid_to)`，结束为空表示开放区间。开始为空只允许结束也为空，明确表示未知时间；默认不参与严格有效时间查询，调用方可以显式选择包含未知时间。

系统知识版本保存 `[recorded_at, retired_at)`，同时维护作用域内单调递增的事件 head。相同时间可以提交多个批次，时间查询看到该时刻所有已提交事件，`at_head` 可精确指定其中一个提交边界。注入时钟倒退会拒绝提交。

修订既不覆盖原始事件，也不直接修改旧断言内容。旧知识版本记录退役边界，新版本携带新的断言投影。归约器支持：

| 操作 | 明确语义 |
| --- | --- |
| add | 为新身份增加断言；已撤销的身份也不可复用 |
| reinforce | 对来源去重并集，不修改断言内容、置信度、权威或认知状态 |
| supersede | 对同作用域、种类、主语、谓词和限定条件的事实，替换其有效区间尾部 |
| contest | 新断言与旧断言的时间可能重叠时，将双方标记为争议 |
| retract | 有证据地撤销目标的当前知识版本，保留过去已知的视图 |

`supersede` 若从旧区间内部开始，则新旧投影分割为相邻半开区间；若从同一起点开始，则属于纠错，旧断言被撤销而不生成空区间。新断言必须覆盖旧区间剩余尾部，不能改变原终点或向旧起点之前扩展。未知时间断言可被明确替代。任意中间区间切分、自动实体消歧以及语义冲突判定留待后续协议，本轮会拒绝无法明确表达的修订，不猜测日期。

争议断言不能直接 supersede。宿主可以在一个原子批次中明确 retract 争议断言并 add 经准入的新断言。仅撤销争议一方不会自动为另一方清除争议。`add` 不自动发现同键但不同值的矛盾，宿主必须明确选择 contest；这不是已经完成的语义冲突检测器。

每个目标修改要求 `expected_revision`。一个批次内每个新身份或目标只能出现一次，避免内部动作顺序造成隐式含义。归约器纯计算，持久化实现负责关闭旧版本、写入新版本。

## 事务、幂等和重建

独立 SQLite 文件采用 `application_id` 与 `user_version=1`，所有持久契约的 `schema_version=1`。拒绝未知版本和其他子系统的数据库。没有现有数据需要迁移；后续版本必须增加明确迁移路径，不允许把 Session 数据库当作 Memory 数据库。

同一 `BEGIN IMMEDIATE` 事务写入：

1. 规范化批次及操作者、策略版本、时钟与归约结果组成的事件；
2. 不可变的来源描述；
3. 双时间版本投影；
4. 可选的事件消费游标。

同作用域的 `batch_id` 绑定规范化内容 SHA256 和操作者。相同重试返回原回执，即使原先的 CAS 或游标条件已经过时；同 ID 不同内容或操作者拒绝。游标只能推进一个上游序号，重复消费不会重新写入；有意拒绝保存时可以提交零条 mutation 的游标批次。提取失败时应不调用 commit，不能用空批次伪装成功消费。

Memory 和 Session 数据库之间没有原子事务。将来消费器使用至少一次投递、稳定来源 ID、确定的批次身份、CAS 游标与幂等回执建立最终一致性；本轮只提供可执行的内核协议，没有后台 Session 消费器。

`rebuild` 从不可变事件逐条重放来源、断言和游标，核对 head、时间、批次摘要、归约结果和游标条件；失败则整个重建回滚。词项索引按每次可见快照重建，不是权威数据。原始会话来源仍归其原存储，本轮仅保存引用，没有跨存储的数据备份或来源内容恢复功能。

## 召回与预算

读事务固定作用域 head，再应用 `at_head` 与 `known_at`，选取该知识边界的版本，然后执行现实时间、状态、主语及谓词筛选。未来退役信息会从历史返回视图中移除，避免通过 `retired_at` 或 `retired_head` 泄露后来发生的修订。审计 API `history` 和 `events` 按页读取完整事实，语义不同于 as-of recall。

候选通过精确过滤后，使用 BM25：`k1=1.2`、`b=0.75`，IDF 为 `log(1 + (N-df+0.5)/(df+0.5))`。Unicode NFKC 与 casefold 归一化英文和数字，汉字使用单字与相邻双字，保留短词可检索性。数字和汉字分别切分，避免日期吞掉后面的中文词项。该分词没有中文语言理解，可能引入单字噪声；它是当前可解释基线。

与网页建议的 SQLite FTS5 有一项明确取舍：第一批使用 **SQLite 精确筛选 + 可见快照内的 Python BM25**。全库 FTS 统计会让其他作用域或未来知识影响 IDF；先按全库 top-k 再过滤还可能漏掉有效候选。为保证本轮时间和作用域隔离，直接在已过滤的有界语料上计算统计量。代价是每次查询需要扫描候选并重建词频，不声称适合百万规模。未来可增加分区的持久词项索引，但必须保留同一快照语义。

候选数默认最多 10,000，候选序列化数据默认最多 16 MiB，超限明确失败；单批提交默认不超过 1 MiB。召回最多返回 100 条，输出预算覆盖整个 `MemoryRecall` 序列化 UTF-8，包括版本、分数和完整来源描述。超大断言可以跳过并继续尝试后续候选；不切断断言、不丢来源，记录 `omitted_count`。字节预算不等于 Token 预算；第二批 Context 集成还必须计量完整模型请求。

返回的 head/index_head 均绑定一个可见快照。排序分数只表示词项相关性，不改变置信度和权威等级。未解决冲突保持 contested，不自动挑选一个事实当成真相。

## 异步生命周期与失败边界

每个实例只拥有一个线程，最多 64 个已提交工作排队；没有脱离调用生命周期的写入任务。SQLite 独立连接可以共享一个本地文件，通过写事务串行化、修订 CAS 和 100 ms 的锁等待处理竞争。

调用方取消时，如果操作已交给线程，必须等待它提交或回滚再传播 `CancelledError`；若已经提交，调用方可以使用原批次 ID 消除结果不确定性。不能声称取消等于没有写入。close 等待已提交操作并关闭连接与线程，自身被取消时仍负责清理。

deadline 使用真实 UTC 检查排队后的开始时间和事务提交前时间；重建还在每个事件之间检查。已经开始的 SQLite 调用和同步 Python 计算不能被硬抢占，外层 `asyncio.timeout` 也会等待已交给线程的操作收尾。因此这是有界合作式资源管理，不是硬实时终止或外部 exactly-once。

SQLite/schema 故障归一为 `MemoryStorageError` 并保留异常原因，权限、前置冲突、容量分别有独立错误。内核不向普通 Trace 输出正文；事件审计本身包含记忆内容，只能经同作用域授权读取。没有隐私物理删除能力，retract 不是删除，不能向用户声称遗忘了底层内容。

## 验证与下一步

验证包含公开 API 的双时间修订、同起点纠错、争议与撤销、独立连接 CAS、重复来源和消费游标、事务故障回滚、重建修复与损坏日志拒绝、取消和关闭清理、deadline、中文短词与日期检索、预算、跨作用域排序隔离，以及真实进程在提交前后被终止。

`examples/memory_kernel.py` 冻结三个时序查询并与最新值基线对照；记录本地检索耗时。它是合成机制实验，不是论文复现、自然语言提取评测或真实 Agent 行动收益证据。结果与运行说明见[记忆内核与双时间事实](../记忆内核与双时间事实.md)。

下一步应建设带来源定位的候选提取与独立 Admission，优先解决原文支持、语义归一、事实变化和纠错的区分，再把有界 MemoryView 接入任务准备与上下文编译。不能将本轮显式宿主命令当作自动记忆决策已经完成。
