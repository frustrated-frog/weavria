# ADR 0056：任务声明的统一纠错与局部语义修复

## 问题与证据

同一个真实请求在初次解释和独立覆盖审计之后，可能因语义修复返回非法规格而直接终止。
初次解释已经支持一次格式纠错，语义修复却只有一次生成机会，而且要求重写完整 TaskSpecification。
修复无关的路由、意图、目标和澄清元数据因此也重新暴露给非确定性输出。

2026-10-29 的原始失败记录显示：输入 12575 token，允许 24320 token，59041 字节，
请求准入通过；失败阶段为 semantic_repair，异常只有 ValidationError。没有进入工具执行。
这不是上下文溢出，也不能通过取消证据校验来解决。

## 决策与请求流程

ModelTaskInterpreter v9 用同一个生成状态机处理初次解释和语义修复：

1. 从原始任务、能力上限与已接受上下文构造声明请求。
2. 每次发送前重新经过 ModelRequestContextCompiler；纠错新增内容同样受准入约束。
3. 对规范化动作执行原有 Schema、能力、字段与目标校验。
4. 可纠正的协议、声明错误最多获得一次格式纠错。两次尝试共享同一个阶段截止时间，阶段仍受
   TaskUnderstandingEngine 的父期限约束；传输故障、外部取消和不可修复输出不进入这一重试。
5. 修复声明通过后，宿主合并并重新校验完整规格，随后重新执行冻结任务义务的覆盖审计。

语义修复使用私有 repair_task_specification 声明，只返回 information_needs、capability_needs、
completion_criteria 三个数组。宿主保留 route、intent、goal 和澄清绑定。模型无权通过修复重写这些
字段；多余字段会被拒绝。必需能力的机械完成边继续由既有归一化逻辑生成。

这不是任意 JSON Patch，也没有改变公开 TaskSpecification、TaskFrame 或持久化 Schema。
正常任务仍可在宿主能力上限内补充真正需要的能力；已经解析的澄清行动仍受原有冻结约束。

## 提前校验与诊断

真实复测另外发现，模型把新闻、财务等事实类别误填成 target key。原逻辑直到覆盖通过后的
执行计划编译才拒绝，已经错过纠错机会。现在在声明接受前检查：目标键必须来自生产能力声明的
target_rules，跨度必须落在原始任务文本中。没有 target_rules 时不得凭空填入 targets。
完整计划编译仍保留原校验，提前检查不替代最终证据绑定。

另一次冻结复测发现：一项覆盖判断可以由多条需求共同满足，计划编译却把需求集合与证据面集合
做了笛卡尔积，误要求每条需求都能生产所有证据。TaskUnderstandingEngine v9 只给每条需求绑定
它实际声明的生产能力和字段所覆盖的证据面，与独立审计的主机归属规则一致。同一工具的两个字段
以及两个独立工具的组合都有回归，既不跨生产者绑定，也不向每条需求额外增加兄弟需求的字段。

拒绝声明与字段错误放在 TaskInput.constraints 的低信任数据通道中；系统指令只包含静态纠错规则。
持久诊断保留阶段、尝试序号、请求准入和安全错误代码；未知的模型字段名以 `<extra_field>` 表示，
不保存模型任意填写的值或私有推理。最终失败消息附带相同代码，避免只暴露笼统英文错误。

独立覆盖审计升级为 v4，明确区分“规划是否表达所需事实”和“运行时是否已经取得证据”。
selector 指输出 JSON Pointer；不能因为后续检索才能发现的记录 ID 尚未知，就拒绝一个具备
合法生产能力与字段的计划。对于开放数据包，使用适配器声明的容器字段，不要求未声明的嵌套键。
助手旧回答和候选自己增加的格式要求也不能成为新的用户任务义务。宿主的字段校验、覆盖降级与
冻结义务保持不变；没有把审计返回的 underspecified 自动提升成 covered。

## 取舍与不变量

- 不扩大父期限或关闭审计；格式纠错与语义重审是不同的有界步骤。
- 不再次重写完整规格；需要修正范围以外的意图，应走正常任务修订。
- 不自动补齐模型猜测的实体、字段和领域事实。目标与证据契约仍由公开宿主能力提供。
- 不将模型输出提升为系统指令，失败诊断也不收集隐藏推理。
- 通用实现不理解 FinScope 名称、财务字段、来源格式或金融流程。

## 验证与当前局限

领域无关回归覆盖：非法修复后恢复、连续非法声明、安全字段诊断、能力越界、供应商 JSON 解析错误、
不可修复输出、纠错请求超限、截止时间清理、外部取消，以及无声明目标被提前纠正。
已有目标身份、澄清绑定和独立覆盖拒绝回归继续运行。

这些测试证明执行与边界，不证明自然语言规划从不犯错。真实服务各轮结果和失败过程统一记录在
[任务链路稳定性回归](../任务链路稳定性回归.md)，不能用单次成功代替稳定性证据。
