# 澄清恢复与接续分页修复

澄清关联属于已接受的输入和语义变更。恢复比较运行配置时只排除这一请求字段，仍核对模型、工具、预算与其他运行配置。恢复继续使用原 Run 已持久化的状态和语义头，任务理解不会重跑。

跨会话接续扫描已接受工具结果时，将框架的分页结果视为派生视图。框架确认源 Artifact 已在任务链中重新授权、读取工具版本匹配，并用同一分页算法复算原文指针、范围和输出。同 Run 的本地分页必须有已接受的依赖记录。派生页通过验证后沿用原始来源，不占独立来源名额。普通会话历史读取和无法还原到任务原文的分页继续拒绝。

接续 Run 的 `read_task_source` 使用任务授权闭包按 Artifact ID 和 JSON Pointer 分页。每次读取重新核对目标会话、历史来源及工具 Policy，分页调用进入已有工具执行、反馈预算和事件记录。来源工具的闭包只在本次接续 Run 有效，常规 Resume 遇到需要重新绑定该闭包的 Run 会按配置不匹配拒绝。

进程退出回归覆盖澄清、补充、结算后退出和同 Run 恢复，也验证真正改变运行配置仍拒绝。组合回归覆盖原会话读取大资料并分页，接续会话直接回读原文后只查剩余文档。
