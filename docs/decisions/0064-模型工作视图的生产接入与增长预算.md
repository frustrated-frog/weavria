## 本次解决的问题

完整 TaskFrame 适合保存任务解释、覆盖审计、匹配计划和版本，但每轮都把它全部发送给模型，
会重复发送实现细节；同时，完整宿主状态和模型当前需要的工作状态并不相同。

本切片让同一份已提交语义状态有两条消费路径：宿主继续使用完整 Frame/Ledger 判定权限、
进度、收尾和完成；模型只接收确定性 TaskModelView。投影位于上下文选择和计量之前，
不是 Provider 发送前删除字段，也不创建第二份权威账本。

这一步必须同时解决三个问题：精简后是否保留决策所需含义；工具结果引起的视图增长怎样进入
执行前容量证明；发送的视图是否确实来自当前已提交状态。只定义一个类型或测量初始压缩率，
不能算接入完成。

## 新请求及职责边界

- Core 新增 TaskModelView、TaskModelViewSource、TaskModelViewReceipt。
  Core 只理解来源、摘要、版本、阶段和容量，不解释 NeedStatus 或业务字段。
- ControlRequest v5 携带 task_model_view，完整 task_observation 必须为空。v3/v4 仍使用原
  字段、顺序和序列化，不增加新空字段。外层 SessionRequest 仍为 v5。
- v5 用 allow_context_recovery 显式表达运行是否启用了恢复；recovery_enabled 为统一读取
  属性。v4 保留原来的恢复含义，v3 仍不支持；格式升级不等于恢复授权。
- ContextCompilation v9 保存投影收据，绑定来源语义版本、观察/账本/视图摘要、稳定定义及
  增长容量，同时保留原交付清单、BPE Token 和完整传输字节诊断。
- TaskModelProjector 是可注入的公开端口；TaskModelViewProjector 是 Harness 的独立实现。
  SessionEngine 默认不使用投影。启用时要求任务准备、上下文编译和完整传输计量一起配置。

SQLite 表结构和旧持久化数据没有修改。新内层请求及报告有明确版本；旧读者不能读取新格式，
不会被伪装为旧版本。ConversationView 也明确识别 context-compiler/9 策略。

## 稳定定义与动态进度

definition 在同一 Task Revision 内保持稳定，包含：解释目标、路由、歧义、已选澄清、所有
需求的身份/描述/依赖/字段/新鲜度/完成模式/最低证明等级、目标联系、原请求目标选择、交付
要求和带原 trust 的导航上下文。不会按 top-k 删除需求，SATISFIED 的需求也不会消失。

progress 每个需求保留一行：当前状态、已声明字段及通用哨兵的缺口、获取状态、重试性、
绑定数量、观察到的结果类别、探测状态、证明等级，以及失败总数与最近一次分类。

第一版明确采用有界摘要：

- 不复制持续增长的 bindings、probes、失败列表、异常原文或证据正文。
- 额外的自定义缺口标签用 additional_gap_count 标明数量；完整名称仍保留在宿主账本和来源
  中。不能把零个已知字段缺口解释成“没有其他缺口”。
- 失败计数与最近分类不代表完整失败历史；旧失败细节仍由 Trace、工具反馈及原始事实保存。
- 结果类别会结合 Probe，因而可以显示 empty/not_found；not_applicable 不被当作匹配结果。
- 状态和证明等级不是答案事实核验等级，也不证明正文已经送入本次请求。实际交付仍由
  Compiler 的 EvidenceDeliveryManifest 和原 FinalizationPolicy 判定。

这是与 ADR 0062 离线原型的一项明确区别：原型保留完整 bindings，本切片采用有限进度结构，
避免把完整账本重新包装成另一份不断膨胀的 Frame。其他需要完整自定义缺口或失败原文的宿主
目前可以继续使用原观察路径，不能声称新视图无损替代全部内部元数据。

普通决策和 synthesis 阶段显式区分，收尾保留完整需求定义和限制。Finish-only 仍由 Runtime
执行，而不是仅依靠一个 phase 字符串。恢复特性位表达运行配置，当前是否允许行动还受收尾
阶段约束；收尾指令不再公布探索工具。

## 一次请求的源码流程

1. SessionEngine 接受输入，TaskAwareSessionPreparer 准备并提交 Frame、Ledger 和语义版本。
2. _SessionAdapter.prepare_turn 读取已提交状态；Runtime 同时获得完整 observation 和
   semantic_state，继续用于 Progress、Intervention、Completion 和 Finalization。
3. Runtime 用 BaseControlContextBuilder.build_control_request 传递完整 base 请求。
   旧的 build_control 端口保留，避免通过散参重建丢失新字段。
4. Adapter 调用 TaskModelViewProjector.project，检查 TaskInput 摘要、需求身份、Frame/Ledger
   版本及进度摘要。相同任务修订内，Work、投影版本、定义摘要和容量布局不得偷偷改变。
5. 投影替换模型输入中的完整观察；Compiler 选择原文和历史，对最终实际请求计量并生成 v9
   收据。无历史的中间模板暂带 feedback，最终请求才在工具结果全部选入后校验反馈配对。
6. Runtime 接受 ContextSelected 与 ModelStarted；SQLiteSessionStore.prepare_request 在同一
   事务核对执行位置、请求摘要、编译收据和当前 semantic_heads，再保存实际请求快照。
7. Provider 对相同请求编码并再次准入后发送。模型返回 Finish 时，宿主验收继续读取完整状态。

关键实现位于：

- src/weavria/harness/task_view.py：确定性投影、信息保留与最坏进度行。
- src/weavria/core/task_view.py：来源、容量和收据；不承载业务解释。
- src/weavria/sessions/engine.py：投影组合、稳定布局和完整请求构建。
- src/weavria/context/compiler.py 与 admission.py：当前请求分配和执行前反馈证明。
- src/weavria/models/openai_compatible.py：实际编码、BPE、HTTP 字节与 v5 容量上界。
- src/weavria/sessions/store.py：发送留证事务中的语义头核对。

上述不变量附近增加了必要中文注释，解释原因和临时模板边界，不逐行复述赋值。

## 下一轮增长怎样进入预算

不能把当前进度当固定前缀：第一次读取前失败列表可能为空，执行后可能出现缺口、空结果、
冲突或重试状态。也不能假设工具说明固定，证据刷新可能发现备用能力。

本切片采用以下保守证明：

1. 每个需求的最坏进度行包含所有已知缺口、最长状态/分类、全部可能的结果及探测类别，计数
   按 64 位十进制上界计算。当前行必须能放进声明的 max_progress_bytes。
2. 来源摘要长度固定，版本数字按 64 位上界、阶段按较长字符串预留；稳定定义不会随普通工具
   反馈变化。任务修订使旧布局失效，需要重新构建。
3. Adapter 从本 Run 的不可变工具上限计算最大说明 JSON 编码字节，并比较普通和收尾指令。
   只预留容量，不提前向模型暴露未选中的工具。将来新增说明不能超过该上限。
4. Compiler 在 Token、规范请求字节及 HTTP 字节三个约束中预留视图/说明增长；收据保存同一
   证明。会话水位和省略轮次另留两个 64 位计数的 38 字节余量。
5. Runtime 以实际 v5 请求作反馈模板，保留完整视图增长、说明增长、每个调用反馈和可读来源
   的因果闭包。容量不足时在工具执行前拒绝，不等工具完成后再裁反馈。

当前 BPE 计量是实际值，但 v5 的未来反馈容量采用整个规范请求每字节最多一个 Token 的
充分上界，不沿用 v3/v4 的固定前缀优化。HTTP 容量用固定传输包络加两倍规范 JSON 字节
证明，覆盖控制字符、反斜杠、多语言和等长替换时转义比例变化。只计算当前/未来长度差并不安全。

因此本版反馈准入可能比旧格式更保守。它优先保持证明正确，没有宣称已经实现 ADR 0062 中
更精细的稳定定义 BPE 前缀证明。未来优化必须继续覆盖任意后缀分词边界和布局变化。

## 发送前核对的边界

请求自身的摘要只能证明内部一致，不能证明内容来自已接受状态。因此保存快照时还必须核对
来源 Work、运行、完整 SemanticVersion、观察摘要、账本摘要和语义头的工具视图摘要。
该工具摘要绑定业务语义头，实际执行视图仍由 Runtime 加入通用读取工具并独立执行权限检查。

语义头已更新、来源被伪造、快照写入失败或编译收据不匹配时，模型传输不能开始。取消沿用
既有事务结算边界；steering 不宣称撤回已经发送的请求，但旧版本的回答会被丢弃，新轮次重建
来源与布局。没有把投影摘要升级成事实证据或执行许可。

## 如何启用与观察

```python
from weavria.harness import TaskModelViewProjector

engine = SessionEngine(
    path,
    model=provider,
    tools=tools,
    task_preparation=preparer,
    context_compiler=compiler_config,
    token_counter=counter,
    task_model_projector=TaskModelViewProjector(),
```

不要求 TaskFrame。
