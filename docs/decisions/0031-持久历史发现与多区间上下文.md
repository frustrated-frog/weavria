# 0031 持久历史发现与多区间上下文

## 状态与问题

已实现，2026-10-23，基线 `cf870cb`。本切片解决最近 64 次交互之外的历史发现，以及同一文本字段中分散事实的精确交付。沿用 ADR 0030 的当前 Run 证据访问闭包；主动恢复动作与重新准入留在下一阶段。

## 机制决策

索引覆盖已结束交互的用户文本、助手文本与追加要求，候选保留原交互的工具成果目录。历史成果正文继续通过现有受限 Session 工具读取，不伪造当前 Run 工具结果。本阶段不索引 Artifact 正文，也不生成摘要。

在 SQLite 中维护可重建的倒排索引。原文接受时仅事务登记来源目录和最终交互摘要，不在执行提交锁内进行全文索引。查询前按工作额度增量补建，单交互的片段、词项和水位原子提交。索引落后、工作额度耗尽与真正未命中分别报告。历史只搜索同 Session、当前 Run 之前、接受位置不晚于查询截止位置的来源。

沿用 Unicode 规范化、英文词和中文双字词项，以片段为检索单位计算 BM25，按需求聚合到交互，保留有界近期候选与检索候选。精确证据锚点通过已接受成果身份定位生产交互，不以模型提供的 ID 授权。原文仅加载最终有限候选；加载时核对来源目录摘要。查询和索引支持工作额度、超时与协作式取消，停止后清理 SQLite 回调并等待所属线程结束。

多区间表示新增独立版本，记录完整原文摘要、总字符数、有序且互不重叠的原始字符区间。每个片段必须来自当前原文。先在来源内部按边际覆盖生成少量不同粒度的组合，再在来源之间执行既有联合分配；区间重叠合并、来源元数据共享，最终完整请求仍复核 BPE 和字节预算。不声称全局最优或语义理解。

新能力显式配置，旧历史选择、单区间表示和旧序列化保持可用。检索报告与实际模型请求、编译报告一起提交，绑定任务修订、查询摘要、索引版本、水位、候选来源及命中位置。报告不把“检索到”当成“已交付”或“任务已满足”。

## 取舍与不变量

- 扩大历史窗口仍会加载全部候选正文；倒排召回将搜索范围与编译规模分离。
- 本阶段采用 SQLite 普通倒排表，复用项目的中文词项与精确字符地址，避免依赖 FTS 默认分词和可选扩展；BM25 参数与策略版本冻结，可替换但不引入空 Provider 层。
- 索引是派生数据，损坏或版本变化可以显式清空重建；不得更改权威事件和原文。
- 必要近期反馈与当前 Run 依赖闭包仍由编译器保护。检索不得扩大已准入工具批次的读取集合。
- 任务修订后重新检索和选择，不能提交旧修订计划；不可变索引可以复用。
- 首次大历史补建可以分多次完成；范围不完整必须可观测，不能冒充全历史未命中。
- 未实现跨 Session 记忆、语义向量检索、模型恢复动作、生成式压缩或自动执行恢复。

## 验证与结果

验证跨 64 次交互的真实 Session 生命周期、分散原文区间、中文检索、重启和增量补建、索引重建、Session/时间隔离、篡改拒绝、取消和事务回滚。冻结任务与原文标签，比较近期窗口、历史召回配单区间、历史召回配多区间，分别报告召回、交付、来源正确性和成本。合成/Fake 结果只验证机制，不宣称真实模型任务收益。


Schema v6 增加目录、来源、片段、倒排、水位与前缀统计；报告/编译策略 v3 增加检索证据，文本表示 v3 采用精确多区间，旧外层协议与既有文本表示保持兼容。前缀语料统计随整份交互事务更新；迁移一次聚合终态位置；倒排表另建片段索引以支持高效重建清理。

冻结实验共七个场景、三组策略：近期窗口、检索单区间、检索多区间分别交付 1/11、5/11、9/11 个目标短语；所有区间符合原文及请求预算。词面不匹配场景三组均失败，重复片段场景多区间没有交付收益且增加成本。这些结果不能推导真实模型任务成功率。数据摘要、参数、成本、调用流程与当前局限见 [实现说明](../持久历史发现与多区间上下文.md)。
