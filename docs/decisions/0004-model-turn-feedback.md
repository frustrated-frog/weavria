# ADR 0004：模型轮次与完整反馈汇合

- 状态：已采用，第一阶段
- 日期：2026-10-11
- 范围：决策、只读工具调度、反馈与任务修订
- 前置：[ADR 0003](0003-execution-backed-context.md)
- 后续协议修复：[ADR 0005](0005-timeout-feedback-outcome.md)，明确 v2 请求与成果报告；本 ADR 的日志规则继续适用。

## 问题

原先 `ModelResponse.action` 一次只能提出一个调用，`ToolRecorded` 接受后立即进入下一次模型决策。模型无法同时提出独立的资料读取；简单加入 `gather` 又会留下四个问题：调用预算只够部分批次时执行哪一部分、失败是否抹掉兄弟结果、完成顺序是否改变下一轮输入、任务更新后哪些调用仍会开始。原先上下文只强制保留最后一个调用，直接用于批量决策还会隐藏其他兄弟的失败反馈。

这些问题必须由同一个执行协议解决，不能分别隐藏在 Provider、工具后端和 Prompt 中。

## 决策

### 一轮决策是一个可验证单元

新增 `ModelTurn.decision = ToolBatch | FinishAction` 与 `TurnModelProvider.generate_turn`。批次最多 32 个调用，非空、标识唯一；一个决策不能同时调用与结束。声明多个调用并不授权并行执行。Provider 能力必须显式声明，框架重新验证返回值，包括用 `model_construct` 构造的实例。

批次输入相互独立。工具收到的是本轮开始前已接受的 Artifact 视图；同轮兄弟即使已经写入 Store，也不能通过 `ToolContext` 读取。依赖某个新结果的工作应在下一轮提出。工具代码本身仍是可信插件，这个能力边界不等于进程沙箱。

### 分开发生顺序与反馈顺序

`TurnDecided` 接受整轮；每个 `ToolStarted`、`ToolRecorded` 单独接受。结果完成即可入账，发生顺序保留在日志中。只有所有调用都有结果或 `CallSkipped` 事实，才允许 `TurnSettled` 进入 `READY`。状态中的本轮结果此时按调用提出顺序排列，下一次模型输入不受谁先完成影响。

普通工具错误是对应调用的安全反馈，保留成功兄弟。框架身份错误终止运行，并取消、等待未完成子任务；已经接受的结果保留。取消没有伪造的失败 Observation，未完整汇合的轮次没有 `TurnSettled`。

### 并发由宿主明确启用

`ToolScheduling` 默认串行。只有宿主声明可并行的只读、可安全重复读取工具，才进入有界调度。不能根据 `read_only` 自动推断后端线程或并发安全。调度器把相邻可并行调用组成组，非启用调用成为独占屏障；组内按提出顺序派发，槽位释放就补充调用。

一个 TaskGroup 拥有本轮所有子任务；只创建有可用槽位的任务，不先创建整个批次再用 Semaphore 阻塞。子任务自行取消也会传播为 Run 取消。调用预算在派发前按整批准入，不因剩余预算不足执行任意前缀。运行 Deadline 包括等候、模型、工具和存储；工具自身超时可以形成可纠正反馈。

### 修订使尚未开始的决策失效

模型等待期间修订任务：合法的旧响应被丢弃。工具执行期间修订任务：已开始的只读调用完成并记录其事实，未开始的调用记录 `CallSkipped(task_changed)`，不再派发。下一次模型请求同时包含当前 Task、整轮反馈以及反馈所对应的旧任务版本。被跳过的调用标识仍已被占用，不能在以后重复使用。

这是只读语义，不定义写操作撤销、提交或补偿。

### 反馈是上下文选择的约束

`feedback_call_ids` 从已接受执行事实产生，强制保留整轮所有已执行调用的最小反馈和其依赖闭包，包括失败。先给每个反馈最低限度的可用视图，再使用原有选择策略分配余下预算。装不下整轮最小反馈时明确耗尽 Context Budget，不静默删掉某个失败兄弟。

`TurnFeedback` 仅提供调用状态与任务版本；具体安全错误、内容及来源仍通过配对历史提供。它不包含模型私有推理。预算继续采用规范化请求 UTF-8 字节，包含工具目录和状态摘要；不宣称等于 Provider Token。

## 版本与兼容

- `AgentRun` / `ModelProvider` / `ModelResponse` / `ExecutionEvent` v1 保持原单动作语义。
- `AgentLoop` 使用 `LoopEvent` v2，包含轮次决策、跳过与汇合事实；`ModelDecided` 不属于 v2。
- 两个入口共享内核、模型边界、工具执行器、上下文构建和归约规则，避免维护两套不同的取消及预算实现。
- `decode_event` 能读取两个版本，归约器拒绝同一个 Run 混用版本。读取旧日志不会把它改写成批次。
- 新的轮次类型从自己的 Schema v1 开始；v2 指日志信封语义，既有含义未变的嵌套事实仍为 v1。
- RunState 是内存投影，从日志重建；没有提供可独立持久化、恢复执行的 RunState Schema。

将来若迁移 v1 日志，应按每个已接受单动作构造一调用轮次，只在对应真实 `ToolRecorded` 后增加汇合事实；终态前未结束的调用不能补造结果。还需要保留旧序号映射、原日志和迁移版本。当前没有实现该迁移，也没有 Checkpoint/Resume。

`ModelRequest` 仍是重建的配对证据视图，并非原始供应商对话。原始批次事实保留在日志；接入需要原生多调用消息的供应商时，必须另行定义历史组装契约，不得把平铺视图宣称为无损原生 transcript。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 每个工具调用后重新询问模型 | 容易理解，但模型不能提出一个批次，增加模型往返；继续支持为兼容入口 |
| 任意批次直接 gather | 缺少有界准入、独占屏障、任务修订和生命周期协议；拒绝 |
| 首个结果返回就开始下一次模型决策 | 可能隐藏较慢错误，重叠决策也使状态及预算更复杂；当前采用整轮汇合 |
| 整个批次原子接受结果 | 运行中框架失败可能丢掉已完成兄弟；采用逐条入账、汇合后投影 |
| 一个独占工具让整批全部串行 | 更保守；这里允许独占调用前后两个独立组并行，仍不跨越屏障 |
| 引入调用依赖 DAG 和结果占位符 | 扩展了模型行动语言，校验、恢复和调度复杂度更大；依赖新结果时使用下一轮 |

## 证据与后果

[AgentLoop 文档](../agent-loop.md) 记录固定版本的 Pi、smolagents、LangGraph 源码证据及工程取舍；Weavria 没有依赖这些 Runtime。

确定性并发、失败与回放测试验证协议；冻结文件任务对比串行/并发，依据实际反馈发现资料与修正路径，验证来源、调用成本与运行清理。它证明完整反馈在本机制中的可用性，以及并发调度的行为；固定解释器不具备通用规划能力，不能证明真实 LLM 纠错收益或已经达到成熟框架水准。

后续研究应首先接入一个真实 Turn Provider，冻结领域无关的多资料任务与故障条件，对齐模型、预算和评测器，测量纠错成功、额外调用、来源正确率与延迟。进一步的任务组织、完成验证、重试和恢复应依据这些失败轨迹选择，而不是现在增加一组空接口。
