# 0042 完整记忆组召回与上下文交付

状态：已实现；执行契约和有界消费试验分别验证。

## 问题与决策

记忆内核已经提供带作用域、双时间和来源的逐条 BM25 召回，但单条 top-k 可以保留一般规则而丢掉例外；Context 的标量片段选择还可能拆开值、条件和来源。本切片让记忆真正进入下一次 Session 模型决策，并以完整组承担这项完整性责任。

1. 新增 `recall_groups`，保留原 `recall` 行为。先在一个 SQLite 读事务内按宿主精确授权和两个时间轴过滤，再按 `(scope, kind, subject, predicate)` 分组。组包含全部条件变体和 contested 成员；至少一条词面命中即选入候选组，组分数取成员最大 BM25，避免重复事实靠数量抬高排名。有效期不同但在查询时不生效的事实不进入组，不把历史版本冒充当前冲突。
2. 分组发生在 top-k 和响应字节预算之前。limit 表示组数；一个组及其全部来源装不下就整组省略，分别报告数量限制和字节限制。候选集合超过扫描上限则失败，不能在截断集合上声称组完整。组键采用精确规范化字段，不推断实体别名或任意谓词等价；这是当前形成机制下的边界。
3. Harness 提供 `MemoryContextSource`，显式绑定宿主 access、scope 与有效时间策略。Session 的通用 `ContextSource` 端口接收当前任务与需求，返回不可拆 `ContextBundle` 及内容无关的召回报告。Core 仅定义数据传输契约；Memory 不导入 Core、Context、Session，Session 不导入 Harness 或 Memory。没有自动扩大授权或从模型参数选择 scope。
4. Context 将每个 bundle 作为只有原文一种表示的候选，与历史和工具结果共享实际序列化字节及 Token 预算。评分从内容计算，不能接受宿主预标正确答案。组可以整体省略，不能摘要、切片或隐去冲突。来源和有效时间仍随原文发送；选择记录包含 digest 和 raw/omitted 决定。完整组只保证精确键内的交付完整性，不保证模型正确应用规则。
5. Session 每次决策按最新任务重新召回。一次编译内部冻结同一个召回结果，预算降级重编译也不重新读取。通过已有请求与编译记录事务先持久化再调用模型；任务修订、取消、超时沿用 Runtime 所有权。Memory 读事务可与 Session 记录事务分离：请求携带其读取时的版本快照，不宣称发送瞬间与并发写入线性一致。
6. 新增 SessionRequest v6，承载低信任 bundles；没有供给端口时继续输出完全相同的 v5 字节。新增 ContextCompilation v7 记录来源供给报告，旧版字节保持不变。Run 配置使用 v5 记录供给器版本；不迁移数据库 DDL，不修改已有事件。旧程序无法读取新版本，需升级。来源端口将依赖错误归一化为 `ContextSourceError`，新增 `CONTEXT_SOURCE_FAILURE` 错误类别；授权拒绝和容量超限保留各自的策略拒绝/预算耗尽终态。

## 替代方案与取舍

- 直接把召回文本拼入系统指令：会提升记忆权威性，且绕过联合预算与审计，拒绝。
- 通过普通检索工具返回：可以复用工具通路，但当前通路允许标量摘录，且依赖模型先发起召回。先完成每次决策的显式可选来源端口；主动回取超大组留待下一步。
- 同义词或模型生成分组：存在漏掉不命中例外、授权误并与额外非确定性，本轮使用可验证精确键。实体/谓词表示漂移仍是召回缺口，不能用扩大组的定义掩盖。
- 全库装入：随着记忆增长迅速超过预算；本轮采用有界扫描、词面排名、完整组打包和联合选择，不引入向量数据库。

## 验证与局限

确定性测试覆盖低分/零分例外、争议组、双时间、授权、整组预算省略、容量失败、旧协议字节、取消、编译及持久化前失败、任务修订、重新打开会话。真实模型实验分无记忆、逐条 top-k、完整组，冻结任务及预算，单独统计形成与召回质量；人工构造记忆只验证消费链，不能冒充端到端自然形成收益。生产默认仍不开启，宿主必须配置明确授权的来源。
