# 0142 扩展能力绑定与材料裁决回放

2026-11-20，已采纳。

## 装配决定什么

宿主可能从多个包安装扩展。例如，同一个文档贡献者能接入保留全部段落或者去重的策略。两个包的发现顺序可能随宿主变化。如果最后注册者覆盖前者，同一个会话重启后，模型看到的原文就可能改变。另一种难以排查的情况是，某段原文同时受扩展策略和上下文预算约束，仅检查最终请求无法判断哪个环节移除了它。

宿主可以向 `HarnessExtensions` 的默认配置或某个会话传入 `ExtensionAssembly(plugins, select={"paragraphs": "unique"})`。注册表接受主机安装的插件实例。每个能力名称在该会话装配中绑定一个实现。首个支持的能力协议是只读材料选择，能处理任意扩展的结构化上下文材料。插件声明 `provides_selector` 提供选择器，生产者声明 `uses_selector` 使用选择器。每个生产者最多使用一个选择器。所有注册扩展仍按 Run 挂载，只有当某个生产者使用相应能力时，内核才会调用被选中的策略函数。[声明与解析](../../src/weavria/sessions/extension_plan.py)

解析在注册时完成。只有一个候选时自动绑定。有多个候选时，宿主必须在这份装配的 `select` 中指定名称。缺失实现、无消费者的选择、错误实现名称、重复插件身份和依赖环都会报错。缺省选择不偏向原始注册次序。解析器把已选提供者和显式 `requires` 一起作为前置依赖，在每一批已就绪的节点内按名称排序，再释放下一批。至多 32 个扩展。运行时用解析结果挂载和执行，恢复时使用同一份结果比对身份。显式传入有序元组继续沿用 0141 的语义。空会话装配仍能覆盖默认配置。

## 一次请求的裁决

| 贡献 | 决策者 | 执行结果 |
| --- | --- | --- |
| 每个生产者返回的材料集合 | 宿主收集器 | 立即校验和快照，给编号加上生产者名称，同名本地编号可以来自不同生产者 |
| 读取候选材料的总容量 | 宿主编译配置及各插件的 `source_byte_limit` | 取所有上限中的最小值。按带命名空间的序列化候选计字节，被策略筛掉的内容也消耗容量 |
| 本次准入的材料 | 宿主绑定的选择器 | 接收查询和同一生产者的完整候选副本，返回允许通过的编号子集。空元组表示全部筛掉 |
| 最终交付的材料 | 现有上下文编译器 | 所有准入材料合并后与其他来源一起竞争实际请求预算。保留生产者内原始顺序，选择器无法替换正文、冒认来源或强制交付 |
| 终态观察 | 挂载的观察器 | 共用既有通知期限，按解析顺序广播已提交的装配和计数。已完成输入去重时直接返回已有结果 |

比起让任意插件拦截并重写请求，返回编号子集保留了候选到最终请求之间的来源链。策略可以根据整组材料去重或计算相关性，返回的顺序不表示优先级。调用前，宿主把策略获得的内容与待交付快照分开。策略返回重复或不存在的编号、返回类型错误、取材或策略抛错都会阻止当前模型调用。材料容量耗尽沿用预算耗尽终态。外层取消传给当前策略，已挂载的资源按逆序退出。[执行路径](../../src/weavria/sessions/extensions.py)

## 如何从归档解释一次选择

Run 配置 v8 冻结扩展声明、顺序、候选提供者、所选实现、选择理由和材料上限。只有实际执行过选择器的请求使用编译报告 v19。报告记录每个生产者的输入编号、快照散列、策略准入结果和编译器最终表示。即使候选为零或全部被筛掉，也会记录实际调用。预算回退与内部试编译复用同一批材料及裁决。SQLite 在准备模型请求的事务内比对 Run 绑定、材料顺序、准入材料散列和实际请求。较早的描述与编译报告保留各自的序列化格式。[编译报告](../../src/weavria/core/context.py) · [归档与核对](../../src/weavria/sessions/store.py)

重新打开 SQLite 后调用 `store.explain_extension_request(session_id, run_id, model_call)`，序号从 1 起算。`plan.bindings` 给出能力的选择理由。`selections` 给出策略筛选。`choices` 给出交给编译器的候选及最终去留。`request_sha256` 可与传给模型适配器的请求对照。旧的有序装配可以读取当时的扩展和编译选择，能力绑定为空。缺少已提交的对应编译记录时返回 `KeyError`。归档针对准备好的请求，提供方接收后的行为由相应运行事件说明。

## 验收与边界

运行 `uv run python -m examples.extension_composition`。示例从仓库恢复协议 ADR 取出提到 SessionEngine 的段落，同时登记原件和镜像。固定查询、模型替身、计量器和预算，通过正式 Harness 发出请求，再关闭 Harness，从 SQLite 读取结果。[可复现实验](../../examples/extension_composition.py)

| 宿主选定的实现 | 策略准入 | 编译器实际交付 | 本次输入 token |
| --- | --- | --- | ---: |
| `all` | 原件、镜像 | 镜像 | 1,223 |
| `unique` | 原件 | 原件 | 1,223 |

这组资料的两份正文相同，编译器本来就只选择一份。提前去重改变了交付来源，本次 token 用量持平。该结果用于验证组合能改变真实请求并且可回放。回答质量需要独立的任务集与模型对照。

回归覆盖注册全排列、歧义与环、按会话选择、同时广播、来源快照隔离、空候选、全部被拒、策略异常和取消。真实子进程在一次工具结算后退出。换策略恢复会被拒绝，换回原策略并反转注册顺序则能接续，同一工具只执行一次。此处的里程碑以这三类证据为结束条件，即等价装配一致、冲突前置暴露、逐次请求可由归档解释。[装配与请求验收](../../tests/harness/test_extensions.py) · [进程恢复验收](../../tests/sessions/test_crash.py)
