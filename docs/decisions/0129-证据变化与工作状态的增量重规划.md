# 证据变化与工作状态的增量重规划

日期：2026-11-16。状态：机制已实现；真实模型收益未成立，随 work_recheck 显式启用。

## 问题和取舍

ADR 0112、0122 已实现笔记版本依赖和证据重验，但 Ledger 变化不会自动改变工作图。由模型主动改写根笔记才能触发后继失效，可能遗漏过期结论。本步复用 WorkingState、NeedLedger、Session 事务和现有模型视图，不建立第二套计划状态机。

启用既有 work_recheck 时，新工作状态使用 v4。宿主按每条笔记明确关联的 need_ids 计算规范化证据摘要，包含需求状态、缺失字段和有效绑定内容，不包含全局账本版本、工具失败次数等无关变化。每轮先将新 Ledger 与旧工作状态同步，再归约本轮工作提案；摘要变化令根节点失效并推进工作 CAS，随后沿现有结论图传播。当前仍采用保守语义：关联需求新增支持材料也需要重验，不擅自推断新旧证据等价。

首轮真实执行发现模型经常省略 need_ids。因此接受提案时，宿主通过来源 Run/Call/Artifact/摘要与字段范围匹配补充材料依赖，保留模型显式关联；不推断文字蕴含，超过原有四需求上限则拒绝提案。这一调整保留了首轮失败记录，并在新冻结版本下从头对照。

失效是锁存的，A→B→A 不自动复活；重复同步相同输入不重复推进版本。根结论重验成功即使文字不变，也获得新版本，后继不能跟随根恢复。独立分支的内容和版本保留。用户修订仍经 revise_work 的需求闭包退休，再将幸存笔记同步到新证据。旧 v1/v2/v3 按原契约读取；活跃 Run 的策略版本变化仍由现有恢复准入检查控制。

## 原文、重验和原子接受

失效根参与现有有界重验，模型须引用候选提供的原文；归约器另检查仍保留为结果的根是否引用当前 Ledger 的支持证据、关联需求是否完整。该结构检查不证明模型结论正确。撤回仍需要既有模型重验收据，但不要求不存在的正向证据。改变或删掉 need_ids 不能绕过原根的当前证据检查。

本批工具新增证据与旧工作提案冲突时，证据先引起 CAS 更新，旧提案不能提交。归约无外部副作用，取消/失败不发布部分状态；已有成功工具结果继续保留。状态、工具视图、上下文焦点和完成门禁在同一语义提交中接受。来源引用不增加 Artifact 权限，失效摘要不包含原文。

## 验证和边界

验证根与链式失效、独立分支、ABA、无变化同步、同批旧提案、重验后版本推进、当前来源准入、旧快照与压缩投影、取消和恢复。用同一执行任务比较不连接证据与连接证据的行为，独立验收最终答案和保留工作量；Fake 仅证明状态承诺，真实模型另报告收益与失败。

本步不检测外界未被观察到的变化，不推断没有原文引用支撑的需求关系或遗漏的 depends_on，不把任意新 Artifact 当作旧来源替代，也不承诺语义重验无误。能力发现继续由原有选择器执行，失效恢复的是探索优先级与局部任务组织，不预编排正确工具。

源码资料的最终 12 次对照中，关闭审查正确完成 3/6，开启组合机制 2/6；只有一次开启运行观察到 Ledger 驱动失效，未修复成功。执行机制通过确定性会话验证，但不能据此宣称改善真实长任务能力。详情和短材料诊断见[证据驱动的工作失效与局部重规划](../证据驱动的工作失效与局部重规划.md)。
