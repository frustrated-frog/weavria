# ADR 0027：基于执行反馈的贝叶斯行动价值控制

- 状态：已采纳并实现
- 日期：2026-10-22
- 范围：AgentLoop v3、主动行动干预、事件归约、确定性评测
- 前置：[ADR 0026](0026-进度驱动的主动行动干预.md)

## 背景

ADR 0026 已经让 `blocked / stop` 真正阻止副作用，但对 `continue`、`repair` 和 `replan`
仍一律放行。ADR 0024 的固定行动族阈值能限制同一语义前沿上的参数逃逸，却不能区分以下轨迹：

- 同一工具族在连续前沿上稳定产生实质进展，值得继续使用；
- 调用参数不断变化，但同一控制目标下长期没有义务、覆盖或独立来源收益；
- 工具偶尔产生进展，却需要很宽的批次，单位调用收益过低；
- 工具产生正向结果的同时频繁引入覆盖丢失、义务重开或矛盾。

把“预期收益”交给模型自报不能解决这个问题：该值既不可校准，也可能通过改写措辞逃逸。另一种
简单方案是把五类进度信号压成固定加权分数，但当前没有足够真实任务数据证明通用权重。

本轮目标是在不引入学习式 Critic 或跨任务记忆的前提下，让 Runtime 从已经接受的执行结果中形成
可重放的行动价值统计，并在副作用前给出成本敏感、带不确定性的主动控制。

## 决策

### 1. 价值单元是“控制目标 × 行动族多重集”

每个被检查的 `ToolBatch` 生成 `ActionValueContext`。它绑定：

- 当前 `task_revision`；
- 上一个 `ProgressAssessment` 建议的控制目标：`verify / continue / repair / replan / stop`，
  首轮使用 `initial`；
- 批次中每个调用经 Tool Registry 规范化后得到的 `action_family_sha256`，按摘要排序并保留重复数；
- 原始候选批次摘要和由上述语义字段计算的 `value_key_sha256`。

参数不进入价值键，因此同一版本工具的不同参数可以共享结果统计；工具版本、批次组成、批次宽度
和控制目标变化都会产生不同价值键。`call_id` 仍只负责一次执行关联，不参与语义价值。

这一设计选择批次而不是单个并行调用作为归因单位。当前 `ProgressAssessment` 只对完整结算回合
负责，不能可靠地把一次批次级覆盖增量分摊给并行兄弟调用。按完整行动族多重集归因不会制造虚假的
单调用因果关系，代价是相近但不同的批次暂时不能共享全部样本。

### 2. 结果统计由事件归约产生，不保存在策略私有内存

`BatchAdmitted` 持久绑定已经检查过的 `ActionValueContext`。完整批次结算并接受
`ProgressAssessed` 后，纯 Reducer 根据评估质量更新 `ActionValueProfile`：

- `positive`：有实质进展且没有回归；
- `neutral`：没有实质进展也没有回归；
- `regressed`：只有回归；
- `mixed`：同时存在实质进展和回归。

Profile 同时累计成功、失败、跳过调用数，以及义务完成、覆盖增加和独立来源增加量。四类结果互斥
且必须完整覆盖观察次数；调用状态也必须完整覆盖提议调用数。

`RunStarted.action_value_ledger_version` 固定归约算法版本。`TaskRevised` 清空 Profile，避免旧任务
目标污染新修订。Profile 是 Journal 重放的确定性投影，而不是某个 Python Policy 实例里的易失
计数，因此崩溃后重放会得到相同控制输入。

### 3. 分别估计进展概率与回归概率

默认 `progress-action-intervention/2` 使用两个 Beta 后验：

```text
进展后验：Beta(1 + 正向 + 混合, 1 + 中性 + 回归)
回归后验：Beta(1 + 回归 + 混合, 3 + 正向 + 中性)
```

回归先验 `Beta(1, 3)` 表达冷启动时“回归较少但并非不可能”的弱先验。策略计算后验均值与标准差，
使用版本化的 `均值 ± uncertainty_scale × 标准差` 并截断到 `[0, 1]`。这是确定性的后验矩区间，
不是精确 Beta 分位数；事件中保存实际使用的上下界，不能把它表述成未经证明的置信水平。

成本通过候选批次宽度进入决策：

```text
单位调用期望进展 = 进展后验均值 / 候选调用数
```

默认决策顺序为：

1. `blocked / stop` 立即要求重新决策；
2. `verify` 仍是建议，不让价值统计替代 Completion Policy；
3. 少于 3 次同键观察时保留冷启动探索；
4. 回归后验下界大于 `0.35` 时，以 `action_value_regression_risk` 拒绝；
5. 单位调用期望进展小于 `0.25` 时，以 `action_value_low_yield` 拒绝；
6. 其余候选以 `action_value_supported` 放行。

观察数、收益阈值、回归阈值和不确定性尺度都写入 Policy 版本。当前默认值是冻结实验基线，不声称
已经对开放任务分布完成统计校准。

### 4. 每次判断绑定完整价值状态

`ActionInterventionChecked` 新增候选 `ActionValueContext` 与完整 Profile 集合摘要。Reducer 在接受
事件时重新计算当前投影摘要，并验证：

- 候选绑定当前 Task Revision 和完整 ToolBatch；
- 控制目标与当前 Progress 推荐一致；
- Policy 看到的 Profile 摘要等于 Journal 当前投影；
- `BatchAdmitted` 没有把检查后的价值上下文替换成另一份；
- `ProgressAssessment.cost.proposed_calls` 与完整回执数一致。

策略返回的 `ActionValueEstimate` 持久保存后验均值、上下界、单位调用期望进展和生效阈值。
模型可见的 `InterventionNotice` 只投影价值键、观察数、单位调用期望进展和回归下界，并继续受
1KB 控制通道约束。

### 5. 价值策略不能改写动作

本轮仍遵守 ADR 0026 的干预边界：Policy 只能 `allow` 或 `reconsider`，不能静默删除调用、改参数或
替换工具。重新规划必须回到新的模型决策边界，新的 ToolBatch 仍需经过主动干预、普通准入、Tool
Policy 和预算校验。

## 执行不变量

1. 未结算或未评估的回合不能更新 Action Value Profile。
2. Profile 的归因单位必须与被准入的完整行动族多重集一致，不能把批次结果伪装成单调用因果收益。
3. Policy 判断绑定当时完整 Profile 摘要；过时或伪造的摘要不能进入准入。
4. 同一候选在主动干预和普通准入之间若规范化身份变化，Runtime 失败关闭。
5. Task Revision 改变后，旧 Profile、旧候选和旧评估都不能控制新任务。
6. 冷启动允许探索不代表授权；Tool Policy、能力视图、反馈预算和 Tool Budget 仍独立生效。
7. `mixed` 同时增加进展样本与回归样本，不能只保留对策略有利的一侧。
8. 后验矩区间只是当前版本的可解释决策量，不能冒充精确置信区间或真实任务成功概率。
9. 价值拒绝不自动完成或失败任务；模型仍可提出新的行动族或如实收束，重复忽略拒绝才进入已有
   的有界 `intervention_exhausted` 终态。

## 考虑过的替代方案

### 让模型在 ToolBatch 中声明预期收益

自报值缺少执行校准，而且模型可以通过更换目标描述制造新桶。后续可以增加类型化 Action
Hypothesis 来改善义务级归因，但它只能作为待验证假设，不能取代执行结果；本轮不采用。

### 给五类 Progress Signal 配置固定线性权重

不同任务中义务完成、独立来源、回归和调用成本不可直接用同一手工权重比较。当前只把
`material_progress` 与回归建成两个分离后验，并显式按调用数归一化；真实数据充分后再研究效用模型。

### 按单个工具族平分并行批次收益

会把一个兄弟调用产生的覆盖增量错误归因给所有调用，形成自我强化偏差；拒绝。当前使用完整行动族
多重集，未来若有调用级 Provenance 才做更细信用分配。

### 只使用固定次数阈值

无法区分连续有收益和连续无收益的行动族，也不理解宽批次成本。ADR 0024 的阈值继续作为同一语义
前沿上的执行保险，但不再承担行动价值估计职责。

### 立即引入学习式 Critic 或强化学习

当前缺少足够真实、冻结且可复现的轨迹数据。直接引入模型评分会增加成本和新的非确定性，也无法先
证明状态归因正确；推迟。

## 验证与证据强度

确定性测试覆盖：

- Profile 对四类质量和完整调用成本进行可重放归约；
- 三次中性结果后，第四个同目标、同族候选在 `ToolStarted` 前被拒绝；
- 三次正向结果继续放行，三次回归结果触发独立的风险拒绝；
- 相同收益历史下，一调用候选放行，三调用候选因单位调用期望收益过低被拒绝；
- 篡改 Action Value 状态摘要、候选范围或准入上下文时 Reducer 拒绝事件；
- 旧 v3 Journal 在缺少 Ledger 版本和价值上下文时仍按原协议重放；
- 任务修订、取消、Policy 超时和已有 blocked/stop 干预语义保持不变。

冻结评测 `evaluate_action_value_policy` 包含冷启动、持续中性、持续正向、持续回归和不同批次成本共
7 条轨迹。新策略为 7/7，ADR 0026 的 hard-stop-only v1 基线为 4/7；新策略阻止 5 个被标注为
低价值或高风险的候选调用，误干预为 0。

该实验验证算法区分、成本归一化和实际派发变化，不证明默认先验及阈值能提高开放任务成功率。
本轮没有调用付费模型，结果不能替代真实模型、真实工具延迟和真实任务完成率实验。

## 当前局限与下一步

- Profile 当前只在一个 Run、一个 Task Revision 内生效，没有跨任务层次先验或长期 Memory 写入。
- 价值键按完整批次组成分桶，相近批次之间没有部分共享；这避免错误归因，但样本效率较低。
- `material_progress` 是多种正向信号的并集，尚未表达某个候选究竟针对哪项开放义务。
- 单位成本目前只有调用数；Provider Token、端到端延迟、货币成本和副作用风险尚未进入估计。
- 后验矩区间不是精确分位数，默认先验和阈值尚未通过真实任务校准。
- ADR 0024 的同前沿固定阈值仍可能比价值策略更早阻止探索；两者目前是保险与价值估计的并行机制，
  后续应通过真实轨迹决定是否让自适应策略接管部分固定阈值职责。

下一步应增加“候选行动针对哪些义务、预期改变哪类信号”的类型化 Action Hypothesis，并用实际
Evidence Provenance 校验假设，从完整批次归因推进到义务级、调用级信用分配。随后在冻结的多来源
研究、文件修复和 API 故障任务上记录 Token、延迟、完成率与误拒绝，校准先验和阈值；在这些数据
成立前，不引入学习式 Critic 或跨任务自主策略更新。
