# ADR 0010：有界恢复不完整 JSON 信封

- 状态：已采纳并实现
- 日期：2026-10-16
- 范围：OpenAI-compatible 模型适配器

## 背景

真实模型即使启用 JSON 模式，也可能返回内容和字段都完整、但缺少最外层闭合符的响应。
这种响应无法进入类型化模型边界，因此任务理解和执行都会被归类为模型供应商失败。直接
接受宽松 JSON、删除非法字符或在适配器内部再次调用模型，会分别削弱契约、引入不可解释
改写，或绕过 Runtime 的调用预算。

## 决策

OpenAI-compatible 适配器在去除完整 Markdown 代码围栏后，对 JSON 文本执行一次确定性的
定界符扫描。仅当满足以下全部条件时，才在尾部补齐闭合符：

- 内容从 `{` 或 `[` 开始；
- 已出现的 `{`、`[`、`}`、`]` 严格嵌套且没有错配；
- 字符串与转义状态完整闭合；
- 只需追加不超过 8 个 `}` 或 `]`。

恢复只添加由栈唯一确定的结构后缀，不删除、不替换、不猜测字段值。恢复后的值仍必须通过
标准 JSON 解码以及完整的 `ModelResponse` 或 `ModelTurn` Schema 校验。发生恢复时只记录补齐
数量，不记录模型内容。

## 备选方案

- **一律拒绝**：边界最严格，但真实模型中一个可机械判定的末尾遗漏会使整轮任务失败。
- **适配器自动重试模型**：可能修复更多情况，但隐藏额外模型调用，破坏预算和可观测性。
- **通用宽松 JSON 解析器**：会接受注释、尾逗号等更大输入集合，信任边界过宽。
- **业务层特殊处理**：无法覆盖任务理解和其他应用，也会把供应商协议问题泄漏到领域层。

## 后果与限制

该恢复不消耗新的模型调用，延迟与成本可预测，并同时作用于单动作和 Session 协议。它只
解决结构后缀缺失：错配括号、未闭合字符串、截断字段值、非法 Schema 和语义错误仍明确
失败。当前恢复事实进入进程日志，尚未拥有独立的结构化 Trace 事件；当模型尝试级 Trace
契约扩展时，应把恢复计数纳入供应商归一化元数据。
