# 带引用的阶段工作摘要

本阶段把长任务中已经接受的工作笔记作为摘要输入。工作笔记由模型在执行中通过 `propose_work` 提出，涵盖计划、假设、阶段结论、已排除尝试和待验证问题。独立的生成式摘要可以进一步提炼多轮分析，但需要额外推理和语义保真评测。当前先交付可复现的结构化基线。

使用推荐 Harness 配置，启用 `working_records`，在上下文配置中打开 `work_summary_compaction`。任务视图投影器从已提交的 `WorkingState` 构建模型可见摘要。原工作表示达到 512 UTF-8 字节且压缩能节省至少 64 字节时，交付 v2 工作视图。摘要保留笔记正文、类型、关联需求、下一步以及原文指针，并将同一 Artifact 的调用标识和原文摘要合并到来源表中。模型可以使用笔记中的 Artifact ID 和指针回读，也可以使用来源表中的调用标识和原文摘要进行精确回取。

摘要携带原工作状态摘要、任务版本、工作版本和已消费记录游标。下一次提议仍从当次模型请求绑定工作版本，归约仍用完整的已接受状态进行 CAS 校验。任务修订先应用现有依赖失效规则，再投影新版本。原始工具结果和语义状态继续承担证据与完成验收职责。工作摘要随模型请求留证。

原工作表示较短或压缩收益不足时保留原格式。摘要仍进入现有完整请求计量，决策阶段保留原有工作增长上界，窗口不足继续按原预算语义处理。触发基于工作表示大小，提供可预测的开销界限。当前基线既不压缩整个历史，也不缩小决策阶段的预留容量。

阶段停止条件是通过推荐入口交付摘要并验证后续请求保留阶段信息，验证来源绑定、修订失效和无收益回退，并给出同请求输入成本对照。冻结的五条工作记录样例中，仅替换工作表示后，请求 JSON 从 11208 字节降为 11089 字节，测试计量器从 10438 降为 10324 Token。运行 `uv run pytest -q tests/harness/test_m1_session_chain.py tests/harness/test_acquired_work.py` 可复验。该对照验证信息传递和输入成本，真实模型对长任务的完成质量需要单独评测。
