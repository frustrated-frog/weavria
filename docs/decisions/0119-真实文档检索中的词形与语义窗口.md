# 真实文档检索中的词形与语义窗口

状态：已实现；英文归一化与语义窗口显式可选，默认检索表示不变。

## 问题与边界

ADR 0118 的查询扩展仍不能把 `approves/approval` 与 `approver` 匹配起来。现有 Dense 虽然能处理部分同义表达，但把包含元数据的 JSON 每 256 UTF-8 字节硬切，会割裂句子和主体。本轮用固定版本的真实文档检验这两层问题，不把合成小题的成功率当作成熟度。

检索只改变模型可见的候选供给；任务、权威原文、来源、条件、授权快照与事实族闭包不变。改进不能通过注入答案、调整标注、移除负例或放宽证据审查实现。

## 决策一：词面与词干共存

`MemoryRetrievalPolicy.lexical_normalization="english_snowball"` 启用标准 Snowball English/Porter2。纯 ASCII 单词同时产生 `surface:` 和 `stem:` 两种词项，精确词面仍能贡献 BM25 分数。带下划线、连字符、数字的完整词项和中文不做英文词干转换；现有 NFKC、大小写折叠、中文字符及双字分词继续存在。

选择可选依赖 `snowballstemmer==3.0.1`，不自行维护后缀裁剪表，也不引入 NLP/Agent 大框架。它解决标准形态归一化，不能识别所有同义词、实体或词义。每次检索创建局部词干器和最多 4096 个词的缓存，不跨请求保存文档词项。依赖缺失在配置阶段显式报错；默认模式无需导入该依赖。

双词项的代价是改变文档长度与 IDF 分布，并增加处理成本。完整标识符仍有精确词面，但普通英文标识也可能与自然语言词干相交；这只影响软排名，不能改变事实键或条件相等关系。中文词形归一化、实体别名图和学习式稀疏检索留待另行验证。

## 决策二：带上下文的重叠窗口

`dense_view="contextual_windows"` 将主体、属性和完整限定条件作为每个窗口的头部，正文优先在后半窗的句子、换行或空白边界切分，最多重叠 128 字节。每个窗口最多 1024 UTF-8 字节，元数据最多 512 字节；长无空白文本允许沿 Unicode 字符边界切分。窗口覆盖整个正文，交付时仍返回完整事实族。

字节上限不是 Token 上限。编码器继续按自己的真实 tokenizer 检查输入，超限明确报错，不静默截断。元数据超限属于容量错误；是否回退词法由已有 `failure` 策略决定。向量暂存、完整校验后发布缓存、取消传播和宿主拥有编码器生命周期的规则不变。

拒绝用单个超长全文向量替代窗口：编码器有长度上限，局部支持句也可能被长段稀释。暂不新增 tokenizer/句法解析器端口或训练编码器；真实语料上的窗口策略仍需逐项比较，不能默认越长越好。

## 决策三：扩展别称不重复计算背景锚点

真实模型复测表明，词形打通后旧 sign-off 案例仍失败：`plan/planning` 让背景在主查询与别称中各得一票，固定权重 RRF 将其排在只匹配别称的答案前。

扩展器把已通过原文定位的 `preserve_quotes` 另外记录为 `expansion_anchors`，主查询继续保留它们。检索器使用当前分析器，从**别称查询词项**扣除锚点词项，再执行 BM25；语料文档长度与主查询保持原样。扩展只剩锚点或没有命中时，精确回到主通道。不能减去整个原查询，否则会删除 `beta code` 等真实焦点。没有调整融合权重或增加候选名额。

这些锚点仍是模型提案，可能错误地包含焦点；去重不是语义正确性证明。候选依旧受同一授权快照、完整原问题重审、已有证据保护与缺口单调改善约束。`expansion_anchors` 的有界类型检查和摘要绑定与别称相同，不进入长期记忆。

## 版本与兼容

策略身份升为 `task-memory/2`，包含两个表示选项；候选身份还包含 Snowball 实际包版本。扩展策略升为 `memory-query-expansion/3`，Reranker 的扩展候选分布标记升为 `lexical-expansion/2`。旧校准结果不能自动套用新身份，应重新校准。新增策略字段放在 Dataclass 末尾，保留原位置参数含义。

没有变更持久化 Memory Schema、Context 报告 Schema 或历史事件。查询摘要现在同时绑定别称及去重锚点，报告仍记录策略身份、输入/输出摘要与失败分类。旧记录原样可读，不为其补造新策略下的结果。
