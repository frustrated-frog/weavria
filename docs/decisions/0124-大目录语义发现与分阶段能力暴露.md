# 大目录语义发现与分阶段能力暴露

日期：2026-11-13。状态：首个垂直切片已实现，默认关闭。实现与两轮结果见[大目录语义发现的实现与验证](../大目录语义发现的实现与验证.md)。

## 问题与本轮边界

ADR 0063 允许理解器查看完整小目录；超过候选数量上限时，工具仍先经过 BM25 与字段匹配。不同语言、动作同义表达或有词法干扰项时，正确工具可能在理解前被删除。本轮处理任务准备时的大目录发现，沿用已有任务解释、需求编译、执行工作集与授权。目标规模为几十至几百个工具，硬上限显式配置。

本轮选择**全覆盖的有界语义扫描 → 候选合并 → 完整协议展开 → 原有任务理解**。全覆盖仅表示每张能力卡都进入一次模型请求，不保证模型召回正确。尚不实现执行模型主动搜索、Skill 组合、向量索引或自动替代有副作用的动作。

## 为什么先采用这个机制

- 继续使用词法 top-k 再做语义重排，无法纠正召回阶段已丢失的工具。
- Dense/混合索引能够降低在线扫描成本，但引入编码模型、表示选择、近邻召回和索引版本的额外误差。本轮先建立不依赖词法预筛的语义基线，测清能力收益及成本，再决定如何加速。
- 一次发送完整大目录会支付所有 Schema 的上下文成本，并可能在调用前超限。
- 任意截取目录前几页会把顺序误当成相关性。扫描未完成必须失败，不能将局部未命中包装成目录没有能力。

代价是发现输入及调用数随目录规模增长，后续理解还会再次消费入围能力的完整协议。不会据此宣称比全目录或 BM25 普遍省 Token。方案默认关闭，使用宿主显式提供的模型和实际请求计量器，不新增依赖。

## 数据、算法与阶段边界

1. **授权范围先行。** CapabilityResolver 从本次注册表构造发现策略允许且 available 的不可变目录快照。私有或不可发现能力不进入语义模型。发现允许查看副作用描述，不等于执行批准。
2. **能力卡。** 保留稳定身份、版本、完整说明、行为、风险和审批标志，以有界字段名概览表达输入前提和输出。完整输入输出 Schema 暂不发给发现模型；卡只用于发现，不能据字段概览生成正式执行参数。卡和完整协议都绑定同一描述符摘要。
3. **确定性分批。** 按稳定身份排序，结合数量限制与正式请求 Token/字节准入逐张装入批次。超长单卡明确失败，不截断后假称已完整扫描。任务原文、适用的历史和当前上下文是所有批次的共同条件。
4. **语义提名。** 每批一次结构化调用，模型返回有界的候选身份。必须来自该批、无重复；模型提供的分数不参与跨批排序。局部名额可能漏掉相关工具，这是可测量的召回边界。
5. **全局比较。** 合并各批提名并去重。并集超过最终候选限额时，在相同任务下再次比较紧凑卡，选择数量受限的候选，避免按不同批次自报分数直接截取。合并请求过大时明确容量失败；不能默默丢掉尾部候选。并集未超过限额时保留全部提名，不增加无必要的模型筛选。
6. **协议展开。** 只将最终候选对应的原始注册对象交给 TaskUnderstandingEngine。其完整 CapabilityView（含证据画像）仍接受既有目录预算、Token、语义与字段准入。解释器实际声明的能力才进入 Runtime；发现候选不直接成为可执行工具集。直接回答可以选择零项能力。

这是一种分阶段披露：卡片是召回材料，完整协议是理解材料，执行视图是受约束的行动集合。两次语义筛选都是低信任提议，无法证明工具能满足任务、自动填充未知参数或提升输出证据强度。

## 执行与失败语义

- 单次调用 Token/HTTP 字节、累计发现输入 Token、候选数、调用次数、目录字节和总期限分别设限。理解期限从发现前开始计算，所有发现与解释共享父准备期限。
- 顺序执行，不创建脱离任务或内部并发。取消向上传播，未完成发现不会安装半份执行视图。
- 超时、非法输出、越界身份、模型故障和容量不足显式区分；失败不偷偷切换词法结果或重复调用。空提名只是本策略未找到候选，不能证明世界上没有相应工具。
- 目录、策略、模型配置、实际编译请求、候选和最终选择均有摘要。报告只记录工具身份、成本和诊断，不记录正文、认证信息或模型隐藏推理。
- 报告作为发现结果及准备记录返回，失败携带已完成步骤；成功报告可通过宿主提供的接收函数保存。Session 的 preparation_version 保留发现策略身份，正式语义快照继续保存最终能力与目录身份。详细发现报告不自动写入 Session Journal，需要完整发现报告归档时须配置接收函数并保存失败异常携带的报告；取消不会等待额外归档 I/O。未将每次运行的报告摘要塞进策略版本字段。
- 原有 TaskUnderstandingRecord v1 序列化保持不变，携带报告使用 v2。原 TaskFrame、Runtime、Tool 与 Session 持久化 Schema 不变。

## 验证计划

确定性测试覆盖跨批筛选与全局比较、身份越界、空候选、目录顺序稳定、完整协议延迟暴露、策略过滤、真实请求预算、累计预算、模型故障、超时、取消和资源清理。真实 Session 测试验证候选未获执行权、最终最小视图、持久化摘要与标准 ToolRecorded 链路。

冻结领域无关的大目录与任务，比较 BM25、小目录策略原样用于大目录的基线、语义扫描；按需加入可容纳的完整协议目录对照。真实模型自主选择，评测标签不进入模型请求。报告候选召回、误选、最终选择、每阶段输入与供应商用量、延迟和失败；合成工具目录与小样本不证明普遍应用收益。保持所有失败，不能通过改名、追加题目专用同义词或放宽完成策略追求成绩。

## 后续判断依据

若召回有效而扫描昂贵，下一步以此为参照研究可版本化的混合索引；若卡片误导严重，先改进输入前提与输出语义的表示；若完整协议经常否定候选，再研究带补搜预算的交互发现。上述阶段各自需要独立反例和成本对照，不在第一版中同时引入。
