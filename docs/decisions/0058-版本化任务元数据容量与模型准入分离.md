# ADR 0058：版本化任务元数据容量与模型准入分离

## 问题与边界

冻结真实失败的声明和审计后，先修复了需求与证据面的交叉绑定。重放同一声明不再因绑定报错，
却触发 task_observation_size：完整 Task Frame 同时携带规格、编译需求、义务、证据匹配计划和
覆盖审计，其合法元数据可能超过旧 TaskObservation 的 16 KiB 限额。

这与模型上下文是否能容纳请求是两个问题。16 KiB 是早期内部包络的容量约束，不是模型窗口、
Token 限制或证据正确性条件；也不能依据这个错误要求用户删除真实需求或缺失项说明。

## 决策与迁移

TaskObservation 显式增加 v2，编码上限为 65536 字节；默认构造和已有 v1 仍保持 16384 字节。
所有严格字段、信任等级、任务修订绑定与 NaN 拒绝规则不变。ApplicationObservation 不变。
旧消费者需要升级才能接受 v2；这是一项公开 Core 契约演进，不是无版本扩大旧限额。

Harness 用统一的 task_frame_observation 工厂创建包络：先完整校验 v1，只有拒绝原因确为包络
容量时才尝试 v2，其他错误直接拒绝。v2 同样必须通过完整类型和有限容量校验。
TaskUnderstandingEngine 升级为 v10。初次编译、账本投影、证据刷新和 Frame Patch 归约共用同一
确定性规则，避免只修正第一处构造，后续账本摘要改变又在另一处越界。

没有重新编码或删减完整 TaskFrame，没有丢弃审计、义务、来源或目标绑定。能放入 v1 的原快照
继续生成相同 v1 包络；归约旧快照不自动把旧事件改成新版本。跨过容量边界的新快照才使用 v2。

模型请求仍经过独立的 Token、输出预留和宿主字节预算准入。v2 能被保存不意味着可以全部发送；
若强制上下文确实超出模型窗口，仍应在发送前明确拒绝。更大任务需要单独设计语义状态的模型视图，
不能不断放大此包络，也不能把内部容量当作任务理解正确性的代理指标。

## 验证

v1 仍拒绝 17 KiB 内容；v2 可以完整往返中等元数据，超过 64 KiB 则拒绝。版本号仍拒绝布尔、
浮点、字符串和未知值。会话归约验证小包络到 v2 及后续刷新，旧快照归约行为保持。
实际失败声明的本地重放不再在执行计划或包络阶段报错；该重放使用记录的模型声明、正式应用
工厂及当前只读后端，不把私有数据保存为仓库 Fixture，也不冒充一次新的真实模型成功。
