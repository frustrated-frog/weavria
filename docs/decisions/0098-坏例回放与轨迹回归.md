# 0098 坏例回放与轨迹回归

历史对话回放能重建用户看过的消息。诊断运行回归还需要判断哪一步先偏离了执行约束。例如，最终引用缺失可能始于原文回取、上下文编译或交付。发布门禁需要分别看到这些边界。

## 重跑与复查

```bash
uv run python -m examples.trajectory_regression
uv run python -m examples.trajectory_regression --export /tmp/weavria-trajectory.json
uv run python -m examples.trajectory_regression --replay /tmp/weavria-trajectory.json
uv run python -m examples.trajectory_regression --case poll-resume
```

重跑使用固定脚本模型、真实 Runtime、真实 SQLite 和临时目录。复查读取版本化检查点文件并重新应用同一套规则。冻结的检查点保留可观测约束，运行所需的输入与工具行为由场景脚本定义。命令每条轨迹输出一行 JSON。退出码 0 表示所选用例通过，1 表示发现回归，2 表示输入或运行错误。失败行包含规则、事件序号、期望检查点和实际检查点。

从现有数据库提取单个 Run 时，命令在同一只读事务读取已接受事件和模型请求快照。导出目标需要是新文件。

```bash
uv run python -m examples.trajectory_regression \
  --capture session.db --run-id RUN_ID --export /tmp/weavria-run.json
```

该命令输出单条 `Trajectory`，可作为添加用例和编写规则的起点。`--replay` 接受内置用例生成的版本化套件文件。需要指定来源区间或应用引文格式时，调用方可以通过投影 API 传入相应参数。

## 首批覆盖

| 场景 | 检查点 |
| --- | --- |
| 原文与最终引用 | 阶段笔记依赖原始 Artifact，回取覆盖原文区间，交付请求确实携带该区间，验收读取原文，最终输出带来源 |
| 工具失败后的重规划 | 允许一次合法重试，拒绝无进展的重复提案，下一模型请求收到绑定既有失败的反馈，替代来源随后成功 |
| 后台任务等待时进程退出 | 第二次运行状态结算后退出进程，恢复同一 Run，按原动作和时间继续查询，完成时使用完成结果交付，持续运行时沿用原查询额度结束 |

## 投影与定位

`project_trajectory` 以单个 Run 的连续 `ControlEvent` 日志为输入。可信调用方可以另行提供实际模型请求、需要覆盖的来源区间和应用自己的引文解析器。下一轮是否收到重规划反馈，通过请求摘要与已接受的 `ContextSelected` 对账。原文交付通过 `EvidenceDeliveryManifest` 核对。查询时间和动作身份由已接受的运行状态、准入信封与派发事件比较。持久化字段限于事件序号、检查点类型、枚举分类和局部整数别名。原始模型请求、工具参数、Artifact 正文、摘要值、运行身份和最终回答只在本地分析时使用。

规则按执行顺序排列，只比较所选检查点。事件序号用于定位，规则本身依赖语义检查点，因而额外的内部事件可以使序号变化。相比逐字比对整条 Trace，这种设计保留对约束的检查，同时减少内部事件增删带来的误报。相比仅校验最终输出，失败报告可以区分准备、派发、反馈和交付。

当前用例是根据历史故障整理的独立、脱敏复现。普通运行通过固定外部响应验证执行约束，真实模型策略收益仍由独立的行为评测判断。冻结报告用于离线复查，受信任的宿主也可以通过投影 API 读取自己的 Run 日志。原始历史会话及正文由宿主留在原存储中。

回归测试覆盖冻结格式、真实缺引用输出、放开重复派发、原文交付缺口、提前查询和恢复后额外查询。负例应命中第一条可观测偏差。
