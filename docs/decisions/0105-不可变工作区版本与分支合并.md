# 不可变工作区版本与分支合并

## 问题与结束条件

单次隔离计算已能输出文件，但下一轮只能手工选取 JSON Pointer；未修改文件容易丢失，并行调用也没有明确的文件版本关系。本阶段提供显式基线、自动保留未修改文件、显式删除、失败不发布版本，以及同一基线两个直接子版本的三方合并。执行、成果存储、重新打开 SQLite 后复用、冲突与取消必须有可复现验证。

## 状态与执行决定

工作区是不可变 UTF-8 文件快照，不是持久容器。版本哈希绑定排序后的完整文件内容和父版本；路径、数量、字节预算均在边界校验。宿主配置每版本容量，默认 8 KiB，最高 64 KiB、8 个文件。此阶段以有界完整快照换取明确的独立恢复语义，存储成本为每个版本 O(文件总字节)，尚未做块级去重。

新增 execute_workspace_python 工具，不改变 execute_python v1 的输入输出。模型选择已接受 Artifact 及其精确 revision；ToolContext 校验归属并登记依赖。基线文件送入既有沙箱的只读 inputs；新输出按路径替换，未修改文件保留，删除必须明确声明。额外 Artifact 输入是计算资料，不自动成为版本文件。执行失败不返回新 workspace；成功但成果越界也不发布版本。无宿主路径、无长驻进程、无共享可变 HEAD。

工具只返回候选结果；现有 ToolExecutor 存储 Artifact、Runtime 接受 ToolRecorded 才形成可复用版本。存储成功但事件未接受时，孤立 Artifact 不能成为下一调用的基线。版本哈希仅验证内容一致性，不是身份授权或代码执行证明；输入和计算结果始终为低信任数据。

## 分支与合并

并发调用显式引用同一基线，独立生成子版本，不相互覆盖。merge_workspace 只接受基线的两个直接子版本（不遍历任意祖先）。逐路径比较 base/left/right：两侧相同则接受；一侧等于基线则取另一侧；否则报告冲突。不存在文件与空文件不同，因此删除/修改会冲突。最终再次检查文件/目录前缀冲突与容量；发生冲突时不发布部分版本。相同内容的并行结果可合流。

不自动选择一个全局最新版本，也不声称实现 compare-and-swap；模型必须选择具体 Artifact 或显式合并。相对于共享可变 HEAD，此方案不新增需要与 Runtime 事件跨事务提交的副作用。相对于持久解释器，牺牲进程内变量与缓存，获得文件来源清楚、取消可丢弃和并发分支隔离。今后若需要工作区主分支指针，须在事件接受事务中设计 CAS，而不是在工具内部更新数据库。

## 验证与限制

确定性测试验证三方合并真值表、路径冲突、版本/内容篡改、原子失败、来源拒绝、大小上限、取消和依赖。显式 Docker 测试验证多步修改、失败后复用旧版本及容器间隔离；SQLite 重开验证文件状态持久化，不能冒称运行中进程恢复。新增两阶段源码统计示例，独立核验每个阶段文件；脚本模型只用于故障注入。当前不包含跨 Run 授权、任意历史合并、文件行级合并、二进制文件和长任务自动恢复。

该决定基于 ADR 0104、现有 Artifact 接受不变量与三方合并规则，不引入外部 Agent Runtime 或新依赖。
