# 0069 记忆消费与模型工作视图协同

状态：已实现，2026-10-31。补充 ADR 0042，不改变长期研发宪章。

## 问题

Memory 已有形成、准入、双时间版本与作用域存储，但主线模型请求尚未消费它。旧召回分支能够按完整事实组交付，却早于主线的工具交付清单、完整 HTTP 计量、TaskModelView 及收尾预算修复。直接覆盖会造成 ContextCompilation v7 编号碰撞，并可能恢复已经修复的探索期限和取消行为。

整合来源为 `codex/memory-context-recall-v1` 的 `d5e9133`，适配主线基点 `8823263`，没有覆盖后者的恢复和收尾修复。

本次只解决“宿主明确授权的记忆，如何完整、安全地进入当前决策及收尾”。不自动写长期记忆，不改变证据验收，不引入沙箱或代码执行。

## 决策与执行流程

1. 保留独立 `memory` 子系统，通过 Harness 的 `MemoryContextSource` 实现 Context 的来源端口。Session 仅依赖端口和 Core 的 bundles/供给报告，不导入 Memory 或领域应用。宿主绑定身份、精确 scope、有效时间和知识快照；每次构建按当前任务与信息需求查询。
2. 使用同一读事务内、时间筛选后的 `(scope, kind, subject, predicate)` 完整组。一个成员命中即可带回全部适用条件变体、争议和来源，组分数取最大成员 BM25，组数与响应字节限制在闭包后应用。原逐条 `recall` 行为保留，不引入实体或谓词同义推断。
3. Context 为每个 bundle 创建只有 raw 表示的原子候选。索引片段用于需求覆盖评分，不用于交付摘录；与历史和工具共享预算，可以整组省略，不能只交付一般规则而切掉例外。必须交付的工具证据仍受原有交付清单约束。
4. 一次编译的来源快照冻结，反馈预留降级重编译不再次读取；新决策、synthesis 预编译和修订任务重新读取。报告绑定来源版本、task_revision、需求摘要、读取快照摘要、供给摘要和省略计数。Session 事务在 Provider 调用前核验实际已选 bundle 摘要并持久化请求与报告。
5. Runtime 的 deadline/cancellation 贯穿召回，存储 worker 先结算清理再返回取消，不产生脱离任务。当前任务授权失败为 POLICY_DENIED，容量失败为预算耗尽，依赖/快照故障为 CONTEXT_SOURCE_FAILURE；原始 cause 本地保留，公开固定诊断。若失败属于召回期间已被 steering 替换的任务，只丢弃该旧准备结果，新任务重新查询。
6. 保留主线显式 phase、稳定定义、探索期限、恢复等待及收尾纠错。记忆始终是观察数据，不能更改工具授权、系统指令或完成门禁，也不自动把尚待工具核验的需求标成已满足。

## 协议与计量

| 类型 | 本轮版本与条件 | 兼容承诺 |
| --- | --- | --- |
| SessionRequest | v6 仅在配置来源时使用 | 无来源保留 v5 原有字段和字节，不输出空 bundles 字段 |
| ControlRequest | 原有 v3/v4；工作视图仍为 v5 | 外层 bundles 与内层工作视图互相独立 |
| ContextCompilation | v11 绑定来源；可组合 receipt v2、工具交付、历史检索和传输计量 | v1–v10 原字段语义和序列化保留，不复用主线 v7 |
| Run 配置 | v6 记录 context_source_version | 保留已有配置元数据、投影器及预算信息，无 DDL 变更 |
| OpenAI-compatible 计量器 | session/6 | 在外层 v6 下把已选 bundles 纳入本次稳定前缀，重新召回后重新计量 |

v11 不隐式要求 TaskModelView 或某个 HTTP 适配器；普通 TokenCounter 可不提供传输大小。配置 TaskModelView 时则继续要求完整 HTTP 计量及 phase-aware receipt v2，不能用来源供给绕过主线要求。

稳定前缀证明只适用于本次选定的 conversation、bundles、task 和工作视图定义；说明文本、phase/source/progress 与未知工具反馈仍按可替换内容计量。整组变化必须生成新编译报告及反馈上界。旧程序不能读取新版本或新错误类别，需要升级；不重写历史持久化记录。

## 替代方案

- 把记忆拼入 system：会提升不可信内容的权威性，绕过来源选择和交付留证，拒绝。
- 复用普通工具的标量摘录：无法保证一般规则、条件例外和争议完整同行；本次选择原子来源候选。主动发现与回取超大组需要另外设计。
- 将读取结果固定为整个 Run 的隐式缓存：会错过 steering 和并发修订；选择每次构建查询、编译内部冻结。读取快照与 Session 提交不是跨库线性一致事务。
- 新增一套记忆专用预算与完成策略：会重复并破坏现有联合选择与验收；沿用现有策略，不让记忆端口决定最终预算。

## 验证与证据强度

确定性回归验证完整规则/零分例外/争议闭包、双时间、授权、整组省略、无 HTTP sizer 的来源接入、v5 字节兼容、v11 来源绑定、工作视图 decision→工具→synthesis、完成纠错、已发送快照一致性、取消与依赖失败、steering 后重新查询以及失效失败的丢弃。外层 v5/v6 均在多语言、转义、最大版本与未知反馈的字节边界验证 Token/HTTP 上界。

真实模型使用原冻结 10 个项目设置任务，三臂各两次重复；60/60 正常完成，无记忆 6/20、逐条 top-1 18/20、完整组 top-1 20/20。数据、预算、评分和失败记录见[记忆消费真实模型评测](../记忆消费真实模型评测.md)。这是固定规范化准入后的消费实验，不证明自然形成质量、超大组回取或长任务整体提升；完整组也尚未与提高单条 k 作完整消融。

本轮保持显式 opt-in。下一步优先补足自然形成与修订后的跨会话消费闭环，再依据真实失败设计检索和超大组机制，不能从这一小数据集宣称记忆系统已成熟。
