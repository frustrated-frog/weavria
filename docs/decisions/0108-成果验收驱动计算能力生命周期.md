# 成果验收驱动计算能力生命周期

状态：已实现，2026-11-06。实现与完整运行记录见[成果验收与计算能力生命周期](../成果验收与计算能力生命周期.md)。

## 问题与决定

ADR 0107 保留当前任务声明的隔离计算，避免一次调用成功后过早退出。进一步发现：CompletionObligation 自动关联同一工具的信息需求，第一阶段资料满足并不证明整个计算目的完成。因此不能简单把 SATISFIED 当作计算退休证据。

本阶段增加宿主注册的 CapabilityOutcomeVerifier。它面对原始 TaskInput、完整 TaskFrame 和已接受成果，判断当前能力的完整目的与完成条件，返回 verified、repair 或 unverifiable。验收器读取的是具体内容，不能仅返回模型自述；框架记录验收器版本、任务/语义范围摘要、工具版本与实际读取的不可变 ArtifactRef。只配置展示策略不授予执行权限，也不绕过最终 CompletionPolicy。

验收投影存入现有 NeedLedger 的 v7 扩展字段；资料状态保持原义，不把成果验收转写成所有需求已满足。旧 v5/v6 保持原线协议，无验收器时仍保守保留计算。选择器只在完整范围一致、证明引用仍在接受记录中、资料没有缺口时释放计算覆盖目标与该工具的信息覆盖；其他工具和未完成需求照常参与选择。进度与主动收尾消费同一结论；最终候选不能覆盖明确 repair，verified 不自动升级为自然语言答案正确。

## 执行与失败语义

每次工具反馈刷新从当前事实重新验收，不使用成功次数或上一轮 verified 缓存。上下文只允许当前 Run 已接受结果和同一生产者的直接附件，校验内容摘要与精确引用；限制读取量与验收时间，并在返回、异常、超时、取消后关闭读取。验收器异常不伪装成 verified，外层取消继续传播。Steering 先重新理解，不继承旧成果投影。

任务创建时只为实际配置的验收器登记未验收槽位,并固定模型进度容量。不能到首轮反馈后再扩容,也不能让未启用验收的紧窗口任务支付额外预留成本。

范围摘要包含请求锚点、任务规格、信息需求与完成义务，不包含由证据/菜单自身推进的 Frame 版本，避免更新视图导致自身失效。任何新目标或要求变化都会使旧证明失效。不可变版本以存在有效交付为语义，不隐含全局 HEAD 或“最后一次调用覆盖全部成果”。

## 替代方案与验证

不采用按工具名/轮次预编排菜单、不采用模型工作笔记作为证明、不把任意结构化输出升级为语义满足。通用机制不理解工作区文件或源码；示例验收器复用原有冻结任务的独立 AST 与版本检查，并严格限定其能验证的任务。

完成条件：中间成果和失败保留，完整成果可退出，范围变化重新开放；篡改引用、无读取的虚假验收、附件越界、超时取消和持久化回读具有确定性回归；同一冻结任务观察真实菜单变化及含任务理解的总成本。固定任务验收不能证明开放领域通用语义验收能力，单次真实运行不能证明普遍收益。
