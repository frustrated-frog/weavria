# 0147 按实体与字段条件复用单读经验

2026-11-23，已采纳为显式接入能力。延续 [ADR 0144](0144-用已核验的原文交付指导下一次读取.md) 的预测和实测闭环。

## 经验何时适用

精确匹配把整个目标与所有候选一起绑定，改写问题或切换实体会出现冷启动。此前按文件名迁移的实验又说明，文件可读和文件支持所问字段是两件事。发行版本、wheel 格式版本可以一起出现于同类任务，但证据责任不同。某个包缺少入口文件也不能预测另一个包的入口文件缺失。[原跨任务对照](../跨任务读取经验的成对验证.md)

宿主可以给正式构造入口传入版本化的 ReadRetryScopeResolver：

```python
harness = AgentHarness.from_config(
    path,
    config=config,
    model=model,
    tools=tools,
    token_counter=counter,
    read_retry_scope_resolver=resolver,
)
```

解析器同步接收当前 TaskInput 和一个已校验候选的归一化参数。宿主已能识别任务所问实体、字段与来源类别时，才能返回 ReadRetryScope。这个类型包含来源角色、期望实体摘要、输出中的实体 JSON Pointer，以及最多八个必要字段的 JSON Pointer。来源角色应覆盖适用的数据契约和条件，例如同一类冻结发行包元数据。条件不明、任务存在歧义，或候选属于别的实体时，解析器返回 None。解析器版本冻结于 Run 配置，应与宿主解释逻辑一起更新。未传入解析器时沿用精确匹配。

## 从核验到运行决策

1. Runtime 先检查每个候选当前可见、是符合条件的只读调用、且能在反馈预算内单独提交。至少两个去重后的候选才进入原有经验路径。
2. 精确场景有经验时沿用其选择。否则，Runtime 按工具名与版本、来源角色、实体输出位置和字段集合计算作用域摘要，在当前会话和配置内查询近期已核验收据。一个作用域最多回取一条收据。只有一个当前候选有对应正向证据时才采用。出现多个匹配候选时沿用原序。实体值用来核对旧结果属于旧任务对象，以及由适配器核对新候选属于新任务对象。索引按可迁移的角色和字段查询。
3. 宿主仍使用 AdmissionNotice.retry_read 建议模型重提当前候选。当前操作必须照常经过参数校验、预算和 Policy。旧原文没有进入当前模型请求，也没有替当前操作取得权限。
4. 写入沿用原经验归因。模型重提选中动作并实际收到下一次请求中的完整原文后，存储层比对 Artifact 摘要及当时的交换。然后在原件中核对实体摘要和所有字段均非空。通过后才建正向索引。失败、节选、引用、实体不符与字段缺失都无法建立跨任务支持。
5. ReadRetryPrediction v2 保留选中作用域和被采用的历史收据。收据指向原 Run、拒绝序号和模型请求序号，便于追查原决策和实际交付。未使用作用域的 v1 预测维持原序列化。SQLite v12 为已有试验追加状态和索引，旧记录继续支持精确匹配，只有经过新条件核验的记录才会进入迁移索引。

方案只在原只读准入分支执行，额外一次有界存储读取，每批最多查询三十二个作用域，不增加模型调用。选择仍是建议。当前核验可证明原件中字段存在且实体匹配；字段的现实权威性与适用性依赖宿主契约，当前答案仍需其独立验收。精确场景评分继续采用原来的完整交付指标。完整 SoMem 主题组织与主动联结导航属于独立能力。
