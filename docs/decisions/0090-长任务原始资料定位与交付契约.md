# 长任务原始资料定位与交付契约

保存的请求把 M1 长任务失败分成三个独立边界。文档模型常从聚合文件中读取到使用指南，而未定位规范文件。源码模型有时已获得正确原文和阶段结论，但把数值或右侧表达式输出成字符串数字或完整比较。部分两类运行在获得新证据之前就被反馈预算或模型协议阻断。

文档接入提供冻结语料的完整原始路径目录，模型可用既有读取工具定位原文。目录仅用于导航，候选路径未从评分器筛选。重复请求使用完全相同的目录观察，以保留原有输入幂等语义。长任务交付策略验证用户要求的带来源工作提案，源码任务另外声明字段类型。字段契约只包含名称和类型，不能读取评分答案。错误由已有 CompletionRepair 反馈，反馈包含有界旧候选，模型可用既有原文重新提交。宿主不把字符串强转为数字，也不代替模型选择表达式。

预算和评分保持冻结。接入说明用短句，减少下一次反馈预算中静态指令的负担。诊断使用 `python -m examples.m1_harness --run --case <case> --diagnostic-repetitions 1`，每项每种策略一次。

用旧源码失败请求做隔离回放，将已保存的最终请求与真实类型诊断交给同一模型，结果通过冻结字段和引用评分。这证明修复反馈可纠正既有候选，不计作端到端运行。端到端的 `compact-contract-repository-20261103` 中，coverage 和 recent 各严格通过一次，包含既有读回及工作记录条件。同期文档 recent 的所有字段和两份原始 ADR 引用通过，并形成了工作记录，但没有回取，场景仍未通过；coverage 受反馈预算阻断。

最终 `lean-delivery-*-20261103` 使用原文件目录、现有读取工具和紧凑接入说明。源码两种策略再次各严格通过一次，两次均实际分页并形成工作记录。文档两次仍未通过，coverage 到收尾后请求了不允许的读取，recent 耗尽反馈预算的重议次数。它们和已经通过字段及引用评分的文档样本一起保留。单项诊断不关闭 M1 门槛。
