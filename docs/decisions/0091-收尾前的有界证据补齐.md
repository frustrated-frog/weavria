# 收尾前的有界证据补齐

需求账本记录证据是否已经取得，交付清单记录本轮模型输入实际带上了哪些原文。两者可能不同。收尾前仅检查第一份编译结果，会让原文已经在 Artifact 中的任务退回决策，或者在资源边界上带着缺口作答。

需求策略从已完成获取的证据绑定中选取一个尚未交付的原文区间。地址包含生产调用、来源摘要、JSON Pointer、字符区间和区间内容摘要。编译器从已接受的 Artifact 校验地址和内容，并在原请求的字节与 Token 预算内重新选择上下文。单个区间的 JSON 编码最多 768 字节，每次收尾预检最多重编译一次，耗时上限取完成策略超时和 Run 剩余时间四分之一的较小值。过程复用已有区间编译机制，无需调用模型或工具，也不消耗模型主动发起的恢复租约。

只有当重查确认缺失需求集合严格缩小、任务修订号仍然一致，并满足原有收尾准入时，Runtime 才采用候选视图。候选的请求和编译报告一起生效。预算不足、候选覆盖没有改善或补齐时间用尽时，原有决策或有限收尾继续生效。取消沿原路径传播。多个缺口或大字段可能超出单次补齐能力。缺失的原始资料仍须走正常获取流程。已采用的范围由原交付清单记录，未采用的候选不进入请求快照。

确定性验证对比同预算下的普通编译与定向编译，检查指定原文区间确实进入交付清单，且恢复租约未改变。Runtime 验证只尝试一次，覆盖改善才采用，预算拒绝、超时或覆盖不变时回退，模型和工具调用数不变。

2026-11-03 的 M1 文档长任务单次诊断中，recent 通过字段、引用和场景检查。coverage 的字段正确，但缺少 ADR 0078 的引用，记录中也没有对应的文档读取。此结果区分了已获取后遗漏与未取得原始资料两类失败。诊断只各执行一次，无法单独归因于此机制，也不足以关闭 M1 门槛。

同日复测两项 M1 长任务，各策略再跑一次。文档 coverage 在收尾时请求了不允许的操作，recent 耗尽反馈预算重议次数。源码 recent 严格通过，coverage 在读取源码前耗尽模型输出修复次数。模型运行存在波动，这些失败保留在诊断记录中。
