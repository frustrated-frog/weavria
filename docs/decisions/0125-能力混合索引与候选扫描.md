# 能力混合索引与候选扫描

日期：2026-11-13。状态：已实现并完成两轮真实准备对照，默认关闭。实现、结果与限制见[能力混合索引的实现与验证](../能力混合索引的实现与验证.md)。

## 问题和设计选择

ADR 0124 的全目录扫描已经解决词法预筛漏掉跨语言工具的问题，但每个新任务都重新支付全部能力卡的模型输入和多轮网络延迟。本阶段增加可复用的本地混合索引，将模型检查范围缩小为候选集合。全扫描保留为基线与显式的上下文回退路径，默认行为不变。

流程：策略允许且可用的目录快照 → BM25 倒排检索与稠密向量精确检索 → 名次融合 → 候选卡语义筛选 → 完整 Schema 展开 → 原有任务理解及执行视图。

## 数据结构与算法

- 索引拥有一个有界的不可变快照：目录身份、编码器身份、文本片段及单位向量、文档长度、词项倒排表。编码器通过结构型 Protocol 注入，生命周期仍由宿主管理；可直接复用公开的 OnnxE5MemoryEncoder，不导入 Memory 内部实现、不新增运行依赖。
- 表示包含工具名称、版本、完整说明和输入输出字段名概览。长文本按 UTF-8 字节边界分块，不截掉说明尾部。字段概览明确只是召回表示；最终 Schema 始终来自当前原始注册对象。
- 词法通道计算 BM25，仅访问命中词项的 postings。向量通道对全部片段精确计算余弦相似度，工具分数取片段最大值，避免一个长说明占满多个候选位置。当前是 O(片段数 × 维度 × 查询片段数) 的有界精确索引，不宣称 ANN 或次线性语义检索。
- 两路各自按分数排序、工具名称打破平局，再以 RRF：sum(1/(60+rank)) 融合并截取固定候选上限。词法无命中不补零分候选；稠密排名不设伪装成相关性置信度的阈值，直接回答的无关候选由后续语义模型拒绝。通道排名和入围集合均可诊断。
- 排名覆盖无法证明任务覆盖，尤其多意图查询与词法干扰可能挤掉语义候选。索引没有自动补搜或根据标准答案调参。全扫描与索引策略分别计量召回、最终选择、失败和成本。

## 更新、隔离和失败不变量

1. 每次检索接收已过滤的完整目录，并防御复制。不可从历史索引直接回答一个新授权目录。旧快照只为本次相同文本复用向量，不提供旧目录候选；删除、撤权、不可用能力立即退出当前结果。
2. 快照身份绑定完整目录摘要、表示/策略版本、编码器版本和向量内容。Schema、描述、版本变化必定产生新目录身份。相同文本可复用向量；发生编码器身份漂移时拒绝操作，宿主需重新绑定新实例。
3. 构建和查询串行受同一锁及调用期限约束。全体编码及查询成功后才原子发布新快照；失败或取消保留旧快照，绝不能将它当作新目录返回。不创建后台任务，不缓存查询正文；只保留最后一个目录的有界向量缓存。
4. 目录、表示字节、片段数、向量元素数、乘加工作量和候选数分别有硬上限。所有编码批次检查数量、有限值、非零范数和固定维度。编码器故障、容量不足、超时、取消均显式失败，不隐式降级为词法检索。
5. 发现与索引共用任务准备期限；等待锁和冷构建也消耗期限。本地 ONNX 的既有取消语义是等待当前 CPU 批次结束，再传播取消，不能宣称硬抢占。

## 对话上下文和协议演进

本阶段仅对独立任务的目标和显式约束原文建立查询。如果任务携带历史、应用上下文、先前澄清或 ContextSupply，原文可能包含指代，不能只嵌入最后一句便声称完成语义理解：此时显式回到全目录扫描，报告原因 `context_requires_full_scan`。这是范围边界，不做脆弱的代词关键词猜测；未来有独立证据后再引入有来源的查询重写。

发现报告 v1 原序列化与全覆盖含义保留。配置索引后使用 v2，分别记录完整目录规模、扫描范围、索引召回报告、实际检查卡片数及回退原因。只有所有入围卡完成检查才能发布结果；`completed` 不再暗示完整目录已检查。理解记录携带新报告时使用 v3，旧 v1/v2 继续可读。正式 Session 协议与运行授权不变，详细发现报告仍由显式 reporter 归档。

## 替代方案与验证

不采用纯 BM25 预筛，因为跨语言遗漏是本专题的原始问题；不采用全目录模型重写建库，因为它引入额外随机性、离线生成成本和更复杂的更新语义。当前规模先用精确向量检索，待实际容量和延迟证据表明必要时再引入 ANN 或持久向量库。

确定性测试验证增量复用、撤权和目录变更、原子发布、并发、非法向量、容量、超时、取消、报告版本以及真实准备链路。真实实验复用 ADR 0124 冻结的 96 工具/8 任务，比较原词法、全扫描、混合候选扫描和可容纳的完整目录；冷构建与热检索分别报告。模型文件和运行输出不入 Git。真实选择实验不等同工具执行成功，更不能据小样本宣称框架成熟。
