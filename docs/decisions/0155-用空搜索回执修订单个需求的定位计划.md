# 0155 用空搜索回执修订单个需求的定位计划

2026-11-28。安装迁移任务要求给出依赖的锁定版本，用户没有指定锁文件的名称。模型在准备阶段猜测目录中有 `poetry.lock`，搜索返回空列表。它随后改搜 `lock`，唯一命中并读取了 `uv.lock.packages.tsv`。原计划仍要求用第一次查询定位文件，导致已经取到的材料无法归入该需求。[原始实验与两步取证约定](0154-把来源定位与正文读取编译为两步取证.md)

## 哪些回执可以改变计划

宿主可为稳定的只读目录配置 `LocatedReadRoute(schema_version=2, repair="unique_term_after_empty", ...)`。目录要能以成功返回的空列表证明本次查询没有结果，且来源标识在 Run 内稳定。原查询、所需正文、生产者、工具版本和输入输出指针都写入任务定义。准备阶段另检查任务目标、约束与本次可见的用户消息，若其中出现完整查询（忽略大小写），仍执行精确定位。这个保护识别字面指定的来源，对自然语言指代的理解仍依赖任务准备。

一次归约依照已接受工具回执的顺序推进。

| 条件 | 对当前需求的影响 |
| --- | --- |
| 原查询授权成功，原件中的候选字段是空列表 | 保存空回执引用，模型视图显示可试的查询词 |
| 以原查询中的一个完整词再次搜索 | 按定位器和版本检查该词是否只属于一个需求。固定查询也参与排除歧义 |
| 新查询唯一命中，返回标识也包含该完整词 | 固定首次合格的替代查询和回执，定位步骤完成 |
| 随后按同一完整标识读取，读取原件回显该标识且正文有值 | 原需求达到 `acquired`，正文进入后续分析与交付验收 |

词以连续 Unicode 字母或数字切分，保留原查询中可实际传给工具的拼写。目录搜索可能也匹配正文，因此还要核对返回标识。额外过滤参数、定位器故障、多个命中、单靠路径后缀读取以及跨 Run 拼接都无法触发完整证明。一个词可能泛指许多来源类别，即使在当前目录唯一命中，也只证明定位与读取的结构关系。对要求精确来源、目录可能变化或候选语义需要裁决的宿主，v1 是默认选择。

## 证据与恢复

`LocatedReadPlan` 是已接受的定义。每次归约为每条需求构造自己的 `_LocatedReadEvidence`，以原始回执重新推导 `LookupReplan`。修订落在 `NeedState` v3 中，其中保存空搜索与首次合格搜索的 Run、Call、Artifact 标识和摘要。读取结果通过已有的 Evidence Binding 关联到同一证明范围。该范围的摘要包含原计划、完整来源标识及修订依据。工作笔记重验也按计划版本验证绑定。再次搜索其它词不能替换这个选择。

替换整个任务帧会使同一任务中已经取得的其他材料需要重新判断身份。这里沿用 `need_id` 和原任务依赖，只改变一次查找可以采用的查询。旧状态继续按 v1/v2 读取。丢掉原始空回执后，单靠前一次账本或剩余两条回执无法恢复修订。取消沿原有异步 Artifact 读取路径传播。

每次归约按需求顺序扫描相关记录，原有扫描上界为需求数乘以记录数。启用修订时，另外按原查询总长度建立词归属计数，对可能接受的替代命中扫描一次候选标识。局部修订最多保留两份回执引用。模型视图只增加静态候选词和当前选词，预算在首次投影时预留，模型仍从工具结果或 Artifact 恢复完整标识与正文。

```sh
uv run --offline pytest -q tests/evaluation/test_located_read.py tests/evaluation/test_revision_delivery.py
uv run --offline python -m examples.located_read_replay --compare-query-repair .weavria/revision-delivery/located-stages-20261127/migration-3/located.db
uv run --offline python -m examples.revision_delivery --compare-query-repair --case migration --repeats 3 --catalogue-proof --live --env-file .env.m1-openai --out .weavria/revision-delivery/new-query-repair
```

历史回放以已接受任务帧中的两个查询为起点，两组消费相同的四条定位与读取回执。清单需求 `pyproject.toml` 在两组均为 `partial`，其正文仍然缺失。锁定版本需求 `poetry.lock` 在精确组为 `pending`，允许修订后经 `lock` 达到 `acquired`。回放只读数据库，原运行的终态仍为交付被拒绝。没有原数据库时，确定性测试可从仓库冻结提交重建目录，按同样顺序执行四个调用，并逐个核对原回执的内容摘要。测试还覆盖了一个已取得正文的兄弟需求，逐项比较修订前后的绑定，同时从公开会话入口核验阶段顺序、状态持久化和上下文预算。

正式在线对照使用冻结的安装迁移题、GPT-6 Luna medium、同一评分器和预算。每对从同一份首版会话复制，两组修订均启用两步取证和旧回执重验，交替执行顺序。实验组额外允许本 ADR 定义的局部修订。下表的交付按预定配对计，成本仅计修订阶段实际报出的用量。正式批次的清单和按轮结果存放在本地实验目录 `.weavria/revision-delivery/query-repair-release-20261128`。

| 修订策略 | 三个预定配对中交付 | 两次实际修订中交付 | 模型调用 | 报告的总 Token |
| --- | ---: | ---: | ---: | ---: |
| 精确两步取证 | 1/3 | 1/2 | 23 | 138,136 |
| 启用局部修订 | 1/3 | 1/2 | 23 | 147,799 |

第一对首版因缺证据被拒绝，两组都没有进入修订。第二对精确组完成了两次定位和两次正文读取。实验组查到了清单和锁文件，但只打开了会话原件；三份候选答案都通过独立字段评分，本轮正文证据始终缺失。第三对精确组未取齐材料；实验组一开始就选中 `pyproject` 和 `lock`，随后按完整标识读取两份文件并通过交付。

两次实验组修订都未触发空回执后的改词。因而这一批无法估计触发后的在线交付收益。两组通过数相同，实验组多用 9,663 Token。三个配对来自同一道题，模型在任务准备时也会选出不同查询，不能据此推断总体成功率或成本。宿主仍需显式选择该策略。

在线批次运行时，空回执的探针仍沿用旧诊断标签。交付版将允许继续搜索的空回执明确记录为 `partial / empty / located_lookup_empty`。用交付代码重放正式批次四次修订的搜索和读取记录，逐需求比对，全部十项需求的终态、绑定和探针均与在线存档一致。此前工作树还运行过一次开发诊断，发现工作笔记重验使用了旧版本号后中止，未计入正式对照。

下一次实验宜转向历史原件和本轮证明之间的交接。可对照一份保持原版本、一份内容已变化的来源，观察模型能否从历史阅读转到恰好缺失的本轮重验，并分别记录独立答案质量、交付率和多余读取。
