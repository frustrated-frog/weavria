# 0030 上下文预算交换与证据访问闭包

## 背景与状态

已实现（2026-10-23）。承接 [ADR 0029](0029-任务感知的联合上下文编译.md)，修正 `d3e085f` 中联合上下文编译的分配、准入与资源边界。本决策替代 ADR 0029 中“最新结果先获得实际数据表示”的分配规则，并收紧显式启用编译器时的当前 Run 成果访问范围。默认字节选择路径保留既有行为。

问题来自绑定网页讨论“选择上下文工程”的评审快照（采集于 2026-10-22 16:56:07 UTC，只有采集时已加载的分支），随后对照当前源码和回归用例验证：

1. 按工具顺序给最新结果预分配正文，会让低价值来源先占预算；只增不减的贪心无法撤回它。
2. 编译器省略旧来源，但工具仍可读取全部已接受成果；准入必须为全部潜在依赖预留空间。只缩小预留而不限制实际读取，会破坏下一轮最低回执保证。
3. 候选数量达到配置上限是资源容量不足，不能作为 Runtime 不变量错误结束。
4. 重复索引、重复评分和完整请求分词放大长历史成本；仅限制来源数量和最终片段数不足以控制准备阶段。

## 最终决策

### 可撤回的表示分配

硬约束仅包含必要调用的最低回执、依赖祖先、最近两次交互条目及请求骨架。每个必要调用的实际数据表示获得独立的 `availability:{call_id}` 特征，权重 0.25；引用没有此收益。它是显式策略启发式，鼓励数字和不透明 ID 可见，不保证所有最新输出都能展开，也不等于任务价值概率。

密度与绝对收益两条贪心从同一个最低集合开始。选择较好的可行结果后，执行最多四轮局部修正：检查单项降级、删除或替换，再检查最多 16 个低损失供给项与 16 个高收益接收项的组合。每次变化重建依赖闭包、恢复硬约束，并实测完整请求的 Token 与字节成本。接受效用增加，或效用相同时成本更低的结果。不能假设较低表示序号一定更便宜，也不能把来源成本简单相加。

`max_allocation_steps` 默认 4096，为两条贪心分别保留约三分之一工作量，其余用于修正。搜索截断返回已检查的可行解，不删硬约束。计量缓存不替代候选访问计数；最低集合与最终验证仍必须执行。报告记录 `allocation_steps` 和 `allocation_exhausted`，后者表示任一搜索阶段被工作额度截断，不表示一定用满总额度。

不声称全局最优、任意排列等价或经典近似界。单供给项/单接收项邻域可能漏掉多项交换；依赖补入的引用也可能留下可进一步裁剪的空间。调用与历史的时间顺序仍有协议含义。

### 同一证据闭包贯穿决策、准入、执行和回放

新增 `EvidenceAccessView` v1，绑定任务修订、已接受的 `ControlRequest` SHA256、按时间排列的完整记录闭包 SHA256、调用 ID 和精确 `ArtifactRef`。成功、失败与纯依赖记录都进入闭包，只有含成果的记录提供读取许可。它缩小当前 Run 已接受证据的读取范围，不授予外部工具权限。

执行过程：

1. Runtime 接受 `ContextSelected` 与 `ModelStarted` 后，从权威记录重建访问视图。
2. `reserve_feedback` 验证视图，只为该闭包与提议调用的最坏最低回执预留空间。
3. `BatchAdmitted` v2 持久化同一视图，归约器重新验证请求摘要、任务修订、记录身份、顺序和依赖闭包。
4. 派发时将该批次的精确成果引用传给已有 `ToolContext`。不在集合中的 ID 在存储读取前拒绝；空集合明确表示无可读成果，不能转为旧接口中的 `None`。
5. 工具上报依赖必须属于准入集合，回放同样检查。已启动调用在 steering 后继续持有原准入视图；排队的过时调用按既有规则跳过。

当前 Run 完全省略的来源，即使模型记得其 ID，也不能直接读取。已选引用或片段仍可恢复其原始成果。后续需求变化可以重新选择旧来源；本轮没有自动扩展访问集合的动作协议。Session 历史读取仍受既有 Session 与生产 Run 顺序约束，不能借此读取当前 Run 被省略的来源。可信 Python 工具绕过 ToolContext 的外部 I/O 不属于这个机制的沙箱保证。

未启用编译器时，`BatchAdmitted` v1 继续保留全历史准入与读取语义。编译报告升级为 `ContextCompilation` v2，策略为 `context-compiler/2`；v1 报告与 v1 准入保持原样序列化。外层 `ControlEvent` v3、`SessionContextCompiled` v1、`SessionEvent` v4 和 `SessionRequest` v5 不变，嵌套载荷独立升级。旧读者需要升级后才能读取新嵌套版本，无数据库 DDL 迁移或历史改写。

### 显式准备容量与协作式取消

新增来源编码字节、索引编码字节、索引片段数、估算评分工作量与分配步数限制。原始历史索引按原文摘要缓存，工具索引按 Run/成果身份缓存并重新核对精确引用。任务改变重算评分与选择，不能复用旧选择结果。

JSON 遍历使用惰性迭代器栈；按树节点与片段数量主动让出事件循环。评分使用词项倒排表和单次编译内的片段特征缓存，排序和分配循环也定期让出。取消不发布半成品索引或计划。来源缓存与组合计量缓存各有界；编码字节额度是估算，不是 Python 堆内存或 RSS 上限。

数量或准备容量超过限制抛出 `ContextCapacityError(resource, requested, capacity)`，Runtime 以 `budget_exhausted / context_capacity` 终止。`mandatory_units` 与 `candidate_units` 区分必需闭包过大和总候选过大。本次仍拒绝整个超限候选集，不静默截断，也未实现可溢出的预检索层。最低请求超出 Token/字节预算继续使用 `context_tokens` / `context_bytes`。

## 替代方案与取舍

- 只移除预分配：可修正特定顺序反例，但不能撤回贪心已选低收益表示；因此加入有限交换，同时显式暴露其额外成本。
- 保留全成果读取、仅预留可见来源：不能证明下一轮闭包可放入，拒绝采用。
- 完全取消已省略成果的回读：损害精确恢复；改为允许选中来源的完整回读，并明确完全省略来源需要先重新进入决策视图。
- 解析模型参数并临时扩大读取范围：自定义工具参数不具有统一的证据语义，也不能用模型声明绕过准入。未来若需要范围扩展，应作为受控的新决策与重新预留过程设计。
- 精确背包求解或后台线程分词：前者成本不适合完整请求非加性计量；后者不能靠取消 Future 停止实际 CPU 工作。本次使用有界近似与协作式取消，保留单次同步解析、散列和 BPE 的不可抢占局限。

## 验证与后果

顺序回归在旧代码复现：预算只允许展开一个结果时，低价值来源先出现会遮住 `VIOLET`；交换顺序才可见。新实现两种顺序均保留关键片段。局部交换的独立五项背包用例从两条贪心都得到的效用 29 提升至穷举最优 34，只证明该反例。

40 条记录中仅开放一条时，预留量等于只有该条记录的情况。实际 Session 验证隐藏 ID 拒绝、可读结果依赖、批次 steering、重放以及篡改摘要/修订/依赖的拒绝。容量、索引取消、缓存复用与搜索截断另有回归测试。

冻结信息保留语料在三个窗口下的分数未变；局部交换增加了小语料编译成本。百万字符、64 次历史与 16 个需求的资源探针限定搜索到 512 步，三次编译约 408/384/383 ms，未证明真实任务收益或延迟 SLA。复现方法与完整限制见 [上下文编译修复与资源边界](../上下文编译修复与资源边界.md)。
