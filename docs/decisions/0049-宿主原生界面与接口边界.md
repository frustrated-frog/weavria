# ADR 0049：宿主原生界面与接口边界

## 背景

ADR 0009 为快速隔离样式和会话状态，让 FinScope 通过 iframe 加载 Sidecar 自带的 Widget。
真实试用表明，这种方式虽然隔离明确，却在 FinScope 内形成第二套标题、欢迎页、主题和错误展示，
宿主也无法使用自己的组件体系处理 Agent 返回结果。运行时接入与产品界面因此被错误绑定。

本次调整只纠正应用边界，不改变 Weavria Runtime、任务理解、工具执行、持久会话或完成验收语义。

## 决策

1. FinScope Sidecar 只提供健康检查、创建会话和发送消息的结构化 JSON 接口，不再托管 HTML、
   CSS、JavaScript 或 Markdown 渲染器。
2. FinScope 使用自己的 React 组件渲染完整问答页和市场悬浮窗，并负责输入、加载、错误、
   Markdown、工具轨迹和响应式布局。
3. Sidecar 继续拥有 Agent 会话、Run 和 Runtime 状态；宿主只保存不透明的 `session_id`，不得
   解释或修改 Weavria 的内部状态。
4. 页面上下文仍是导航元数据。回答所需的权威事实必须由 Runtime 通过已注册的只读工具重新读取。
5. 浏览器跨 Origin 调用继续使用显式允许的宿主 Origin；API 响应统一禁止缓存和页面嵌入。
6. 本轮不新增 FinScope 后端代理、流式协议或通用 Managed Runtime Host。同步接口保持现有契约，
   避免将界面重构扩大为 Runtime 改造。

## 备选方案

### 继续维护 iframe Widget

可以保持最强隔离，但宿主视觉、可访问性、错误语言和交互状态需要重复实现，且每个接入应用都会
得到一套独立页面。真实试用已证明代价高于收益，不采用。

### 在 FinScope Java 后端复制会话接口

可以形成同源调用，但会增加一次无业务价值的转发，并把会话错误映射复制到 Java 服务。当前
Sidecar 只绑定回环地址且已有明确 CORS 边界，本轮不采用。

### 将 UI 抽象加入 Weavria Core

会把 React、主题和产品交互变成 Runtime 依赖，直接破坏领域无关性，不采用。

## 后果

- FinScope 页面与现有视觉、主题和可访问性规则保持一致，返回数据可以在宿主侧直接呈现。
- Weavria 应用适配器的公开表面积缩小为 JSON API，不再承担产品 UI。
- 完整页与悬浮窗仍可共享持久会话，但各自的临时输入和滚动位置由对应 React 组件维护。
- 移除 iframe 不会修复模型结构化输出失败；这类问题仍属于通用模型适配与 Harness 诊断边界。
- 若未来需要远程部署、认证或流式事件，应单独设计通用 Host 契约，而不是重新把应用 UI 放入
  Sidecar。
