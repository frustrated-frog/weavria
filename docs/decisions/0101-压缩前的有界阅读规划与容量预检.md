# 压缩前的有界阅读规划与容量预检

## 问题与阶段边界

0100 的真实实验已经能把压力提示送到模型，但实际交付经常只有几十到几百字节的摘录。原策略要求单项至少 1 KiB、合计至少 4 KiB，无法给出具体来源；模型也不知道下一步应读哪个已接受范围。另一个问题是，某个补读窗口即使满足恢复载荷上限，也未必能和指令、工具协议、历史、受保护范围及反馈预留一起放入下一轮请求。

本次把“何时可以压缩”和“压缩前先读什么”接成一个有界机制。阶段验收要求：只对已显示内容建议压缩；补读建议必须指向已接受原文，通过完整请求预检，并能在预览的下一轮产生覆盖该窗口的压缩建议；失败、取消和重开不能暗中接受恢复事实。真实模型是否采纳、摘要是否保真、任务是否改善，另用实验回答，不以协议测试代替。

通过 `ContextCompilerConfig(semantic_compaction=True, summary_guidance=True, summary_preparation=True)` 启用。前两个开关单独开启仍保持 0099/0100 策略；新增开关默认关闭，不新增运行依赖。

## 来源成本与候选选择

`summary_pressure.py` 继续计算实际压力、排除已压缩/已尝试范围，合并相邻且确实交付的文本范围。准备策略把候选绑定成 `CompactionInput`：原文地址、Artifact 引用、真实字节数、内容摘要，以及是否为摘要节点。这里读取的是不可变快照，不生成摘要正文。

`summary_preparation.py` 根据真实来源构造只用于尺寸计算的临时节点，扣除来源表、节点字段和最小陈述结构的成本，再预留 64 字节净节省。剩余空间至少能容纳 512 字节陈述时才有候选，交给模型的建议正文预算最高 1024 字节。临时占位文本不持久化、不进入模型视图。

先按来源体积减来源元数据成本排序，取前八项，再穷举至多四项的 162 个组合，选择净容量最大的可行组合。搜索每步可取消，没有无界组合爆炸。这是有界的字节成本启发式，不声称全局最优、语义保真或 Token 节省。陈述拆分、引号和转义还会增加开销，`compact_context` 必须用模型实际提交的完整节点重新核验压缩收益。

这使不足 4 KiB、但足以支付真实来源成本的范围也有机会被建议压缩。对于只有很短片段或元数据很大的来源，仍然拒绝；不以降低工具校验来保证摘要成功。

## 补读规划与完整请求预检

如果没有可压缩材料，则沿现有 `CoverageScorer` 找到与任务有关的原文段落。候选只来自当前 Run 已接受的普通 Artifact，不能把摘要作为待恢复的权威原文；排除已完整交付、已摘要覆盖和当前已恢复范围。

一次最多建议一个连续窗口，字符上限 4000，JSON 编码载荷上限为 `min(3072, max_bytes_per_round, max_total_bytes)`。用二分搜索确定字符边界，按实际 UTF-8 与 JSON 转义计量；不能把字符数当字节数，也不能跨越已经恢复的后续范围拼接缺口。窗口自身还必须能够支付摘要元数据成本。

编译器随后使用已有恢复规划器与自身的编译过程预演：

1. 从不可变快照生成临时 `RecoveryResolved`，不提交恢复事件、不更新配额。
2. 按实际 retention 方式组合恢复保护范围，保留普通请求的任务、历史、最低反馈、下一步预留和其他容量约束。
3. 编译恢复后的完整请求。内部 `_summary_probe` 禁止再次生成补读建议，避免递归规划；仍可对预览中已显示的窗口建议压缩。
4. 除了请求可放入，还要求预览建议确实覆盖本次目标窗口，不能借另一个来源的压缩候选冒充成功。
5. 不可行则将字符长度减半，最多尝试三次；仍不可行时交付 `idle/recovery_budget`，不强行恢复或降低保护。

预检只证明当前视图、当前范围和预估恢复通知下的局部可行性。编译器没有 Runtime 全部累计恢复计数，预演使用第一轮/零已用字节；真正执行仍由 Runtime 按全部历史、真实轮次、累计字节、重复范围、当前任务修订和完整请求重新检查。之后状态改变，建议仍可能被拒绝。当前失败通知或 remaining_rounds 为零时，不再主动建议补读。

三次预览增加本地编译开销；成功返回的预览计量次数纳入 compilation.evaluations，预算异常中断前的内部计量尚不单独归集。没有额外模型调用，没有后台任务。取消直接传播，预演返回前没有可提交的半成品请求。仅允许最终回答的 synthesis 阶段不生成建议，并释放建议预留。

## 契约、状态与兼容

- `SummaryAdvice` 新增 v2 / `summary-preparation/2`，显式包含 `reason`、可选 `recovery`、`preparation_bytes` 和 `statement_budget_bytes`。
- `recover/read_before_compact` 表示尚未读到的精确目标，`sources` 必须为空；只有下一轮正文真正交付后才允许 `compact/compactable` 或 `merge/compactable`。
- `idle` 区分无压力、材料不足、恢复不可用、恢复预算不足和建议自身放不下。`attempted` 表示不重复催促同一已尝试范围，不禁止工具合法重试。
- 来源仍需由本轮交付清单或已展示的摘要节点证明可见；存储层额外核验恢复建议的 call_id/digest 属于当前 Run 已接受的原始 Artifact。
- 请求新增 v10、编译报告新增 v16，旧父版本不得携带 v2 建议。未开启准备策略时仍产生原来的 v9/v15 或 v8/v14；建议 v1 不序列化新字段，旧记录无需批量迁移。
- 建议不授权执行、不构成来源证据、不更新任务完成状态，也不要求模型在可以直接回答时强制压缩。

## 取舍与尚未解决的问题

选择复用 Runtime 恢复与完整编译，而不是自动调用摘要模型或单独估算一份“阅读容量”。前者保持显式决策、账本和取消语义，后者避免两套预算模型漂移。代价是额外本地编译，以及保守预留可能使小窗口也无法准入。

仍未实现语义缺口规划、对多候选窗口的全局搜索、按剩余运行预算优化摘要时机、摘要内容保真评估、跨 Run 摘要继承或自动长期记忆。第一层摘要才会被主动建议合并的既有边界保持不变。模型可能忽略建议，或生成不节省空间/丢失条件的摘要；当前策略不能保证这些问题消失。

## 验证与证据

确定性测试验证补读前没有虚假交付、补读后不足 4 KiB 的范围可产生合法摘要、原文保护不被移除、Unicode/JSON 字节配额、恢复失败后的停止、窄预算缩窗/撤回、预检取消清理、旧 Schema 与新版父子绑定、synthesis 释放预留，以及真实 SQLite Harness 四次显式模型决策后的重开幂等返回。替身决定行为，因此不证明自主采纳和语义质量。

真实实验复用冻结 M1 文档、模型配置与调用预算，新增 `prepared` 组、逐轮可见范围尺寸及原因诊断。首轮暴露“载荷可放入、完整请求放不入”，据此增加预检。后续结果与运行命令见[执行过程与实验](../分层语义压缩的执行过程与实验.md)。本次没有新增论文复现主张；设计依据为 0099/0100 的机制和这里记录的可复现失败。
