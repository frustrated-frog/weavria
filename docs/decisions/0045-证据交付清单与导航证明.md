# ADR 0045：证据交付清单与访问证明

- 状态：已采纳并实现
- 日期：2026-10-27
- 范围：Context Compilation、Artifact、Runtime State、Action Intervention、Replay
- 前置：[ADR 0029](0029-任务感知的联合上下文编译.md)、[ADR 0035](0035-结构化成果分页与模型协议恢复.md)、[ADR 0044](0044-完成建议下的有界成果续页.md)

## 背景

`ContextChoice` 只记录某个来源被编译为 `raw`、`excerpt`、`reference` 还是 `omitted`。
`ContextSelected.selected_call_ids` 也只能说明某次 Tool Call 在请求视图中可见。两者都不足以回答：

- 本次模型请求实际携带了哪个 Artifact 的内容；
- 携带的是完整值，还是哪些 JSON Pointer 与字符区间；
- 后续控制决策依赖的证据，是否真的出现在那个确切的模型输入中。

原有有界续页逻辑在 Runtime 中临时返回一个布尔值。它能检查 Artifact 客观存在和游标
连续，却无法证明上一页已交付给本轮模型；布尔值也没有记录证据来源，因而无法在持久
化事件和回放中重建“为什么允许这一步”。更进一步，真实运行出现了一个混合批：模型同时
请求一个精确续页和一个当前请求只交付了片段的父路径首读。语义 Need 已覆盖，但模型尚未
取得形成答案所需的原文；单调用续页例外仍会把整个批判为“应当完成”。

## 决策

### 内容无关的交付清单

`SessionContextCompiler` 在最终分配决策和完整 `SessionRequest` 都已确定后，生成
`EvidenceDeliveryManifest`。它只携带身份、摘要与范围，不复制任何证据内容：

- `task_revision`；
- Runtime 真正发给 Provider 的 `ControlRequest` 摘要；
- Session 传输请求 `SessionRequest` 摘要；
- 每个交付 Artifact 的 Run、Call、Artifact 身份、内容摘要和字节数；
- `raw` 完整表示，或 `excerpt` 下的精确 JSON Pointer、标量值标记与 Unicode 字符区间。

`raw` 不允许再携带区间；`excerpt` 必须有至少一个去重后的精确范围。清单中的每个交付
必须与 `ContextChoice` 的最终表示一致。`ContextCompilation` 升级为 v7，并将清单绑定到
完整传输请求摘要。

### 进入 Runtime 的持久事实

Session 适配器仍只把 `ControlRequest` 交给 AgentLoop。Runtime 在模型调用前解析编译回执，并将
清单放入 `ContextSelected` v3。归约器同时验证：

- 清单的 `control_request_sha256` 与当前 `ContextSelected.request_sha256` 一致；
- 每个交付 Call 确实被选中；
- Artifact 已通过执行事实接受，且 Run、Call、ID、SHA-256 与大小全部一致。

RunState 只保存最新一次确切请求的清单；任务修订时清空。这是“当前模型看到什么”的
短生命周期事实，不是长期记忆或证据真值。

### 类型化的逐调用访问证明

当进度建议模型完成、但模型提议继续 `read_artifact` 时，Runtime 只在以下条件全部成立
时构造 `EvidenceAccessProof`。证明必须与批内调用一一对应；只要一个调用无法证明，整个提案
就不获得例外。每个调用只能属于以下一种：

1. **精确续页**：最近一次同源、同 Pointer 的读取结果在当前清单中以 `raw` 完整交付；
   Runtime 从 Artifact Store 按摘要重新解析 `ArtifactReadOutput`，验证上一页确实满足
   `start < end < total`、`has_more=true`，且新调用的 `start == previous_end`。
2. **缺口首读**：该源 Artifact 在当前请求中只以 `excerpt` 交付、调用从 `start=0` 开始，
   且当前 Run 尚未成功读取过同一源与 Pointer。Runtime 以源 Artifact 的已接受摘要读取值，
   将直接片段和本轮完整交付的既有分页结果都投影回源 JSON Pointer，再生成一个仍未覆盖的
   `EvidenceDeliveryRange` 作为具体缺口见证。已完整交付的 Pointer 不能获得首读证明。

证明绑定任务修订、当前 ControlRequest、交付清单、完整提案、源 Artifact，以及每个调用的
缺口或游标。`ActionInterventionChecked` v3 持久化新证明；v2 的单页
`EvidenceNavigationProof` 只用于已有事件兼容。归约器重新验证当前请求、清单、提案顺序、
已接受 Artifact、缺口见证和前一页调用。`verify + neutral` 下，纯续页记录
`evidence_navigation_continuation`，含缺口首读的批记录 `evidence_access_pending`。

证明成立说明模型可见证据前沿会推进，因此语义停滞计数不再阻止该批；规范化动作重复、
Tool Policy、反馈预算、工具总预算和运行时限仍继续生效。首读不能重复同一源与 Pointer，
续页只能单调推进到 `total`，没有把任意模型探索升级为进展。

## 关键不变量

- Artifact 客观存在不等于它的内容已交付给本轮模型。
- `selected_call_ids` 或 `raw` 字样不能单独授予访问例外；决策必须依赖绑定当前请求的清单。
- 摘要和范围可进入 Trace，证据内容不因本机制被复制进事件。
- 一个混合批中的每个调用都必须有证明；不静默删除或改写模型提案。
- 无清单、源仅为引用或省略、缺口不存在、Artifact 或游标不匹配时一律失败关闭。
- 该证明只授权有界证据访问，不改写任务义务、证据真实性或完成验收结果。

## 考虑过的替代方案

1. **保留布尔 `bounded_continuation`**：实现简单，但无法审计来源，也不能证明当前模型已见
   上一页，拒绝。
2. **仅依赖 `selected_call_ids` 或 `ContextChoice`**：无法区分参考回执、片段和完整内容，拒绝。
3. **把实际证据内容写入清单**：可自给验证，但会在 Journal 中复制大块且可能敏感的 Tool
   Output，违反 Artifact 卸载和 Trace 最小化，拒绝。
4. **把访问读取计为新义务或新证据源**：会污染语义进度度量并让同源分页虚假增益，
   拒绝。
5. **只要批内含一个合法续页就整批放行**：会让普通工具或重复读取搭便车，拒绝；采用逐调用
   证明和全批失败关闭。

## 结果与局限

本机制建立了从“编译后的确切模型输入”到“允许下一步证据访问”的可回放因果链。
它不建立跨多轮的累计可回答性，不证明最终答案已覆盖所有义务，也不把通用 Completion
Evaluator 的 `unverified` 结果提升为已验证。当前清单只代表最新一次请求；跨轮证据闭包、
独立的 Finalization Reserve、答案义务覆盖和引用正确性需要后续独立设计与评测。

## 验证

- 契约测试验证 v7 Context、v3 Intervention、双请求摘要绑定、内容无关序列化、区间并集
  覆盖与重复源位置拒绝。
- Compiler 测试验证必选自适应反馈和完整分页反馈都保留实际交付描述，且清单不含原文。
- Runtime 正例验证单续页，以及“精确续页 + 未交付首读”的混合批；反例验证没有当前交付
  清单时，即使相同 Artifact 和游标都可用，干预仍会拒绝。
- 回放测试逐事件归约真实运行，验证清单与逐调用访问证明能重建到同一终态。
