# ADR 0044：完成建议下的有界成果续页

- 状态：已采纳并实现
- 日期：2026-10-26
- 范围：Artifact、Progress、Action Intervention、Agent 收敛
- 前置：[ADR 0035](0035-结构化成果分页与模型协议恢复.md)、[ADR 0028](0028-行动收益量纲与局部失败控制修正.md)
- 修订：[ADR 0045](0045-证据交付清单与导航证明.md) 用持久化的类型化证明取代了临时布尔信号

## 背景

进度评估以任务义务和证据覆盖为主。当一个大型 Artifact 已经证明某个宽路径存在时，Need
可能投影为 `SATISFIED`，但模型仍需继续读取该路径的下一页，才能形成可交付答案。续页不会
增加独立来源或义务覆盖，因此被评为 neutral；默认干预策略在 `verify + neutral` 下要求模型
直接完成。

真实 FinScope 轨迹中，模型正确读取 `/data/recentRegimes` 第一页并得到 `has_more=true`、
`end=3`，随后三次请求 `start=3`。Runtime 把这些请求全部判为“完成后多余动作”，最终以
`intervention_exhausted` 失败。这里不是模型拒绝收敛，而是进度量纲没有表达“同一权威成果的
有界读取尚未闭合”。

## 决策

1. Runtime 在干预前识别窄而可证明的 Artifact 访问：提案只能包含 `read_artifact`，且每个
   调用都必须由 [ADR 0045](0045-证据交付清单与导航证明.md) 的逐调用证明覆盖。
2. 最近一页必须来自当前 Run 已接受的 Artifact，严格通过 `ArtifactReadOutput` 校验，声明
   `has_more=true`，且新请求的 `start` 必须精确等于上一页 `end`。
3. 当前请求只交付源 Artifact 片段时，也可以证明一个从零开始、具有具体未交付范围见证的
   首读；同一源与 Pointer 已成功读取过后不能伪装成首读。
4. 只有在进度建议为 `verify` 时，完整证明允许一次 `verification_advisory` 派发。普通工具、
   跳页、回读、已完整交付内容和结束页都不获得例外；混合批中任一调用无证明则整批拒绝。
5. 每一页执行后重新评估。若仍有下一页，下一次请求必须再次满足连续性证明；`has_more=false`
   后恢复原有完成干预，防止无限读取。
6. 干预策略版本升级为 `progress-action-intervention/7`；该证明只改变是否允许读取，不把派生
   页错误计为新的独立证据来源。

## 取舍与限制

本次不把任意“模型认为还需要信息”的动作视为进展，也不修改 Need 的证据覆盖语义。它只承认
框架自有、可验证游标的严格续页，或当前请求中可定位的实际交付缺口。跨页摘要质量仍由模型
和完成策略负责；未来若加入其他有游标的框架级恢复工具，应定义各自的连续性证明，不能仅靠
工具名白名单放行。

## 验证

确定性回归构造三段文本 Artifact：首次读取在 productive→verify 边界按原规则放行；进度变为
neutral 后，精确的下一页仍被派发并留下 `evidence_navigation_continuation`
决策及类型化证明；另一个回归同时提交精确续页与有缺口见证的首读，验证两个调用都执行并
留下可回放的 v3 证明。没有当前请求交付清单时，即使 Artifact 客观存在，同一续页也必须
失败关闭。
原有“verify 后阻止普通工具”和“反复忽略干预显式失败”测试继续成立。
