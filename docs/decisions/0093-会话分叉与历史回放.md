# 会话分叉与历史回放

宿主可以通过 `AgentHarness.fork(source_session_id, through_run_id, session_id=..., access=...)` 或 `SessionEngine.fork` 从已完成的历史轮次创建新会话。宿主把已认证主体绑定到 `SessionForkAccess`，分别授权读取源会话和写入目标会话。锚点包含在继承范围内。已完成的历史轮次保留用户输入、助手文本及用户发起的任务修订，子会话下一次输入创建自己的 Run 和任务状态。

SQLite 在同一个事务中创建目标会话并写入其第一条 `SessionForked` 事件。事件携带父会话、锚点及有界的对话快照。之后读取历史只合并这份不可变快照与子会话自身的轮次。通过源会话、锚点和目标会话这组身份重复请求会返回原结果，目标会话被其他来源或锚点占用时拒绝。进行中的锚点也会拒绝。单个快照最多包含 64 个轮次，事件载荷上限为 256 KiB。

分叉继承的是当时已交付的对话，执行日志、Artifact 读权、活动任务、待澄清状态和记忆形成游标均由各自会话管理。回放使用已有历史分页和事件读取 API，能在重启及本地执行投影重建后读到同样的继承前缀。新的模型请求经正常的上下文预算编译，在持久化请求前按原文核验范围和摘要。首版对分叉会话使用有界的历史窗口，持久倒排索引仍服务普通会话。后续可扩展对继承历史与本地历史的统一索引。

`uv run pytest -q tests/sessions/test_fork.py` 覆盖历史锚点、并发重试、父子隔离、二次分叉、重启回放、授权拒绝、取消以及跨会话原文读取隔离。脚本模型验证实际请求里的历史边界。
