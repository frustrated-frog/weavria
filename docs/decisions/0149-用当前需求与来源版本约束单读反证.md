# 用当前需求与来源版本约束单读反证

状态为已实现，按工具显式启用。适用于同一会话内，反馈预算拒绝一组只读工具、至少两个候选可以单独完整交付的场景。

## 一份完整交付的原件可以推翻读取建议

此前的精确匹配会用最近 16 个现场的完整交付次数估计下次送达率。模型读到时刻表的撤回声明，并可据此改读公告，但这次完整交付提高了下次先读旧表的概率。仅按文件名降权会影响新版时刻表，也会影响确实需要旧版的历史查询。再调用一次模型判断会增加读取前的时间和费用。

本次沿用原有工具反馈轮。模型可以在一次响应里说明来源对当前任务适用、明确不适用或证据不足，同时继续读公告或作答。这是可错的模型判断。宿主能验证谁看到了哪句话，判断其语义仍由模型负责。

## 从一次纠错到下一次选源

1. 内容可寻址的外部只读工具可在注册时指定 `result_sha256_parameter`。该参数位于通过工具校验的归一化输入中，非空值指向完整结果的规范 JSON SHA-256。规范编码为 UTF-8、对象键排序、紧凑分隔符、保留 Unicode。适配器可以从已有的版本清单填入摘要。执行器在写入 Artifact 前核对实际结果，版本不符产生 `INVALID_TOOL_OUTPUT`。缺少版本时仍可普通读取。
2. 支持这种工具的会话模型随正常决策返回判断。负向判断携带指向 `output.data` 内字符串的 JSON Pointer 和 1 至 384 字符的原文引句。OpenAI 兼容适配器只为当轮的单条完整反馈定位引句。规范化后留下原件摘要、指针、字符区间和引句摘要。附注遗漏、引句不存在或重复时，普通决策仍可执行。
3. SQLite 投影在接受 `TurnDecided` 的同一事务内匹配原先拒绝、紧接的单独重提、调用身份、任务修订和反馈请求。在核对完整交付后，重新根据持久原件验算区间和摘要。自定义 Provider 同样要通过这层核验。成功后同时记录 `delivery=full` 和适用性判断。
4. 下次排序先按会话、可见性、冻结配置、目标、约束和归一化候选集合回取记录。使用版本固定的动作时，有任务模型视图则同时绑定投影器版本和任务定义摘要，仅有任务观察时绑定完整观察。在窗口内，对当前动作及其固定摘要取最近一次明确判断。反证使该候选排在其他可行候选之后。同组继续按原有 Beta(1,1) 平滑的完整交付率排序，同分保留提案顺序。证据不足不覆盖先前的明确判断；没有匹配判断时沿用原排序。该机制只影响建议，模型仍可主动复核任何获准的来源。
5. 版本、需求或候选集合变化会切断该现场的反证复用。普通未固定版本的读取继续使用交付统计。任务理解生成的定义变化也可能降低命中率，本轮没有验证改写需求之间的反证迁移。

`ToolDescriptor` v11 标识内容版本参数。`ModelTurn` v4 表达随决策提交的判断，`ReadRetryOutcome` v2 表达核验后归属到完整交付的判断。旧版编码保持原样。SQLite v14 给原索引增加可空的判断列，旧记录保留交付事实，升级时不补造判断。

## 成对验证

实验使用冻结的虚构公交资料。每个分支从独立会话开始，固定触发拒绝的首个提案和种子任务的第一次实际读取。目标任务仅固定首个提案；之后由模型自行选择实际读取和答案。两组使用相同的目标、预算、候选顺序和资料，基线使用原交付排序，实验组开启工具版本核验、随轮判断和反证排序。每组两轮，第二轮对调组序。种子与目标都通过 `AgentHarness.send()`。严格答案只有在本次模型请求确实包含指定原文时才计为正确。

2026-11-23 使用 `gpt-6-luna`、`medium`。表中每格依次为基线和实验组，两轮合计。

| 目标任务 | 有效首读 | 实际读取次数 | 有原文且答对 | 目标阶段真实模型调用 |
| --- | --- | --- | --- | --- |
| 同版本再次查当前时刻 | 0/2 → 2/2 | 4 → 3 | 2/2 → 2/2 | 7 → 5 |
| 同名时刻表更新并恢复有效 | 2/2 → 2/2 | 5 → 5 | 1/2 → 2/2 | 8 → 7 |
| 查询撤回前的历史时刻 | 2/2 → 2/2 | 3 → 2 | 2/2 → 2/2 | 5 → 4 |

包括种子在内，两组实际 HTTP 调用合计分别为 34 和 28。判断没有独立模型调用，但提示和输出会多占 Token。实验组 6 个种子中 5 个形成了可核验反证，历史查询的一轮没有形成反证。确定性回归另外覆盖已形成反证时的历史查询、版本未知、弃权、伪造引句和来源不符。

最初用可选附注说明时，真实模型经常正确改读公告却省略判断。明确响应的两个顶层字段后，两轮重复任务都先读了公告。其中一轮模型拿到正确公告后又读了旧表，另一轮只读一次。首读修正得到复现，稳定节省整次读取的门槛仍待验证。此次样本量仅支持该冻结现场的观察。历史查询的读取差异也可能来自模型波动和提示变化。

## 复现

```bash
uv run pytest -q tests/test_read_counterevidence.py tests/test_scoped_read_retry.py
uv run python -m examples.read_counterevidence --env-file .env.m1-openai --rounds 2
```

真实实验需要配置模型凭据，脚本使用临时独立数据库，只打印指标和这组公开合成任务的答案。
