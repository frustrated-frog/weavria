# 0082 来源语境与可执行阅读反馈

状态：已实现并完成局部复测，2026-11-02；M1-06 仍未通过。范围仍为 M1 的阅读、回取、工作记录与收尾链路。

## 问题与依据

网页评审《代码评审与规划》（2026-11-02 19:12 同步）提出的断点经代码和保存请求核对：

- `/text` 的短片段缺少所在文档、章节和函数，示例值容易被当作配置默认值。
- 首次源码诊断中，反馈预算为 30626 字节；4000 字节页需 31680 字节，3000 字节页仍需
  30680 字节。原反馈只建议一次调用，无法指导一个调用应该读多少。
- NeedFinalizationPolicy 把整字段交付作为唯一可用证据，局部原文及其回取页无法支持有限收尾。
- WorkUpdate 要求模型重复填写任务版本、工作版本和笔记编号。模型仍承担结论与引用，宿主应该
  从产生这次提案的视图绑定这些机械字段。

第一候选的两个原始长任务、两策略各三次诊断均未通过，工作提案仍为零。进一步观察发现，源码
中的缩进注释被当作 Markdown 标题；回取后模型会误用 `/data/value` 并读回取页而非原始来源。
这些都是阅读表示与模型交互的问题，不能靠调整评分或强制写笔记解决。

## 机制

### 有来源语境的多粒度摘录

`text_windows` 保留 Unicode 原文偏移，以 320 字节片段作为紧凑候选。通用装饰标题、Markdown
标题、Python 类和函数形成有界语境；缩进代码注释不成为 Markdown 标题。语境携带原文和精确
区间，不生成摘要，不提升其可信度；其序列化成本计入索引和 Prompt。

CoverageScorer 保留 IDF 词项覆盖，增加带下划线或限定名的完整标识符匹配。正文匹配权重高于
作用域匹配；来源锚点只给较小的可用性权重。较大表示将中心片段扩展到同作用域的相邻原文，
最多约 1200 字节；紧预算仍能选择最小片段。它改善可读性与符号定位，不声称实现语义检索。

模型请求的交付 Manifest 同时记录正文和语境范围，不能把只在元数据里出现的整个文件视为已读。
主动回取仍沿用已有 ContextCompiler 和原始 Artifact，按现有轮数与字节额度执行。

### 由真实预算算出页长

ToolDescriptor v5 可声明 `feedback_page_parameter`，表示一个有有限整数上下界、对反馈成本
单调的页容量参数。它必须同时提供 complete feedback 和版本化成本估计器。

拒绝时 Runtime 对该参数作二分搜索；每个候选都重新归一化、生成绑定 Action 的包络，并调用
原来的 reserve_feedback。计算包括请求固定部分、任务视图增长、因果依赖回执、完整结果、
控制反馈和编译器根据 Token 容量给出的反馈预算。AdmissionNotice v2 给出原批次索引、参数名
和单独重提时的最大值；0 表示当前最低输入页也容纳不了。

这是建议，不改写已提出的 Action；重提仍经过原来的准入和执行。建议针对同一位置、参数和
当前快照；它不承诺任意更换参数、调用 ID 或预算后仍然可用。页内容的最小编码大小仍由实际
工具校验，结构化子项可能只能返回地址。

read_artifact v6 / artifact-read-output/2 返回 `next_read`，直接指向原始 Artifact、原始
pointer 和返回的 end，避免模型按字节加游标或读取外层 `/data` 包装。下一页元数据也被完整
成本估计器覆盖。旧保存页缺少 next_read 时仍可解析。

### 连续恢复形成有界阅读工作集

第二候选的保存请求暴露出更深一层断点：每次 recover_context 都替换当前恢复片段，而 seen
继续累计。模型的下一次请求看不到先前片段，也无法用同一查询重新取得它们，最后甚至在 limit
反馈中丢失全部恢复内容。独立请求之间没有隐藏对话记忆，不能把这个缺口交给模型自行记住。

RecoveryLimits v2 增加 `retention="chain"`，推荐装配启用此语义；各项轮数、每轮范围数、每轮
与总字节限额保持原值。连续恢复将新片段并入当前工作集，预编译验证整个集合能进入下一次请求
后才接受。预算不足、无命中、重复或额度耗尽保留旧集合，不接受未交付的新片段。普通工具批次
结算、终态或任务修订释放工作集；提案被拒或最终答案要求修复时不提前释放。

旧 v1 配置继续使用 latest 语义且序列化不增加字段。配置持久化于 RunStarted，因此同一事件流
的重放不会因新版本默认值而改变。工作集只保留精确来源区间，不替代 WorkingState 的结论记录。

### 局部原文可以支持有限收尾

完整字段交付仍用于判断完整覆盖，语义满足仍决定是否可提前收尾。在预算、停滞等既有收尾
边界上，只要请求实际交付了所需来源的局部原文，可以进入 limited；缺口继续保留，完成判定
仍为不可验证。原始 Artifact 只剩回执但完整回取页可见时，将页区间映射回同一个来源。

因此“能给出有限回答”与“已穷举资料／验证结论”保持不同语义；引用回执不能开启这条路径。
导航和收尾共用 Runtime 的页区间映射，不让 Context 反向依赖 Tool。

### 从提案视图绑定工作记录

propose_work v3 接受 WorkDraft：模型填写笔记种类、摘要、关联需求、来源与下一步意图。任务
版本和 base_revision 缺省时取自本轮模型已看到的 WorkingState；笔记编号缺省时按内容散列
生成。ToolContext 只提供产生提案的 TaskModelView 快照，返回独立副本，不暴露最新可变状态。

接受后仍产出原有 WorkProposal / WorkUpdate，保留明确版本、CAS 和重放语义。同批提案不能
看到兄弟执行的新状态；旧客户端的显式版本继续有效，独立使用工具且无视图时仍须显式传版本。
框架不代写事实、不伪造工作记录，也不把笔记设成所有 Finish 的必经条件。

## 版本与替代方案

- 保留旧 AdmissionNotice v1 和 ToolDescriptor v2–v4 的线格式；新字段须声明对应版本。
- ContextCompilation / ConversationView 在组合供给链路采用 v12；旧报告仍按原版本解析。
- 统一装配 v8、RecoveryLimits v2、TaskModelView 投影器 v4、NeedFinalizationPolicy v4；WorkingState、NeedLedger 的持久结构不变。
- 拒绝扩大输入窗口来掩盖分页问题，也不引入自动执行的隐藏读取。模型选择要读什么，宿主计算
  怎么表达与执行；不依赖 M1 文件名、字段答案、FinScope 数据或金融术语。
- 不引入新的存储或 Agent 循环。完整代码语法树、语义检索、跨源结论验证不在本次范围。
