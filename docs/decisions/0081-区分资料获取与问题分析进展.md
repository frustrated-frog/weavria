# 0081 区分资料获取与问题分析进展

状态：已实现，2026-11-02。对应 M1-06，不扩展里程碑范围；真实任务收益仍未证明。

## 问题

第二轮真实验收中，documents_long_context 的多个问题均绑定 `/text`。读取整份研究资料后，
StructuralEvidenceExtractor 只检查字段存在，NeedLedger 却把所有问题标成 satisfied。
工具选择随后撤下阅读工具，上下文降低需求权重，提前收尾把执行转向 synthesis。
repository_long_context 还有把具体问题解释成“取得整份源码”的情况。两组实际均未调用
propose_work；工作记录的入口存在，不能证明模型用它完成了分析。

这里有三种不同进展：资料已取得、模型已有阶段结论、需求有语义证据覆盖。需要分别表达，
并让它们改变下一次行动和上下文。不能只加强最终答案检查，也不能要求每次回答都先写笔记。

## 设计与执行过程

1. EvidenceResolver 仍按接受的 ToolRecord、Artifact、字段、作用范围和时间条件归约。
   覆盖不完整时保持原来的 pending/partial/stale/contradicted 等状态。
2. 字段覆盖完整但语义证据不足时进入 `acquired`。只有 semantic/scoped_semantic 的子集
   自身覆盖完整需求时才进入 `satisfied`，不能用一条语义片段给其余结构资料整体升级。
   此规则对所有结构输出成立，不按工具名称、`/text` 字段名、资料长度或应用场景猜测语义。
   直接返回业务事实的适配器可以继续使用已有 EvidenceExtractor 声明其具体语义。
3. acquired 保持阅读能力候选和来源锚点，基础上下文权重为 2；不会触发“全部需求满足”的
   主动提前收尾。结构字段的新覆盖仍算资料获取进展；需求义务不因此记为完成。
4. 复用已有 WorkingState、propose_work 和接受流归约。对 acquired 需求，关联其当前
   Artifact、散列和相交 JSON Pointer 的 result 笔记产生 `finding_recorded`，探索权重乘
   0.25；无来源、来源不适用的笔记不能降权。issue/rejected 产生 `open_question`，权重乘 2。
   显式 next_need_ids 最后覆盖为 2 倍，使模型可以重新检查已有结论。最终权重仍封顶 8。
5. 工具选择和上下文选择消费同一份权重。未决问题摘要还进入对应 ContextDemand 的查询；
   原始证据锚点不因结论存在而删除。笔记被替换、删除或随用户修订失效后，权重从当前状态重算，
   无需维护第二套完成标记或隐式任务队列。
6. TaskModelView 显示资料状态和独立的 analysis 摘要，说明如何按需回取原文、保留阶段结论、
   继续处理未决问题。任务理解保留用户问的事实、关系和限定条件，不能用读取文件替换问题。

工作笔记仍是 model_inference，不改变 NeedLedger、用户目标或权限；上述降权是有界启发式，
不表示结论已被证明。框架没有新增规划模型、答案抽取调用或执行轮次预算。

## 正常完成与资源收尾

模型取得资料并综合作答，可以主动 Finish，默认仍返回 unverified。CompletionEvaluation
此时把信息义务标为 unknown，并使用 source_material_acquired_answer_unverified 原因，
不伪称语义满足。缺资料、时间不符、冲突、独立动作未完成和应用答案校验仍沿用原有处理。
简单任务无需额外的工作工具调用。

主动提前收尾仍要求 mandatory_satisfied；acquired 不满足该条件。预算、停滞后的有界收尾
仍按 Runtime 原规则执行，最终模型能看到多少资料仍由实际交付清单决定。没有为避免提前收尾
而放宽请求容量、执行预算或来源交付校验。

工作更新本身不算事实覆盖增长，也不豁免无进展策略。模型重复写笔记或重复读相同资料仍会
消耗预算；本次没有把自然语言笔记当作新的事实收益。

局部真实诊断发现，新增解释文字会侵占下一轮反馈预留。因此精简重复提示，不重复罗列工具
Schema 已有的字段说明，保留资料/语义/工作推断的区别以及回取指引。组合回归用与 M1 相同
的 cl100k_base 编码、32K 窗口、4096 输出预留、1024 安全预留和 96000 传输字节上限，验证
四个需求在读取大材料、提出带来源工作记录之后，仍能调用 4000 字节的原文分页并完成。
这不承诺任何工具集合、需求数量和调用组合都能容纳最大分页；超限时继续保留原有拒绝行为。

## 替代方案与取舍

- 只提醒模型继续分析：无法纠正工具退休、上下文降权和宿主提前收尾这三个确定性决策。
- 用文本字段名称判断资料类型：对字符串业务事实、结构化文档和不同适配器都不可靠。
- 自动逐需求调用分析模型：引入额外调度、截断与成本问题，并与冻结执行预算冲突。
- 强制 result 笔记作为 Finish 门槛：会增加简单任务开销，仍不能证明笔记真实。

当前选择让执行模型承担阅读、比较和形成结论，Harness 负责保留继续探索的资源并传递当前
工作进展。代价是只有结构输出的工具不再自动退休，模型也可能忽略笔记或过早作答；有界工具
选择、正常预算与真实任务评分继续约束这些失败。不能宣称该改动已经解决 M1 长任务。

## 版本与迁移

- NeedLedger v5、NeedState v2 新增 acquired；v1 状态不能写入 acquired。
- load_need_ledger 升级旧外层版本，保留历史判断及 progress_sha256。下一次 resolve 才重新
  投影并推进 evidence_revision，不能读取旧快照时悄悄破坏 Frame 与账本的绑定。
- WorkNote、WorkingState、TaskFrame、Core 的持久化形状不变；TaskModelView 的不透明投影
  增加 analysis，最大增长预留同步增加。SQLite 不改表结构。
- 相关解释器、提取器、投影器、工具选择、完成、进度、装配版本分别更新；propose_work v2
  更新行为说明，输入和输出 Schema 保持 v1。

## 验证范围

组合回归用真实接受工具记录和 Artifact 验证 acquired 不等于 satisfied、混合证明不能升级、
资料读取能力保留、来源回取、带来源结论与未决问题共同改变工具/上下文选择、错误来源不降权、
移除笔记后恢复探索、旧快照摘要兼容和下一次归约更新。已有取消、冲突、用户修订和重放测试继续
覆盖工作归约。提前 synthesis 的视图测试改用明确的测试领域语义提取器，继续验证原执行承诺。

真实模型先运行冻结长上下文任务的两组局部诊断，完整保留失败与成本；局部结果不计作 M1
验收通过，也不改题目、材料、预算或评分器。结果记录在对应本轮修复文档中。
