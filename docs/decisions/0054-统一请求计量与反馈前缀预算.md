# ADR 0054：统一请求计量与反馈前缀预算

## 问题与范围

一次真实运行在已进入收尾阶段后，被本地 Provider 拒绝，未发出最终模型请求。内部
SessionRequest 为 59,241 字节，HTTP JSON 请求体为 64,958 字节；输入只有 20,591 Token，低于
28,416 Token 输入限额。Compiler 和 Provider 把同一个 64,000 字节配置用于不同表示，造成
前者通过、后者失败。它不是模型真实窗口耗尽。

同一运行还发生 13 次反馈预算拒绝。首个七工具批次的最低反馈需要 40,339 字节，但计算出的
额度为 36,465 字节。旧算法只按实际 Token 计算系统指令，将已经知道的任务、页面语义与历史
仍视作未知反馈，按每字节一个 Token 预留，导致反复拒绝本可容纳的批次。

本轮修复计量口径、未知反馈预留和应用默认限额。保留真实 Token 窗口、输出预留、父 Deadline、
工具权限、发布验证和执行次数上界；不调整无进展策略，不加入通用远端错误重试器或有损摘要器。

## 三个独立的量

1. 模型输入 Token：使用实际消息内容的 BPE 计数，加明确的 framing、输出及安全预留。
2. 主机内部请求字节：SessionRequest 的 UTF-8 JSON，限制内存与持久化输入规模。
3. HTTP 请求体字节：包含协议、模型配置和嵌套 JSON 转义后的最终传输表示。仅在网关有明确限制时配置。

新增可选公开端口 `SessionRequestSizer`，提供最终请求体大小和可选的请求体上限。
OpenAICompatibleTokenCounter 实现该端口，并复用 Provider 的 `_session_request_body`；不会在
Context 层复写供应商协议。没有此端口的既有自定义计数器保持原行为，不能宣称已检查传输大小。

Compiler 在每个分配候选上检查最终 HTTP 大小。未知 control 和下一步反馈预留仍在内部字节
域声明；UTF-8 JSON 再嵌套一层时，按最多两倍扩张预留传输空间。不可行候选由现有有界分配器
排除，继续选择依赖闭合的历史片段、证据摘录或引用。普通 coverage 策略能够重选，刻意要求
完整输入的 full 对照策略仍可明确失败。

处理发生在 ContextSelected、请求持久化和 ModelStarted 之前。重选只读已经接受的原始
ConversationTurn 与 Artifact，不重发工具、不重放副作用、不把被选视图覆盖到事实存储中。
必需输入本身超限时，返回实际传输大小和限额，不请求模型反复协商。

## 反馈额度：已知前缀与未知后缀

OpenAI-compatible 用户消息的固定前缀包含当前选中的会话、任务和 TaskObservation；只有后面的
history、feedback、control 可变。系统协议和指令不变。

不能直接把“前缀 Token 数 + 后缀 Token 数”当作精确总量，因为跨边界 BPE 合并不是可加的。
BPETokenizer 使用 tiktoken 的 `encode_with_unstable` 获取任意后续文本都不会改变的稳定 Token
前缀，对剩余不稳定前缀字节与整个未知后缀按每字节最多一个 Token 计算。看起来像特殊 Token
的外部文本仍按普通文本处理。tiktoken 在调用时加载，没有新增依赖。

设系统及 framing 成本为 S，稳定前缀 Token 数与剩余前缀字节数之和为 P，固定前缀字节为 B，
输入限额为 T；未知后缀最多占 T-S-P 字节。再加回 B 和内部表示中提升到 system 消息的固定
字段字节，得到完整 SessionRequest 的充分字节上界。它不是平均 bytes/token 估算。

如果还配置 HTTP 上限，使用空 history、feedback、control 的固定请求测量剩余传输容量，将
未知内部增量按两倍转义扩张限制。最终 feedback_budget_bytes 取 Token、内部资源、可选传输
三个独立约束的交集，并扣除当前会话包络开销。新版本计数器为 `openai-compatible-session/3`。

该充分界要求固定会话、任务、TaskObservation、指令和 Schema 不变；它不允许拿某次请求的
额度用于另一个任务。Runtime 每个决策前重新编译；Steering 仍使用原有版本边界使旧提案失效。
可选会话过多时，已有 feedback floor 机制可以重选会话腾出反馈容量。完整交付页面继续使用
action-bound feedback envelope，不能为适配预算而二次截断。

## 持久化与应用配置

ContextCompilation v8 增加 `transport_request_bytes` 与 `transport_budget_bytes`，记录最终
HTTP 表示的大小及可选上限。v1–v7 的字段、校验含义与序列化形状保持不变，读取 v8 需要升级。
request_bytes、request_sha256 和交付清单中的 transport_request_sha256 仍绑定原来的
SessionRequest，避免把旧字段静默改成另一种表示。有工具来源时 v8 仍要求交付清单。

FinScope 默认将 WEAVRIA_RUN_MAX_REQUEST_BYTES 从 64,000 改成 1,048,576，作为有界的主机
资源配置。Token 输入窗口和输出预留不变，因此不会把 1 MiB 都塞进模型。新增可选
WEAVRIA_MODEL_MAX_REQUEST_BYTES，默认不设置；理解阶段与执行阶段 Provider 都遵守它。
理解阶段 Compiler 同样使用最终传输字节计量。配置示例和 README 同步更新。

Provider 最终准入仍独立执行，防御错误的自定义 Compiler 或计数器。残余拒绝的错误消息分别
给出 input tokens 或 HTTP body bytes 的实际值与限额，不再统一声称“上下文耗尽”。

## 验证与当前证据

- 确定性测试使用离线冻结 BPE，覆盖 Unicode、引号、反斜杠、特殊 Token 文本、HTTP 编码一致性、
  未知反馈边界、传输超限重选、不可缩减输入拒绝、旧 Schema 往返及独立环境变量。
- 重选后的确切请求通过真实 OpenAICompatibleSessionProvider 本地准入并到达 Fake Transport，
  测试不把 HTTP 限额调大来掩盖错误。
- 对失败 Run 的已保存输入做只读本地复算，首批反馈额度变为 46,852 字节，能够容纳原提案所需的
  40,339 字节；同一批已接受工具结果重选后可以在原 64 KB 传输上限内编码。不调用模型或工具，
  不把用户原始内容写入 Fixture。

这些证据证明计量与准入缺陷得到修复，不证明真实模型必然完成该任务，也不证明启发式无进展
控制已经合理。供应商真实 tokenizer 与配置不一致、隐藏提示词、远端窗口拒绝、必需内容过大，
仍可失败。本轮没有自动识别所有远端 overflow 并重试，也没有执行付费模型对照实验。

## 取舍与下一步

仅扩大 64 KB 会隐藏口径错误；完全删除预算会失去资源上界；按平均 bytes/token 换算会让未知
反馈突破窗口；把拒绝原样交给模型反复重写又会浪费调用。当前选择独立量纲、共享编码器、
稳定前缀充分界和发送前有界重选。

下一步应冻结领域无关真实任务，在相同模型、窗口、总调用与时间上界下，比较软控制开关、
按需能力暴露与历史回收对任务完成、证据质量和成本的影响；不把本轮确定性回归当作能力收益证明。
