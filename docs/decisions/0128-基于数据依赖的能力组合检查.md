# 基于数据依赖的能力组合检查

日期：2026-11-16。状态：已实现，显式启用，默认关闭。

## 问题与选择

ADR 0127 的冻结执行任务暴露两种失败：已有归档版本全文仍寻找专用比较工具，以及模型拼接不存在的 Schema 引用路径。只调整 top-k 或放松引用校验不能解决。本步增加显式可选的组合检查，默认保留原操作检查和请求摘要，使用同一任务、预算和执行链作对照。

## 机制

检查模型逐一判断候选工具，并提交有界依赖图。节点分为 tool（外部获取或副作用）、given（用户已经提供的数据）、derive（基于输入进行比较、提取、整理、格式化或概念解释）、missing（缺失的外部能力）。每个节点绑定原请求引文；模型自行分解任务，宿主不预先提供工作流或正确工具。产出根节点明确哪些结果服务于请求。

宿主检查节点身份、依赖存在、无环、深度、所有节点都被产出依赖、工具节点与受支持候选一致。以拓扑次序传播可行性：missing 及依赖它的节点不可行；有未解决节点才生成补搜查询，没有缺口且需要工具则 ready，没有工具且无缺口则 no_tools。普通转换必须有输入，概念解释可以没有外部输入。这是结构闭合检查，不是语义蕴含证明；模型仍可能漏掉用户动作、误标转换或错认来源，后续执行 Policy 和独立结果验收不能省略。

derive 不能代替外部数据获取、真实副作用、任意代码执行或计算保证。已取得两版全文后的比较与未获取文件字节就推断其指纹不同。图不生成调用参数，不进入 Runtime 调度，不把预期数据当作已经取得的证据。

## 引用与状态

宿主从当前描述符的说明字符串叶子生成带内容摘要的引用标识，同时展示原 JSON Pointer 和正文。覆盖嵌套属性、数组与 $defs；不解析远程 $ref、不修改 Schema、不搜索相似字符串来猜测修复。模型只能选择当前工具的现有标识；宿主重新解析为原路径/原文后使用既有严格引用校验。标签使用 `r` 加 64 位摘要降低复制负担，同表碰撞拒绝；它不是授权凭据，支持原文仍以完整摘要归档。过期、跨工具、伪造引用仍失败，不自动重试。

每轮组合图、引用目录绑定当次完整候选；补搜后重建，已有支持能力按原逻辑保留。沿用发现器的总调用、Token 和期限，不新增独立循环。图的节点、深度和引用数量有硬上限，超过容量不截断为看似可行的部分结果。

## 契约与验证

CapabilityFitConfig 新增默认关闭的 composition；关闭时序列化不增加字段。组合子报告 v2 只持久化图结构、可行状态与正文摘要；发现报告 v4 和理解记录 v5 显式承载新报告，旧记录保持旧形状。节点标签替换为宿主拓扑编号，引用、任务文本及查询全文不写入报告。版本摘要绑定新提示词、提议 Schema、引用格式和配置。

确定性测试覆盖组合、缺口传播、参数依赖、循环/悬空/无用节点、引用身份、容量、取消/超时、共享预算、补搜和序列化兼容。真实模型复用上一轮完整执行任务，对照旧操作检查、组合检查、混合发现与完整目录；保留能力缺失负例，不能只选比较题。先保持结果验收冻结，再报告误拒绝、错误接受和成本；另以未出现过的任务验证泛化限制。

最终四臂对照共 96 次真实 Harness 执行尝试。组合检查在原任务正确交付 12/16，旧检查 9/16；新增任务分别 6/8 与 5/8。组合缓解了比较任务的误拒绝，但仍有缺失能力时的协议失败与只停止不答复，成本也未优于不检查的基线。不能据此默认启用。完整机制、早期协议失败、逐臂成本和局限见[能力组合检查与协议引用](../能力组合检查与协议引用.md)。
