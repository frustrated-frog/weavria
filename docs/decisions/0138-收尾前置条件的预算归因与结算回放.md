# 收尾前置条件的预算归因与结算回放

## 三次停止发生在哪里

M1 源码长任务要求先提交至少一条有来源的结果笔记，再发布答案。归档中的三次分页读取都成功了。取回的文本与冻结的 `src/weavria/runtime/agent.py` 逐字符一致，但截至该轮结算，工作状态里的笔记均为空。此时已经用完 14 次普通模型调用，余下 2 次预留给收尾。即便工具调用次数还有余额，收尾阶段也没有机会再调用 `propose_work`。

原终止原因是 `finalization_evidence_unavailable`。从结算点重放实际 Runtime，任务的发布预检先返回未就绪，随后就提交了终态。三个样本全部止于生成收尾请求之前。这三份原文能否在另一份收尾请求中放得下，归档没有给出测量结果。[上轮定向验收](../反馈预算修复后的定向验收.md) · [长任务的工作状态条件](0095-用已提交工作状态判断收尾就绪.md)

## 决策

Runtime 继续遵守宿主的收尾预留和应用声明的发布条件。在正常探索期间，前置条件未满足时仍可使用工具。到了必须关闭工具的边界，`RunEnded.reason` 记录阻断发布的资源，终态仍是 `BUDGET_EXHAUSTED`。

| 原因 | 命中条件 |
| --- | --- |
| `finalization_prerequisite_model_reserve` | 剩余模型调用已进入收尾预留 |
| `finalization_prerequisite_tool_budget` | 工具调用次数已达上限 |
| `finalization_prerequisite_time_reserve` | 剩余时间已进入收尾预留 |
| `finalization_prerequisite_unmet` | 当前路径已进入或强制要求收尾，前三个硬边界均未命中 |

多个边界同时命中时，按表中顺序记录主因。收尾视图无法建立以及证据策略判为不可用仍沿用原原因。Runtime 在接受终态时校验任务修订号，旧版本的预检不能终止刚刚修订的任务。历史事件按原值读取，事件字段及序列化格式保持兼容。按原因统计预算失败的消费者应将新值纳入分类。

把成功回执直接升格为工作结论会跳过来源绑定和工作状态归约，挪用预留调用会改变已冻结的执行条件。这个边界只归因，不改变任务的验收标准。[收尾预留](0053-父预算内的证据感知收尾.md)

## 同现场验证

以最后一条已结算的执行决议作为回放起点。读取 SQLite 时使用只读事务，逐份验证 Artifact 引用、分页原文和冻结材料。重新归约原事件和决议，用当时的任务修订、已提交工作状态、模型与工具计数执行下一步。成功对照复用经过摘要核对的原请求和原模型候选，再执行原发布检查及外部字段、引用评分。
