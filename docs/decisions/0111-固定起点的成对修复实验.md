# 固定起点的成对修复实验

状态：实现与确定性验收完成；真实效果实验受模型余额限制，2026-11-06。

## 问题与决定

上一阶段的真实模型对照同时改变了任务解释、首次生成代码及失败位置，不能把成本差额归因于反馈选择。本阶段固定 TaskSpecification 与源码资料，经正式 Runtime/Policy/Artifact 链路执行确定性的初始化程序，生成同一错误工作区，再交给真实模型自由修复。初始化只用于实验控制，不计作模型自主能力，不旁路写入接受状态。

场景覆盖统计错误、报告格式错误、父版本内容保留错误，以及无需修复的负对照。两组只改变 prefix / dependency_frontier；相同的初始化程序、任务解释、预算、模型配置、验收器、源码版本及工具配置进入比较摘要。真实运行必须核对初始化工作区与预计算版本一致。固定解释控制本实验变量，不作为任务理解能力证据。

## 不变量、失败与取舍

初始化同样经过执行、授权和预算。如果没有生成预期状态，不得把后续结果当成可比较试验。报告保留初始化失败、模型失败、预算耗尽、未知 usage 和取消，不能只统计成功修复。成对比较拒绝重复、缺失成员和不同配置，初始化不一致的成员标记不可比较。

任务原文和验收谓词保持不变，不提供正确修复程序或脚本化后续动作。默认不联网，显式 --run 才使用模型和 Docker。每次运行独占 SQLite 与模型包装器；取消传播并关闭资源，已完成成员立即追加到本地报告。SQLite 留在显式输出目录供检查失败，不入 Git；报告只含紧凑指标和无正文的 Provider 状态。固定一个源码任务只能验证此任务的错误位置，不能外推到跨领域或一般纠错成功率。

采用真实工具初始化而非伪造 Trace 或篡改工具反馈，以保留工作区父版本、权限、成果归属及预算语义。复用当前统一 Harness 装配与独立验收，不为实验引入新的生产执行循环，也不把故障注入放入生产包。

## 证据与限制

四类初始化均通过真实容器验证。全仓检查与取消、重复配对、错误摘要、未知 usage、独立重验和成本拆分测试通过。真实模型首次请求遇到 HTTP 错误，诊断返回余额不足；不能根据这些失败判断策略收益。新增 401/402 停止逻辑保留部分批次，并将这类成员排除出能力比较。完整流程及复跑方式见[固定起点的成对修复实验](../固定起点的成对修复实验.md)。
