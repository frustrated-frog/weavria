# 0140 结构化收尾纠错的原文交付

2026-11-20，已采纳。

## 故障发生在哪里

在源码长任务 `coverage-1` 的第 15 次模型调用中，候选答案正确给出了默认次数、工具名和来源。另两个字段却写成了比较式。宿主要求把 `first_start` 改成整数，把 `continuation_start` 改成表示取值的表达式。第 16 次调用正常结束，供应商适配器报出 `schema_mismatch`，随后耗尽了模型输出纠错次数。

归档记录了响应长度和 SHA-256。把四个正确字段和来源按紧凑 JSON 编码，所得 136 字节与归档指纹吻合，其中两个修正值分别是 `0` 和 `"page.end"`。这个完整对象可以直接作为答案。原适配器还要求在外层写出 `decision.kind = "finish"`，把答案作为字符串装进 `output`。重新派发读取工具或增加纠错次数都会让模型重做已有结果。

## 谁能选择原文交付

1. `JsonOutputContract` 校验收尾候选时，如果形状或字段类型有误，可以签发 `CompletionRepair` v2，在当前通知中列出允许原文交付的顶层字段。通知沿用原候选摘要和错误码。字段名必须唯一、非空，与动作协议的保留名无冲突，序列化后最多 160 字节。无法容纳时继续使用 v1 和标准 Finish 格式。v1 的序列化与历史记录兼容。[宿主输出契约](../../src/weavria/runtime/output_contract.py) · [控制通知](../../src/weavria/core/control.py)
2. OpenAI 兼容会话适配器同时检查当前投影处于 `synthesis`，且宿主的纠错通知列出了字段。满足两项条件才在系统指令中提供原文交付选项。普通决策、工具结果、自报的阶段和旧通知均不能开启这个选项。标准 Finish 在纠错轮也有效。发送和计量使用同一份报文，下一轮反馈的 token 和 HTTP 字节预留覆盖两种系统指令。[适配器与计量](../../src/weavria/models/openai_compatible.py)
3. 供应商以 `stop` 结束，且顶层键集合精确匹配时，适配器对收到的原字符串执行完整 JSON 检查。重复键（含嵌套）、非 JSON 数值、截断和代码围栏均触发错误。检查通过后将原字符串交给 `FinishAction.output`，保留空白、字段顺序与转义。字段类型、任务证据和发布结论仍由原检查链决定。适配器无须知道字段的正确答案。

## 验证与适用范围

回放逐轮核对前 15 次请求的摘要，在第 16 次仅替换纠错通知。脚本还从已提交笔记的两个引用区间读取原 Artifact，与冻结源码比对，并检查四项结论各自有对应原文。同一份 136 字节响应在旧通知下复现归档错误，在新通知下完成发布并通过原评分。另一次仅重跑第 16 次调用的真实模型验收也通过。本次结论限于这个失败现场，完整六次基线仍为 1/6。[运行结果与命令](../反馈预算修复后的定向验收.md#结构化收尾纠错的单次分叉验收) · [回放入口](../../examples/json_finish_repair_replay.py)
