# 有界成果诊断与修复反馈

状态：已实现，2026-11-06。执行链路、测试与真实对照见[成果条件诊断与修复反馈](../成果条件诊断与修复反馈.md)。

## 问题和验收边界

上一阶段的成果验收只有总状态与原因码，无法指出具体失败条件。模型需要自行猜测统计、文件保留、版本关系中哪项错误。本阶段让可信验收器输出条件、预期、观察、修复建议和可选成果位置，框架验证引用、限制反馈体积，并将同一诊断交给模型视图与完成拒绝。目标是失败定位与重规划反馈，不新增自动执行工作流。

## 决定

验收器显式声明 repair_feedback_bytes 才启用详细反馈。初始槽位即固定容量，旧验收器保持 v1 和原预算。新 CapabilityOutcome v2 保存诊断及截断数量；NeedLedger 外壳仍为 v7。记录只能引用该验收器实际读取的根成果，位置是诊断标签，不赋予文件或附件读取权限。

超长反馈按验收器提供的优先顺序保留完整条目，报告未展示数量，不截断半个 JSON 条目。verified 不允许携带未解决问题；重新验收覆盖旧反馈，任务修订重新初始化。诊断措辞变化不进入进展摘要，不清除已有重复动作记录、重试预算或授权决策。

模型视图从初始状态预留字节上界；旧任务无需支付新容量。最终拒绝反馈指向同一组诊断，仍遵循既有 CompletionRepair 长度限制。宿主验收器必须生成适合展示的脱敏内容，不能把任意日志当成指令。

## 方案取舍与验证

不直接提供自动执行的工具调用，不把验收器变成规划器。结构化诊断支持宿主独立验证具体领域条件；框架负责证据归属、寿命、预算及一致消费。冻结源码工作区示例按实际内容和父版本检查提供诊断，不预排模型的修复动作。

验证旧线协议、初始容量、Unicode 与溢出、伪造引用、旧范围、成功清理、取消和恢复；通过真实容器检查代码错误及内容错误，再对照只给原因码与详细反馈的同任务真实模型运行。单任务结果不能证明一般纠错能力提升。
