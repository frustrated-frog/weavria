# 工作证据定位与依赖提案准入

状态：已实现并完成工程验证，2026-11-13。固定起点的引用交付改善已观测，尚未证明端到端收益；默认不开启语义重验。

## 问题与证据

上一轮 `release` 真实轨迹暴露三个表示错误：模型把 Artifact 的 `size_bytes` 当文本字符长度，把展示包装 `/data/text` 当原始 JSON Pointer，以及在省略笔记 ID 后用 `n1` 等猜测 ID 建依赖。最后一种错误被旧工具接受，结果成为缺失父节点的失效结论，无法进入重验前沿。固定起点审查还出现原文转述、拼接或同文档不同区间混淆，错误候选得到 `unverified` 而不是有根据的 `insufficient`。

本切片处理“模型选材料，宿主绑定身份与坐标”的边界，不增加审查轮数，不发现语义漏边，也不替模型修正结论。

## 决策与流程

1. `propose_work` 的来源输入支持 `WorkQuoteReference`：指定已授权 Artifact、必填的原始 JSON Pointer 和最长 512 字符的精确短句。宿主在该字段内检查唯一出现，计算 Unicode 字符的半开区间，再持久化原有 `WorkReference`。重叠重复也视为歧义；不自动模糊匹配，不跨字段搜索。旧坐标输入继续有效。自动笔记 ID 基于正规化后的来源生成，同一原文的短句写法与坐标写法不会产生不同身份。
2. 错误反馈包含具体笔记/来源下标；错 Pointer 给出有界的原始根地址，范围越界给出字段字符长度。只有授权读取成功后才生成反馈，不把原文或供应商错误字符串塞进诊断。
3. 推荐 Harness 路径的宿主视图中，新依赖必须指向同一全量工作集中的显式身份。只有已接受状态原本存在的同一笔记、父 ID、版本边允许保留为缺边，支持父节点删除及旧状态修复。未知 ID 在提案工具内拒绝，不能先接受后让模型陷入重验死路。宿主不猜测 `n1` 对应哪个自动 ID。底层直接工具调用若不绑定工作视图，无法区分新造缺边与旧图删除，继续保留旧语义，不宣称具有此准入保证。
4. 重验材料按原始换行分段，长行每 256 字符分段；不删空白、不摘要。模型选择证据编号及一基、包含端点的行号范围，每次至多八行。宿主将其解析回精确原文和范围并存入附件，不再要求模型誊抄引句。相同句子通过不同坐标消歧；空白、越界和遗漏父证据组仍拒绝。对象字段的坐标明确属于 JSON 渲染，不冒充文本字段坐标。

材料行表不重复保存一份整篇文本；所有行拼接应精确等于原区间。完整材料（含行表开销）仍有 64 KiB 上限，并先通过真实请求计量。单提案仍最多一次模型调用，取消、权限、原子接受、回放和收据绑定规则不变。

## 兼容与替代方案

工具版本升级为 v7，审查策略升级为 `work-evidence-recheck/4`，会话准备版本同步变化。新增选择器只在输入层出现；持久化工作状态、提案、收据的 Schema 不变。旧事件回放继续按原契约，不重新准入或审查旧提案；运行续接仍校验版本。

未选择模糊引用修复，因为它可能把错误引句绑定到相似但相反的事实。未采用自动补全依赖 ID，因为没有依据把猜测编号映射到某条结论。原文行号避免抄写，但仍可能选错语义片段；引用存在和父组覆盖不能证明结论正确。短句定位有唯一性要求，重复文本应改用已交付的精确范围；没有新增模型调用帮助寻找坐标。

## 验证路径

确定性测试覆盖中文和 emoji 的字符/字节差异、CRLF、重复及重叠短句、错误地址、授权失败、旧来源输入、未知父 ID、删除后缺边保留、引文行号越界、跨区间混淆、逐层重验及回放。保留原有取消、容量和完整会话测试。

真实验证复用同一冻结三任务集与预算，并记录来源失败、依赖失败、未核验与实际审查次数；固定真实起点比较原候选与错误候选，分别报告坐标交付成功和语义判断。完整失败轮次全部保留；不把受控探针或一次正确结果等同于端到端收益。

结果：全量 1919 项测试通过、24 项跳过。固定起点的新审查器三次正确接受原候选、三次以证据不足拒绝错误候选；旧审查器的错误候选三次均卡在引文定位。完整任务两轮六次中，关闭/开启语义重验分别正确 5/6、3/6，且均未实际触发审查，不能推导端到端收益。详见[实验与源码说明](../工作结论的证据重验与实验.md)。
