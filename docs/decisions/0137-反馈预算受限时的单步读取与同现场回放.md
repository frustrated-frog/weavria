# 0137 反馈预算受限时的单步读取与同现场回放

2026-11-20，已采纳。

## 问题与判据

M1 上批有一次单文件读取需要预留 30,564 字节，当轮上限是 30,418 字节。旧宿主建议单独重提，模型已经只提了一个文件。相反，在另一个现场，宿主给出的页长虽然远小于提案，模型照做就能继续。两次都记作 `feedback_budget`，处置应当不同。[上批报告与四类现场的选择依据](../M1冻结任务在当前主分支的完整复测.md)

验收固定原来的任务修订、预算、可见工具、已接受证据、模型输入和首次提案。宿主可以直接准入原提案，也可以退回后给出一次具体读取。成功要求正式执行取得题目所需文件，并在后续模型请求中找到逐字相同的内容。单凭建议、准入成功或 Artifact ID 都不能通过这项验收。

## 读取依赖如何改变预算

对一个能够任意读取可见 Artifact 的工具，下一条工具回执可能依赖其中任意一项。原准入算法为每个可读祖先保留最小回执，并为新调用的成功与失败反馈预留上界。这是未声明工具的兼容行为。

1. 可安全重放的只读工具通过 `artifact_read_inputs` 声明单次调用所需的已有 Artifact。空元组表示读取外部来源，例如冻结文件。内置 `read_artifact` 声明 `("artifact_id",)`。字段取自已校验的参数，只能指向本次模型请求可见且已接受的来源。
2. Runtime 先做原计量。已超限的单次读取可以收窄：从声明的来源沿已接受记录逆序收集实际依赖，再按事件顺序重建闭包。字节计算仍包含完整工具反馈上界、任务投影增长和控制反馈预留。多调用批次维持原边界。
3. 若单读可行，`BatchAdmitted` 同时持久化可读闭包、请求摘要和调用反馈上界。执行器只给后端这份闭包。误报“无需旧材料”的后端尝试读取旧 Artifact 会得到 `POLICY_DENIED`。后端调用仍经过现行 Tool Policy。减掉的每一份旧回执都对应实际收回的读取能力。
4. 拒绝后，宿主先检查原提案中能保留来源与游标的分页读取，再按提案顺序尝试其他已声明读取。对页长上下界和二分中点，都以正式单读流程重新计量。页长不超过模型原请求。若有可行的普通单读，在控制通道内原样携带公开提案；过长的参数不会被截断。已检查的候选都无可行建议时，返回 `recommended_max_calls=0`，模型仍可改换来源。重提后的权限、可见性、进展和预算独立重检。

一次中间对照暴露了排序的重要性。按提案原顺序直接挑首个可读文件，会打开 ADR 0075；同一批中还有一个明确指向 ADR 0079 的续读游标。旧宿主能读到 0079，换成 0075 会丢失所需来源。因此排序保留原有可行的分页路径。评分要求的文件名只供离线验收使用。

工具描述符 v9 保存读取声明。准入事件 v4 表示单读使用原可见证据的严格子集；归约时重建同一请求下的闭包。退回通知 v7 携带具体的非分页读取或明确没有受检建议。既有分页通知继续使用原协议。旧描述符、回执与事件保留原序列化格式。

## 四组冻结现场的结果

每行是一对独立回放。两组从同一个已结算事件前缀开始。字符数来自交给模型端口的实际请求，核验时同时比对了来源文件 SHA-256、返回的正文或页内容、工具回执和字符游标。页长参数按 JSON 有效负载字节计，表中区间按 Unicode 字符计，右端不包含在内。

| 上批试验与拒绝序号 | 当轮反馈上限 | 按旧建议执行 | 当前实现 |
| --- | ---: | --- | --- |
| `documents_multistep-coverage-1` · 53 | 30,418 B | 原要求 30,564 B，单独重提仍被拒绝 | 原文件读取直接准入，预留 27,493 B，送达《统一执行链的调用过程与使用》全文 4,657 字符 |
| `repository_long_context-recent-1` · 92 | 30,946 B | 原要求 32,791 B，最大页长为 0 | 原请求的 1,200 B 页直接准入，预留 30,692 B，送达 `agent.py` 的 [67526, 68698)，共 1,172 字符 |
| `documents_long_context-coverage-1` · 30 | 30,510 B | 按旧 115 B 页建议，ADR 0079 送达 [303, 373)，共 70 字符 | 从通知重提同游标的 560 B 页，送达 [303, 585)，共 282 字符 |
| `repository_long_context-coverage-1` · 26 | 30,760 B | 按 2,192 B 页建议送达 `agent.py` 的 [65317, 67455)，共 2,138 字符 | 同一建议再次通过正式准入，送达相同的 2,138 字符 |

四个现场中，采用旧建议有两处送达所需原文，当前实现四处均送达。前两处省去一次重规划，后两处在重新编译的下一轮提交建议。文档长任务的旧建议在本次受控回放中也有效；上批真实模型当时没有采用它。

## 复现与边界

在有上批本地归档的工作区运行下列命令。程序只读打开归档，用内存 ArtifactStore 恢复截至拒绝点的输入，按行输出成对结果。默认目录可通过 `--batch` 指定。

```sh
uv run python -m examples.feedback_read_replay
uv run pytest -q tests/runtime/test_page_advice.py tests/sessions/test_evidence_access.py
uv run pytest -q tests/runtime/test_control_loop.py -k narrowed
```

首轮校验持久化的外层会话请求、内层控制请求和被拒提案的摘要。旧组使用旧工具描述符重算原预算与页建议，并遵循历史通知。新组直接重放原模型提案，如需重提，仅从实际送达的通知构造调用。两组使用同一语义快照、真实上下文编译器、Token 计数器、执行器和冻结语料。读取结果进入后续模型输入后即停止。预算可行的读取仍可能遇到文件缺失、游标无效或单个字符超出页长，这些情况以工具回执为准。该探针固定任务理解和模型选择，不产生新模型答案。四处是上一批选定的诊断现场，M1 任务成功率仍以完整端到端验收为准。
