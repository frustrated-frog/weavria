# 长任务回取协议与收尾前置条件

## 从失败请求定位问题

源码 coverage 首次提出 `read_source(path="runtime/agent.py")`，冻结目录中的实际键是 `src/weavria/runtime/agent.py`，读取因此失败。接下来的三次响应都为 66 字节、同一 SHA-256，且被分类为 `schema_mismatch`。以存档请求重放，复现了相同摘要，内容为 `{"decision":{"kind":"recover_context","query":"runtime/agent.py"}}`。它少了 ModelTurn v2 外层版本，已有的通用修复提示未能改变响应。

文档 coverage 的两个读文件结果都有 `/text`，结构提取器因此把四项事实以及路径需求都标为已获取。该次根本没有读取工作记录的原始 ADR，也没有保存有效工作记录。执行循环在模型调用预留点接受了 `complete` 收尾，随后模型继续请求工具，被收尾边界拒绝。修复后的一次复测找到了两份原始 ADR，随后又揭示工作记录工具将无效的 `/data/text` 指针误报为后端故障，模型无法据此纠正参数。

## 机制与边界

兼容模型适配器仅在请求明确启用恢复、且当前允许决策时，为已明确选择 `recover_context` 的响应补上省略的外层版本。查询与地址仍走严格契约和既有授权，错误版本或其它未知字段继续被拒绝。收尾投影对应独立的 Finish 协议提示。冻结文件工具只在索引内解析唯一的相对路径后缀，并返回标准路径，歧义或越界路径仍拒绝。

Completion Policy 可声明必须在锁闭工具前满足的条件。分层完成策略合取各层条件。在探索预算尚可用时，Runtime 保留决策视图。在预算边界仍缺该条件时，以资源不足结束，避免发送无法履约的收尾请求。长任务接入使用已成功、带原文引用的工作提案作为前置条件，原有答案验证继续执行。该前置条件检查已发生的工作事件，结构化证据仍只能证明字段存在，原文语义和最终引用由任务评分独立验收。

工作记录工具将无效原文指针和超界区间分类为可纠正的参数错误。文档接入提供由完整冻结目录生成的设计记录路径，并标明原文 JSON Pointer，避免把观察包络误当作 Artifact 内容。数据集、评分器、模型配置和预算沿用冻结版本。

直接原文件的工作引用可以省略字符区间并保留原路径。聚合文本仍需要精确区间才能归属到某个章节。分页预算拒绝反馈在已选原文有可行单页时，携带原 Artifact ID、Pointer 和起点。旧版本仍按原字节序列化。回放检查游标与被拒绝的动作、当前可见来源一致。新反馈为模型重提提供输入，重提仍经过原有准入检查。

## 复测

确定性测试覆盖与失败摘要相符的恢复响应、关闭恢复及显式错误版本、唯一后缀、无效引用、收尾前置条件和分页重提。会话测试用非零起点的三页提案触发预算拒绝，随后按反馈游标重提单页并成功执行。

2026-11-03，`m1-cursor-retry-*-20261103` 以冻结模型和预算复测两项长任务，每项 coverage 与 recent 各两次。源码四次都读取了标准原始路径、成功回读并形成工作记录，coverage 与 recent 各有一次严格通过。其余两次分别在工具名字段和交付修复停滞处失败。文档四次均未通过，三次耗尽反馈重议，一次到预算预留点仍缺有效工作记录，前置条件阻止了收尾。迭代中两种文档策略各有独立通过样本，尚无稳定的端到端结果。此次诊断不关闭 M1 门槛。
