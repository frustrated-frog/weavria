# 0141 按会话装配扩展与只读轨迹观察

2026-11-20，已采纳。

## 要解决的问题

宿主希望在同一进程里给源码会话提供项目文档，给其他会话保留普通请求，并能事后解释两次运行看到了哪些材料。已有装配入口可以替换理解器、记忆和验收策略，上下文编译器也可以对完整材料组进行取舍。本轮增加两处宿主扩展点，共享已有模型调用、预算、事件和 SQLite 提交路径。

| 扩展点 | 输入与时点 | 可观察的效果 |
| --- | --- | --- |
| `before_compile` | 执行模型的一次决策或收尾视图构建前，接收任务目标、约束、修订号和阶段 | 返回带本地来源 ID 的完整材料。编译器决定采用或省略，模型接收低信任数据 |
| `after_run` | Run 已经结算，执行路径正常返回且仍有剩余时间时 | 观察已提交的终态、会话和 Run 身份、有效扩展清单、已准备请求数与已结算工具结果数 |

## 挂载、选择与释放

宿主向 `AgentHarness.from_config(..., extensions=...)` 传入有序装配。会话专属配置完全覆盖默认配置，空元组表示该会话关闭扩展。每个扩展声明名称、版本、钩子和依赖。依赖必须出现在同一装配的前方。缺失依赖、环和重名在装配时就会被拒绝。版本由宿主提供，须覆盖配置或材料中会影响行为的变化。示例文档插件用实际文件内容指纹作为版本。

Session 先在接受输入的事务中固定清单，再按声明顺序为本 Run 进入异步上下文。相同插件定义可以复用，挂载资源按 Run 独立创建，退出时逆序释放。后续挂载失败时，已经进入的上下文也会释放。重复提交已完成的输入直接返回原结果，不再挂载。插件是宿主安装的可信 Python 代码，作用域约束的是框架传入的数据和资源生命周期，进程内插件自行持有的全局对象由插件作者负责。[装配与钩子](../../src/weavria/sessions/extensions.py)

## 从来源到模型请求

扩展返回的每个资料编号都带上宿主分配的生产者前缀，例如 `extension:project-docs:manual#1`。宿主在调用下一个扩展前快照内容，拒绝同一生产者内重复的身份。扩展与记忆都以完整材料组参与预算竞争。记忆先经过已有证据审查，扩展材料单独记录来源，不能满足或替换记忆的证据依赖。容量超限或取材失败沿用现有终态，取消传递给正在执行的钩子。

一次构建内的预算回退与摘要成本探测复用同一批材料。Runtime 可能尝试多个候选视图，平台只在实际请求提交时记录最终采用的编译结果。任何有材料的编译都用 v18 报告记录有序候选 ID，以及每项材料的散列和交付选择。提交前，SQLite 用 Run 的清单检查生产者和顺序，用实际请求检查所选材料的内容摘要。[请求编译](../../src/weavria/context/compiler.py) · [提交与回放](../../src/weavria/sessions/store.py)

扩展装配作为 Run 配置 v7 的一部分进入恢复比对。旧配置按原版本读取。完成后调用 `store.extension_trace(session_id, run_id)` 可以在没有安装原插件的进程中读取当时的装配和计数。逐次采用及省略的来源可在原 `SessionContextCompiled` 事件中查看。恢复执行仍需相同装配，历史回放只读归档。观察器共享最多 250 毫秒且不超过剩余时间一半的通知预算，普通异常只记插件名与错误类型。外部取消继续传播。进程退出可能漏掉在线通知，存储中的运行事实可独立查询。扩展的挂载和资源清理由调用栈持有，异步插件应配合取消。

## 验收结果

`uv run python -m examples.harness_extensions` 从项目的只读恢复 ADR 构建段落目录，向两个会话提交相同的查询。两组都挂载了独立的轨迹观察器。启用文档扩展的会话实际收到了该 ADR 的第 2、3、4 段，对照会话收到零段。两组各准备一次模型请求。一次本地运行的输入计量分别为 1,735 和 1,095 token，计入材料、协议提示和会话标识。模型用固定结束动作，实验验证作用域、实际交付与成本，答案质量尚未进行真实模型对照。[可运行示例](../../examples/harness_extensions.py)

回归覆盖同名局部来源的隔离、材料快照、超预算材料整组省略、记忆证据与扩展共存、一个会话取消时另一个会话继续、部分挂载失败、观察器失败与超时。进程退出实验在工具已结算后更换扩展版本，恢复被拒。换回原组合后继续且工具只执行一次。[扩展验收](../../tests/harness/test_extensions.py) · [记忆证据对照](../../tests/memory/test_sufficiency.py) · [崩溃恢复实验](../../tests/sessions/test_crash.py)

## 设计取舍与来源

选用两个窄钩子，插件只获得相应阶段的只读值。模型调用、工具授权、预算和状态提交继续由已有内核裁决。通用的 `around(next)` 会进一步允许扩展跳过、重入或重复执行，当前两个场景均无此需要。此次参考 DeerFlow 的有序装配和装配描述，以及 DeepSeek Harness 对插件生命周期与持久事实的区分，源码核对日期为 2026-11-20。[DeerFlow 装配描述](https://github.com/bytedance/deer-flow/blob/e3edd05114c17d09082221a1ce1555bfbffeec16/backend/packages/harness/deerflow/agents/assembly_descriptor.py#L442-L504) · [DeepSeek Harness 插件与事件](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/docs/architecture.md)
