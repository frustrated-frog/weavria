# 0156 把本轮定位回执交给待核验的读取器

2026-11-28。在安装迁移实验的一次失败修订中，模型读了历史会话原件，又在本轮查到了清单和锁定版本表。四条需求都缺本轮正文，它连续提交了能通过独立字段评分的答案，最终仍因缺少本轮读取回执而失败。目录查询已经解决了「在哪里读」，模型工作视图需要进一步表达「哪些需求可以通过同一次读取补齐」。[失败运行的背景](0155-用空搜索回执修订单个需求的定位计划.md)

## 从已接受的回执生成下一步

宿主可在配置两步只读取证路线时启用 `HarnessConfig(source_read_handoff=True, ...)`。默认关闭。以两个需求共用一份发布清单为例，执行经过以下边界。

1. 本轮定位器成功返回唯一结果。证据账本保存探针与绑定，两个需求仍是 `partial`，各自只缺正文。投影器按需求检查最后一个适用的定位探针，跳过为别的查询产生的探针。在已接受的绑定中逐一核对范围、Run、Call、Artifact 标识、内容摘要和候选字段指针。
2. 当读取器可见时，决策视图中的 `pending_source_reads` 提供读取器、参数位置、定位调用、原件和候选值的位置。例如应从定位原件的 `/paths/0` 取值，填入读取器的 `/path`。指向同一读取器、版本、参数位置、定位回执内容摘要与字段位置的需求共享一项。摘要按整份定位回执计算，两个不同回执仅仅恰好包含同一路径时，仍可能各占一项。
3. 上下文编译器沿同一原件地址检查已选摘录。只有在整份回执可用、整次请求的字节和 Token 都不增加且仍符合预算时，才升级为完整回执。模型可根据工具能力恢复被省略的定位值。实际读取仍经授权、执行和回执归约。读取器如支持跨轮复用，会根据当前来源版本决定复用或重新读取。
4. 正文回执满足需求后，对应条目在下一次投影消失。随后一次适用查询变为空或歧义、读取器被隐藏、存在该读取器的不可重试失败，或绑定来自另一 Run 时，都不显示该项。收尾阶段只合成已有材料。

直接复制路径会把来源数据重复写进任务指令，还可能在路径截断后给出错误参数。把定位和读取编成自动工具链则会替模型决定调用。这里保留模型选择权，投影只引用已接受原件中的完整值。每次决策最多显示两项，按需求声明顺序分配 1,200 个 UTF-8 字节，需求标识必须能完整放入。适用任务帧从第一次投影就预留这部分进度预算。较后的来源可随前项完成进入视图。恢复时从持久化的语义快照重新推导，启用开关会进入投影器和准备器版本信息。

## 固定一次真实失败决策

取安装迁移失败修订的第 12 次主循环模型请求，逐字段核对旧视图能否从对应语义快照重建。保留原请求中的历史摘录、反馈、工具与预算，只替换任务视图。GPT-6 Luna medium 在同一请求上每组调用三次，交替执行顺序。独立评分要求在一个批次中分别按精确参数读取 `pyproject.toml` 和 `uv.lock.packages.tsv`，不含额外调用。

| 模型收到的视图 | 恰好提出两项读取 | 直接提交答案 | 每次输入 Token |
| --- | ---: | ---: | ---: |
| 原视图 | 0/3 | 3/3 | 9,050 |
| 含待核验来源的视图 | 3/3 | 0/3 | 9,421 |

这六次调用只观察下一步决策。两组请求的 SHA-256 前缀分别是 `1d0aa7f8`、`06726303`，新视图每次多用 371 个输入 Token。这是选自一条失败轨迹的一个决策点，任务交付和其他任务上的表现需要分别测量。

## 如何复核

无需模型凭据即可运行确定性测试和两份归档的材料核对。

```sh
uv run --offline pytest -q tests/evaluation/test_located_read.py -k handoff
uv run --offline python -m examples.revision_delivery --compare-source-reads --case editions
```

持久化测试从公开会话入口先读历史的两个正文，再定位两份本轮来源，分别打开清单与登记。逐次检查模型真正收到的定位值、需求数从三减到一再清零，以及后端只重读已换版的登记。另一测试在唯一命中后制造歧义，并检查大量需求共用一个来源时的序列化上限。Fake Provider 固定动作，仅用于验证上述不变量。

原始实验位于本地 `.weavria/revision-delivery/source-handoff-20261128/`，包含两组请求的散列、逐次模型用量、会话数据库和分轮结果。固定决策回放需要上轮归档数据库。新检出可从仓库夹具直接运行换版实验。

```sh
uv run --offline python -m examples.source_handoff_replay .weavria/revision-delivery/query-repair-release-20261128/migration-2/replanned.db --call 12
uv run --offline python -m examples.source_handoff_replay .weavria/revision-delivery/query-repair-release-20261128/migration-2/replanned.db --call 12 --live --env-file .env.m1-openai --repeats 3
uv run --offline python -m examples.revision_delivery --compare-source-reads --case editions --catalogue-proof --repeats 3 --live --env-file .env.m1-openai --out .weavria/revision-delivery/new-source-handoff
```

下一轮优先检查任务准备与完成验收之间的证据归属。第二组首版留下了同一候选、两条真实读取回执和拒绝原因，可以直接重放，并加入缺少一份正文的反例，检验修正能否同时保留正确拒绝。
