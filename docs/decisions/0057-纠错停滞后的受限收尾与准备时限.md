# ADR 0057：纠错停滞后的受限收尾与准备时限

## 问题

重复真实回归确认，任务准备通过后仍存在两种可避免的空交付：

- 普通上下文准备仍使用整个父期限，可能占用已经为收尾预留的时间。
- 完成检查连续返回同一 missing_evidence，模型连续改写“说明缺失”的回答，却没有新增证据。
  Runtime 直接以纠错停滞失败，已接受且可交付的证据也无法形成有限回答。

前者是资源边界遗漏，后者是纠错停滞后缺少明确的交付路径；不能通过接受被拒候选解决。

## 决策

沿用 ADR 0053 的显式 FinalizationStarted 和同一份证据账本，不新增成果或恢复 Schema。
开启收尾预留时，普通决策上下文准备也受“父期限减去预留”的子期限约束。子期限到达后，取消并
等待该次准备清理，再在原父期限中编译收尾视图。外部取消继续传播，不转成降级回答。

后续源码评审发现，该版本的子期限只覆盖上下文构建，遗漏了先执行的 `TurnPreparer` 和工具结算后
的语义刷新。本条目标的完整实现与安全快照边界由
[ADR 0059](0059-完整准备时限与运行配置留证.md) 补全；不能将本版本视为已经约束整个准备链路。

当同一完成修复在同一语义前沿上重复、即将触发已有停滞终止时，Runtime 可以消费已配置的收尾
预留，向独立 FinalizationPolicy 请求当前证据的收尾判断。只有原有真实证据与交付检查允许时，
才能提交阶段转换，随后重新请求一个 Finish 候选。原候选不发布，原拒绝事实不删除。

此路径使用 resource_reserve 原因，表示纠错探索停止并开始消耗已保留的交付资源；触发它的重复
CompletionChecked 与相同前沿仍完整留在 Trace 中。语义不依赖某个应用的 issue_code 字符串。
关闭预留保持原有停滞失败语义。

新候选仍经过完整分层验收。缺少的义务仍是 unsatisfied；有限交付只能是 unverifiable。
独立必需行动、冲突证据、独立答案核验与应用发布拒绝均不能由该路径绕过。无可交付证据时仍失败，
不从旧候选、日志或不可见来源拼接答案。已经进入收尾后继续停滞，也不会再次开启收尾或无限重试。

## FinScope 运行配置

真实响应的 usage 证明，执行模型曾将全部 4096 个输出 token 用于推理，可见回答为空；任务理解
阶段已经显式指定 none，执行阶段却遗漏配置。FinScopeSettings 新增 model_reasoning_effort，
默认 none，通过 WEAVRIA_MODEL_REASONING_EFFORT 配置；omit 可以恢复供应商默认行为。
任务理解和执行分别配置，通用供应商适配器与 Runtime 不根据模型名称推断推理模式。

FinScope 的可选收尾时间配置默认从 10 秒调整为 30 秒，仍取自原有 180 秒父时限，没有增加总时间
或模型次数。它覆盖上下文准备、回答生成与验收，通用 RunLimits 默认值不变。开启预留仍须设置
WEAVRIA_FINALIZATION_MODEL_CALLS。较慢供应商或大型上下文仍可能超时，预留不是必然交付保证。

工具参数说明同时区分 events、reaction_events 和 news_window 的标识命名空间；前者的数字 id
不得直接用于另一个资源。未把这些领域映射加入通用 Harness。

## 验证

- 同一领域无关任务、模型脚本与父预算：关闭预留时重复信息修复失败；开启后只增加受限 Finish
  请求，交付 unverifiable，工具没有重复执行。
- 慢上下文准备在探索子期限取消并清理后，可以使用保留时间生成有限回答。
- 未完成的独立必需行动仍阻止降级；应用发布否决在切换后仍可拒绝新候选。
- 原有收尾取消、Steering、回放、无证据拒绝、上下文交付证明回归继续作为门禁。
- 正式应用工厂测试验证两个阶段的 reasoning_effort 与输出上限分别进入实际 HTTP 请求，并验证
  所有权关闭；真实响应正文和私有推理不进入评测输出。

实际服务回归、成本与未通过情况见[任务链路稳定性回归](../任务链路稳定性回归.md)。本轮没有建立
逐句事实核验器，也没有证明所有工具参数都会被模型正确选择。
