# 0077 统一执行链的组合契约与请求期限

状态：已实现，2026-11-01。承接 ADR 0075、0076；不修改研发宪章。

## 问题

统一入口已存在，但四种组合仍有缺口：增强记忆审阅与默认准入不兼容；运行中修订目标未取得理解背景；业务工具退休连带隐藏原文回读；前后记忆阶段与 Session 各自有界但没有共同时间上限。

本轮修复既有路径，不新增调度 Agent、第二个 Runtime 或业务适配。不同时展开工作笔记、摘要与 Skills。

## 选择与执行语义

### 记忆按完整配置装配

`HarnessMemory.from_model(profile=...)` 统一构造提取器、审阅器、准入器。`basic` 保持基础语义，`fact_sets` 启用事实集与族对齐，`conditions` 再启用语义条件关系。增强配置使用结构化生成协议，默认 `max_repairs=0`，额外修复调用须显式配置。竞争解释搜索不在这些默认组合内。

底层仍允许显式注入三个组件。`MemoryReviewFeatures` 描述审阅输出需要的语义能力，准入器公开其支持能力。Harness 在创建时检查包含关系，不解析版本字符串或猜测供应商名称。已有自定义审阅器未声明能力时按基础协议处理；高级自定义审阅器应实现 `MemoryReviewFeatureProvider`。无法静态证明任意插件会遵守声明，运行期原有验证仍保留。

不选择“自动给所有审阅器启用最宽松准入”：配置增强能力必须是显式决策，增强模型解释也不等于可信事实。`from_model` 是推荐接入路径，底层替换只服务确有需要的高级使用者。

### 相同理解阶段使用相同背景供给

新输入、澄清续接和 steering 都通过 `_preparation_supply` 按当前 TaskInput 查询。结果的 task revision 必须匹配。steering 经 `SessionSemanticContext.context_supply` 进入既有 `prepare`，不拿第一次召回充当新任务背景。单纯工具反馈归约不增加理解阶段检索。

读取期间接受下一次 steering 时，原查询仍绑定旧任务；Runtime 在准备结果返回后检查当前 revision，不会把旧供给送进新版本的模型请求。后续再次准备新版本。取消沿现有调用链传播并等待清理。此处没有跨 Session/Memory 的快照事务，也没有通用召回缓存。

### 业务工具退休不撤销成果访问

动态策略继续决定业务工具工作集。Session 刷新时，如果存在已接受的 Artifact，保留既有支持工具；因此需求满足后可以不再查询外部系统，但仍能读取已有成果。访问范围仍由现有 Run/Session Artifact 授权约束。初始直接回答且没有选中业务工具时保持短路径，不因本轮修改提前暴露全部工具。

这里选择按已有成果保留整个小型支持工具组，避免每个分页步骤都独立改变能力 epoch。没有实现“所有原文已读完”的消费游标，因此支持工具可能保留到 Run 结束；不宣称逐个工具的最小最优暴露。

### 父请求时间预算

`AgentHarness(max_request_duration=T, memory_catchup_fraction=f)` 从 send 开始建立一个单调时钟期限。默认 T 取 RunLimits.max_duration，f=0.1。

- 前置追赶期限不超过 `min(记忆局部上限, f*T)`，保留至少约 `(1-f)*T` 给正式执行，除协作式清理开销。
- Session 接收剩余时间；新增 `SessionEngine.send(max_duration=...)` 只能缩短构造时的上限。Runtime 原有探索、收尾资源分配继续生效。
- 后置形成只使用父期限剩余时间，并继续受记忆局部上限约束。已完成 Run 不被形成超时改写；形成返回 deferred。
- 外层 timeout 也覆盖 Session 接受输入等 I/O。若此时耗尽，调用可抛 TimeoutError；已接受事务需要完成取消结算，重试应使用相同 input_id。
- `flush_memory` 是独立显式操作，使用记忆自身期限。关闭和用户取消仍等待所有被拥有的任务退出，无后台逃逸。

父期限是协作式异步期限，不是硬实时上限；阻塞插件和事务清理可能延后退出。时间来自 event loop，Session 内部通过剩余时长转换为其自身时钟的 RootBudget，避免混用绝对时钟域。

此轮只统一**时间**，并非所有阶段的模型调用计数或 Token 账本。RunLimits 的模型调用上限仍约束执行循环；任务理解、记忆提取/审阅/修复仍有自己的有界策略。后续统一调用额度应设计共享计量端口，不能把几个局部计数相加冒充强制父预算。

另暴露原有领域无关 `completion` 扩展点，保持 Session 的分层验收行为，不复制业务验收实现。

## 版本与迁移

Harness 配置版本改为 `unified-harness/3`，TaskAwareSessionPreparer 改为 `task-aware-session/10`。新配置记录父期限、追赶比例与准入版本，Session 配置记录实际收到的阶段时间。未新增持久化 Schema。

与 v2 的重要变化是默认整次请求共享 RunLimits.max_duration，而非“Session 时间加两段记忆时间”。希望更宽松的总时长应显式设置 max_request_duration；单次工具和执行循环仍受自己的局部上限约束。不能再将配置了写入等同于保证本次完成准入，调用者应读取 memory 报告。

## 验证与局限

组合回归覆盖：

- 三种记忆模型配置的配套与非法组合启动拒绝；真实 SQLite、接受输入、脚本审阅产生事实集修订、跨会话召回的完整路径。
- 形成历史约定后，在另一会话运行中修改目标；新理解与执行都看到对应背景。
- 背景读取期间再次修订或取消；过时版本不进入决策，取消清理完成。
- 首选失败、备用成功、所有业务工具退休后，实际调用 read_artifact 成功，不只检查工具名称。
- 前置形成阻塞仍给执行留时间；后置形成受父期限截断、保留成功结果、重试不重复运行；原有取消/关闭回归继续生效。
- 完成策略拒绝初稿并驱动修复，统一入口不丢失该行为。

均使用 Fake 模型与脚本语义输出，证明组合与生命周期，不证明自然记忆质量或长任务效果改善。未运行付费模型评测，未接入 FinScope。下一主线为有界工作状态对上下文与能力选择的实际影响，随后衔接阶段摘要和原文回取。

最终验证：`uv run pytest -q` 全量 1363 项通过（72.55 秒）；随后强化的 90 KB 成果回读场景在两种入口下均通过，工作集相关 11 项定向回归通过。Ruff、全仓格式检查与 Pyright 无错误，示例 `--help` 入口通过。未执行真实模型调用。
