# 分叉会话的统一历史检索

分叉后的早期约定会随着本地轮次增长退出近期历史窗口。分叉会话现在可以使用已有的 BM25 索引和请求预算，在同一语料范围内搜索已继承的对话及分叉后提交的本地轮次。

历史目录用 `(session_id, run_id)` 表达一份原始轮次在哪个会话中可见。分叉目录保留原始 Run ID 和字符位置，原文来自子会话第一条 `SessionForked` 事件的快照。继承轮次的接受序号是子会话的 1，本地轮次仍使用其终结事件序号。词项统计、倒排命中、近期候选和原文加载都按同一子会话与查询截止位置过滤。父会话在锚点之后的轮次不在分叉快照中。Artifact 锚点只匹配当前会话实际执行的 Run。

SQLite v10 迁移扩展目录键，从已有的分叉事件补登记原文，并保留已建立的倒排表和索引水位。新分叉将目录和快照同事务提交。显式重建从分叉事件重新生成继承目录。请求提交时同时校验检索来源、原文摘要和分叉快照。旧分叉上按窗口配置启动的中断 Run 仍以原配置恢复。新 Run 按宿主的检索配置执行。

确定性验收在分叉后写入 66 个本地轮次。两个目标分别来自继承历史和早期本地历史，原 64 轮窗口覆盖 0/2，统一检索将 2/2 交付到实际模型请求。继承原文的片段逐字符核对，父会话在锚点后的同词内容被排除。测试还验证 v9 迁移、重启后相同的命中地址和重建时从权威快照恢复损坏的目录。此实验测量固定样本上的召回与原文交付，真实模型收益与大规模查询延迟仍待测量。
