# 工作区清单与受控附件恢复

## 问题与完成条件

完整工作区反馈将正文复制进每轮请求，并把最大文件容量转化为大额反馈预留。本阶段把模型可见清单与权威文件状态分离：执行、合并默认交付版本/路径/大小/哈希和有界诊断；按路径分页读取正文；计算在宿主边界恢复原文件。必须验证接受视图、附件归属、取消、SQLite 重开、反馈预算与相同任务的上下文成本。

## 决定

在 ToolContext 增加 stage_attachment/read_attachment。附件仍是现有 ArtifactStore 中的不可变内容，以当前 Run/Call 标识暂存，受调用生命周期、数量和总字节上限约束。宿主工具将 ArtifactRef 写入正式结果；只有父结果被接受且在本轮可读视图中，才能沿父结果指针读取附件。读取检查 Run、生产 Call 和完整引用一致，不以单独附件 ID 授权。验证后只在当前 ToolContext 内授予后续内部读取，依赖仍归属父结果的生产 Call。未知状态失败最多遗留不可读的孤立存储，不更新工作区 HEAD。

新版工作区工具把原 v1 完整结果保存为一个附件，正式结果采用 v2 清单及执行摘要。此阶段不做存储去重，复制成本仍按完整版本计；收益发生在模型请求和上下文索引，不宣称降低持久化体积。版本哈希继续沿用完整 WorkspaceSnapshot 的定义；恢复后核验其 revision，并重新计算清单以验证两者一致。

提供新版 workspace_manifest_tools 装配入口，使用相同 execute_workspace_python/merge_workspace 名称和不同工具版本；保留原构造器作为完整快照基线与兼容入口，不能在一个 Registry 同时注册两个版本。新增 read_workspace_file 按固定版本和虚拟路径分页，不接受容器或宿主路径。JSON 字节预算与 Unicode 字符游标复用现有 Artifact 分页实现，返回精确来源、哈希与下一页参数。

模型默认只收到清单及日志，不自动看到文件正文；显式读取后的片段才成为新的工具结果。此机制不提升低信任文件内容的权威性，也不放宽跨 Run、历史来源或压缩后证据访问权限。父结果已退出授权视图时，应先走现有来源恢复流程，不能凭 revision 越权读取附件。

## 取舍与验证

不新增通用的 Context 投影策略或新的 Runtime 事件，避免在多个编译器中重复实现清单投影。将结果本身定义为完整的清单协议，既有 complete-feedback 机制即可精确预留并完整交付诊断。相对只设置 context_paths，这能避免 raw 候选再次把全文送入模型。

默认离线测试覆盖归属伪造、未接受父结果、直接附件读取拒绝、关闭上下文、容量、取消、清单篡改、分页 Unicode/边界、混用 v1/v2 与预算。真实容器与 SQLite 测试覆盖两个版本的执行和关闭重开，固定文件任务比较正文在请求中是否缺席及 JSON/Token 成本。单次真实模型成功不等于普遍质量提升。
