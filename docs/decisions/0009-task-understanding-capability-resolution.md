# ADR 0009：版本化 Task Frame 与最小能力视图

- 状态：已采纳并实现
- 日期：2026-10-16
- 范围：通用 Harness 的任务理解垂直切片

## 背景

AgentLoop v3 已经能校验模型动作、限制预算、管理 Tool Batch、任务干预和持久会话，但宿主
提交的 `TaskInput` 仍直接进入执行，完整工具目录也默认暴露。它能可靠执行模型决定，却没有
独立回答当前请求需要哪些信息、是否应先澄清、应暴露哪些能力，以及什么条件代表完成。

第一版任务理解实现证明了类型化 `TaskSpecification` 和最小工具视图可行，但把规范化目标与
模型生成的规格写回了 `TaskInput`，并只接到旧的单次 `AgentRun`。这混淆了原始请求和模型
推断，也没有进入真实的 v3 Session/AgentLoop 主路径。

## 决策

任务理解仍属于 Runtime 之上的 `weavria.harness`，但采用两层数据语义：

1. `TaskInput` 是宿主拥有的原始任务事实，任务理解不得改写；
2. `TaskFrame` 是模型推导的版本化语义投影，通过低信任 `TaskObservation` 传给执行模型。

`TaskFrame` 包含原始请求锚点、解释器版本、能力目录摘要和类型化
`TaskSpecification`。Frame 的内容地址标识覆盖输入、规格、解释器版本与能力目录；它只在
对应的 input ID 和任务修订号上有效。Runtime 请求同时保留原始任务和 Frame，使 Trace、
回放、评测和后续修订能够区分事实与推断。

`TaskSpecification` 表达：

- `direct`、`clarify`、`execute` 三种当前路由；
- 意图与规范化目标；
- 信息来源、时效性和必要性；
- 必需或可选的能力及用途；
- 阻塞执行的歧义；
- 回答、澄清和能力结果三类完成条件。

模型输出必须通过严格 Schema 与跨字段不变量。`ModelTaskInterpreter` 只产生规格，不执行
工具。能力目录包括工具输入 Schema，避免解释器只凭名称选择能力；合法目录不设置人为的
64 工具或 512 字符描述上限，真正的大目录预算和检索由后续机制解决。

`SessionEngine` 增加通用 `SessionTaskPreparer` 扩展点。在原始输入成功落库后，准备器读取
已接受会话历史并返回 Frame Observation 与能力名称。宿主 Registry 再次解析这些名称：

- `direct` 和 `clarify` 使用空业务能力视图；
- `execute` 只包含选中业务能力，并按需加入通用 artifact/session 证据读取能力；
- 提示中声明的能力与实际 Registry 保持一致；
- Tool Policy、参数校验、风险和审批语义保持不变。

Task Frame 进入 AgentLoop v3 的初始请求。若 steering 修改任务修订号，旧 Observation 不再
发送，防止过期语义静默控制新任务。当前阶段不自动重新解释，保持行为诚实可见。

相同的 revision-bound Observation 会提供给 `CompletionContext`，使可信验收策略能够按任务
路由选择不同义务。该能力不把 Frame 提升为事实或自动验收器；Policy 仍须独立决定哪些模型
推断可以影响验收，并只能把实际 Tool Record 与 Artifact 当作外部事实证据。

## 关键不变量

- 原始 `TaskInput` 的 goal、constraints 和 revision 不被模型推断改写；
- Frame 明确标记 `model_inference`，不能成为系统指令或授权依据；
- 准备器只能缩小宿主能力集合，不能创建或升级能力；
- 隐藏能力即使被执行模型猜中，也必须以 `unknown_tool` 失败且不产生副作用；
- 准备失败发生在 AgentLoop 启动前，已接受输入以明确中断原因保留；
- 取消继续传播；模型、工具与 SessionEngine 的所有权关系不改变。

## 失败、超时与取消

- 解释器超时和模型失败沿用稳定的 `RunError` 分类，并由 `TaskUnderstandingError` 暴露；
- 非法 Schema、错误路由组合、错误合成工具或未知能力属于非法模型响应；
- `SessionTaskPreparation` 的版本、input ID 和任务修订必须与已接受输入一致；
- 准备失败记录为 `task_preparation_failure`，不会调用执行模型或业务工具；
- 能力选择表示可见性，不表示授权，副作用仍由 Tool Policy 控制。

## 备选方案

- **固定意图分类器**：不能表达复合信息需求、能力用途和完成义务，拒绝。
- **覆盖 TaskInput**：实现简单，但丢失原始请求并提升模型推断的信任级别，拒绝。
- **应用传入正确工具名单**：可作为人工基线，但把核心 Agent 决策交回宿主，不作为默认。
- **暴露全部工具并提示少用**：无法形成安全、可测的能力边界，拒绝。
- **把语义分析放进 Runtime 状态机**：混合非确定性理解与确定性执行语义，拒绝。
- **提前实现大目录向量检索**：当前没有规模与质量证据支撑，引入会掩盖核心契约，暂缓。

## 验证与证据强度

确定性测试覆盖规格不变量、原始请求不可变、Frame 锚点与大小边界、多轮会话历史、输入
Schema 传输、超过 64 个能力的合法目录、最小能力暴露、隐藏高风险工具隔离、准备失败和
取消传播。完整 Runtime 测试验证 TaskObservation 只在相同任务修订上有效。

冻结消融只能证明已知正确规格下，最小 Registry 能减少无关能力和阻止隐藏副作用；它不
证明解释模型的语义正确率。真实模型评测入口已存在，但 2026-10-16 的本地尝试因供应商
HTTP 401 未进入规格生成，所以不得宣称任务理解能力已经得到真实模型验证。

## 当前刻意未实现

- 没有把完成条件冒充自动验收器；
- 没有实现 clarify 等待与补充输入后的 Frame 演进；
- 没有实现 steering 后增量重理解；
- 没有实现大能力目录的候选召回、预算分配或语义索引；
- 没有对非法解释进行模型自修复或多解释器投票；
- 没有把任何应用领域标签、数据结构或工作流加入通用层。
