# ADR 0009：任务理解与最小能力暴露

- 状态：已采纳并实现
- 日期：2026-10-16
- 范围：通用 Harness 的第一个任务理解垂直切片

## 背景

现有 `AgentRun` 能校验模型动作、限制预算、执行工具并从接受的事实重建上下文，但
`TaskInput` 明确由宿主直接提供，所有注册工具都会暴露给模型。它能够可靠执行一个决定，
却没有回答当前请求是否需要工具、需要哪些信息、是否应先澄清，以及什么条件代表完成。

单一意图标签不能解决这个问题。`identity_query` 一类枚举既容易变成应用业务分类，也不能
表达外部事实、时效性、歧义、能力需求和完成义务之间的关系。反过来，让应用预先标注正确
工具，会把最关键的 Agent 决策重新交给宿主。

## 决策

新增位于 Runtime 之上的 `weavria.harness`。第一版使用类型化 `TaskSpecification` 表达：

- `direct`、`clarify`、`execute` 三种当前执行路由；
- 自由文本但有界的意图与规范化目标；
- 信息来源、时效性和必要性；
- 必需或可选的能力及用途；
- 阻塞执行的歧义；
- 回答、澄清和能力结果三类完成条件。

路由与各字段存在结构不变量。直接任务不能要求外部事实或能力；澄清任务必须指出歧义且
不暴露能力；执行任务至少选择一个能力；每个必需能力必须有对应完成条件。模型输出经过
严格 Schema 和跨字段校验，不能因为生成了一段看似合理的 JSON 就获得执行权。

`ModelTaskInterpreter` 通过现有供应商无关 `ModelProvider` 请求一个名为
`declare_task_specification` 的合成工具调用。它只产生规格，不执行工具。原始任务、会话和
能力目录保持在模型请求的数据字段；工具描述和模型生成的解释不会提升为宿主指令。

`TaskUnderstandingEngine` 将解释器输出与宿主实际登记的能力目录再次核对。未知能力在
Runtime 创建前失败。`ToolRegistry.select()` 生成不可变的最小能力视图：直接和澄清任务
看到空目录，执行任务只看到规格选中的能力。未选择能力不是低优先级建议，而是在该次
Runtime 中不可用。

规范化目标和完整规格以明确标记的模型派生数据写入 `TaskInput`，供现有上下文构建器发送
给执行模型。`TaskUnderstandingRecord` 保存解释器版本、输入摘要、可用与选中能力及规格，
不保存隐藏思维链。

## 失败、超时与取消

- 解释器超时和模型失败沿用稳定的 `RunError` 分类，由 `TaskUnderstandingError` 暴露；
- 外部取消继续传播，底层模型调用必须完成清理，不能转换成普通理解失败；
- 非法 Schema、错误路由组合、错误合成工具或未知能力均作为非法模型响应失败；
- 理解失败时 Runtime 尚未创建，不会留下伪造的 Run 事实或执行任何能力；
- 能力选择不能绕过后续 Tool Policy，选择表示可见性，不表示授权。

## 备选方案

- **固定意图分类器**：成本低，但无法表达复合任务和完成条件，且很快吸收应用术语，拒绝。
- **由应用直接传入工具名单**：适合作为人工基线，却不能证明 Agent 自己完成了能力选择，
  不作为默认机制。
- **继续暴露全部工具，只在提示词中建议少用**：不能形成安全或可评测的能力边界，拒绝。
- **让 Runtime 自己推断意图**：会让非确定性语义判断进入执行状态机，破坏分层，拒绝。
- **把解释结果拼接进系统指令**：会把模型输出和工具描述升级为更高信任内容，拒绝。

## 验证与证据强度

单元测试覆盖规格不变量、供应商 JSON 边界、未知能力、超时清理、直接回答零工具和执行任务
最小能力暴露。冻结消融使用身份说明、文档读取、当前时间和歧义副作用四个领域无关任务，
比较“暴露全部能力”和“按规格解析”两种策略。正确规格下，后者 4/4 精确暴露，前者
0/4，并在 4/4 场景暴露了无关高风险能力。

该实验只证明能力解析与隔离的因果行为。解释器使用冻结规格，不能证明真实模型能够理解
这些任务，也不能证明最终答案正确。下一步必须使用固定真实模型、相同任务集和预算比较
规格准确率、澄清决策、无效工具调用、完成率、Token 与延迟。

为此新增供应商无关的 OpenAI-compatible JSON Action 适配器，以及显式启用的真实模型结构
评测入口。HTTP 客户端只属于 `openai-compatible` 可选依赖和评测脚本，模型包仍通过
`ChatCompletionTransport` 隔离网络。2026-10-16 使用本机配置执行 3 次重复、共 12 次调用，
供应商认证全部返回 HTTP 401；调用没有进入规格生成，所以不能形成语义准确率结论。该失败
只证明评测链路能够如实报告传输失败，不证明任务理解成功或失败。

## 当前刻意未实现

- 没有把自由文本完成条件冒充自动验收器；
- 没有对非法解释进行模型自修复或多解释器投票；
- 没有获得有效的真实模型评测结果，也没有 Token 计量；
- 没有持久化理解记录、跨请求任务演进或多 Agent 规划；
- 没有把任何应用领域标签加入 Core、Runtime 或 Harness。
