# 工作区动态能力选择与展示成本

状态：已实现，2026-11-05。流程、失败记录和真实成本见[工作区动态工具接入与成本验证](../工作区动态工具接入与成本验证.md)。

## 问题与本阶段完成条件

工作区清单示例关闭了任务理解，并在固定 instructions 中重复放入全目录，动态工作集因而没有参与。另有两个通用机制缺口：选择器按包含输出 Schema 的完整注册契约计费，实际执行提示词只展示名称、描述和输入 Schema；独立 capability_result 的一次成功会移除隔离计算工具，无法表达需要多轮编辑、检查和纠正的计算任务。

本阶段接通真实模型任务理解、现有需求覆盖选择、Runtime 视图和工作区工具，删除示例中的重复目录。完成条件是：一致的展示成本、计算能力不因单次结果提前退休、非声明计算及 Policy 边界不放宽、多步容器回归通过，并对同一任务计入准备成本进行真实运行观察。实验不预先编排真实模型的能力选择。

## 决定与取舍

复用同一工具展示函数生成 Runtime 菜单和选择器的每项描述字节成本。成本不包括外层数组分隔符、框架回取工具及其他 Prompt，最终发送仍由既有完整请求字节和 Token 准入负责。保持旧 Journal 的表示兼容；选择器版本升级，持久化 Schema 不变。

显式声明的 isolated_compute 视为当前任务可反复使用的计算能力，加入独立覆盖目标；一次工具返回不证明整个计算目的完成。该目标仍参与相同数量、字节预算和效用选择，不保证无条件常驻。只读信息需求保留原有退休规则，side_effect 不获得同样待遇，发现器不能自动激活未声明的计算。Steering 改变任务声明后按新 Frame 重算，无跨任务缓存。

这一保守决策可能保留已不再需要的计算工具，但避免把“调用成功”误当作“多阶段工作完成”。更精确的退休需要可验证的成果义务生命周期，不能靠成功次数或工具名猜测。此阶段不新增工作区专用调度状态机、不按轮数硬编码执行/阅读/合并菜单。

示例增加显式动态模式，私有工具的发现由宿主对当前注册版本逐项允许，执行仍由 SandboxToolPolicy 独立授权。记录实际提交的能力视图与模型请求成本，不把未执行动作当作可用性证据。静态目录和动态模式使用同一清单工具集；动态模式额外的理解调用纳入总成本，不能用上阶段含重复目录的结果作唯一基线。
