# 记忆证据充分性与条件适用审查

状态：机制已实现并完成真实模型对照；实验性质，未达到默认启用标准。

## 问题与本轮边界

ADR 0114 的两个剩余无答案误召回分别把缓存规范当成数据库版本证据、把归档命名偏好当成上次完成日期证据。相关性分数无法判断材料是否给出了所问的信息。本轮对已经授权、经过检索和源预算选择的完整事实组增加审查；不重新搜索记忆，也不替代最终答案验证。

## 机制

1. 第一轮模型只读原始需求，拆分必须回答的原子信息，并提取有原文定位的任务条件。不给它候选记忆，避免按已有材料缩小问题。
   条件明确区分 `given`（问题指定的场景约束，包括问句中的限制）和 `unresolved`（可能但未定的情境）。只有前者进入条件图；未知不能变成一个与所有可能值互斥的新取值。
2. 第二轮模型同时读原需求、分解提案和完整事实族，检查分解是否完整、条件是否有依据，并逐需求逐成员判断直接支持、背景相关或冲突。每个成员必须出现，相关的证据必须给出逐字引文。
3. 宿主验证覆盖、身份、版本和引文；复用条件图计算任务条件是否蕴含事实限定。未知条件不能当作成立，争议成员不能当作确定事实。模型解释只是可出错的提案，不把引文定位当成语义蕴含证明。
4. 输出 supported / missing / conditional / conflict / unverified。仅背景相关的组不进入最终模型上下文；条件未知和冲突材料保留完整事实族，并显式提示限制。
5. Context 编译器把审查结论作为必计预算的低信任诊断交给主模型。若软分配删掉了结论依赖的任一完整组，结论降为 omitted，不能继续声称证据充分。

## 不变量与失败语义

- 不扩大作用域，不更改记忆，不提升权威性，不允许正文改变工具许可。
- 分解、审查最多两次调用，共享绝对期限；输入、需求、事实成员乘积和输出均有上限。没有隐式重试。取消传播，失败不释放未经审查的候选。
- 模型漏审需求、漏审成员、捏造引文或版本均使本轮审查失效；显式 unverified 允许主模型继续寻求其他来源，而不是断言答案不存在。
- 供给报告升级 v4，SessionRequest 升级 v11；旧版本序列化保持不变。诊断绑定需求摘要、供给摘要、任务版本和两轮结构化输出摘要。
- 保留条件图前提、语义边、成员版本、引文摘要及模型调用次数。任务理解入口同样过滤被拒材料；Session 持久化前再次比较投影结果，避免请求重建时丢掉审查结论。
- 判定只针对被选择的记忆断言；它不证明原始来源真实、不等于全库无答案，也不直接决定任务完成。

## 替代方案与验证

不用词表猜测问题类型或继续提高相似度阈值；不采用模型自报置信度。分解与审查分开调用增加延迟，但能检查问题是否被偷偷缩小。完整成员矩阵有明确容量上限，当前不实现跨批次递归审查和多组关系连接；原子需求须能由一个成员直接支持，复杂推导应交给后续工作或其他工具。

确定性测试覆盖错误引文、漏成员、版本、条件缺失/冲突、争议、超时/取消、预算淘汰和旧 Schema。冻结领域无关小型任务集，比较仅相关性供给与证据审查，报告充分性误判、支持保留、条件处理、调用数和延迟；真实模型不可用时明确保留未验证状态，不用 Fake 结果替代收益结论。

## 实验结论与发布决策

2026-11-09 使用真实供应商返回的 `deepseek-flash`，在相同完整事实集上对比朴素单轮充分性判断与两轮条件审查。这里隔离的是充分性判断，不重新测检索排名。开发集 13 题，单轮 12/13；初版两轮 9/13，明确场景模态后为 10/13。修正后另行冻结、只运行一次的不同事实验证集 9 题，单轮 9/9，两轮 6/9。

两个旧误召回均被判为缺少信息，但基线也正确处理了它们，因此不能归因于两轮结构的额外收益。两轮机制增加了过度分解、非法条件边和保守扣留，平均延迟约 3.6–3.7 秒，单轮约 1 秒。不能宣称两轮推理更可靠，也不能宣称已提高最终任务完成率。

决策是保留可选机制和审计链路，默认不启用，不加大重试次数去掩盖问题，不按案例添加词表或放宽引文/条件校验。下一步应比较更少语义转换的结构化联合判断，重点解决“用户请求的答案字段”与“模型自行想出的规划前置条件”混淆；不得在当前机制未证明收益时继续堆叠第三轮自审。
