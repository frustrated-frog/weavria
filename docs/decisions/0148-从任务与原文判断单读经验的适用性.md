# 从任务与原文判断单读经验的适用性

状态：接受，显式启用。复用收益仍需在更多语料和预算下验证。

## 问题与决策

[ADR 0147](0147-按实体与字段条件复用单读经验.md) 要求适配器定义来源角色和证据字段。面对未建模的文档、同义问题或新来源名称，适配器需要提前知道应用将问什么。本轮把适用性判断交给模型，从当前任务要求、当次归一化的候选参数以及受授权的历史原文推断是否值得调整首读顺序。宿主负责候选资格、当前授权、事实回执与原文定位。

普通 Harness 调用可以启用模型审查。调用方为所选模型和推理配置提供稳定标识。此模式和 ADR 0147 的宿主解析器是两种可分别装配的策略。

```python
from weavria.harness import AgentHarness
from weavria.runtime import ModelReadRetryReviewer

harness = AgentHarness.from_config(
    db_path,
    model=session_model,
    tools=tools,
    token_counter=counter,
    read_retry_reviewer=ModelReadRetryReviewer(
        structured_model,
        configuration_id="gpt-6-luna/medium",
    ),
)
```

## 主链路

1. 批次因反馈预算被拒时，先检查工具可见性、参数合法性、反馈上限等资格。至少两个不同的整读都能单独交付时，才进入经验排序。相同任务与候选集合沿用已有精确交付统计。
2. 新现场从同一会话和冻结配置检索最近四条同工具的完整交付回执。每条回执连接到旧决策时的任务、被重提的工具回执及摘要匹配的 Artifact。当前 Policy 重新授权其归一化入参，当前注册版本必须一致。SQLite v13 增加仅覆盖完整交付的部分索引。升级保留 v11 和 v12 已有归因数据，审查模式的配置指纹独立积累试验。
3. 一次结构化模型调用比较当前任务、候选及历史原文。模型可以弃权，或者指定候选和历史记录下标、逐字摘录当前需求，以及能支撑该需求的旧 Artifact 字符串字段和唯一引句。输入最多 14,000 字节，单份历史 Artifact 最多 2,200 字节。
4. Runtime 校验选中的候选、工具身份、需求摘录与实际任务的匹配，以及引句在指定 JSON Pointer 下的精确字符位置。v3 预测记录审查状态、历史回执、Artifact 摘要、定位和摘录摘要。模型只能改变已有的 `retry_read`，后续主模型仍自行重提该调用并消费本次工具反馈。
5. 每个 Run 最多发起一次审查。审查受 `max_intervention_duration` 和当前剩余探索时间约束，已提交的审查通过 Run 事件恢复额度。弃权、无历史、超时、供应商失败、非法引句和越界候选沿用首个可行项。取消沿调用链传播。审查调用独立于执行回合计数，实验分别统计两侧的调用和费用代理指标。

直接在主模型上下文塞入旧全文，会让取证和旧答案混杂，也难区分推荐是否采用旧经验。独立审查使历史披露和可选动作都有显式边界。旧原文只证明旧现场确实交付过相似信息。相邻字段、适用条件和来源优先级是否相符仍由模型判断。当前来源的时效和内容要在重读时确认。

## 跨领域对照

2026-11-23 使用 `gpt-6-luna`、`medium`。领域从已安装 Python 包元数据更换为公交运营文档。十组冻结的虚构运营文档允许独立指定正确原文和预期迁移范围。两组各用相同的历史任务、固定的首轮批次参数及候选顺序；真实模型负责拒绝后的选读、改读与回答。先在原提示上跑一次，再在要求明确摘录目标字段的提示上跑完整一轮。表中是后一轮的观测。

| 指标 | 精确匹配基线 | 加模型审查 |
| --- | ---: | ---: |
| 首读有用 | 8/10 | 9/10 |
| 有用原文完整交付 | 10/10 | 10/10 |
| 取证后严格答案正确 | 10/10 | 9/10 |
| 目标任务工具读取 | 16 | 15 |
| 目标任务模型调用 | 26 | 25 |
| 目标任务模型含审查总调用 | 26 | 34 |
| 目标任务模型含审查总 Token | 51,460 | 58,426 |

审查另外消耗 9 次模型调用和 9,190 Token，中位审查请求耗时为 4.65 秒。所有线上请求返回 HTTP 200。同现场控制样例直接使用精确统计，审查次数为零。

- 换线路和改来源名称的两例都选中正确原文，各少读一次。改名例在补跑时复现。首轮提示曾对改名例弃权。
- 首轮曾拿末班车原文支持首班车读取。加入当前要求与原文引句后，本轮在首班车、节假日、明确版本、实体错配和需要双向时刻五例弃权。
- 撤回例中，当前候选名看起来仍是官方时刻表，模型先读了这份旧表。读到撤回提示后再读公告并答对，定向补跑复现了误选。另有一例对原本就在首位的官方公告作了多余的正向批准，首读排序没变。
- 版本例的审查弃权，正确原文已经交付，但最终严格答案有一次未通过。该例补跑时答案通过，说明最终答案得分仍受后续模型输出波动影响。

本轮语料覆盖显式和隐式失配，样本量不足以支持默认开启。工具少读 1 次的收益低于本轮观察到的审查开销。撤回例说明最需要验证的是当前来源的有效性，而旧证据相似度和引句校验只能覆盖其中一部分。
