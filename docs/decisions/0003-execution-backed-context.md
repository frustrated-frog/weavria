# ADR 0003：从已接受执行事实重建可回取的任务上下文

- 状态：已采纳并实现
- 日期：2026-10-11

## 问题

ADR 0002 的选择器只消费大小、时间和人工必要性标记，无法发现相关证据；手工构造的 ToolExchange 也不能证明真实执行。此轮完善模型与上下文切片，核心问题是：在有限输入预算下，怎样从真实工具执行中选择当前任务相关的信息，同时保留完整结果、来源与跨调用读取关系。

## 决策

实现串行、有界的模型—工具循环。工具注册时声明类型、版本、行为、超时、重试、风险和审批要求；独立 Policy 决定能否执行。当前默认仅允许无需审批的低风险只读工具，不实施写操作与自动重试。

工具结果经过工具专有 Schema 校验后保存为运行作用域内的内容快照。模型接收结果的投影，完整数据可通过显式工具再次读取。工具执行上下文自动记录读取过的成果，生成跨调用依赖；依赖由执行访问产生，不由模型或宿主预先标注正确证据。

工具可声明结果的 `context_paths`，限制参与打分的内容子树，避免协议元数据遮蔽正文；完整成果不受影响。这是工具布局契约，不是任务答案标签，也不是隐私过滤机制。

使用当前任务的目标与约束检索精确来源片段。采用确定性的词项检索与有预算的依赖闭包选择；保留近期工具反馈，相关内容使用片段表示，依赖来源至少保留可回取引用。完整输入再次编码计量，不允许裁剪后的历史失去调用身份与来源。旧的 required_call_ids API 保持兼容，仅作为显式保留基线。

每份成果提供引用与不同数量的片段候选，小结果优先使用更省空间的完整表示。选择先为最新反馈提供可容纳的最小片段，再按新增相关性与新增字节的比值逐步增加或升级结果表示；成本包含缺失的依赖来源。此顺序来自实验发现：单纯优化相关性可能让旧证据挤掉刚读取出的值，破坏读取反馈闭环。当前采用有明确反馈下限的确定性贪心分配，不宣称求解全局最优。

授权记录绑定工具版本、Policy 版本与独立的归一化参数快照。成功收据必须与成果及允许决策一致。框架端口身份错误终止 Run；参数或后端错误才作为模型可消费的工具反馈。自定义 Policy 不能绕过尚未实现的写操作、未知幂等性与审批流程。

执行事实写入实例内的版本化事件记录，状态通过纯归约器更新；上下文读取状态投影，不自行维护另一份执行事实。事件和成果使用序列化快照防止嵌套修改。取消继续传播，取消终态可从记录观察；时限、模型轮次、工具次数与输入预算都具备明确终止行为。

## 备选方案与取舍

- 继续让宿主标注必要调用：可验证保留契约，但把发现相关证据的难题交给宿主；保留旧接口作历史基线，不作为当前机制。
- 直接截断工具正文：无法恢复省略内容，缺少可靠来源范围；选择完整成果存储与精确片段投影。
- 用模型摘要替代原始结果：额外引入摘要失真、调用成本和新的非确定性；当前先用可回取片段验证信息交付，需要语义压缩时再评测收益。
- 仅按相关性最大化输入：容易忽视刚执行的读取反馈；为最新反馈设置可用性下限，再比较边际收益。
- 把可变上下文作为执行状态：视图遗漏会丢失事实，任务重排也会污染历史；以事件归约为权威，视图随任务重新构建。

## 当前范围

不引入完整 Agent 框架或新 Runtime 依赖，不实现持久化恢复、分布式运行、长期 Memory、多 Agent、写工具或自动审批。检索提供词项相关性，不保证语义理解、证据真实性或答案正确性；依赖仅表达通过受控成果读取建立的关系，不宣称发现全部语义依赖。当前继续使用归一化 JSON 字节预算，不冒充供应商 Token 预算。

验证采用真实工具执行和依赖输入内容的确定性测试模型；冻结数据与模型行为，对比近期窗口、完整内容和相关片段策略。正确答案与必要来源只由评测端检查，不作为上下文策略输入。测试模型用于证明执行与信息交付的因果关系，不能证明真实 LLM 收益。

## 验证结论与后续条件

Fixture / Solver / Evaluator v1 的四个场景、三种策略共 12 次实际运行。相关策略在旧证据被近期噪声挤压的场景中交付可验证答案；近期基线丢失答案，完整历史超预算。大结果尾部与显式成果读取场景也能在有限输入下完成，全部运行保持预算、读取闭包和事件状态回放不变量。源码流程、精确成本与局限见 [当前说明](../model-context-selection.md)。

当前来源枚举由测试模型固定，不能据此接受真实模型能力提升结论。下一步应冻结真实模型配置与领域无关任务，采用供应商实际输入计量，检验遗漏恢复、任务修订和错误反馈的收益；若词项检索暴露同义词、冲突或证据遗漏问题，再根据失败证据调整机制。
