# 局部工作补丁与宿主版本绑定

日期：2026-11-16。状态：已实现，实验策略，默认关闭。

## 问题

ADR 0129 的真实执行中，模型经常在全量替换六条工作记录时丢失身份、填写错误父版本或引用地址。降低协议负担应保持既有 CAS、依赖失效、来源权限和语义重验，不能由宿主猜测结论或替模型批准更新。

## 决定

增加显式 `work_updates="patch"`，默认保留 replace。仍使用 propose_work 和原有 WorkProposal/WorkingState 归约链。输入包含 upsert、remove、review；note_id 必须显式稳定，已有节点字段省略即保留，新节点必须声明 kind/summary。未触及节点原样保留。next_query/next_need_ids 同样区分省略与显式清空。每类操作内部 ID 必须唯一，remove 不得与 upsert/review 相交。upsert 已隐含按需重验，同一 ID 同时出现在 review 时合并为一次意图；不能产生第二份候选或收据。拒绝未知 ID、空操作、超限、环和非法引用。

模型只选择依赖节点名。编辑或重验节点时，宿主从本次绑定视图取父版本；不会给未触及的节点换绑。新建节点可以在同一补丁组成有界 DAG；依赖一个本批编辑的既有父节点则拒绝，要求先提交父节点再审查后继。失效上游不能通过批量自动换绑复活下游。整个补丁编译为一个原子全量 WorkUpdate，沿用原来的 CAS 与同批证据先行归约，不自动合并并发旧提案。

WorkUpdate v4 增加显式 recheck_note_ids，以区分局部重验意图和旧协议的自动根重验；未触及的失效节点继续阻止交付，不因补丁更新独立分支而被暗中审查或刷新。变更/删除失效结果仍强制走重验，空选择不能绕过门禁。旧 v1/v2/v3 保持原语义。

补丁的来源使用已授权 artifact_id 和精确 quote，可选 pointer。省略 pointer 时在有界 JSON 字符串叶子中定位唯一出现，宿主计算实际路径；重复、跨字段歧义、越界容量直接拒绝。不做模糊匹配，不改变 Artifact 权限，不把定位成功当作语义支持。

## 取舍与验收

保留稳定显式 note_id，避免数组位置随删除变化；不引入第二套持久化 Patch 事件或工作状态。不自动推断自然语言依赖，不自动选择最终答案。编译需要读取绑定的模型视图，不能在无视图的直接工具调用中猜测当前版本。

确定性测试覆盖独立内容保留、宿主版本绑定、新 DAG、前沿限制、删除、重复与未知身份、并发 CAS、原文歧义/容量/授权、取消和重放。真实对照固定 work_recheck=True，只切换 replace/patch，使用原三项资料与两项短材料、相同预算和独立答案，记录失败、失效触发与实际审查，不能把没有进入机制的成功算作修复收益。


## 实验反馈后的设计修正

首版 patch/1 严格要求三类操作的 ID 完全互斥。完整对照显示，模型经常同时提交同一笔记的 upsert 和 review。两者具有相同的重验意图，无须判定冲突。patch/2 因此合并这类冗余声明，仍拒绝一类操作内部重复及任何 remove 冲突，保留原文、前沿、收据和 CAS 门禁。回归测试验证重验只执行一次、父版本推进一次且后继仍失效；这不是允许含糊的并发合并。

两轮完整实验分别留证，不删除初版失败；最终配置、结果和限制见[执行机制与实验](../局部工作补丁的执行机制与实验.md)。
