# ADR 0052：任务目标定位与双向证据匹配

## 问题与决策

ADR 0050 的静态参数匹配可以隔离操作类别；ADR 0051 可以隔离调用失败。但两者都不能单独证明
“这份完整结果属于本次请求中的对象和版本”。本次把目标绑定编译进现有 Match Plan，不创建另一套
事实库，也不让通用框架理解公司、订单或具体领域名词。

采用以下链路：

1. 受信 EvidenceSurface 声明 `target_rules`：目标键、输入 JSON Pointer、输出身份 JSON Pointer。
2. 解释器在 InformationNeed 中提议 `targets`，通过 Unicode 字符起止位置定位当前 TaskInput.goal
   或 constraints 中的文本。页面数据、旧助手文本不能作为此处的直接来源。
3. 宿主 TargetResolver 从已接受的身份映射进行无副作用解析，返回规范值、允许的输入别名与来源引用。
   默认 LiteralTargetResolver 只保留所选原文，不猜测名称对应哪个 ID，也不执行网络请求。
4. 主机根据原始请求、当前任务版本、受信 Rule 与解析结果生成 EvidenceTargetBinding，纳入 Plan
   身份和 Requirement 指纹。绑定保留 input_id、Task SHA-256、revision、原文位置、解析器版本和来源。
5. Resolver 先校验规范化调用参数，再校验返回值中的规范身份；两者通过后，才允许语义提取器建立
   Binding。正确调用返回错误对象时生成 `evidence_target_mismatch`，不能升级成已满足证据。

这使相同工具读取不同对象、相同对象读取不同版本，以及响应串用成为可执行的反例，而不是只依赖
需求描述或 Prompt。Tool Policy 仍独立授权；目标映射不赋予任何执行权限。

## 公开契约与使用

`EvidenceSurface`、`InformationNeed`、`EvidenceMatchPlan` 分别增加 v2，只有 v2 才可携带目标字段。
v1 保持原始线格式，序列化不会额外写入空目标字段；旧 Frame 和 Plan 不被补造目标证明。
Task Frame 继续使用 v6 包络，其嵌套契约通过自己的 Schema 版本演进。

例如，宿主的对象读取工具可以声明：

```python
EvidenceSurface(
    schema_version=2,
    surface_id="record.value",
    description="指定对象的指定版本",
    required_fields=("/value",),
    target_rules=(
        EvidenceTargetRule(key="subject", input_pointer="/subject", output_pointer="/subject"),
        EvidenceTargetRule(key="version", input_pointer="/version", output_pointer="/version"),
    ),
)
```

对于 `Read A v1`，解释器可选择 `subject: [5,6)` 与 `version: [7,9)`；主机把它们分别绑定为
`A`、`v1`。实际调用 A/v2 不适用，调用 A/v1 返回 B/v1 也不能成为证据。
需要别名时，通过 `TaskUnderstandingEngine(target_resolver=...)` 注入宿主映射；规范身份与被允许
的输入别名分开保存，返回结果必须给出规范身份。数值 ID 等非字符串身份也由适配器解释。

配置了目标规则但没有选中受信 Surface、缺少必要目标、位置越界、解析失败，或规范值不符合工具
输入 Schema 时，准备阶段拒绝该规格。不能回退为不带目标的强语义证明。当前没有为目标解析另起
不受 Runtime 管理的联网预取；需要在线解析的应用，应先通过受管工具取得可信身份映射。

## 不变量、取舍与边界

- 当前任务修订与绑定版本不一致时，旧调用和旧 Binding 均不能继续提供目标证明。
- 输入别名不等于返回值别名；适配器应把来源身份归一化为规范值。
- 不从自然语言描述中硬编码抽取实体，不要求模型凭空构造授权或受信身份。
- 定位到用户原文证明的是出处，不保证模型对比较关系、修饰关系或冲突指令的理解必然正确。
  覆盖审计、澄清与宿主解析策略仍承担这些职责。
- 没有声明 target_rules 的既有 Surface 保留原有保证。本次没有为 FinScope 所有异构响应虚构
  身份字段；应用应逐个对有权威身份契约的证据面采用该机制。
- 16 KiB TaskObservation 限额继续生效；目标元数据超限时拒绝，不静默丢弃约束。

备选的纯描述匹配缺乏可执行身份约束；只核对调用参数不能发现错误返回对象；把页面实体直接设为
目标会让导航上下文覆盖用户原文。均不采用。

## 验证

`tests/harness/test_target_binding.py` 从真实 TaskUnderstandingEngine 和覆盖审计入口编译，而非
手工拼装 Match Plan。覆盖正确身份、错误身份、错误版本、错误返回对象、宿主别名映射、越界选择、
旧任务证明失效和 v1 线格式兼容。这里使用受控工具和 Fake Provider 验证契约，不把它当作真实模型
理解能力或整个 FinScope 综合分析正确性的证明。
