# 用已提交工作状态判断收尾就绪

`propose_work` 成功只表示工具产出了一份提案。归约仍可能因版本冲突或未知需求拒绝它。任务修订也可能使已接受的记录失效。长任务的发布条件需要一条当前仍适用、带来源的结论，因此以已提交的工作状态为准。

Session 准备阶段把已提交的语义快照交给 Runtime。Runtime 绑定同一 Run 和任务修订号，给收尾前置条件与完成验收提供独立快照。新增的 `CommittedFinalizationPrerequisite` 可读取该快照，已有的记录型前置条件继续使用原接口。分层策略逐层检查各自的条件。Runtime 只传递 Core 的语义快照，工作记录的解释由应用策略承担。

长任务策略要求当前工作状态包含一条有实际来源记录的结果笔记。版本冲突、未知需求或任务修订之后，旧提案成功事件不能满足此条件。探索预算允许时保留普通决策，提前提交结果时使用既有完成修复提示，资源预留点仍无法满足条件时沿用预算终止语义。

集成回归通过真实的提案工具、工作归约、Session 持久化和 Runtime 收尾路径，覆盖接受、版本冲突、未知需求及运行中修订四种情况。普通任务继续使用各自的完成策略。验证采用确定性模型。
