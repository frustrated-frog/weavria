# 隔离计算与显式成果导出

## 问题与本阶段结束条件

工具执行器目前只接受可重放读取，Agent 需要宿主预先实现每种计算。本阶段支持领域无关 Python 数据处理：接受原始 Artifact → 隔离运行 → 反馈错误 → 正常模型轮次修正 → 校验并导出结果 Artifact。必须证明资源限制、取消清理、路径隔离、输入来源绑定和默认权限拒绝。真实任务采用数据转换与统计，脚本模型只证明控制链，真实模型用于检验自行编程和修复。

## 设计决定

新增独立 `sandbox` 子系统，只依赖标准库和 Pydantic；公开后端端口与版本化输入/输出边界由此拥有。`tools` 通过其公开 API 适配，不把 Docker 协议放入 Runtime。首个后端为 Docker CLI，固定镜像内容 ID，禁止自动拉取。无新 Runtime 依赖。Backend 是宿主可信插件，不能由模型注册。

工具行为增加 `isolated_compute`（ToolDescriptor v8）：允许在一次性环境内产生临时文件，没有宿主或网络写入能力。`replay_safe` 只表示重新执行不叠加外部业务效果，不表示时间/随机数完全确定。默认 ReadOnlyPolicy 不授权计算；专门策略绑定宿主允许的工具名称和版本。已有 external side_effect 拒绝不变。跨会话任务接续和崩溃恢复仍只支持原有只读边界，不假称新能力已支持进程恢复。

容器只读根目录、断网、能力收窄、no-new-privileges，并限制 CPU、内存、PID 和 tmpfs。可信容器监督程序以 root 启动，仅保留设置目录属主及切换 UID/GID 所需的 CHOWN、SETUID、SETGID，用户代码以 65534 身份、清理后的环境和独立工作目录运行；输入文件归 root 所有。监督程序不执行生成代码，仅启动子进程并有界收集输出。不挂载任何宿主路径、Docker socket 或凭据。

输入只可经 ToolContext 读取当前已接受 Artifact 的指针，形成工具依赖。导出限定 UTF-8 普通文件，逐层使用目录描述符与 O_NOFOLLOW 拒绝符号链接/路径穿越；不在宿主解包容器 tar。返回内容继续是低信任计算结果，不能凭 exit_code=0 当作业务验收。stdout/stderr、代码、文件数量和字节均有独立上限。

每个调用创建唯一容器，完成或失败后删除。容器内部有壁钟期限，宿主超时/取消还会主动 force-remove。所有 CLI 与清理任务均由调用者持有、等待；重复取消不能留下无人跟踪的清理任务。Docker 不可达、删除无法确认时保留可定位容器名称并报告清理失败；取消仍作为 CancelledError 传播，附带清理诊断。主进程崩溃、Docker 故障和内核漏洞不属于绝对安全保证。

## 替代方案

没有采用宿主 subprocess 或 Python exec 充当沙箱；临时目录无法约束宿主访问。首版不实现持久 Jupyter 内核，避免把不可序列化解释器状态和重试语义隐藏起来。结果通过显式 Artifact 继续下一轮，原输入每次重新准备；未来需要多步文件编辑时再研究版本化工作区。容器隔离依赖可信 Docker daemon 与镜像，不宣称可替代面向恶意多租户的专用虚拟机沙箱。

- [Docker 容器运行](https://docs.docker.com/engine/containers/run/)：内容寻址镜像、资源和权限限制。

- [Python 3.12 异步子进程](https://docs.python.org/3.12/library/asyncio-subprocess.html)：显式等待、管道死锁与 communicate 的无限内存风险。

此处借鉴执行隔离与有界输出机制，没有引入外部 Agent Runtime，也没有声称复现某篇论文。

配置、代码流程与验证证据见[隔离代码执行的生命周期与验证](../隔离代码执行的生命周期与验证.md)。新计算行为使用 ToolDescriptor v8、CapabilityDescriptor v2 与 CapabilityView v2，不能写成旧版本。旧只读记录仍使用原版本，序列化与目录哈希不变，无需重写已持久化记录；旧二进制不能消费新计算元数据，须升级后再注册该工具。
