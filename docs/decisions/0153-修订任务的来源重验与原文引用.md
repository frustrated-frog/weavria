# 0153 修订任务的来源重验与原文引用

2026-11-27。上轮发现两种相反的失败。安装组合改了，但清单和锁文件没有改，续接仍然重读；文档任务转向工作记录后，模型用说明文档中的数值作答，遗漏评分要求的设计决策原文。[上轮验收](../任务修订与整体验收复测.md)

## 旧材料如何成为本轮证据

1. 模型仍须在当前任务提出具体工具调用。Runtime 核对工具视图、参数、Policy 和期限。对于显式声明没有 Artifact 输入、无动态 Artifact 解析器、无额外上下文路径、非轮询的可安全重放只读调用，执行器把本次工具身份和规范化授权绑定到短生命周期的 ToolContext。
2. 工具后端先验证本轮对该来源的访问与可用性。若它掌握本次请求完整返回值的可信 SHA-256，可调用 `await context.reuse_verified_result(digest)`。摘要取自当前来源的授权版本清单，覆盖规范化 JSON 的完整输出，例如路径、文件摘要和正文。模型提供的摘要或旧回执中的摘要不能充当本轮版本证明。该 API 适用于自包含的值，宿主负责证明当前请求会产生相同输出。
3. SQLite 只在同一会话紧邻且已完成的前一 Run 的已接受结果内查找。核对工具名、版本、Policy 版本、规范化参数、结果摘要和回执身份，排除带输入依赖的历史回执。命中后走已有 `read_source`，再次核对当前调用仍在执行、生产回执已接受、原件身份与内容摘要一致，并持久化 `SessionSourceRead`。
4. 后端按自己的类型验证取得的值，再走正常输出校验、预算、取消和结果发布流程。本轮回执有新的 Run / Call / Artifact 身份，来源记录可追溯到旧原件，当前任务的证据归约和完成验收照常进行。内容改版、查询不同、工具或 Policy 换版、会话隔离、存储没有这个可选能力时，工具可以执行普通读取。拒绝访问、已关闭调用或原件损坏按对应失败处理。
5. 未重新提出取证请求时，不会把上轮结论填入新账本。工具调用次数与读取原始来源次数分开计量。查询检查上一轮回执，命中仍需从 SQLite 取出并校验正文。本轮快照示例在挂载时遍历材料生成摘要，试验衡量避免多少次读取后端分支，没有测得端到端 I/O 字节收益。[执行入口](../../src/weavria/tools/execution.py) · [持久化查验](../../src/weavria/sessions/store.py)

## 需要新来源时如何处理

冻结文档中，使用说明在正文末尾用相对链接指向底层设计。快照阅读工具可选 v2 输出，在 `referenced_paths` 中给出最多八个已经解析且存在于本轮快照中的不同路径。该实现只解析简式 Markdown 行内相对链接，忽略图片、外部 URL、自引用和不存在的文件。它不请求网络或遍历文件系统，也不自动递归打开目标。模型自行决定是否补读及如何引用，独立评分仍同时检查真实读取与最终答案。固定 M1 默认继续使用 v1；v2 由定向诊断显式启用。[快照阅读工具](../../examples/m1_corpus.py)

选用当前来源的完整内容摘要，是为了让相同路径的新版、相同正文的不同参数和其他会话都不能自动获得旧回执。跨 Run 直接继承 Need 状态会把旧语义结论带入新目标。仅提供历史摘要又无法证明当前来源的版本。对于开放网络数据、没有低成本版本证明的读取、时效要求或缺少可追踪引用的任务，应继续按来源的实际契约取证。

## 验收方法

在冻结的双组件升级、安装组合迁移任务中，每项三次。首版完成后通过 SQLite backup 分出两个相同起点，分别普通续接、开启回执复用续接，交替安排两臂顺序。首版未完成保留在整对分母。材料、问题、模型、工具对模型的声明和独立判据均相同。来源切换另外使用原 M1 的 documents_steering，分别在 coverage 和 recent 配置下重复三次。诊断试验保留了所有失败。

```sh
uv run --offline pytest -q tests/evaluation/test_revision_receipts.py
uv run --offline python -m examples.revision_delivery --compare-receipts --catalogue-proof --live --env-file .env.m1-openai --out .weavria/revision-delivery/new-receipts
uv run --offline python -m examples.m1_harness --run --env-file .env.m1-openai --case documents_steering --diagnostic-repetitions 3 --out .weavria/m1/new-steering
uv run --offline python -m examples.m1_harness --run --env-file .env.m1-openai --case documents_steering --diagnostic-repetitions 3 --source-links --out .weavria/m1/new-steering-links
```

回归测试从真实 SessionEngine 发起调用，验证关库重开、重复输入、来源改版、新文件、参数别名、跨会话与权限变化，以及核验期间取消后的清理。文档链接测试验证列出路径不会生成目标文件回执。模型行为与成本另按真实批次统计。

## 文档转向的定向结果

相同问题与评分器，GPT-6 Luna medium，各组每个策略重复三次。原阅读工具在 coverage、recent 下均为 0/3，没有一次读到或引用 ADR 0078，其中四次候选答案的数值字段正确。v2 在 coverage 下为 3/3、recent 下为 1/3，四次通过的运行都从使用说明继续读取了原始 ADR 并正确引用。其余两次都在任务理解请求失败时结束，未进入执行，保留在分母。原组 81 次调用共 622,341 Token。v2 共 52 次调用，已报告 316,158 Token，两次失败请求没有用量。不能据此比较完整 Token 总成本。

这里改变的是阅读工具的返回结构、版本与说明。六个坐标只覆盖一项定向任务，两批不共用执行中的模型判断。新路径来自文档已经存在的链接。全量 M1 成绩仍以上一轮完整复测为准。

## 修订任务的配对结果

六个首版均通过独立评分。下表只统计分出两臂后的修订阶段。后端读取统计实际执行文档读取分支的次数。重验命中逐次核对 SQLite 的来源记录，确认本轮调用指向首版已接受的原件，且新旧回执内容摘要一致。

| 任务与策略 | 通过 | 后端读取 | 重验命中 | 模型调用 | Token |
| --- | ---: | ---: | ---: | ---: | ---: |
| 安装组合迁移，普通续接 | 1/3 | 2 | 0 | 19 | 129,002 |
| 安装组合迁移，开启重验 | 1/3 | 0 | 4 | 23 | 163,218 |

安装迁移第一对交付了相同的依赖差异。普通续接重读清单和锁文件，开启重验后两份文件都命中，模型调用从 6 次变为 7 次。升级第三对的重验组取回三份未变材料，实际读取新增的 `review-note.txt`，把 linden 的测试回执更新为 `T-697` 并通过。该对普通组预算耗尽，第一对升级则是普通组成功、重验组预算耗尽。六对总通过数各为 2，后端读取从 7 次降到 2 次，模型调用从 60 次升到 63 次，Token 从 406,118 升到 434,127。两组失败的轨迹长度不同，不能把后端读取总数之差当作相同任务完成量下的固定节省。

安装迁移第二对说明了下一个问题。重验组拿到了清单和锁文件的正文，三次提交候选答案都因 `missing_evidence` 被退回，记录中最终缺少 `/text`。任务声明把搜索的 `/paths` 与读取的 `/text` 放进同一个证明范围，但两个字段来自不同调用。下一步应验证能否在任务准备阶段把“定位这份文件”和“从这份文件取得字段”拆成两个有来源关系的要求，并用一个同名文件的反例检查能否排除错误绑定。

本地原始批次在 `.weavria/revision-delivery/receipts-20261127`、`.weavria/m1/steering-source-20261127` 和 `.weavria/m1/steering-links-20261127`。真实模型批次共用当时工作树已有的任务准备与覆盖验收改动，解释范围限于该配置。独立检出的提交切片另行运行工程回归。
