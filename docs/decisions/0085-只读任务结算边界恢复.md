# 只读任务结算边界恢复

只读工具结果已持久接受后，进程可能在下一轮模型调用前退出。重新发送用户输入会启动新 Run，并丢失原 Run 的动作预算与执行位置。本阶段提供显式的 `SessionEngine.resume(session_id, run_id)` 和 `AgentHarness.resume(session_id, run_id)`。

工具批次结算后，Session 先归约并提交语义状态。持久化执行结算决定时，在同一 SQLite 事务中记录执行序列、决定序列及语义头版本。无任务解释器的 Session 也要确认工具记录已结算。这个边界要求状态位于下一轮决策前。后续任意 Run 事件都会使旧边界失效，因而中断发生在 ToolStarted、Artifact 写入、未结算反馈或下一轮 ModelStarted 后时均拒绝恢复。旧数据库升级后保留历史，已有中断 Run 缺少此边界记录时同样拒绝恢复。

恢复领取只允许当前会话最新的中断 Run。它在一个事务中核对配置、事件游标、语义版本、可用预算和历史索引水位，再占有 Session 并写入恢复领取事件。原进程文件锁和 SQLite Session 占有共同保护单机执行权。领取后以当前 Policy 重审旧结果的读取依据并复核 Artifact，校验通过后从已接受事件重建原 Run 的状态、调用计数与决策序列。剩余期限以原始输入接受时间计算，停机时间计入期限。

模型从原 Run 的下一轮读取已接受结果和工作状态。原工具调用不会因恢复被重新派发。当前切片要求工具注册为可安全重放的只读工具，且保守拒绝无法重审的旧结果。运行时内存里的启发式统计按新进程重建初始值，已接受事件中的调用计数、任务修订和动作价值状态继续有效。当前不提供跨会话接续、未知工具调用的恢复或外部副作用重试。

复验命令为 `uv run pytest -q tests/sessions/test_crash.py`。用独立进程真实退出，再用新进程恢复，核对原 Run 身份、原文复用和已提交工作记录。固定资料任务中，正常与中断恢复均得到相同答案，各有两次模型调用和一次工具调用。另测并发领取、授权撤回、预算耗尽以及边界外拒绝。脚本模型用于验证执行语义。
