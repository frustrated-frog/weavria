# 0139 按笔记引用预留反馈与原提案单独重提

2026-11-20，已采纳。

## 问题与选择

源码长任务中，模型把读下一页和保存阶段事实放在同一批。批次被拒后，三次冻结失败中的两条笔记即使单独提交也被挡住。普通 `propose_work` 只读取草稿中显式引用的 Artifact，其中两次准入却分别按六条、四条可见记录预留。失效笔记重验另需读取旧节点和父节点，不能套用这项优化。[原始回放与验收](../反馈预算修复后的定向验收.md)

选择为工具增加按校验后参数求读集的版本化声明。Runtime 只理解 Artifact ID 与已接受的依赖图。把笔记结构写进 Runtime 会使其它工具难以复用，扩大预算又无法解释同一提案真正需要哪些记录。单提选择由模型作出，混合批次被拒时仍是零派发。

## 从一次提案到可核实的写入

1. `ToolDescriptor` v10 可为可重放的只读工具登记确定性读集解析器。普通工作提案枚举所有 `notes[].sources[].artifact_id`。原文引句和字符区间两种引用都按同一身份处理。启用重验的提案、局部补丁分别依赖旧节点或既有工作状态，继续使用完整视图。v9 平面字段声明和旧工具保留原协议。
2. 单调用先按完整可见视图计量。超限时，所有来源都必须出现在本次授权视图中。Runtime 逆序扫描已接受的记录，把来源及其祖先闭合，再按事件顺序为实际可授予的子集预留。该子集随准入事件持久化，执行器按同一范围读原件。指针、区间、工具权限、进展检查及工作状态的版本比较仍由原执行路径核验。[预算计算](../../src/weavria/runtime/feedback_budget.py) · [提案与原件绑定](../../src/weavria/harness/work.py)
3. 混合批次因反馈预算被拒后，宿主对当前可见的候选分别做正式单调用计量。退回通知 v8 可同时携带同游标的分页建议和一个按原参数单提的选项。后者仅提供给公开、低风险且无需审批的已声明工具。单提选项、分页提示总和必须能装入原有的 1 KiB 控制通道，容量不足时沿用原提示。选择时仍重新检查当轮预算和权限。
4. 拒绝事件绑定整个提案的摘要。归约器从事件中的原始批次找出对应的工具和调用 ID，保存待引用的原参数。模型返回显式选择后，宿主分配或校验新调用 ID，从当轮仍有效的通知中还原参数，执行正常准入，最后由工作状态归约和 CAS 接受笔记。事件保留模型选择，回放按同样规则还原。过期选择、工具名不符和参数替换均不能借此执行。[事件归约](../../src/weavria/runtime/state.py)
5. 无状态 OpenAI 兼容适配器在 `return_to_retry_alone` 中呈现完整的 `retry_offered_call` 决策，包含工具名与旧调用 ID。计量和发送使用同一报文。只有完整匹配当轮选项的响应才会转为带引用的 ModelTurn v3。若在该选项有效时只回同名工具和空参数，模型边界返回可修复错误，工具不会派发。明确提交 `{"notes":[]}` 仍走正常工具语义。[供应商编解码](../../src/weavria/models/openai_compatible.py) · [模型边界校验](../../src/weavria/models/provider.py)

## 验收边界

回放分别验证模型选项、工具回执、已持久化摘要和引用，以及分页进入下一请求的逐字符原文。它证明被阻断的阶段事实现在可以保存。自然选择是否改善最终答案由六次独立定向运行衡量。运行暴露的空调用歧义以三个原现场的模型边界回放单独验收。[数据、失败分布及复现命令](../反馈预算修复后的定向验收.md#笔记按来源准入后的六次验收)
