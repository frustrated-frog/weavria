# 带回取地址的上下文压缩基线

启用 `ContextCompilerConfig(extractive_compaction=True, ...)` 后，支持原文回取的请求可以为未交付正文的当前 Run 工具来源补充短摘录。第一版把现有编译器作为对照，优先验证短表示是否能在原文放不下时提供有效的阅读入口。

编译器先完成原有分配，再从剩余来源中按当前需求的加权词项匹配度选取最多四段，每份来源最多一段。每段最多 120 个字符，附带调用标识、原文摘要、JSON Pointer 和字符起点。编译器对完整请求重新计量，预算不足时依次去掉排名较低的片段，最后回退到原请求。原有正文、强制反馈、依赖闭包和工具证据交付清单保留原语义。

摘要属于模型可见的低信任数据。它绑定 Run、任务修订与会话序列水位，每次编译重新构建。回取继续走 `recover_context`，按当前 Run 的已接受结果和既有预算验证精确地址。没有额外模型调用或后台任务，取消由原编译调用传播。

SessionRequest v7 承载实际交付的摘录。ContextCompilation v13 记录启用后的交付状态及请求摘要。旧版本保留原序列化格式。供给报告与记忆包仍按原有契约校验。

当前策略压缩原始资料的可见表示，阶段计划、失败尝试与跨轮分析结论仍由工作状态管理。后续的语义阶段摘要可以在此基线上比较任务完成率、引用准确性、回取次数和 Token 成本。当前确定性对照只验证预算、引用和回退行为。
