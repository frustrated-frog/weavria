# 任务条件化记忆检索与覆盖选择

## 本次能力与问题

原来的 MemoryContextSource 将当前任务和其他需求拼成一次 BM25 查询。它能保持事实组完整，却无法避免某个子问题占据所有候选，也找不到没有词项交集的改写。新增实现允许每个需求独立进行词法或语义召回，在完整字节预算下选择事实组，并将相关度传到最终 Context 编译器。

这是显式启用的可替换机制。原默认路径不变；下面的实验没有证明 Hybrid 可以普遍替代它，也没有证明整个 Memory Engine 已达到成熟框架水准。

## 一次请求如何流转

1. `HarnessMemory.retrieval` 可注入 `TaskMemoryRetriever`；`AgentHarness` 将它交给 `MemoryContextSource`，沿用现有任务需求，没有新增一次生成模型调用。
2. `SQLiteMemoryStore.retrieval_snapshot` 在同一个只读事务内固定 `scope/head/known_at/valid_at`，读取完整可见版本与对应来源。授权、争议保留、候选数量及总量限制在编码之前执行。事务结束后才调用语义模型，避免持锁推理。
3. `TaskMemoryRetriever` 对每个需求分别算 BM25 和 Dense 排名。Dense 输入包含主体、属性、条件和正文，长表示按 UTF-8 边界分块；分块只改变排名输入，不能截断交付的事实。
4. 候选按现有 `(scope, kind, subject, predicate)` 精确键归组，组内最大成员相关度用于排名。同族的零匹配例外、争议和来源仍整体带回。当前没有语义同义实体合并或自然语言条件蕴含判定。
5. 组级 RRF 融合后进行多需求预算选择。`MemoryMatch` 表达每个组对每个需求的序位效用；旧 `MemoryGroup/MemoryHit.score` 置中性值 0，因为此时不存在单一全局词法查询。不能把这些 0 理解为新策略未匹配。
6. Harness 生成 `ContextSupplyReport v2`，绑定任务版本、需求摘要、快照摘要、实际 Bundle 摘要，并记录相关度与降级诊断。Context 编译器只将相关度加入软收益函数；最终 Token 硬预算、完整 Bundle 边界和授权规则仍生效。
7. 编译结果随会话事件持久化。旧供给报告 v1 的序列化保持原样；新的策略身份记在供给报告与编译报告，`ConversationView` 的历史视图协议保持原版本。恢复读取支持两版供给报告，不需要数据库 DDL 迁移。

例如用户需求没有出现 `alpha`，但编码器将它与事实 `alpha` 关联，旧词法路径无法选入；新路径会将关联强度传到最终上下文。若这个事实还有 `only on weekdays` 限定，同一组内的限定必须一起进入或一起退出。确定性测试验证了实际 `SessionRequest` 和会话重开后的事件，而不只验证某个检索函数的返回值。

## 排名、选择和复杂度

RRF 使用 `k=20`，每通道默认最多保留 32 个组。按融合得分排序后，对需求 d、组 g 使用 `r(d,g)=1/rank(d,g)` 作为覆盖效用。缺席候选的效用为 0。这个值不是事实置信度、适用概率或任务成功率。

选择集合 S 的目标是：

```text
U(S) = Σ_d weight(d) × [1 - exp(-Σ_{g∈S} r(d,g))]
```

同一需求不断增加近似结果时，边际收益递减。这样另一个尚未覆盖的需求能够获得预算。RRF 分数本身因偏置常数而过于接近，直接代入会使多个弱匹配被高估；首轮实验暴露了这个问题，现改为序位折扣。

约束同时包含组数和实际序列化字节数。Harness 的计量器序列化完整供给对象，包含版本、来源、条件、相关度和诊断；对事后才知道的诊断计数保留保守上界。选择器比较最佳可行单组和边际收益/增量字节的贪心解，再做有界的一换一改进。组合成本缓存避免反复序列化；只接受严格收益提升，避免交换循环。最终再校验实际字节数。没有全局最优保证，保守诊断空间也可能使结果略少于精确可装入数量。

默认最多 16 个需求、256 个候选组、4096 个编码块、2048 次组合计量。`selection_steps` 统计组合搜索的计量次数；数量已满时，剩余项直接归入数量省略，避免为诊断构造超出协议组数上限的供给。未满时还至多按候选数计量未选组，用于区分字节不足与数量/搜索限制。达到搜索上限返回已找到的可行结果，并设置 `search_exhausted`；不能把它当作穷尽搜索。

Dense 相似度采用归一化向量内积，计算量约为需求数 × 块数 × 向量维度，并有 3200 万维度乘加的工作上限。当前每次从授权快照重新构造候选，适合有界记忆集合；没有 ANN 索引或跨进程缓存。局部 LRU 缓存绑定作用域、编码器身份和表示文本摘要。每次仍先重做授权和时间筛选，缓存不能复活撤回的事实。

## 本地编码、失败与生命周期

可选 `OnnxE5MemoryEncoder` 使用 ONNX Runtime、tokenizers、NumPy。显式提供本地模型和 tokenizer；编码器不联网、不下载、不自动保存向量或正文。模型身份绑定实际读取文件的 SHA-256、输入前缀、池化协议和最大 Token 数。

E5 的 query/passage 前缀对中文也生效；编码器关闭 tokenizer 截断，超过模型 Token 上限时显式报错。使用 attention mask 对真实 Token 的隐藏状态做均值池化；检索器校验输出数量、维度、有限值、非零范数，再归一化。

一个有界 worker 串行执行本地推理。取消时必须等待已提交批次退出，随后传播 `CancelledError`；取消关闭操作也会等待已拥有的工作。这是协作式取消，20 秒总时限不是硬抢占承诺，清理可能超过它。宿主通过 `async with` 拥有编码器生命周期。

`failure="lexical"` 可在编码失败或语义容量超限时回退到逐需求 BM25，并记录原因；`failure="raise"` 则使该次来源供给失败。授权失败、总超时、取消不会被伪装成成功的词法降级。候选合并或来源总体容量超限仍显式失败。

## 实验与真实限制

2026-11-07 使用公开手写语料 `examples/fixtures/task_memory_retrieval.json`，20 条事实、18 个事实组、16 个请求，包含 18 个正向需求和两个没有相关记忆的负例。语料和标签在首次运行之前冻结，标签只用于评分，未进入检索器。

所有策略使用同一 SQLite 数据、时间、来源、每案例组数上限及 16000 字节总供给预算。各案例的向量缓存为空，共享已加载模型。下面是一次本地 CPU 运行；延迟不含模型加载，不代表稳定性能基准。

| 策略 | 事实召回 | 完整需求覆盖 | 无关事实数量 | 负例正确不召回 | 平均供给字节 | 平均耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原拼接 BM25 | 55% | 55.6% | 11 | 0/2 | 2518 | 1.4 ms |
| 逐需求 BM25 + 覆盖选择 | 50% | 50.0% | 12 | 0/2 | 2916 | 5.4 ms |
| Dense + 覆盖选择 | 75% | 72.2% | 10 | 0/2 | 3208 | 205.4 ms |
| Hybrid + 覆盖选择 | 60% | 61.1% | 10 | 0/2 | 3099 | 209.4 ms |

事实召回按预期事实 ID 统计；完整需求覆盖要求该需求的所有标签都存在，包括例外；无关数量按实际送入供给的非标签事实统计。没有生成模型，不测回答正确率。组数限制和字节预算相同，但来源内部序列化结构不同：新策略按完整供给对象保留诊断预算，旧策略沿用旧组召回预算；本次全部实际供给都远低于总预算，比较主要受组数限制。

必须保留的失败结论：

- 本地 E5 当前表示和参数下，三个中文查询英文记忆的案例全部未命中；模型名包含 multilingual 不构成实际效果保证。
- 两个无答案案例全部误召回。固定 `dense_floor=0.75` 不是经校准的拒答门槛；E5 余弦偏高，不能把“超过阈值”当成已经找到了适用记忆。
- Hybrid 在个人住址、饮食例外等案例被词法噪声影响，弱于 Dense；逐需求词法也未优于原基线。融合不是免费收益。
- 首轮使用 RRF 值作为覆盖效用时 Hybrid 只有 50%；根据本开发集诊断后改为序位折扣达到 60%。这是开发集上的机制修正，不能称为盲测提升。
- 本阶段证明了“可选机制可执行、上下文信号不丢失、部分检索案例有收益”；尚未证明稳定的语义拒绝、开放任务收益或复杂记忆推理能力。

## 启用与复现

```bash
uv sync --extra local-memory
uv run --extra local-memory python examples/task_memory_retrieval.py \
  --model /absolute/path/model.onnx \
  --tokenizer /absolute/path/tokenizer.json
uv run pytest tests/memory tests/harness/test_task_model_view.py tests/harness/test_work_dependencies.py
```

输出包含数据摘要、模型身份、依赖版本、策略参数、每个案例选择的公共事实 ID、字节与耗时。模型文件不随仓库分发。真实编码实验需本地模型；默认测试使用有故障注入能力的替身，不依赖网络或付费模型。

宿主接入时，在编码器打开后创建 `TaskMemoryRetriever(encoder=encoder, policy=MemoryRetrievalPolicy(mode="hybrid"))`，传给 `HarnessMemory(..., retrieval=retriever)`。AgentHarness 应在编码器的 `async with` 内运行并先关闭。模型缺失时可选择不配置 retrieval，继续使用原路径；不要伪装成已运行语义检索。

## 下一小步

优先研究并实现带拒绝能力的候选重排与适用性判断：将“词面相似”“语义相关”“条件满足”“足够回答”分开，使用独立数据集验证错误接受率与漏召回代价。先解决本次暴露的跨语言和负例问题，再考虑扩大记忆规模或接入更多存储。不能仅调高阈值使这两个负例通过，就宣称拒绝机制成熟。
