# 完整记忆召回与上下文接入

本次把记忆形成后的消费路径接入 `SessionEngine`：每次模型决策前，从宿主授权的记忆作用域召回当前相关事实，再与历史、工具证据共同竞争 Context 预算。设计记录见 [ADR 0042](decisions/0042-完整记忆组召回与上下文交付.md)。

## 为什么必须按组交付

假设库中有“文档默认中文”和“README 使用英文”。逐条 top-k 可能命中一般规则，却丢掉词面得分低的例外；即使两条都召回，逐标量截取也可能把 English 与 README 条件分开。此时模型看到的内容看似明确，实际上已经改变了原规则。

`recall_groups` 将同一作用域、记忆类型、主体、谓词的全部可见成员组成一组。条件和值不参与分组键，因此一般规则、条件例外和争议值能够同行。有效时间和知识时间先过滤：已撤回、尚未生效、已经到期或当时尚不知道的版本不能冒充当前事实。未知起点默认不包含，可由宿主显式选择包含。

组键使用规范化字段的精确值，不承担实体消歧或任意谓词同义判断。如果形成阶段把同一关系写成两个不同谓词，组闭包无法自动跨越它们。

## 一次请求怎样流转

1. `SessionEngine.send` 接受任务；每次 `build_control` 使用当前任务与已接受 NeedLedger 的信息需求调用 `ContextSource.retrieve`。它不是后台任务，也不会自动写记忆。
2. Harness 的 `MemoryContextSource` 已由宿主绑定 `MemoryAccess`、`MemoryScope` 和时间策略。它把各需求文本按确定性份额装入最多 2048 字符的检索词，调用 `SQLiteMemoryStore.recall_groups`。原任务和完整需求不被截断，查询只承担候选发现。
3. SQLite 在同一读事务中取得 head、进行授权和双时间筛选、加载所有可见成员。超过扫描数量或字节容量就失败，避免在截断集合上伪称“完整”。BM25 在已授权快照中计算，组分数取最高成员分；重复成员不会通过累加提高组排名。
4. 组排名后才应用 limit 与字节预算。每组携带完整 `MemoryVersion` 与全部 `MemorySource`，组过大则整体省略，分别记录数量和字节限制的省略数。旧 `recall` 保持逐条行为；新方法中的 limit 是组数。
5. Harness 将各组投影为 `ContextBundle`。Core 只承载低信任数据与内容无关的 `ContextSupplyReport`，不依赖 Memory 实现。Context 从实际内容计算需求覆盖，每个 bundle 只有 raw 一种表示，参与已有的联合预算分配；不能被变成标量摘录。组可以整体落选，选择记录为 raw 或 omitted。
6. 编译得到 SessionRequest v6 与 ContextCompilation v7。Session 校验已选组的身份和内容摘要，先将请求快照与编译记录原子持久化，再交给模型。模型端收到普通观察数据；记忆不能修改系统指令、工具许可或完成验收。

一次编译内部冻结召回结果，反馈预算降级重编译使用同一结果；下一次模型决策重新召回。并发修订不改变已经记录的旧请求，下一次请求可以看到新 head。这是读取时的版本快照，不是发送瞬间与全部记忆写入的线性一致性。

## 怎样接入

宿主负责打开和关闭记忆存储，也负责授权。下面在已有 `provider`、`counter`、`tools` 的应用组合处显式启用：

```python
from pathlib import Path
from weavria.context import ContextCompilerConfig
from weavria.harness import MemoryContextSource
from weavria.memory import MemoryAccess, MemoryScope, SQLiteMemoryStore
from weavria.sessions import SessionEngine

scope = MemoryScope(tenant_id="tenant-a", kind="project", key="project-a")
access = MemoryAccess(principal_id="host-user", readable_scopes=(scope,))

async with SQLiteMemoryStore(Path(".weavria/memory.db")) as memory:
    source = MemoryContextSource(memory, access=access, scope=scope)
    async with SessionEngine(
        Path(".weavria/sessions.db"),
        model=provider,
        tools=tools,
        context_compiler=ContextCompilerConfig(window_tokens=32768),
        token_counter=counter,
        context_source=source,
    ) as engine:
        await engine.create("new-session")
        result = await engine.send("new-session", "为项目 README 选择语言")
```

`valid_at` 可注入时钟或固定的历史查询时间；`known_at`、`at_head` 可固定知识快照。默认只查询绑定的精确作用域，不隐式继承用户全局或其他项目的记忆。Session ID 不授予权限；需要多租户动态授权时，宿主应实现 `ContextSource`，在调用内验证身份并选择获授权的绑定，不能相信模型提供的 scope。

未配置来源时仍使用原 SessionRequest v5 序列化字节。新增来源时 Run 配置 v5 记录来源版本，Session 事件仍使用现有 v4 外壳；嵌套编译报告升级到 v7。没有数据库 DDL 迁移；旧程序不能读取新请求、编译版本或新增错误类别，需要升级。

本次全量 913 项测试、Lint、格式与类型检查通过。测试覆盖零分例外随命中成员召回、争议成员保留、精确授权、有效时间/知识时间、投影重建、容量失败、整组预算省略、v5 字节兼容、跨任务修订重新读取、取消清理、源结果绑定错误及编译事务失败阻止模型调用。真实模型结果与限制见 [记忆消费真实模型评测](记忆消费真实模型评测.md)。

设当前授权时间快照有 N 条断言、总文本 T、命中 G 个组。BM25 与分组需要扫描 T 和 N，既有成员排序最坏为 O(N log N)，组排序为 O(G log G)，内存受候选数与源字节上限约束。打包会反复测量完整 JSON，没有常数时间索引承诺；Context 再使用已有的有限工作量联合分配和 Token 计数。当前查询不是持久倒排索引，也没有向量召回。

本机合成探针：1000 条事实、100 个组、每组 10 条，十次召回中位约 42.8 ms、最大约 53.8 ms；选择 10 个完整组共 100 条，响应 70,852 字节，另 90 组因数量限制省略。此数字仅是当前机器的有界扫描测量，不代表生产吞吐或大库延迟。

取消沿 Run 传播；提交给 Memory worker 的读取先结束/清理，再传播取消。来源读取失败或容量不足不会被转换为空记忆并继续调用模型。`ContextSourceError` 保留原始异常原因；授权拒绝记为 POLICY_DENIED，容量超限为预算耗尽，存储/快照错误为新错误类别 CONTEXT_SOURCE_FAILURE，不伪装成编译器缺陷，也不公开底层私有路径。Session 记录事务失败时模型也不会收到未记录的请求。读取与发送之间可能发生记忆变化，记录的 head 和完整版本用于解释当时结果。

## 当前边界与下一步

- 默认不启用；没有全局自动读取、自动遗忘、向量检索或多作用域优先级规则。
- 完整性仅限同一精确键和查询时间下的可见成员，不能保证模型正确理解条件或一般语义等价。
- 太大的组整体省略；本轮没有让模型主动发现并回取被省略的记忆组。省略诊断保存在编译报告，模型不能据空结果推断项目没有规则。
- 来源描述、时间与内容摘要可以随组交付；跨 Session 回读原始事件仍需宿主授权的来源解析器，不能绕过现有会话隔离。
- 真实评测使用固定的规范化准入，验证下一会话的消费行为；自然语言形成质量仍须与此前形成评测分别看待。

下一小步应针对超大组和精确键漂移设计有界发现与回取，再用自然形成的记忆验证更长的实际任务；目前最直接的运行瓶颈还包括模型输出协议不稳定，不能用放宽 Schema 接受非法输出来掩盖。
